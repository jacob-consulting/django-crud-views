<interfaces>
CrudView.cv_get_action_label_mode(location, key, button=None, target_default=None) returns a mode. For context,
an own named view-map entry wins, then the supplied button override, then the selected whole ViewSet/settings map,
then target_default or the lazy context floor. The filter has no target, so supply only the first three arguments.
FilterContextButton.get_context(ViewContext) returns {cv_access: False} for a non-filter view or pinned filter.
Otherwise its context contains cv_key, cv_action_label, cv_icon_action, cv_filter_expanded, cv_url and template hooks.
_apply_label, _apply_variant and _inject_template remain the customization chain; stamp cv_label_mode before them.
cv_button_class(location, slot, mode=None) and cv_icon_class(value, location) already provide the required seams.
ListViewTableFilterMixin.post persists filter_expanded; cv_filter_expanded reads that session state for the next GET.
The JavaScript handler already tolerates an empty icon NodeList and preserves state after a rejected POST.
