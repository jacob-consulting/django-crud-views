# Phase 6.1 Plan 01: Cancel link tracer, registry key and contract Summary

**A cancel form button configured through `Button(tag="a")` or `form:cancel-tag = "a"` now renders as a native `<a href>`. This works through the real crispy adapter, normalizer and form leaf. Plan 01 also adds the effective `cv_tag` field to `FORM_LEAF_KEYS`, the `form:cancel-tag` class-table key (default `"button"`) and check error `crud_views.E365`.**

## Accomplishments
- Tracer: one configured cancel travels adapter -> `cv_button_data(raw, "form")` -> bundled leaf as a native link. The anchor gets the cancel destination as its `href`, keeps id/classes/label-mode body/icon/title, and omits `type`/`name`/`value`/`data-cv-cancel-url`.
- Validation policy (D-01 to D-04, D-09, D-11, D-12):
  - An explicit invalid tag always raises `ValueError`, at construction and in the normalizer. List/dict values raise `ValueError`, not `TypeError`.
  - An explicit `"a"` raises unless the control has cancel kind plus native type `button`.
  - A selected invalid table value raises in strict mode, or logs and selects `button` otherwise. This happens even without a destination or when disabled.
  - A valid explicit tag skips the table entirely.
- Effective tag (D-06, D-08, D-10, D-14): `cv_tag` is `"a"` only for selected `a` with a non-empty destination and no emitted `disabled` (presence semantics, case-insensitive). Every other form button gets `"button"`, and all prior fields are kept.
- Registry and checks (D-13): the default table now has 74 keys. Theme and project precedence work through both registration paths. W362 accepts only the exact key. Invalid strings give E365; non-strings give E361 only. Errors are still reported when an explicit tag overrides the table during rendering.
- Public contract (D-16): the `cv_tag` row is in the form-leaf table, the anchor branch is described, and E365 is in the check reference and the `check_button_classes` docstring.

## Decisions Made
- Eligibility is semantic kind `cancel` plus native type `button`. It never depends on the name, the URL or the adapter class identity, so `Button` subclasses are eligible.
- `FORM_TAGS` and `CANCEL_TAG_KEY` are in `button_classes.py`. That module is importable before `django.setup()` and serves both the check and the normalizer.
- In Plan 01 the anchor emits `cv_flat_attrs` unfiltered. Filtering of button-only attributes and extra `href` (D-05/D-07) belongs to Plan 02 Task 1.
