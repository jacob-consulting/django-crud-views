# Phase 6.1 Plan 02: Cancel link attribute safety and compatibility Summary

**A cancel link now has exactly one `href`: the escaped cancel destination. Extra `href`, the WHATWG button-only attributes, `name`/`type`/`value` and the `data-cv-cancel-url` handler marker are dropped in any letter case, but only when the final tag is `a`. Tests now prove this on real crispy renders, custom templates, owners, adapter copies and the four package form pages, and the default goldens are byte-identical.**

## Accomplishments
- **Attribute inventory (anchor only).** These are dropped case-insensitively:
  - `command`, `commandfor`, `disabled`, `form`, `formaction`, `formenctype`, `formmethod`, `formnovalidate`, `formtarget`
  - `name`, `popovertarget`, `popovertargetaction`, `type`, `value`
  - `href` and `data-cv-cancel-url`
  - leftover case variants of the generated `id` and `class`, and of `title`/`data-cv-tooltip` in icon mode
  - Retained: `target`, `rel`, `autofocus`, `aria-*`, other `data-*`, and the caller's `title` outside icon mode. All keep flatatt's existing boolean/value serialization.
- **Fallback parity.** Missing or empty destinations and an emitted `disabled` render byte-identical to the unconfigured button, extras included. An ordinary submit is never filtered.
- **Presentation parity.** The link body, id, classes (with `css_class` and the host icon class), title, tooltip marker and `aria-label` are the same as the button's in label, both and icon modes, for inline and host icons.
- **Escaping.** Hostile, marked-safe, template-looking and lazy values are decoded exactly once to the original text and create no nodes or attributes. The raw opening tag carries exactly one `href`.
- **Compatibility evidence (D-16, D-17):**
  - The unchanged old `CUSTOM` fixture renders the same fields under a configured link.
  - A separate tag-aware fixture receives the effective `cv_tag`, with explicit > subclass > bundled precedence, `%s` pack substitution and the empty-template fallback.
  - Owner-selected label modes, interleaved shared helpers, original and deep-copied adapters before/inside/after `override_settings`, filter-helper layout copies and legacy `add_input()` controls all stay independent and quiet.
- **Real pages.** The create, update, delete and workflow pages each render exactly one `a#button-id-reset`. It is located inside the form that owns the native action, found by that action's expected id (review A5), and it links to the page's existing destination. After the scoped settings exit, the default golden bytes return (review A8). The configured delete page still deletes with its native submitter, and filter Apply/Reset keep their golden bytes.
