# Phase 6.1 Plan 03: Cancel-link publication and acceptance record Summary

**The cancel-link opt-in is now documented with recipes that the tests run as written. The docs cover the theme registration, the project setting, the per-form `get_cancel_button_kwargs()` hooks, a layout `Button(tag="a")` and a tag-aware `PillCancel` template. A new jsdom regression shows that `viewset.js` never intercepts an unmarked anchor. The full automated gates pass. Real-browser acceptance is still pending UAT.**

## Accomplishments
- **`buttons.md` "Cancel links" section.** It is the canonical reference and covers:
  - the values (`"button"`, `"a"`, `None` inherits) and selection order (explicit `tag=`, then `form:cancel-tag`)
  - four executable fences: `myapp_theme/apps.py`, `settings.py`, `forms.py` and a custom layout with a new-tab variant
  - eligibility (kind `cancel` plus native type `button`), validation, E365/E361 and the strict or logged render
  - the destination/disabled fallback, the link's attribute set, and the retained `cv_type`/`cv_name`/`cv_value`/`cv_cancel_url`
  - native navigation, including the explicit `target="_blank"` plus `rel="noopener"` advice
  - the trusted-destination boundary (HTML escaping is not URL validation) and the helper-input boundary (validated, never a link, no automatic migration)
- **Corrected claims.** The Forms bullet no longer says a layout button is always a `<button>`. The Literal text list now notes that `tag` is never an attribute and that `data-cv-cancel-url` becomes the `href` of a link.
- **`theme.md` section "Cancel links in custom form-button templates".** It contains the `PillCancel` class and a `cv_tag`-branching template. It explains that old button-only templates keep their `<button>` and `data-cv-cancel-url` navigation, and that precedence and `%s` substitution are unchanged.
- **CHANGELOG.** A new Added entry covers the key, the keyword, `cv_tag` and E365. The existing Form buttons Breaking entry gains one sentence: a `tag` keyword is no longer an attribute. This is paired with `migrating-1.0.md`, which explains the reserved `tag` keyword (rename to `data_tag`) and adds an optional "Cancel links" subsection (no action on defaults, plus the tag-aware template path).
- **JS regression.** 10 new cases cover label/icon/both link bodies × anchor/label/icon targets, plus a marked button next to a link. They sit before the final `loads without jQuery` test and do not reload the script.
- **`06.1-VALIDATION.md`.** It now records:

## Decisions Made
- **`tag` change filed as Breaking.** Before this phase, 0.30's `get_cancel_button()` passed kwargs to crispy's `Button`, which rendered `tag="x"` as an attribute. A project returning `tag` from `get_cancel_button_kwargs()` now gets `ValueError`. That is a behavior change, so it is recorded in the existing Form buttons Breaking entry and paired with migration guidance (CLAUDE.md rule). The Submit/Button/Reset adapters themselves are new in Unreleased.
- **Own section for the cancel template recipe.** The `PillSubmit` extraction (`(code,) = FENCE.findall(...)`) parses the whole `##` section, so the cancel recipe got its own `##` section.
- **Real base classes in tests.** The form recipes are base classes, so the tests use them as a project would (`type("F", (CancelLinkForm, AuthorForm), {})`) rather than restating their code.
