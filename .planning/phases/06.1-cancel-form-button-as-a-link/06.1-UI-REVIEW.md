## Top 3 Priority Fixes

1. **WARNING — The feature has no visible home in the example app** — A user (or the UAT tester) cannot see a cancel
   link anywhere: `grep -rn "cancel-tag" examples/` returns nothing, and `06.1-VALIDATION.md` tells the tester to
   write a scratch settings module. — Add one example page that opts in, e.g. in `examples/bootstrap5/showcase/`
   (a `CancelLinkForm` subclass per the `forms.py` recipe in `docs/reference/buttons.md`) or
   `CRUD_VIEWS_BUTTON_CLASSES = {"form:cancel-tag": "a"}` in `project/settings_demo.py`, and link it from the
   "The code behind this page" panel. This also gives the pending UAT steps a concrete URL.
2. **WARNING — Browser acceptance (D-14 / D-06) is still unobserved** — No-JS click, Enter on a focused link,
   middle-click/new tab and the disabled fallback are only proven by markup and jsdom; the Experience pillar cannot
   go above 3 until they are seen. — Run the five steps in `06.1-VALIDATION.md` § Browser acceptance and record the
   result there, or add a Playwright smoke in `tests/js/` / `nox` that loads the rendered create page with
   `javaScriptEnabled: false`, clicks `a#button-id-reset`, and asserts `page.url` ends with `/library/author/`.
3. **WARNING — Docs recipes mislabel the cancel link** — `docs/reference/buttons.md:513-518` and the per-form recipe
   use `Button("reset", "Back", tag="a", ...)`. The package renders this control as "Cancel" everywhere
   (`src/crud_views/lib/crispy/form.py:76-80`), the slot is `form:cancel`, and a link that reads "Back" next to a
   "Save" button implies history navigation rather than abandoning the form. — Use `"Cancel"` in the recipes (keep
   `name="reset"` since the generated id `button-id-reset` is a published contract) and add one sentence that the
   name only feeds the id.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

Evidence:

- Rendered label on every package form page is "Cancel" (`cv_action_label` from
  `CrudView.get_cancel_button_context()`, translatable). Rendered output, both configurations:
  `<span>Cancel</span>` — `scratchpad/link-create.html`, `default-create.html`.
- "Save" / "Delete" / "Cancel" are generic by the pillar's grep list, but they are the conventional CRUD verbs and
  are not the phase's concern (unchanged since Phase 6).
- WARNING: docs recipes use `Button("reset", "Back", tag="a", data_cv_cancel_url="/authors/")`
  (`docs/reference/buttons.md:513-518`). "Back" is a different promise from "Cancel" (see Fix 3).
- WARNING (minor): the generated id of the cancel is `button-id-reset` on a control that resets nothing
  (`form.py:77`, `name: "reset"`). Pre-existing crispy convention, now exposed on an `<a>` too; the docs call it
  out only implicitly ("The generated id is crispy's `<type>-id-<slugified name>`", `buttons.md:575`).
- Good: the Cancel-links section explains `target="_blank"` + `rel="noopener"` and the trusted-destination boundary
  in plain words (`buttons.md:545-556`).

### Pillar 2: Visuals (4/4)

Evidence:

- `cmp default-create-desktop.png link-create-desktop.png` and the mobile pair: byte-identical PNGs. The anchor
  branch of `src/crud_views/templates/crud_views/tags/button/form.html:1-2` emits the same class list
  (`{% cv_button_class 'form' cv_key cv_label_mode %}` + `cv_css_class` + `cv_icon_class`) and the same body
  (`<i class="fa-solid fa-xmark" aria-hidden="true"></i> <span>Cancel</span>`) as the button branch.
- Focal point: Save (`btn btn-primary`) before Cancel (`btn btn-secondary`) in `FormActions`; unchanged.
- Icon-only mode: the anchor keeps `title="…" data-cv-tooltip="form"` and the `visually-hidden` label span
  (`form:hidden-label`, `button_classes.py:91`), so the accessible name survives (`form.html` line 1, shared body).
- Semantics: no `role="button"` is added to `a.btn`. That is the correct choice here — the element navigates, and
  AT announcing "link, Cancel" is honest. Noting it so nobody "fixes" it to Bootstrap's generic `a.btn` advice.
- Observation (pre-existing, outside phase): the rendered create/update/delete pages contain a nested `<form>`:
  `view_create.content.html:5` opens `<form class="cv-form" …>` and the crispy helper emits its own
  `<form method="post">` inside it (`link-create.html:401` and `:411`, with two CSRF inputs). Browsers drop the
  inner start tag so it renders, but it is invalid HTML. Identical in the default capture, so not scored here.

### Pillar 3: Color (4/4)

- `grep -c "btn-" form.html` → 0: colours come only from the class table (`form:cancel = "btn btn-secondary"`,
  `button_classes.py:57`). `form:cancel-tag` is a structural key, not a class string, and is validated as such
  (E365, `button_classes.py:294`).
- No hex / `rgb(` literals in the leaf or in the touched Python.
- Accent usage on the page is unchanged: one `btn-primary` (Save) per form.

### Pillar 4: Typography (4/4)

- `grep -o "fs-\|fw-\|text-\(xs\|sm\|lg\)" form.html` → nothing. Both branches share the label/icon body, so
  size/weight are inherited from `.btn` exactly as before.
- Mobile capture: label wraps identically to the button (pixel-identical).

### Pillar 5: Spacing (4/4)

- No margin/padding/gap classes in the leaf; the anchor sits in the same `FormActions` wrapper
  (`<div class="mb-3"><div class="">…</div></div>` in `link-create.html`).
- `a.btn` and `button.btn` share Bootstrap's `.btn` padding/line-height; verified by the identical captures.

### Pillar 6: Experience Design (3/4)

State coverage (code-derived; interaction capture off):

| State | Handling | Evidence |
|---|---|---|
| Enabled cancel with URL, `a` selected | native `<a href>` | `button_data.py:246-276`; rendered `link-create.html` |
| Missing / empty URL | falls back to `<button>` | `_selected_form_tag` + D-08 tests (`test_button_data.py`) |
| `disabled` (any case, any value but False/None) | falls back to native disabled `<button>` | `_emits_disabled`, `button_data.py:278` |
| Button-only attrs / extra `href` on the link | dropped case-insensitively | `_ANCHOR_DROPPED`, `button_data.py:77-95` |
| JS interception | none: `viewset.js:36-43` only matches `[data-cv-cancel-url]`, which the anchor omits | rendered anchor has no such attribute; jsdom cases in `tests/js/viewset.test.js` |
| Invalid configuration | strict: raises; else logs + button; E365 at check time | `button_data.py:259-262`, `button_classes.py:294` |
| Keyboard | `<a href>` is natively focusable/Enter-activatable | Bootstrap `.btn:focus-visible` ring applies to anchors; NOT observed |
| New tab | middle-click / context menu native; `target`/`rel` preserved | docs recipe; NOT observed |

Findings:

- WARNING: every browser-dependent behaviour the phase exists for (no-JS navigation, keyboard, new tab, disabled)
  is still "pending UAT" (`06.1-VALIDATION.md:192-209`, SUMMARY 03 "Pending Human Verification"). Markup is
  convincing, but the pillar is scored on interaction, so 3 not 4.
- WARNING: discoverability — nothing in `examples/` opts in, so the showcase app still demonstrates only the JS
  button (Fix 1).
- Minor: the docs recommend `rel="noopener"` for `target="_blank"`; `rel="noopener noreferrer"` is the safer default
  when the destination may be cross-origin (`buttons.md:518`, `:548`).
- Minor: `javascript:` destinations are passed through by design (documented trust boundary, `buttons.md:551-555`).
  Acceptable because destinations come from `reverse()` in the package hooks, but a one-line system check or a
  `_selected_form_tag`-level assertion rejecting `javascript:`/`data:` schemes in `cv_cancel_url` would make the
  anchor branch safe even for careless `get_cancel_button_kwargs()` overrides.
- Good: an unsaved-changes guard is not expected here (the button never had one either), and the delete page's
  cancel link does not interfere with the confirm checkbox + Delete submitter (`link-delete-desktop.png`;
  `test_configured_delete_page_still_deletes_with_its_clicked_submitter`).
