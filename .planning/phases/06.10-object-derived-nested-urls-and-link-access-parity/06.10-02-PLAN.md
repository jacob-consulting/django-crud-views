## Adapter mechanics

An explicit private helper can run a parent gate and then the public access hook, but that alone cannot prevent a cooperating custom cv_has_access(user, obj_B) from running the new public callable parent composition against B a second time. An explicit-only design would require changing public arguments, bypassing cooperative hooks, or removing the selected callable parent behavior. Retain the small ContextVar carrier for that compatibility seam, plus a forwarding private rendering adapter for create's existing special hook; ordinary inputs remain explicit and request-free ViewSet.get_url never reads it. C1-H1's certified availability adapter declares parent-gate ownership in the frame and performs its own mandatory parent check, including when custom cv_has_access does not delegate. This records control-flow ownership, not cached permission results.

Open one scope around one URL/access/state action assembly. Match by target class, user identity and original object identity; store the rendering view and explicit child-parent role. Stock cv_get_router_and_args/cv_get_child_url publish the exact selected resolution. A matching frame with no publication lazily invokes the resolver using its rendering view and page scope; a missing/mismatched frame returns no resolution and must never borrow another frame's page kwargs. It does not parse arbitrary custom URLs or certify them. Such overrides retain routing responsibility; plan 04 certifies their exact candidate.

ContextVar values are immutable frames. Publishing replaces the frame rather than mutating a frame shared by copied contexts. The manager always resets its original token in finally. The owner thread and asyncio task identities prevent an inherited/copied frame being consumed by another concurrent execution owner. A nested scope restores the outer frame. No user permissions/results are stored. A user/target/object mismatch returns no matching frame and uses normal resolution/fallback behavior.

The existing custom cv_has_access override runs exactly once with its original arguments. Guardian's cooperative super() path reads the matching resolution in plan 03. Existing custom overrides that intentionally do not delegate retain responsibility for their policy. State and label hooks still receive their established action object; nested create remains the existing explicit parent-state exception. No class attribute mutation, temporary monkeypatch or second invocation of access to recompute another parent.

Scope roles (C1-H3): SiblingContextButton keeps raw current-URL ancestor kwargs and calls access with obj=None; do not install a destination-parent permission frame around that no-object check. FilterContextButton remains its existing collection URL with no row and no new access gate. ParentContextButton keeps its current-URL parent object for the public hook and the current ancestor kwargs for routing. For a middle-tier parent collection, bind its target's remaining page ancestor chain in a scope rather than deriving ancestry from a potentially divergent parent-row FK. For object parent targets, preserve the current URL-parent identity. Test a three-level fixture where page ancestor A differs from the parent row's related ancestor B; collection href and gate remain A. D-10 is checked before ordinary matching-frame parent resolution whenever obj=None.

Ordinary action and column URLs retain strict error behavior from plan 01: null/unscoped parent outcomes raise ValueError; invalid inputs and custom exceptions propagate unchanged. They do not become hidden/disabled actions. ViewSetKeyFoundError remains the action-skip/detail-column missing-target seam, and missing/falsey cv_get_cls_assert_object assertions remain ViewSetError. Protected previews own the optional display policy separately.

Rendering cost contract (C2-M01): navigation_preservation_queries in tests/test1/test_nested_url_rendering.py measures actual in-scope multilevel list action rendering for N=1/4, with the same fixed action set, separate fresh ORM, creation-cached and select_related rows. Keep query capture around URL/action assembly distinct from row fetching, permission SQL and labels. Use plan 01's measured pre-change baseline and publish exact numeric ancestry counts and deltas.
