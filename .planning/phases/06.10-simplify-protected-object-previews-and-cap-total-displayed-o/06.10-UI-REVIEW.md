## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1 — inherited wording tension, nonblocking:**
  `src/crud_views/templates/crud_views/snippets/delete/related_objects.html:20` says related objects “will also
  be deleted” immediately beneath a blocked-deletion warning. Both screenshots exhibit this tension. The
  contract explicitly preserves that string and the full aggregate summary, so it is not a Phase 06.10
  deviation. If a later copy change is authorized, consider conditional language for a blocked operation and
  update translations/contract together. Do not change the summary to displayed counts.
- **WARNING C2 — inherited generic dismissal, nonblocking:**
  `src/crud_views/templates/crud_views/tags/alert.html:5` uses translated “Close”. This agrees with the approved
  checker flag and has an accessible label; no new icon-only unlabeled control was introduced. A future
  shared-component copy review could distinguish alert dismissal from closing a modal.
- Exact D-13 sentence appears once under the truncation guard at `related_objects.html:5`; generic hidden
  blocker recovery guidance is present at line 13. `protected_objects.html:1` renders full escaped labels.
  Empty cascade details introduce no generic “No data” message. German rendering/catalog results are recorded
  in Plan 04; native-speaker quality is unverified and is not inferred from exact-string tests.

### Pillar 2: Visuals (3/4)

- **WARNING V1 — changed-state evidence gap:** `tests/browser/protected-delete.cjs:221` captures only modal
  click cases, whose scenario is finite-exact. Both inspected images therefore lack the new shortening
  notice. They establish neither its visual priority relative to danger nor translated/long-text composition.
  This is also explicitly acknowledged in 06.10-ACCEPTANCE.md. Follow priority fix 2 before human sign-off.
- Both images visibly show the same stock/copied composition: a centered white modal, strong danger heading,
  two plain blockers, separate two-book summary, and nested Publisher/Book cascade anchors. The escaped
  malicious-looking label remains readable text. No confirmation form or Cancel appears inside the modal.
  The blocked warning is prominent without relying on color alone.
- **WARNING V2 — inherited capture noise, nonblocking:** a faint “Delete” tooltip remains visible behind the
  modal over the originating table action in both images. The capture waits for `.tooltip.show` to disappear
  (`tests/browser/protected-delete.cjs:224`), which need not establish completion of a fade/removal. At the
  next capture, wait for the tooltip to be removed or fully transparent. This does not obstruct the preview
  and is not evidence that a blocked deletion action exists inside the modal.

### Pillar 3: Color (4/4)

- **Positive finding:** `related_objects.html:10` uses the existing error frame; lines 5, 18, 20 and 25 select
  semantic warning frames for distinct states. Four warning call sites do not mean four simultaneous alerts:
  the complete/incomplete summary branches are mutually exclusive. The inspected finite-exact state has one
  danger and two warning frames. No new hardcoded color or primary-color utility is introduced in these leaves.
- Two cascade anchors are visible per inspected modal; neither protected label is blue or underlined.
  `related_objects_tree.html:5` preserves native underlined anchors through host CSS. Danger/warning backgrounds
  remain distinguishable and text/icons/headings provide non-color signals.
- The white modal, neutral backdrop/chrome and localized blue anchors follow the contract's qualitative
  60/30/10 intent. That ratio is explicitly not an area quota; large semantic warnings are not accent overuse.
  No fresh contrast measurement, dark-mode or assistive-technology certification is claimed.

### Pillar 4: Typography (3/4)

- **WARNING T1 — visible baseline discrepancy with uncertain cause:** both retained images have visibly
  monospaced-looking body labels and headings. UI-SPEC prescribes the inherited system-ui/platform sans-serif
  stack. `tests/test1/app/templates/app/base.html:14` loads Bootstrap 5.3.3, as does the example base at line 16;
  the changed delete leaves add no font-family override. The cached Bootstrap CSS declares its normal sans
  stack. The available report records no actual rendered-font measurement, so this review cannot attribute
  the appearance to product CSS, platform fallback or capture environment. Resolve attribution as priority 1;
  do not silently count these images as proof of the expected glyph metrics.
- `tags/alert.html:4` supplies semantic strong headings; the leaves supply no new font-size/weight classes.
  In the reviewed alert region the declared distribution is one inherited body size and two weights (regular
  content, bold headings); compact/large action sizes are not exercised by these blocked screenshots. Visible
  headings and labels remain legible with clear weight contrast. No ellipsis, clamp or uppercase transform
  was added. Page/modal title typography remains an explicitly excluded inherited scale.

### Pillar 5: Spacing (4/4)

- **Positive finding:** `related_objects.html:3` has one `mb-3` utility; shared `tags/alert.html:4` uses one `me-2`
  icon gap. The four delete leaves introduce no arbitrary px/rem spacing, fixed height, per-row gap or new
  breakpoint. `related_objects_tree.html:9` retains native nested-list indentation; protected labels retain ul/li.
- In both inspected modals, alert edges align, padding is consistent, sections have clear gaps and the nested
  Book row remains visually subordinate. The escaped label wraps at a natural boundary without overlapping
  the alert frame. No clipping is visible at 1280×900 for these contents.
- This score is limited to the declared preservation contract and inspected state. Unlimited/deep lists,
  narrow viewports and unusually long unbroken strings were not visually inspected. The contract preserves
  existing host overflow behavior and introduces no universal word-breaking guarantee; do not invent one.

### Pillar 6: Experience Design (3/4)

- **WARNING X1 — acceptance gap, not demonstrated navigation failure:** the four UI-kind confirmations and
  three unresolved presentation probes remain pending. Human keyboard acceptance also remains pending.
  `tests/browser/protected-delete.cjs:234` directly focuses the anchor before Enter: valid activation evidence,

- Source review confirms visibility filtering precedes selection (`src/crud_views/lib/views/delete.py:319`),
  protected entries have null URLs (line 258), and optional cascade URL work follows selected trees (line 329).
  Complete blocking is captured before filtering (line 318). `view_delete.content.html:15` guards the whole
  form independently of displayed labels, while lines 5–12 separate incompleteness, protection errors and
  preview inclusion. The tree anchor at `related_objects_tree.html:5` has no AJAX/modal trigger attributes.
- Fresh read-only validation of the retained report passed: 45 exact required cases, current source/recipe
  hashes, screenshot hashes, status, and owned cleanup. This comprises 36 state cases, eight click/Enter
  cases and a repeated navigation. It verifies finite/exact/overflow/exhausted/hidden/unlimited/preview-off/
  escaping/link-off behavior on stock/copied pages/modals, with blocked forms absent and native Book
  document navigation. These are retained automated executions, not a new browser run by this auditor.
- Loading/error/empty handling is appropriate to the server-rendered scope: ordinary document loading is
  preserved, protection errors and generic hidden-blocker warnings remain, empty detail frames are omitted,
  and no optimistic delete or fabricated retry state was added. A spinner or new client error boundary is
  not required by this contract. Write-time enforcement is supported by the recorded Python gates; this
