## 06.12-01

**Summary.** Plan 01 composes three real seams: the single request-free renderer at `src/crud_views_workflow/lib/mixins.py:37-42` (also consumed for history at lines 75-76), the layered registry at `src/crud_views/lib/button_classes.py:150-170`, and the one-line leaf at `badge.html:1`. The app-owned default seam is new code, but the lifecycle rules now line up with Django's actual registry behaviour. The plan is executable as written; the residual risk is in the in-process lifecycle tests, not the product design.

**Strengths.**
- Presence-before-normalisation is the right primitive: `get_button_class()` collapses missing, `None` and non-str to `""` (`button_classes.py:165-170`), so D-02 versus D-03 can only be distinguished by membership in `get_button_classes()`. The plan says exactly that.
- The `:icon-host` / `:container-single` special branches at `button_classes.py:300-320` test `key.endswith(":icon-host")`; a custom colour `workflow:badge-icon-host` ends in `-icon-host`, so the plan's claim that it stays an ordinary badge slot holds.
- The two inventory tests the plan says it must adjust are the real blockers: `test_none_or_empty_settings_add_no_overrides` asserts `get_button_classes() == DEFAULT_BUTTON_CLASSES` (`test_button_classes_checks.py:257-261`) and the template literal scan subtracts `DEFAULT_BUTTON_CLASSES` (`test_button_classes_templates.py:51-57`). The 88-key sentinel at `test_button_classes.py:108-120` is untouched by app defaults.
- The `btn` token guard (`test_button_classes_templates.py:22-48`) only matches `btn*` tokens, so stock badge/table strings on the workflow AppConfig need no exemption.
- The tracer is feasible with existing fixtures: `wf_activate` requires no comment (`tests/test1/app/models.py:127-134`), `campaign_new`/`user_campaign_change` exist (`conftest.py:559-563, 663-668`), and `Campaign.STATE_BADGES` covers five of the eight colours (`models.py:113-118`).
- StrEnum formatting: `f"workflow:badge-{klass}"` with a `BadgeEnum` member yields `workflow:badge-success`, so the key construction works without `.value`.

**Concerns.**
- **MEDIUM — in-process `override_settings(INSTALLED_APPS=…)` removal case.** Django's own docstring on `set_installed_apps` warns that re-population re-imports models and cannot be replayed safely; it also re-runs `ready()` for every app in the new list. Upstream `ready()` hooks are import-only (`crud_views/apps.py:8-9`, `crud_views_workflow/apps.py:9-10`) so they are idempotent, but the test project installs guardian, polymorphic and object-detail apps (`conftest.py:51-72`) whose hooks were not inspected. The plan already allows subprocess probes "where model registry isolation requires them"; the removal/restoration case should default to the subprocess path and keep in-process overrides for the identity-replacement case with the same app list plus a temporary AppConfig.
- **MEDIUM — the hook also reaches list tables.** `CampaignTable.state = tables.Column(accessor="state_badge")` (`tests/test1/app/views.py:604`) means registry classes change the campaign list page too. That is desired under D-04, but Plan 01 never asserts it and no golden covers the list column, so a regression there would be silent.
- **LOW — class-attribute mutability.** Declaring the mapping directly on `CrudViewsWorkflowConfig` as a plain dict is "immutable by convention" only; a `MappingProxyType` costs one import and makes the "never mutate the source mapping" rule enforceable.
- **LOW — accepted consequence of C1-M2.** Raising from `get_button_classes()` means a colliding declaration breaks every page render and turns `manage.py check` into a traceback. The ledger records this as a deliberate choice; I note it so the public-surface handoff states it.

**Suggestions.**
- Add one assertion to the tracer for the campaign list page column, since the same renderer feeds it.
- Make the lifecycle test choose the subprocess probe for the removed-app case explicitly rather than leaving the fallback to executor judgement.
- Keep the collision exception message including both the app label and the key, as the plan says, and copy that wording into 06.12-PUBLIC-SURFACE.md.

**Risk: MEDIUM.** The product changes are small and traceable; the risk is concentrated in the registry lifecycle tests, which have a documented escape hatch.
