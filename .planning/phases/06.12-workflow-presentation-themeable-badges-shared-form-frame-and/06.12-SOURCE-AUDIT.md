## Planning choices and capability gates

- The ten literal defaults live directly on `CrudViewsWorkflowConfig.crud_views_button_class_defaults`.
  Research's separate data module was a proposal; an import-safe AppConfig declaration avoids another file.
  Core adds one private effective-default getter and a small snapshot tied to active app-map identity. No model
  imports, callbacks, duplicate registration stores or new general formatting/provider framework.
- The existing companion ready hook filters only new workflow registrations when the optional workflow app is
  absent. This preserves clean no-workflow configurations under the deliberately active-only W362 grammar.
  Plan 04 now publishes and executes that installed/absent condition as a public recipe (C1-M1).
- Review round 1 (`4716635`) retains first-lookup ImproperlyConfigured for malformed/colliding static app
  declarations, explaining check/render propagation without new diagnostics state (C1-M2). App-map identity
  detection makes added INSTALLED_APPS signal invalidation redundant, so Plan 01 removes it while preserving
  pre-ready and restoration guarantees (C1-M3). Tests restore the saved theme mapping before cache reset (C1-M4).
- Plan 05 corrects the Django 6.0 executable to the verified crispy-floor environment and labels crispy 2.0 /
  pack 2023.10 coverage (C1-H1). Mobile normal-table width is a lower bound, with equality only for fitting desktop
  data; local scrolling and no page widening remain required (C1-H2). The existing stock fixture's explicit
  Bootstrap 5.3.3 stylesheet is the browser asset authority (C1-M5). No task/wave/threat scope expands.
- Review round 2 (`052e3a6`), C2-M1: Plan 04 explicitly updates the existing public W362 table definition and
  Precedence formula, with documentation assertions and actual installed/absent custom-colour checker cases.
  New recipes alone are insufficient; the authoritative existing definitions must agree with Plan 01.
- API coverage detector ran over real phase scope plus plans: `detected:false`. No external API integration
  matrix is required. Existing theme asset loading is browser verification, not a new external service API.
- Assumption-delta detector matched `fallback`; Plan 01 records `no-change` to state/colour identity and promotion
  of no second identity model. The existing registry remains the class customization path.
- Schema push: no model/schema/migration change is planned. Package legitimacy: no package installation or
  upgrade task; reserved SC threats document the gate if execution scope later changes.
- Spec-less requirement probe skipped visibly: no phase requirement IDs to probe. No generated predicates or
  requirement-ID coverage is claimed. D-01–D-13 and all roadmap criteria remain mapped above.
- UI deterministic gate: frontend=true, hasUiSpec=false, block=false, hasFrontendEvidence=false. UI-SPEC is not
  a prerequisite; actual browser acceptance and human-check are explicitly planned.
- Knowledge graph absent; current tracked source and supplied PATTERNS/RESEARCH take precedence over older maps.
  API-SURFACE symbol hint was empty and is not exhaustive source authority.
- Estimate calibration: factor 1, sample_count 0, confidence low. Plan projections are 30k/19k/18k/16k/28k raw
