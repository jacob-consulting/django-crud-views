1. **C1 — Make the Tabler light-state label readable.** “New” is nearly invisible in both Tabler images.
   Make a bounded theme-owned decision for `workflow:badge-light`, using an existing legible neutral badge
   treatment or a foreground that works on the actual surface. Verify the result in the user's light/dark
   environments. Preserve the core default and registry/escaping contracts; do not silently redesign all badges.
2. **S1 — Apply the action gap to the container that directly contains the buttons.** The mobile Tabler submit
   and Cancel controls abut vertically. Correct the companion crispy pack's action-container styling so its
   existing `gap-2` intention produces separation after wrapping. Check horizontal forms and modal rendering
   before adopting the bounded pack change; a new workflow-only layout is unnecessary.
3. **E1 — Complete live keyboard and modal acceptance.** In both themes, tab to and scroll the history region,
   select a radio with the keyboard, submit/correct a required-comment error, and open/submit/close the supported
   modal while checking focus placement and return. Record actual outcomes; repair a proven accessibility defect
   at its owning layer. Programmatically assigning `scrollLeft` and requesting a modal fragment do not prove this.

## Detailed Findings

### Pillar 1: Copywriting (4/4)

**Positive finding — no copy deviation found.** `src/crud_views_workflow/lib/forms.py:20` supplies the exact
“Process Workflow Step” CTA; `:38` supplies “Add your comment…”; `:70` retains the required-comment correction.
`src/crud_views_workflow/lib/views.py:31` and `:37` retain object-specific success text and field labels.
The apparent LABEL/HELP placeholders in the form declaration are replaced in `views.py:68`; the screenshots
show real labels, not placeholder copy. Generic-label grep matches in shared components are not workflow defects.

`view_workflow.action.html:6` conditions the action heading/form and `:18` preserves the exact no-transitions
message. `view_workflow.history.html:3` omits the entire empty section, `:10` preserves all six column labels,

The Cancel transition choice is application data, distinct from the inherited Cancel navigation control;
this preservation phase does not authorize relabeling either. Long translations still require E2 review.

### Pillar 2: Visuals (3/4)

**WARNING V1 — weak visible mobile scroll affordance; needs_human_review: true.** All four images cut through
the Comment column at the right edge, with Timestamp offscreen. No persistent scrollbar is visible in these
captures. A reader may not discover how to read the remaining history. `view_workflow.history.html:6` supplies
a plain responsive wrapper; `tests/browser/workflow-presentation.cjs:100` proves movement by assigning
`scrollLeft`, not discoverability. The new local wrapper is correct; no before screenshot establishes a regression
in affordance. Review actual touch/trackpad/keyboard scrolling and native scrollbar visibility first. If users
cannot discover it, choose a minimal theme-owned indication while preserving the table-only scroll region.
Do not interpret a static screenshot's hidden overlay scrollbar as proof that scrolling is broken.

The principal hierarchy otherwise works: history precedes action in `view_workflow.content.html:3`, the stock
frame is undecorated (`src/crud_views/templates/crud_views/snippets/form_frame.html:1`), and the Tabler frame's
card/card-body encloses heading and form (`../tabler-test/src/crud_views_tabler/templates/crud_views/snippets/form_frame.html:3`).
The blue submit remains distinct from secondary navigation. No workflow-specific decorative panel or new
icon-only control was introduced. The faint badge is scored under Color, not counted again here.

### Pillar 3: Color (2/4)

**WARNING C1 — observed inherited badge legibility defect; needs_human_review: true.** The old-state “New” badge
is almost invisible in `workflow-tabler-normal-390.png` and all three rows of `workflow-tabler-wide-390.png`.
The DOM receipt confirms text exists with `badge bg-light-lt`; this is not empty data or an escaping failure.
The delivering slot is `../tabler-test/src/crud_views_tabler/buttons.py:10`. Stock's equivalent remains legible
with `badge rounded-pill text-bg-light` (`src/crud_views_workflow/apps.py:18`).

Provenance is explicit: the companion's pre-phase leaf at
`506ed891:src/crud_views_tabler/templates/crud_views_workflow/badge.html:3` used
`badge bg-{{ class }}-lt`. The new complete string preserves that exact light convention. This is an inherited
theme defect surfaced by review, not evidence that retiring the copied leaf changed its color. No numeric
contrast ratio was measured, so this review does not invent a WCAG ratio or claim a dark-mode test.

Color inventory: eight explicit stock semantic badge entries (`apps.py:12`) and eight actual theme entries
(`buttons.py:4`); normal screenshots show two status badges, wide screenshots six. These semantic colors are
allowed exceptions to the accent budget. In the workflow templates/default declarations, no new hex/rgb values
or colored history/action wrapper are present. Neutral surfaces dominate and the primary action carries the
main accent. The contract's 60/30/10 guidance is not a pixel-area quota. C1 alone prevents a color pass despite
otherwise correct registry and accent use.

### Pillar 4: Typography (3/4)

**WARNING T1 — intended-host typography acceptance is missing; needs_human_review: true.** The four screenshots
render with a conspicuous monospace appearance. `browser-evidence/05-03-fontconfig.json` resolves system-ui,
sans-serif and Arial to Fira Code in the test host. The browser receipt's computed font-family string names
the intended stack but does not establish which physical font rendered. This is an environment limitation,
not a new product font-family declaration or a reason to add a bundled font.

Source preserves the hierarchy: two workflow `cv_heading level=5` calls, ordinary form/table text and inherited
badge internals; zero explicit font-size/font-weight utilities or declarations were added in these workflow
templates. Core heading size-5 remains `h5` (`src/crud_views/lib/button_classes.py:23`). The contract retains
four stock reference sizes (14/16/20/28px), two reference weights (400/500), and explicit badge/header/theme
exceptions. Those are contractual values, not newly measured font metrics. No ellipsis or text clamp was added.

Check the user's normal browser at mobile and desktop widths with the declared host stack, including long
translated labels and errors. Until then, keep this score provisional and do not call the images universal
typographic approval. Preserve host font ownership rather than compensating for Fira Code in product CSS.

### Pillar 5: Spacing (2/4)

**WARNING S1 — observed wrapped controls have no vertical gap; needs_human_review: true.** In both Tabler images,
Cancel starts immediately beneath the primary button. The companion declares `form:actions = d-flex flex-wrap
gap-2` at `buttons.py:48`, but `../tabler-test/src/django_tabler/templates/crispy_tabler/layout/formactions.html:4`
places those classes on the outer footer while `:9` introduces the inner div directly containing both buttons.
The gap therefore separates outer flex children, not the wrapping buttons. Core
`src/crud_views/lib/crispy/actions.py:52` supplies the classes as configured; the owning issue is pack structure.

The same pack file is unchanged across companion `506ed891..b35bd3b`, and the old button mapping already used
`gap-2`. The mechanism is inherited; the newly adopted card reduces the available action width and exposes
wrapped behavior in these captures. No pre-phase image proves identical prior geometry. Fix the intended gap
at the direct button container, preserving the pack's horizontal-form/label structure and modal behavior.

Other phase spacing conforms: the stock frame introduces zero padding; wrapper and table default to
`table-responsive` and `table` (`apps.py:20`). Workflow templates add no arbitrary pixel/rem spacing, fixed
history heights, row gaps or breakpoints. Retained `col-1`/`col-3` cells and pack-owned badge padding are explicit
preservation exceptions. The large wide-history width is a deliberate long-data fixture, not a new fixed width.

### Pillar 6: Experience Design (3/4)

**WARNING E1 — keyboard and live modal behavior unverified; needs_human_review: true.** The scroller has no new
explicit focus/accessible-name contract in `view_workflow.history.html:6`. Whether native scrolling is reachable
and understandable must be checked in the supported browser; absence of a tabindex alone does not establish
failure. The runner's modal case (`tests/browser/workflow-presentation.cjs:254`) requests a generic fragment
over HTTP; it does not open a modal, exercise focus trapping/return or capture a loading state. Do not introduce
a new scrolling interaction solely to satisfy an untested assumption. Perform priority fix 3 and record results.

**WARNING E2 — seven visual backstops remain unaccepted; needs_human_review: true.** The retained captures show
normal/wide history and ordinary English choices only. They do not show the full long-translation/error/empty
or live-modal experience. Current badge equality is checked by parsing the renderer output into a detached
document (`workflow-presentation.cjs:246`), which cannot prove long current-state readability in its real host.
Complete the seven backstops below in both themes. Do not equate escaped text, no page overflow, or HTTP status
with readable and usable controls.

State implementation evidence is substantial: the full-page choices branch owns one POST form, one CSRF token,
and one crispy render (`view_workflow.action.html:8`); the no-choice branch omits those controls. Invalid POST
browser cases retain the form and required-comment error. Request regressions in
`tests/test1/test_theme_form_requests.py:201` cover retained values, invalid/success modal statuses and ownership.
The shared frame does not own a second form. The existing synchronous lifecycle and modal handling remain
authoritative; adding spinners, new confirmations or retry panels would contradict this preservation contract.
No new destructive operation or independent asynchronous region was introduced.
