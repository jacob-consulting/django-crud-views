## Responsive and Accessibility Contract

Use the existing responsive-table CSS on the direct wrapper. Preserve table/thead/tbody, header scope=col,
six columns and all existing cell classes. Heading and action area must never move inside the scroll region.
Preserve ordinary full-width table behavior; no display:block/table-width/nowrap workaround or page-wide scroller.

Plan 05 measures both actual stacks at 390x844 and 1280x900 after CSS/fonts load, including invalid POST output:

- Wrapper fills the available content width within 2px; table width is at least wrapper.clientWidth minus 2px.
- Desktop normal-data table and wrapper widths agree within 2px. At 390px there is no table-width upper bound:
  six-column intrinsic width may exceed the wrapper, but the overflow must stay local.
- Deliberately wide history has scrollWidth greater than clientWidth, computed horizontal overflow permitting
  scrolling, and observable scrollLeft movement. Document width is at most viewport width plus 1px.
- Wrapper contains only the table, placing its scrollbar directly below it. Heading/action ancestry proves
  both are outside. Disabling responsive classes deliberately removes that styling; geometry assertions apply
  to stock and delivered theme configurations, not arbitrary user-disabled/custom CSS.

Retain native radio/textarea/submit keyboard behavior, visible labels, label associations, focus styles and
existing modal focus behavior. Do not create a custom grid or suppress outline. Check usable local scrolling
and long translated labels during both-theme visual/keyboard review. If inherited behavior exposes a concrete
accessibility defect, record it and resolve its bounded scope explicitly; do not claim unperformed assistive
technology testing or silently introduce a new scrolling interaction.
