# Business-error literal rendering repair

The confirmed T-07 injection is repaired at `_check_transition_business` in
`src/crud_views_workflow/lib/execution.py`. The independent SECURITY verdict is
unchanged; phase completion remains pending the orchestrator's review.

## Cause and bounded change

`ValidationError` preserves SafeString messages, and crispy trusts those messages
when rendering field errors. Initial form cleaning and late execution refusals
both reach that renderer. The prior force-escaped preview did not protect POST
field errors.

The business-hook boundary now copies each error leaf after Django performs its
normal interpolation, converts the resulting string to an ordinary `str`, and
retains its error code. Interpolation must precede normalization: Python's plain
`"%(detail)s"` formatting can return a SafeString parameter itself. The copied
leaf has no params because they have already been applied; percent signs in the
result are never interpolated again. The caller's original exception, params,
and safety markers remain unchanged, and it remains the raised refusal's cause.
Order and transition-field mapping are unchanged. No HTML escaping is performed
early, so the normal renderer and preview force-escape each display literal text
once. Comment validation, forms/views, custom form errors, and exceptions from
transition/save/history/callback origins are unchanged.

Only the execution module and `tests/test1/test_workflow_buttons.py` changed.
No dependencies, rendering overrides, network endpoints, or schema changes were
introduced.
