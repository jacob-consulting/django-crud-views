## Detailed Findings

### Pillar 1: Copywriting (4/4)

**PASS:** `src/crud_views_workflow/templates/crud_views_workflow/widgets/transitions.html:8` preserves each full action label, escapes it, and supplies the conditional visible asterisk plus translated hidden `Comment required`. Line 14 renders one conditional legend; lines 9–10 retain separate help and ordered escaped reasons. Missing optional help produces no placeholder. The generic radio caption remains `Process Workflow Step` (`src/crud_views_workflow/lib/forms.py:27`); button mode suppresses only its generic action row (`forms.py:75`).

`src/crud_views_workflow/lib/views.py:32` retains success copy; lines 38–41 retain field labels. `view_workflow.action.html:18` preserves the no-steps message. All-blocked actions stay distinct from zero actions. Description/render tests exercise literal HTML-looking text, missing help, marker conditionality and raw retained values (`tests/test1/test_workflow_buttons.py:257`). Plan-05 German PO/MO/render evidence establishes integration, not translation quality. No generic-copy replacement or invented blocker wording was found.

### Pillar 2: Visuals (3/4)

**WARNING UI-02:** Screenshot inventory is restricted to four oversized invalid fixtures. The 375px modal image shows its title, long field label and beginning of guidance; it cannot establish the appearance of the action group below it. Ordinary enabled/blocked hierarchy and invalid recovery placement therefore need representative captures. This is a capture gap, not evidence of clipping.

**PASS:** Template lines 6–10 stack each caption, optional help and semantic reason list together. Full text is present, controls are not icon-only, required status is expressed in words, and the group has an accessible label (`transitions.html:3`). Existing page/history composition and modal title remain intact. The long fixture intentionally repeats adversarial content; its extreme vertical length is not an actionable design defect under a contract that forbids truncation or caps.

### Pillar 3: Color (4/4)

**PASS:** The new widget template contains **zero hardcoded color values**, one repeated semantic `form:submit` class-resolution site and one hidden-label class-resolution site (`transitions.html:8`). Cancel is supplied through the existing form action mechanism (`forms.py:75–86`). No transition-name-derived destructive color or variant API was added.

Captured disabled fills follow the stock Bootstrap treatment, while blocker text remains adjacent ordinary text. Error paragraphs use the inherited renderer, with browser assertions requiring visible dimensions/display (`tests/browser/workflow-validation.cjs:54–74`). No rule equates blue color alone with availability. The contract explicitly defines 60/30/10 as inherited composition rather than an area quota; counting repeated long-fixture buttons is not a valid palette violation. Host theme variables remain authoritative.

### Pillar 4: Typography (3/4)

**WARNING UI-03:** The retained visual evidence uses a monospace-looking face, and local fontconfig resolves both generic system-ui and sans-serif to Fira Code. This limits evidence for the contract's platform sans-serif baseline. No new production font-family declaration was found; do not fix this by imposing a library font or downloading a dependency without a separate need.

**PASS:** The new template has no explicit font-size or font-weight overrides. Three `form-text` sites cover guidance, per-action help and legend, preserving Bootstrap's 0.875rem/normal styling; captions and reasons inherit 1rem/normal, and renderer field errors retain inherited emphasis. Existing larger context action variants are not overridden. No line clamp, ellipsis or abbreviation is introduced. Actual font-family/size/weight/line-height assertions are absent from the receipt and should accompany the representative recheck.

### Pillar 5: Spacing (4/4)

**PASS:** Two `mb-3` template sites provide inherited 1rem group spacing (`transitions.html:2,6`); semantic lists retain inherited indentation. No new arbitrary pixel/rem gaps, fixed-height blocker box or fixed-width action card exists. `max-width:100%`, `text-wrap` and local `overflow-wrap:anywhere` protect action content; `forms.py:51–56` extends wrapping to stock transition/comment columns only in button mode.

All four retained long cases assert eight action entries, sixteen exact reasons, document width within viewport, element bounds within owners and zero clipped visible elements (`tests/browser/workflow-validation.cjs:175–215`). Both 375px and 1440px page/modal cases pass. Stock radio and custom layout ownership remain preserved; arbitrary third-party layouts are outside this wrapping guarantee. No tablet capture is claimed or required by this phase's explicit 375/1440 contract.

### Pillar 6: Experience Design (3/4)

**WARNING UI-01:** `keyboard-page` directly calls `.focus()`, records styles and presses Enter (`workflow-validation.cjs:308–312`). It neither reaches the button by Tab nor asserts visible focus; the retained values are `outline: none` and a transparent zero-size box shadow. Programmatic focus can legitimately differ from keyboard `:focus-visible`, so those values are not proof of a product focus defect. Add actual Tab-path assertions before claiming this part of the contract demonstrated.

**PASS:** Receipt cases prove explicit first/second action submission, required-comment whitespace rejection/recovery, implicit Enter on a custom input, textarea newline without POST, omission of unauthorized actions, zero versus all-blocked behavior, page 200/modal 422 refusals, modal load/replacement/success, retained custom fields and non-submitting Cancel. Loading remains native navigation or the existing modal lifecycle as specified; no new spinner is needed.

`widgets.py:16–18` prevents label clicks from activating a submit control; `widgets.py:30–47` builds descriptions; `forms.py:61–63` gives each button-form instance its own namespace. `forms.py:88–109` associates renderer errors without discarding application descriptions. Browser assertions validate owner/token counts and references against the full document. `views.py:94–105` reloads persisted context after late refusal and follows the invalid path. No success callback/redirect is inferred from a failed POST.

The Django 4.2/crispy-bootstrap5 2026.3 unreferenced vendor `_error` wrapper duplication is explicitly documented in plan 05; owned IDs and all reference targets remain checked. It is not a universal document-uniqueness pass for that combination. Native disabled semantics and readable adjacent reasons are implemented, but human screen-reader discovery/announcements remain untested.
