- **D-01:** Add empty `card_root` and `card_header` blocks to `crud_views/tags/card.html`.
  `card_root` is the first child of the card root, before the body. `card_header` is inside the body,

## Summary

Implement this as two empty template extension points plus a documented, executable consumer configuration.
Keep production Python navigation and permission code unchanged. The existing card template owns the action
group, overflow forms, and action container; the focused inheritance test already compares inherited markup
against the stock rendering after masking CSRF tokens. [VERIFIED: src/crud_views/templates/crud_views/tags/card.html:1–15;
tests/test1/test_card_blocks.py:37–62]

The main documentation trap is the custom table origin. Automatic cancellation accepts only the conventional
list/card keys, plus detail for object forms. A table registered under the agreed custom key needs explicit
allowed-origin configuration on its destination forms to return there. Successful saves still default to cards.
This is supported configuration, not a defect or a reason to expand scope.
[VERIFIED: src/crud_views/lib/view/cancel.py:37–49; src/crud_views/lib/view/base.py:929–980;
tests/test1/test_cancel_state.py:428–439]

**Primary recommendation:** Keep one small phase with a template/test change and a recipe/integration-test/docs
change. Run the existing card, action and cancellation regressions; add no package, routing abstraction, or JS.

### Pattern 1: Preserve output with empty extension points

The stock template's exact block names are
<!-- DATA_0d98c9d3_START -->
`card_title`, `card_content`, `card_actions`.
<!-- DATA_0d98c9d3_END -->
[VERIFIED: src/crud_views/templates/crud_views/tags/card.html:6–13]

Place the new empty tags next to existing markup rather than introducing extra rendered newlines/indentation.
Assert direct-child ordering for the root insertion; assert that the header insertion precedes, and is outside,
the heading. Keep actions inherited. Django supports parent blocks overridden by child templates and default
variable escaping. [CITED: https://docs.djangoproject.com/en/5.2/ref/templates/language/]

Existing golden normalization collapses whitespace, so goldens alone cannot prove byte-identical unused-block
rendering. Add a comparison that preserves rendered whitespace and normalizes only nondeterministic tokens;
do not regenerate goldens to accept noise.
[VERIFIED: tests/test1/test_action_menus_golden.py:53–56; tests/test1/test_card_blocks.py:44–47]

## Common Pitfalls

1. **Whitespace-only regression:** New empty block lines can still add output whitespace. Compare stock output
   directly; use unchanged goldens as a second check.
   [VERIFIED: tests/test1/test_action_menus_golden.py:53–56; tests/test1/test_card_blocks.py:44–47]
2. **Custom table origin silently falls back:** Automatic keys exclude the custom key. Add explicit configuration
   only to the recipe's form and test both default and opt-in behavior.
   [VERIFIED: tests/test1/test_cancel_state.py:428–439; src/crud_views/lib/view/cancel.py:37–49]
3. **A route-only test misses the deliverable:** Exercise actual rendered links, permissions, Cancel and successful
   POST, not only class attributes or URL reversal. This is acceptance scope. [VERIFIED: phase CONTEXT.md:48–50]
4. **Shadowing theme templates:** An overridden template must itself expose the new blocks; upstream edits do not
   amend the consumer file. Document this instead of implementing a downstream theme.
   [VERIFIED: phase CONTEXT.md:27–29,137–138]
5. **Wrong-checkout verification:** A reusable editable environment may import a different checkout. Force current
   source on PYTHONPATH and print the imported package path. The research probe verified the current checkout
   before running tests. [VERIFIED: 2026-11-06 runtime probe and baseline command]
