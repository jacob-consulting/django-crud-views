## 06.14-01

### Summary
The plan's premises hold against source. The stock card template is exactly 15 lines with the three existing blocks at `src/crud_views/templates/crud_views/tags/card.html:6-13`; the root `<div>` opens at line 4 and the body `<div>` at line 5, so inserting `{% block card_root %}{% endblock %}` and `{% block card_header %}{% endblock %}` directly after those opening tags on the same line is byte-neutral when unused. The existing inheritance test already does the drop-and-compare the plan extends (`tests/test1/test_card_blocks.py:51-62`), and lxml's `drop_tree()` folds the removed node's tail into the parent, so a root/header insertion followed by the stock whitespace compares equal after removal. The plan is bounded, test-first, and leaves every Python path untouched.

### Strengths
- **Insertion positions are unambiguous in the real template.** `card.html:4` (root), `:5` (body), `:6` (heading via `cv_heading`). Placing `card_header` at the end of line 5 keeps it a direct body child and outside the `<h5>`, satisfying D-01.
- **Existing comparison machinery is reusable as claimed.** `_markup()` masks only the CSRF value (`test_card_blocks.py:44-47`); `_card()` selects `.row > div > div` (`:37-41`), which is unaffected by children inserted inside the root.
- **Byte-identity test is feasible with the real context.** The `cv_card` tag renders the card with `{"object","view","request"}` and `request=` (`src/crud_views/templatetags/crud_views.py:640-650`), so a test can render the frozen pre-change string with the same inputs and compare raw output.
- **Breadcrumb/actions ownership stays in the parent.** `card.html:8-13` keeps `cv_render_list_action_form` and the container include inside `card_actions`; consumers extending the template never copy plumbing (D-02).
- **Doc delta is correctly targeted.** `docs/reference/card-list-view.md:196-204` currently lists three blocks and says a theme "keeps the three block names"; D-03's five-name rewrite is exactly the stale text.

### Concerns
- **MEDIUM — Engine choice for the frozen-template comparison is unspecified.** Rendering `CARD_TEMPLATE_BEFORE_INSERTION` via `django.template.Template(...)` bypasses the configured engine's context processors, so `{% csrf_token %}` in the included hidden forms renders empty and the comparison will spuriously differ (this exact trap is documented in `crud_views.py:645-648`). The test must use `engines["django"].from_string(...)` and `.render(context, request=request)`. The plan says "equivalent real request/view/object context" but does not name the mechanism.
- **LOW — Doc fence attribute must exist on the test model.** `test_documented_insertion_blocks` renders the exact published fence against `Author`. If the example interpolates something like `{{ object.status }}`, Django renders an empty string and position assertions pass vacuously while escaping assertions have nothing to check. The example should use `first_name`/`last_name`/`pseudonym` (the contract Plan 02 already states).
- **LOW — Locmem loader needs an explicit `loaders` list.** `tests/test1/conftest.py:83-98` uses `APP_DIRS: True`; an `override_settings(TEMPLATES=...)` that adds a locmem loader must drop `APP_DIRS` and list `filesystem`/`app_directories` loaders explicitly, or Django raises `ImproperlyConfigured`. Executor detail, but worth naming in the task.
- **LOW — Changelog deferred to Plan 02.** Plan 01 adds two public block names with no release entry; D-10 is only satisfied once 02-02 lands. Acceptable within one phase, but Plan 01 alone is not shippable.

### Suggestions
- Name the engine API in 01-02's action (`engines["django"].from_string`, `render(..., request=request)`) and assert the rendered string contains a non-empty `csrfmiddlewaretoken` before masking, so a silent empty token cannot make both sides equal.
- Have the doc example interpolate `{{ object.pseudonym }}` (or another real `Author` field) and assert the rendered text, not just element presence.
- Add one assertion that `card_header` content is not a descendant of `h5` using `h5//*` XPath, matching the D-01 wording "must not become part of the heading".

### Risk Assessment
**LOW.** Two zero-output blocks in a 15-line template, with the comparison test proving byte-neutrality. The only real pitfall is the template-engine/CSRF trap above, which is detectable by the test itself.
