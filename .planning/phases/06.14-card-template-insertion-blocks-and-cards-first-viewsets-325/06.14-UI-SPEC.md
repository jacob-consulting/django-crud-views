# Phase 06.14 — UI Design Contract

This is a preservation contract for the already approved phase, not a new visual design.
The only production change is two empty Django template blocks. The second deliverable documents and tests
existing cards-first/table-secondary configuration. D-01–D-12 in 06.14-CONTEXT.md and the two approved PLANs
remain authoritative; this document adds no requirements or implementation work beyond them.

D-11 delegates example details to the planner. D-12 prevents reopening settled design without a concrete
contradiction. None was found. The generic UI template's new spacing, palette and typography selection steps
are inapplicable to this unchanged-default scope: preserve existing class resolution and consumer CSS instead
of prescribing new numerical tokens. Evaluate those dimensions against preservation, not a new design system.

## Structure and Interaction Contract

| Surface | Contract |
|---------|----------|
| card_root | First insertion point immediately inside the existing card root, before the body; empty by default |
| card_header | Immediately inside the existing body, preceding and outside the existing heading; empty by default |
| Existing blocks | Preserve card_title, card_content and card_actions, their defaults and relative placement |
| Inherited actions | Keep parent-owned inline/menu rendering, linked hidden POST forms, methods and nonempty CSRF inputs |
| Shadowing theme | Replacement templates must expose all five blocks; adaptation remains a separate downstream task |
| Cards route | Recipe registers cards as list with empty cv_path |
| Table route | Recipe registers the real table as table at table/, with cv_home_key=list |
| Switch | Follow existing permission-aware context actions; preserve model records and existing semantic icons |
| Home | Existing default home button targets list; do not claim cv_home_key controls that button |
| Breadcrumb | Container points to registered list/cards; table's current breadcrumb item remains unlinked |
| Save | Default successful create/update POST persists data and redirects to list/cards independently of Cancel |
| Direct/static Cancel | Resolve to accessible list/cards using existing rules |
| Origin-aware Cancel | Explicit recipe allow-list permits table; restore its captured query using existing signed origin handling |
| Destination denial | Preserve actual request authorization as well as action visibility; inaccessible origin falls back, and no accessible origin/fallback means no Cancel |
| Query state | Ordinary switches do not copy general filter/order/page state; existing persistence remains view-key scoped |
| Compatibility | Preserve conventional table-first configurations and conditional card-only list-to-card fallback |

Sources: D-01–D-09, both PLANs, RESEARCH.md Architecture Patterns, card template and existing
card/list/action/Cancel documentation. No router, permission, default-list, icon-registry or JavaScript change
is authorized. Existing accessible labels, heading semantics, focus behavior and DOM attributes remain intact.
This is preservation of existing behavior, not an accessibility certification.
