## Summary

Implement a small configuration selector inside the existing object-detail mixin, followed by the existing parser and resolver. Preserve the property adapter as the dynamic override seam. Change only the selector label expression upstream. The current path reads "raw = self.property_display", then decides whether the entire list is typed from "isinstance(raw[0], PropertyGroupConfig)"; the parser itself currently assumes every entry is a dict. [VERIFIED: src/crud_views_object_detail/lib/mixins.py:36-46; src/crud_views_object_detail/lib/config.py:92-94]

The smallest coherent parser change is per-entry normalization: retain typed groups and construct typed groups from dicts. It handles mixed ordering without a parallel parser or new configuration object. Keep structural checks structural: reuse the existing checks for every declared mapping value and attach model-specific locations. Do not run the full resolver at startup. This recommendation follows D-03, D-08–D-12 and the inspected existing normalization seam. [VERIFIED: src/crud_views_object_detail/lib/config.py:71-94; src/crud_views_object_detail/lib/mixins.py:61-122]

**Primary recommendation:** three bounded implementation units: upstream behavior/checks/tests, public documentation/changelog, then required downstream adoption/verification/report. Downstream completion has an environment prerequisite: the configured extension source is missing and its widget app prevents Django startup; preserve that as an explicit execution preflight rather than reporting a successful downstream check. ### Runtime selection and override compatibility

Read the effective property first, then branch only when it is a mapping. That preserves overrides returning lists even when their declared static configuration differs. Use exact type lookup and raise Django's ImproperlyConfigured with the actual model label and view identity when absent. Do not call get_object(), query ContentType, inspect MRO, or write onto the class. Keep the current None-to-empty behavior and empty list behavior. An empty mapping may pass structural checking but every runtime object must raise the missing-entry error; document this deliberately. These are recommended delegated mechanics implementing D-04–D-07; they are not new product decisions. [VERIFIED: phase context D-04–D-07 and Planner discretion]

A list-only view can currently override get_object_for_detail() without setting self.object. Preserve this path by accessing self.object only in the mapping branch. [VERIFIED: tests/test1/od/test_object_detail_view.py:78-102, quoted behavior "return Info(text=\"Widget\")"]

## Common Pitfalls

1. **Mixed groups only work in one apparent order.** Typed-first returns a dict unparsed; raw-first raises. Fix the existing parser rather than duplicating mapping parsing. [VERIFIED: mixed-order probe above]
2. **Validating only the first subtype.** Include a non-first malformed value, malformed key, bad property, and icon warning; assert model and index in diagnostics. [VERIFIED: phase context D-08/D-09]
3. **Checks accidentally execute dynamic code.** Guard view construction, model construction, dynamic properties, and object-loading hooks in tests; invoke class checks only. A clean startup check does not certify override results. [VERIFIED: phase context D-07/D-10/D-11]
4. **Acronyms or translations degrade.** Test lower-case first letter plus an internal acronym, already-uppercase acronym, lazy translated label under an active locale, and unchanged IDs/order. Capfirst preserves the remainder in the installed implementation. [VERIFIED: inspected Django capfirst source; phase context D-01]
5. **Wrong-checkout green tests.** Verify import roots of all affected apps in the same process environment used for consumer tests. Existing consumer sources explicitly use "../django-crud-views". [VERIFIED: downstream pyproject.toml:19-21]
6. **Premature report resolution.** The report is already modified (31 insertions, 2 deletions observed); patch only findings 10–11, retain existing work, and record actual passing evidence only after the environment blocker is resolved. [VERIFIED: downstream git diff --stat probe; phase context D-16]
