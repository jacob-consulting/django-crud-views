# Phase 06.16 — UI Design Contract

This contract records the approved object-detail presentation changes in CONTEXT.md D-01–D-20,
REQUIREMENTS.md ODV-01–ODV-05 and plans 01–03. It adds no product decisions or implementation scope.
Choice text, selected help text and exact empty textual values change; existing row structures, layout
selection, navigation, styling, permissions and custom-template ownership remain authoritative.

This is a contract for implementation and verification, not evidence that every behavior has shipped.
It was written during execution gate remediation. No browser review or human acceptance is claimed.
The existing Phase 06.14 preservation contract provides the local precedent for documenting inherited
design tokens without imposing new typography, spacing or palette rules on consumer applications.

## Value and Interaction Contract

### Choice text and ownership

1. Use choices_display=True by default for supported scalar model fields, including string, integer and
   boolean choices and terminal fields reached through single-object FK/O2O paths. Use the terminal owner's
   display method, preserving unknown-code fallback and application overrides.
2. A missing scalar related owner stays empty. A present owner with a declared non-empty label for a blank
   stored value displays that label. Choice presentation precedes the exact empty-text check.
3. Collection paths remain collections at zero, one and many members. Preserve their values, order,
   duplicates and existing rendering. Computed properties/methods and view-callable fallback do not acquire
   inferred choice metadata. Terminal relation fields themselves retain existing relation rendering.
4. Preserve dispatch ownership: resolved badge, then explicit property template, then choice-text rendering,
   then ordinary type/fallback rendering. An explicit type does not disable choices; choices_display=False
   is the raw escape hatch. Custom template packs retain their documented char/default fallback.
5. ResolvedProperty.value and template value remain raw. choice_label carries the separate display result;
   display_value selects that result when present, otherwise raw value. Missing supported scalar choice
   owners may project empty text while retaining their original raw None or list result.
6. Badge color functions/maps, badge label maps and links receive stored values. A truthy explicit badge
   label wins; empty mapped labels retain existing fallback behavior. A raw opt-out does not cancel an
   explicit badge label. Preserve the badge's existing raw-None guard and empty-string behavior.
7. Preserve translated text and Django escaping. Choice labels resolve under the language active during
   resolution; already-resolved labels are retained. Supported lazy help/detail follows rendering language.

Sources: D-01–D-04/D-13–D-15; plan 01 and plan 03's public template-context contract.

### Help-text selection

Project setting CRUD_VIEWS_OBJECT_DETAIL_SHOW_HELP_TEXT defaults to False. View attribute
cv_object_detail_show_help_text defaults to None, inheriting project policy; a boolean overrides it.

| Property detail | Required result |
|-----------------|-----------------|
| Omitted or None | Inherit view, then project, then False |
| True | Terminal field help text, or no detail if absent |
| False or empty string | Suppress detail regardless of inherited policy |
| Non-empty string or supported lazy translation | Explicit text regardless of inherited policy |

Automatic detail uses only terminal field metadata; intermediate relation help never leaks into a terminal
or computed value. Missing related instances do not remove available terminal metadata. Computed paths can
still use explicit descriptions. Already-resolved groups retain their selected detail when rendered under
another view/project policy. Normal views, raw tags and direct resolution use the same policy entry point.

Keep each layout's existing presentation: card-rows uses the existing property-detail button with tooltip
title and aria-label; table-inline/split-card use small text below; striped-rows uses its inline detail;
accordion/tabs-vertical use their existing small block; list-group-3col retains its detail column and icon.
Suppressing detail removes only the existing conditional detail content/control. Do not move descriptions
to a new location, replace tooltips, change keyboard behavior or modify tab/accordion adapters.

Sources: D-05–D-08; seven existing layouts/*/property.html files; plan 02.

### Exact empty text

Stock char, text and fallback default leaves render the existing muted em dash only when final display_value
is None or the empty string. Preserve 0, False and whitespace-only strings as values; do not trim or use a
broad truthiness test. Preserve text's linebreaks/linebreaksbr configuration and ordinary autoescaping.
Rows, titles, explicit detail and configured ordering survive empty values. No new badge/relation/collection
empty-value policy is introduced. Explicit custom templates retain raw value access and output ownership.

Sources: D-09/D-10/D-14/D-15; plan 02 task 3. These are required final behaviors, not a statement that the
partially executed source already implements every case.
