## Interaction Contract

### Accordion initial state and subsequent actions

1. Reuse the existing GroupPresentation.selected projection. Exactly the first group of every nonempty
   component starts open. A selected button omits collapsed and has aria-expanded=true; its panel has
   collapse show. Later buttons include collapsed and aria-expanded=false; later panels omit show.
2. Preserve scoped IDs, button aria-controls, panel aria-labelledby and the component's data-bs-parent.
   Standalone render_group retains its selected one-group projection and has no absent-parent reference.
3. A zero-group component emits no group control or panel. A one-group component starts open and may
   close. With multiple groups, opening another closes the prior group; closing the open group may
   leave all groups closed. Independent components keep independent state.
4. Apply the same server-rendered initial state to pages and newly loaded modal content. Refresh or
   fresh content starts first-open again. Existing Bootstrap Collapse behavior owns switching and
   transitions. Add no JavaScript solely to establish initial visibility.
5. Consumers order the most useful group first. No configurable selected field, start-collapsed option,
   open-all mode, persistence, accordion controller rewrite or change to value/group resolution.

Sources: D-01–D-05/D-13; ODT-01; presentation.py; accordion templates;
tests/test1/od/test_object_detail_identity.py and test_layout_a11y.py; Plan 01.

### Tabs, focus and theme boundaries

1. Add cv.adapters.tab.init(element) and dispose(element) through cv.bootstrapAdapters(namespaceOrProvider).
   Resolve the namespace for every call. Initialization calls Tab.getOrCreateInstance(element), never
   show() or focus(). Disposal calls Tab.getInstance(element)?.dispose(), never a constructor.
2. Missing Tab or an absent instance during cleanup is a no-op. Errors from a present provider,
   component or adapter remain visible. Do not mask a broken custom adapter as missing-library fallback.
3. Route object-detail tabs.js through the adapter; remove its direct globalThis.bootstrap lookup.
   Retain factory defaults and early/late override conventions. No Tabler fallback, Bootstrap alias,
   namespace registry, additional dependency or change to other adapters.
4. Only triggers owned by data-cv-od-tabs tablists are dispatched. A marked root is included; closest
   tablist boundaries exclude unrelated/nested unmarked tabs. No owned triggers means no adapter lookup.
5. Preserve cv.initObjectDetailTabs(root=document), DOMContentLoaded, already-ready document handling,
   and cv:modal:loaded. Repeated setup preserves instance identity, selection, focus and single handlers.
6. Dispose owned old modal instances on cv:modal:unload while their controls remain attached, before
   content replacement. Initialize new content after insertion; preserve page and unrelated instances.
7. Preserve first-tab selection: selected control active/aria-selected=true/tabindex=0; other controls
   aria-selected=false/tabindex=-1. Preserve role=tablist, vertical orientation, reciprocal controls/labels,
   and the selected panel active/show. Panels retain role=tabpanel and tabindex=0.
8. The UI library owns keyboard activation and focus. ArrowDown and ArrowUp wrap through vertical tabs;
   Home activates the first and End the last. Active control, visible panel, aria-selected and tab stops
   agree. Initialization must not steal focus; distinguish this from existing modal-shell focus handling.
   No custom key handler is added. Missing Tab does not promise usable keyboard fallback tabs.

Sources: D-06–D-12/D-14–D-16; ODT-02–ODT-04; Plan 02; tabs-vertical templates;
tests/js/adapters.test.js, tests/js/object-detail-tabs.test.js and tests/browser/presentation.cjs.

### Acceptance and documentation boundaries

Real-browser acceptance must inspect active and inactive Tab instances under stock Bootstrap and a
namespace named tabler with globalThis.bootstrap absent. Clicking alone is insufficient. Cover keyboard
wrapping, Home/End, ARIA/tab stops, insertion focus, repeat initialization and attached-instance disposal
before real HTTP modal replacement. Use existing harnesses; preserve asset version/hash/SRI checks.

For three tabs, the acceptance sequence is ArrowDown: 1,2,0; ArrowUp: 2,1,0; End/Home/End: 2,0,2,
starting at index 0. One/two-tab cases retain correct wrapping. One ArrowDown after repeated setup must
produce exactly one activation. Source assertions and JS mocks cannot establish real-library acceptance.

Update copied accordion recipes and executable adapter examples, including complete custom adapter maps
and the custom-insertion initializer recipe. Pair changed-default/template/custom-adapter migration in
CHANGELOG.md and docs/migrating-1.0.md. Preserve prior value/help-text and exact-model-group contracts.
No downstream release/adoption, cross-browser certification or human/assistive-technology approval is implied.
