## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Nested Guardian dispatch state gate used the overridable parent hook**
- **Found during:** Task 1, once the parent-none fixture setup was repaired (previously masked).
- **Issue:** 06.18-03 changed `GuardianParentPermissionMixin.dispatch` to call `self.cv_get_parent_object()` for the no-object state gate. Before 06.18 the dispatch did its own lookup. A failing hook override meant for late context resolution therefore also broke dispatch: `test_list_create_control_late_parent_failure_skips_state_hook` returned 404/500 instead of 200.
- **Fix:** read the parent the ancestor guard resolved on this request (`_resolved_parent(self)`). This keeps D-51 identity reuse and leaves the hook to context rendering.
- **Files modified:** `src/crud_views_guardian/lib/mixins.py` (outside the plan's file list; a production consumer defect owned by 03, corrected as the plan's verification section directs).
- **Verification:**
  - The 2 cases are green.
  - `test_ancestor_guardian.py`, `test_ancestor_helpers.py`, `test_guardian_composition.py` and `test_action_enabled.py` pass (135).
  - The full suite is green.
- **Committed in:** `834b7482` (RED in `dbb1bb78`)

**2. [Scope note] `tests/test1/app/views.py` unchanged**
- 06.18-03 had already moved the shared Guardian Book to the default policy.
- The shared nested custom endpoints already carry exact action entries: E268 passes, the example check is clean and the full suite is green.
