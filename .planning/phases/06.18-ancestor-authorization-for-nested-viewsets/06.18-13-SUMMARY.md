# Phase 06.18 Plan 13: Guardian Missing Permission Key Gap Closure Summary

**A Guardian view whose `cv_permission` key is absent from its ViewSet's permission map now fails with a named `ImproperlyConfigured` (ViewSet, view key, permission key, `manage.py migrate`/restart hint) on its list and object request gates, and `cv_has_access` denies every actor. Before, guardian raised an opaque `TypeError`/`AttributeError`. This closes the code branch of G-06.18-2.**

## Decisions Made
- The error message mirrors `ancestors._permission_name`: `ViewSet 'x' view 'list': permission key 'view' is not in the permission map of ViewSet 'x' — if the model is new, run `manage.py migrate`; a server started before the migration may need a restart`.
- The vocabulary check stays after `_check_nested_auth`, keeping the default-database boundary order from 06.18-03.
- The following were deliberately left unchanged: `GuardianQuerysetMixin.cv_has_access` (it never reads the vocabulary), `GuardianCreateView.cv_has_access`, `GuardianViewSet`, the ancestor guard, and the strict helper `ValueError`.
- The test helper reads `viewset.permissions` before saving the cache. This makes sure the saved object is the populated vocabulary, so restoring it gives back `"view"` even though the deleted `Permission` row is still gone inside the test transaction.
