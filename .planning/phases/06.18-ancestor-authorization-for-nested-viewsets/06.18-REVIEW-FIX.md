## Fixed Issues

### WR-01: Test helper restores one ViewSet's cache while its row deletion affects every ViewSet on the model

**Status:** fixed (test-only change; no production code touched)
**Files modified:** `tests/test1/test_guardian_vocabulary.py`
**Commit:** 897d40d8
**Applied fix:**
- Test first: new `test_helper_restores_sibling_viewsets_on_the_same_model` makes the core `cv_author` ViewSet
  cold, reads its `permissions` inside `without_permission_key(cv_guardian_author, "view")`, and asserts that its
  cache is back to cold (`None`) after the block. Against the old helper it failed: `cv_author` kept the reduced
  `{add, change, delete}` vocabulary, which is the process-lifetime leak the review describes.
- `without_permission_key` now snapshots `_default_permissions` for every registered ViewSet whose `model` is the
  target's model (via `crud_views.lib.viewset._REGISTRY`) and restores all of them in `finally`. The snapshot is a
  list of `(viewset, cache)` pairs because Pydantic ViewSets are not hashable. A cold sibling is restored to cold,
  so it rediscovers the full vocabulary once the test transaction restores the row.
- The docstring now states why every same-model ViewSet is restored.
- Kept simple per the CLAUDE.md maintainability rule: one list comprehension and one loop, no new public API. The
  test module reads the private registry, as `test_workflow_execution.py` already reads `_default_permissions`.
