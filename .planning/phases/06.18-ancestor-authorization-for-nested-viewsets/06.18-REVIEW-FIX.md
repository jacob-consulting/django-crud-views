## Skipped Issues

### R1-IN-01: Already-defended-elsewhere — `_check_nested_write` re-tests `_is_nested_orm` after its only caller did

**File:** `src/crud_views/lib/ancestor_db.py:105` (caller `src/crud_views/lib/view/base.py:373`)
**Reason:** Neither check can be removed safely without adding code:
- The outer early return in `CrudView._cv_check_nested_write` is required. It runs before
  `self._cv_attachment_routes()`, and `CreateView._cv_attachment_routes` dereferences `self.cv_viewset.parent`,
  which is `None` on top-level views, and loads the parent object. Removing it would break every top-level create
  POST.
- The inner check is the documented contract of the boundary helper. Both the `ancestor_db` module docstring and
  the function's own docstring say "Top-level views return immediately". Removing it would make a future direct
  caller enforce the default-database rule on top-level ViewSets, which wrongly rejects a top-level write routed to
  another database.
- A single owner would need a lazy `related` argument (a callable) so the helper could check before the routes are
  computed. That is more abstraction than the duplicated one-line predicate, which costs nothing and is easy to
  explain. Per the CLAUDE.md maintainability rule, the code stays as it is. The reviewer filed this as Info for the
  same reason ("may legitimately gain direct callers").
**Original issue:** `_check_nested_write` returns early on `not _is_nested_orm(view)` although its only caller has
already returned on the same predicate.
