## Fixed Issues

### WR-01: `GuardianQuerysetMixin.cv_has_access` reads the vocabulary without the nested default-database boundary the core helper applies

**Status:** fixed: requires human verification (authorization logic)
**Files modified:** `src/crud_views_guardian/lib/mixins.py`, `src/crud_views/lib/ancestor_db.py`, `tests/test1/test_ancestor_auth_databases.py`
**Commit:** a4f84061
**Applied fix:** TDD. First added `test_guardian_list_access_helper_refuses_nested_shard_auth_records` next to the
Guardian object-helper case. With `Permission` reads routed to `shard`, the test expects
`adb.GList.cv_has_access(user, None)` to raise `REFUSED` with a warm vocabulary cache and again with a cold one
(`adb.gloc._default_permissions = None`). It also expects the top-level `adb.GTList` not to raise. The test failed
before the fix ("DID NOT RAISE"). The fix adds
`_check_nested_auth(cls, actor=user, model=cls.cv_viewset.model)` to `GuardianQuerysetMixin.cv_has_access`. The
order now matches its siblings: inactive-actor check, then the nested boundary, then the vocabulary read. It uses the
core helper's default `provider="model"`, because the read touches only the auth and content-type tables.
The module docstring of `ancestor_db.py` now lists "the list access helper" among the checks that call
`_check_nested_auth`. CHANGELOG.md is unchanged: the IN-02 entry describes missing-key denial, and the default-only
rule for authorization records is already published as a general 06.18 contract (`docs/reference/nested.md`,
"Databases").

### IN-01: `GuardianQuerysetMixin` docstring says "every active actor" but anonymous actors also get `True`

**Files modified:** `src/crud_views_guardian/lib/mixins.py`
**Commit:** 3296ff08
**Applied fix:** Rewrote the docstring paragraph to describe the actual rule. `cv_has_access()` returns `True`
without a model permission for every actor except an inactive authenticated user, and only when the permission key
is present. Anonymous actors are included, and their configured anonymous behavior applies at request time. The
code is unchanged.
