<objective>
Make `crud_views.lib.table.Table` honour a subclass's `Meta.sequence` (appending `actions` last unless the sequence
names it) and omit the `actions` column when the owning list view declares `cv_list_actions = None`, while tables
without a `Meta.sequence` keep today's order byte for byte and an empty list keeps today's (empty) column. GitHub
issue #337 is the public record (D-15); origin is tabler-test finding 26.

Purpose: a table author's declared column order was silently overridden by the unconditional
`sequence=("...", "actions")` default, and a read-only list (for example a Resource file list) could not get rid of an
empty "Actions" header without reaching into `Meta.exclude`. Both fixes live in `Table.__init__` behind two small,
independently testable helpers; nothing in views, templates, settings or the permission pass changes (CLAUDE.md
"Decision Rule: Developer Maintainability").

Output: `src/crud_views/lib/table/table.py` with `Table.cv_default_sequence()` and `Table.cv_exclude_actions(view)`,
the new test module `tests/test1/test_table_sequence_actions.py` (15 tests), one `### Changed` changelog bullet, the
`### Column order and the actions column` subsection in `docs/reference/list_view.md`, and the Resource docs example
switched to `None`.
