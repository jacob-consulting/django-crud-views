Close the two gaps recorded in `06.19-VERIFICATION.md` (status `gaps_found`, 6/8 truths) without widening the phase:

1. **Gap 1 (truth 1, review WR-01):** `Table.cv_default_sequence()` returns `(*declared, "actions")` for a
   `Meta.sequence` that contains no `"..."`, and django-tables2's `Sequence.expand` then appends its own `"..."`
   *after* `actions`, so every unlisted column renders after the actions column (`("last_name",)` renders
   `last_name, actions, id, first_name`). The goal text, D-01, the changelog bullet and the docs subsection all
   promise `actions` last. Fix: insert `"..."` before `"actions"` when the declared sequence has neither.
2. **Gap 2 (truth 4, reviews WR-02/WR-03):** the `exclude` merge splats the raw caller kwarg, so under
   `cv_list_actions = None` an explicit `exclude=None` raises `TypeError` and `exclude="first_name"` is iterated
   character-wise, re-exposing the column the caller hid (the outcome threat T-06.19-02 is marked closed against).
   Fix: normalise the caller kwarg (`None`/falsy -> `()`, `str` -> one-tuple) before the merge, then re-close
   T-06.19-02 in `06.19-SECURITY.md` against the new tests.

Purpose: both are reproducible public-API defects of `Table` (no code in this repository hits them today) and both
contradict decisions the user locked (D-01, D-05). Each fix is a few lines in the function that already owns the
rule, which is the simplest bounded solution under CLAUDE.md "Decision Rule: Developer Maintainability".
