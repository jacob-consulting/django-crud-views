### WR-01: `actions = None` on a subclass crashes with an opaque `KeyError` from inside django-tables2

**Files modified:** `docs/reference/list_view.md`, `docs/faq.md`
**Commit:** c570e17c
**Applied fix:** I used the review's minimum (docs) option, not the optional code guard. The "not supported"
sentence in `list_view.md` now names the symptom and the reason: it fails at render time with `KeyError: 'actions'`
because the default sequence still names the column. The FAQ entry on reordering and removing the Actions column
names the same `KeyError` next to the `cv_list_actions = []` note and points to `Meta.exclude`.

### WR-02: Changelog "Fixed" entry drops the upgrade consequence for existing `Meta.sequence` declarations

**Files modified:** `CHANGELOG.md`
**Commit:** 6157aed1
**Applied fix:** The entry stays under `## Unreleased` / `### Fixed`; it was not moved to Breaking, so
`docs/migrating-1.0.md` is unchanged. One sentence was added: an existing `Meta.sequence` that does not name
`"actions"` now takes effect and places the Actions column first among the columns it does not list, so add
`"actions"` where you want it. The `Meta.exclude = ("actions",)` guidance is kept.

**Files modified:** `docs/reference/resources.md`

**Applied fix:** `PublisherFileTable` in the example now declares

`PublisherFileListView` has a `# no row actions` comment again. The example now matches the FAQ's table-side
opt-out. The fenced example was checked with `ast.parse`.
