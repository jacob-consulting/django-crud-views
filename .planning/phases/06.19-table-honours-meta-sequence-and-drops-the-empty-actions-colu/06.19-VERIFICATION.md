Two reproducible defects in `src/crud_views/lib/table/table.py` keep the goal from being fully achieved:

1. **`Meta.sequence` without `"..."` does not put `actions` last** (truth 1, review WR-01). This is the only gap that contradicts the goal statement itself, and it is the one a downstream author writing the most common django-tables2 sequence idiom would hit first.

2. **Caller `exclude` kwarg: `None` crashes, `str` is silently dropped** (truth 4, review WR-02/WR-03). D-05 and threat T-06.19-02 require the merge to preserve a caller `exclude`. Both failures occur only when the view has `cv_list_actions = None` and only for a kwarg no code in this repository passes, so no shipped page is affected, but it is a public-API behaviour of `Table` and WR-03 re-exposes a deliberately hidden column — the exact outcome the security register marks as mitigated. One normalisation (`caller = kwargs.get("exclude") or ()`; wrap a `str` in a one-tuple) and two assertions close it.

Both gaps are small, co-located in `Table.__init__`/`cv_default_sequence`, already have reviewer-proposed fixes, and leave every existing table byte-identical (D-02 still holds because the guard only fires for a declared sequence). A single short gap-closure plan can address them together and re-close T-06.19-02.
