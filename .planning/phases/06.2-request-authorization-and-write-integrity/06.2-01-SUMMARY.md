# Phase 6.2 Plan 01: Delete bypass and safe protected previews Summary

**HTTP DELETE now returns 405 on every package delete view through a cooperative dispatch guard, and core/Guardian delete previews show only permitted protected labels plus one independent blocked notice driven by `has_protected_objects`.**

## Performance

- **Duration:** 16 min
- **Started:** 2026-10-29T10:49:51Z
- **Completed:** 2026-10-29T11:06:30Z
- **Tasks:** 3
- **Files modified:** 8

## Accomplishments
- Closed the inherited `DeletionMixin.delete()` bypass (B1). `_DeleteMethodGuardMixin` sits after `CrudView` and before Django's `DeleteView`. Authenticated core requests still go through permission and object gates first, so they get 403 or 404 before the 405. Active top-level Guardian actors get 405 before any object lookup, whatever their grant and whether or not the target exists. Modal `Vary: X-CV-Modal` is kept.
- `_allowed_methods()` drops DELETE, so 405 `Allow` and OPTIONS match for default views and for subclasses that restore `"delete"`.
- Protected-label confidentiality (B3): `has_protected_objects` is computed before `cv_filter_related_objects`. The core hook keeps only labels the user has model-level view permission for, and the Guardian hook keeps only labels the user holds an object grant for (or a global permission when the view's fallback allows it). The templates show the notice based on the flag, so it survives when every label is hidden.
- The POST lifecycle is unchanged: validation, custom protection (200, or 422 in the modal), database PROTECT `ProtectedError`, hook order, rollback and on-commit suppression.

## Decisions Made
- Following A22, the method guard is in dispatch and does not override `delete()`. `DeleteView.delete is DeletionMixin.delete` is asserted for the core, Guardian, polymorphic and concrete classes.
- `http_method_names` is annotated `ClassVar[list[str]]` to satisfy ruff RUF012. It stays a list rather than a tuple, so existing subclass list concatenation keeps working.
- `protected_objects` is now always a fresh list of permitted objects, and `has_protected_objects` is the blocked-state contract that custom templates should read. Plan 06 documents the migration for copied delete templates.
