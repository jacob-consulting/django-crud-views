# Phase 6.2 Plan 02: Parent-None creation and inactive-actor denial Summary

**Guardian nested creation now resolves the URL parent and applies the action state even when the parent permission is `None`. Create helpers and the rendered toolbar, alias and card controls use the configured FK parent, and inactive users get no rows, objects or helper authority on any Guardian request or callable path.**

## Accomplishments
- **B4 (D-10).** The `None` parent policy no longer skips everything. Dispatch always resolves the URL parent, returning 404 when it is missing, and runs `cv_action_enabled(user, parent)` for create. Before the fix, disabled-parent and missing-parent creates both returned 200 or 302.
- **B6.** Both create helpers use the shared resolver `_guardian_resolve_parent_perm_key` / `_guardian_user_has_parent_perm`, so they no longer crash with `'NoneType' object has no attribute 'split'`. No child-add grant is required.
- **H03 / A25.** `cv_has_access` and `cv_create_has_access` accept the parent, or an own child of single-FK nesting. M2M own children and unrelated objects deny, superusers included, and the state hook is not called for them. An explicit M2M parent and URL-bound list/create routes keep working.
- **A24.** The list create fallback goes through the new `_cv_action_enabled_for_context` adapter. An unresolved parent gives `cv_access=False` and `cv_action_enabled=False` without calling any hook with `None`.
- **A23.** The parent mixin declares `cv_guardian_accept_global_perms` and `cv_guardian_anonymous_behavior` as annotations only. W280 recognises them, and later custom mixins' True/404 policies stay inherited.
- **B5 (D-11, D-05).** Inactive authenticated users are denied in five places:
  - parent-mixin dispatch, before parent, method or fragment handling;
  - object and queryset `has_permission`;
  - `get_queryset` (`.none()`);
  - the access and create helpers;
  - `_PermittedPks` and the strict `GuardianViewSet.get_objects_for_user`.

  Active superusers keep full access.
- **H03 controls.** All four `ContextButton` classes and both card-action branches compute state through the same adapter. On a Book page or Book card row, the create hook receives the Publisher; labels, URLs and permission fields are unchanged.

## Decisions Made
