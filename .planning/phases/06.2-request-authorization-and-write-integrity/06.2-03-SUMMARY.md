# Phase 6.2 Plan 03: Fragment authorization and coordinate integrity Summary

**Formset fragment requests now authorize the real target through `get_object()` before anything renders, and a private declaration-aware validator checks every coordinate and the persisted FK ancestry (integer and UUID) before rendering. Malformed or forged input gets a 400. The same plan fixes unsaved UUID-default rows and a formset.js multi-digit-pk bug, so the add-row round trip agrees.**

## Accomplishments
- **B2 (D-09).** `FormSetMixinBase.get()` sets `self.object = self.get_object() if self.cv_object else None` before `get_template_html`.
  - Guardian object permission and action-state gates now run for fragments.
  - Missing and wrong-URL-parent targets return 404.
  - Before the fix, ungranted, view-only, revoked and state-disabled actors received the editor row with the secret Contract choice.
  - The fragment path never builds the full editor context (`get_context_data` is not called).
- **Coordinates (D-09, AUTH-02).** `FormSets._cv_validate_fragment_coordinates` runs before `get_template`. It validates:
  - the declared key path;
  - `num` and row indices, as 1–9 ASCII digits;
  - each identity against the `FormSet.PK` grammar and the owning model's pk field (`to_python` plus validators);
  - the root identity against the endpoint's object (`None` for create);
  - top index 0 and the declared child index at every intermediate level;
  - persisted FK ancestry, via `exists()`;
  - `None` propagation.

  Top-level fragments accept only an omitted or empty parent prefix. Nested fragments need the exact declared depth. Canonical values are what get rendered.
- **A14.** `FormSet.init` renders an unsaved instance as `None` even when a UUID default already set its pk. Before, new-Author create pages and extra UUID rows rendered random UUIDs, and the bound POST rebuilt different ones, so nested data could not bind. Now the metadata, add-row requests and POST bindings agree. Saved UUIDs and instance pks are unchanged.
- **formset.js.** The pk regex `^(.*)(None|pk)-(\d+)$` let the greedy prefix swallow leading digits: `12-0` parsed as pk `2`, so added rows under any integer parent ≥ 10 got prefixes the POST never reads. It is now `^(?:(.*)-)?(None|pk)-(\d+)$`.
- **D-12 preservation.** These all keep working:
  - Guardian/core create and update;
  - nested child create and update;
  - polymorphic declaration selection;
  - existing formset, conditional, transaction, delete and Guardian suites.

## Decisions Made
See `key-decisions` in the frontmatter. Validation runs on every authorized fragment, including views with custom formsets. Any client or test that sent coordinates the server never emits now gets 400:
- a non-root `pk` on update, or a non-`None` root on create;
- a nonempty top-level prefix;
- a missing nested prefix;
- Unicode or overlong digits.

Real browser payloads are unaffected, except that integer parents with pk ≥ 10 now work instead of losing rows silently.

**1. [Rule 1 - Bug] formset.js truncated multi-digit integer pks**
- **Found during:** Task 03-02 (deriving browser payloads from formset.js)
- **Issue:** The greedy `(.*)` in the pk regex parsed `12-0` as pk `2`. Add-row requests under any parent with pk ≥ 10 rendered rows the POST never read, so data was lost silently. With the new validator those requests would have become 400s.
- **Fix:** `^(?:(.*)-)?(None|pk)-(\d+)$`, plus a vitest case covering integer, nested and UUID prefix keys.

## Known Limitations / Handoffs
- **A19, deferred to the proposed 6.3 lifecycle slice (not yet in ROADMAP).** `FormSet.init` numbers sibling child declarations (0, 1, …), but `FormSets.get_template` emits index 0 for the selected fragment. A fragment for a non-first child, such as `books|memos`, therefore returns rows like `books-memos-…-{book}-0-1` instead of extending the initialized `…-{book}-1` formset.
  - This is characterized in `test_two_child_declaration_characterizes_emitted_index_and_keeps_gates` and is not claimed as a working round trip.
  - Authorization and ancestry validation apply to both siblings.
  - Valid nonzero ancestor child indices inside a parent prefix are validated as declared (three-level test).
- **Plan 06 documentation:**
  - fragment requests now return 403/404 per the editor's gates and 400 for invalid coordinates (`docs/reference/formsets.md` "The AJAX template endpoint");
  - unsaved UUID-default rows render `None` prefixes;
  - the formset.js multi-digit pk fix (CHANGELOG);
  - the A19 limitation.

  None of these rename a public API. Whether the stricter 400 contract needs a Breaking entry plus `docs/migrating-1.0.md` is Plan 06's call.
