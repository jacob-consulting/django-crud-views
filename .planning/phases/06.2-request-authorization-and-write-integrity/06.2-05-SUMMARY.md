## Accomplishments

- **A10 actor table.** One fixture registers three families on Publisher:
  - core;
  - Guardian strict;
  - Guardian global-accepting (the same Guardian views with the per-view flag set per test).

  Each family has list, card, detail, update, a separate formset `editor`, delete (modal-capable), a `touch` action that writes a field, and create.
  - Five active actors × 12 route/method cells × 3 families each get one exact status.
  - Guardian list/card rows match the table: grants give only the granted row, and global-only actors get rows only under global-accepting views.
  - Object grants never substitute for top-level create.
  - Every 302 changes exactly one stored row (or one deletion or creation) and fires exactly one matching hook.
  - Every other cell leaves the snapshot and all hooks unchanged.
  - A granted fragment returns exactly `{html, rows}`. Denied fragments reach neither `get_template_html` nor `FormSets.get_template`, and evaluate no choices.
- **A10 response table.** The matrix also covers:
  - inactive sessions with proven request identity;
  - anonymous core redirects and Guardian redirect/403/404 modes;
  - next-request revocation;
  - invalid and custom-protection POSTs (200, or 422 in the modal);
  - database PROTECT re-raise;
  - Guardian DELETE 405 before `get_object` versus the core 405/403/403/404 ordering;
  - missing and wrong-URL-parent 404s;
  - nested parent-gate 403/404, including DELETE;
  - 400 for malformed coordinates;
  - parent-None create.
- **H03.** Child detail, update and delete pages were tested under strict and global-accepting create policies, for six conditions: permitted, denied, other-parent grant, revoked, disabled and global-only.
  - The page stays reachable in every case.
  - `cv_access`, `cv_action_enabled`, the permission filter, the rendered link and direct GET/POST agree.
  - The created child is bound to the URL parent despite a forged FK.
  - The configured FK attribute (`publisher`) differs from the parent ViewSet name.
- **A20.** The manage mode and group are patched on the cached singleton, and live DEBUG uses `override_settings`. Exact 302 and 403 negative controls cover both families.
- **Native seams (D-12).** All six overrides render an allowed sentinel and read only resolved context.
  - Denied rows, protected labels, the manage policy and editor choices are absent from both HTML and `response.context`.
  - A protected-only preview shows exactly one generic notice with an empty item list and an empty summary.
  - Permitted labels and publisher names stay literally escaped.
  - The formset frame keeps `cv-data-formset`, the prefixes, the rows and the management form, and serves nested fragments.
- **Concurrency.** Two sessions interleave on one ViewSet with mixed policies. A revocation and a deactivation between requests affect only the next request of the actor concerned. Interleaved URL parents bind each create to its own parent.
