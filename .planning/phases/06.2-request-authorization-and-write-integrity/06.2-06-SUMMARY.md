## Accomplishments

- **Reference docs (06-01).**
  - `guardian.md`:
    - per-view fallback, the removed ViewSet key and its `ValidationError`, and the always-strict helper (active
      superuser gets every object, inactive user none);
    - an "Inactive users" section;
    - a "What the create access helpers accept" table: parent, FK own child via `get_attribute()`, and denial for
      unrelated, `None` or missing-relation objects, superusers included;
    - the explicit M2M fail-closed boundary, with its supported explicit-parent and URL-bound paths;
    - parent-`None` gates;
    - protected-label filtering with the delete view's fallback for related labels;
    - the manage policy table and context keys, and the unchanged manage gate.
  - `delete_view.md`:
    - an "HTTP methods" section: 405 after the existing gates, `Allow`/`OPTIONS`, restored-name subclasses, modal
      `Vary`, no Django 4.2 warning;
    - "Protected objects", covering `has_protected_objects` and `protected_objects`;
    - "Custom related-object filters", the A21 contract with an example;
    - 200/422 for custom protection, distinct from `ProtectedError`.
  - `formsets.md`: fragment gates (403/404), the 400 coordinate rules, unsaved UUID `None` prefixes, choices that stay
    the application's job, and the A19 known-limitation note.
  - `context_buttons.md` and `faq.md`: `cv_context_has_permission` is permission-only. FK child pages resolve the
    actual parent. List-page `None` and M2M child pages stay `False`. State hooks get the parent while labels keep the
    page object.

  - CHANGELOG `### Breaking` has five entries, and `### Fixed` five.

    audience list, Step zero and Silent breaks have new entries.
