**Guardian delete previews resolve permission codenames against Guardian's own content type, avoiding missing-permission and mismatched-content-type failures while preserving label confidentiality and superuser visibility.**

## Accomplishments

- `_PermittedPks` uses `get_content_type(model)` and `view_<ct.model>` with `klass=model`, preserving per-view global fallback and Guardian's default group handling. No broad exception handler hides configuration errors.
- Auto-created through models bypass ContentType access entirely. Ordinary, inactive-superuser and unauthenticated-superuser actors receive no PKs; authenticated active superusers receive all through PKs.
- M2M-root full/modal GET and confirming POST work for both granted users and superusers. Confirming POST removes the Publisher and through row while retaining Genre. Through instances and labels stay hidden from ordinary users.
- A new test-only RESTRICT model, `Royalty`, omits the view permission. Its hidden labels do not reach ordinary-user context or HTML, but `has_protected_objects` remains true. Superusers see the protected instance and title.
- Test-only `PublisherProxy` and direct calls pin concrete proxy object grants, polymorphic base object grants, strict/global fallback, proxy-only global denial and request-local caching. Guardian, polymorphic, manage and system-check collateral modules pass on both cached versions.

## Decisions Made

- Preserve D-05: active authenticated superusers see auto-created through rows and no-view protected objects like the core view. The existing inactive guard remains first; the through branch separately requires authentication and superuser authority.
- Preserve the existing model-keyed cache: superuser through visibility materializes the entire through model's PK set once per projection, including unrelated rows. This is not a bounded cascade query and carries no new performance claim.
- Global fallback consults `app.view_publisher` for a proxy and `app.view_vehicle` for Car with polymorphic base resolution. Strict mode denies global-only grants; `app.view_publisherproxy` alone never authorizes proxy labels under default resolution.
- Do not introduce a duplicate-codename fixture: existing tests resolve `view_contract` without a content type. Avoidance of app-qualified duplicate-codename resolution is established by source construction (bare codename plus `klass`), not a new runtime regression.
