## Gap being closed

- **gap_id:** G-06.2-3 (UAT test 3, severity major; review WR-02; UI-REVIEW findings 1 and 4).
- **Gap reason (diagnosis):** one structural cause, three conditions. `has_protected_objects` is computed only
  inside the `cv_show_related_objects` branch of `DeleteView.get_context_data` (delete.py:202-205) and no
  control-flow consumer reads it. (1) Copy: `related_objects.html:5` reuses the list-variant heading (trailing
  colon) for the all-hidden case that eda7018 made reachable, and `alert_data()` correctly renders the text body
  with empty text. (2) Submit: `view_delete.content.html:12-18` renders the confirm form unconditionally outside the
  `delete_protection_errors` branch. (3) POST: `DeleteView.post` (delete.py:224-244) honors only
  `cv_check_delete_protection()` errors, so `self.object.delete()` raises `ProtectedError` (or `RestrictedError` for
  RESTRICT; `NestedObjects` puts both in `.protected`) through `cv_form_valid_process`, 500 on full page and modal
  (modal.js then reloads the same blocked page). With the default `cv_show_related_objects=False` there is no flag,
  no notice, an enabled form and the 500. This was a plan-level deferral in 06.2-01 (ledger line 196), not a locked
  decision; D-07, D-08, D-12 and D-14 support the fix.
- **Locked fix shape (UAT):** blocked UI omits the form (option A); theme seam is `has_protected_objects` on every
  delete GET/POST; blocked POST returns the existing protection response (200 / 422, nothing deleted) plus a
  `ProtectedError`/`RestrictedError` backstop; colon-free heading + one generic sentence for the empty-label case;
  revise the three test pins and the heading constants, the de locale, and the docs (06.2-09).
- **Discretion settled here:** the labelled case keeps its current heading, msgid and German translation byte for
  byte, and only the all-hidden case gets its own copy (two branches on `protected_objects` inside the
  `has_protected_objects` block). This confines the change to the defect and keeps the 06.2-01 labelled-case
  acceptance intact. Omitting the form mirrors the custom-protection page exactly (no confirm, no submit, no cancel
  button), so no `CrispyDeleteForm` hook is added. The related-summary alerts still render on a blocked page
  (aggregate policy, D-13). Fixed English copy so tests and template agree: heading
  "Deletion is blocked by protected relationships" and sentence
  "Other objects still reference this one; remove or reassign them before deleting it."
