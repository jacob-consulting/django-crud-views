## Detailed Findings

### Pillar 1: Copywriting (3/4)

**WARNING C1 — Policy vocabulary and absence markers disagree.**
`src/crud_views_guardian/templates/crud_views/snippets/guardian/config_table.html:4` calls the helper method
at line 20 a “Setting”. Its strict phrase at line 22 differs from
`src/crud_views_guardian/templates/crud_views/view_guardian_manage.html:19` and the raw “strict” value
at `src/crud_views_guardian/lib/views.py:344`. The generic renderer at
`src/crud_views/templates/crud_views/view_manage.html:132` prints raw values, including `None`, whereas
the dedicated policy table uses an em dash. Use “Item” or “Policy” and consistent translatable descriptions
and absence markers.

**Resolved:** `src/crud_views/templates/crud_views/snippets/delete/related_objects.html:5-9` now distinguishes
visible labels from an empty permitted list. Hidden labels get a colon-free heading and “Other objects still
reference this one; remove or reassign them before deleting it.” D-07/08 remain satisfied without per-hidden-object
placeholders. The former dangling-colon finding is closed. Named coverage is at
`tests/test1/test_delete.py:290` and line 681 (German); historical execution is recorded in 08-SUMMARY.

### Pillar 2: Visuals (2/4)

**WARNING V1 — Duplicated policy hierarchy.**
`src/crud_views_guardian/lib/views.py:345-350` adds `guardian_policy` to every view.
`src/crud_views/templates/crud_views/view_manage.html:118-135` renders all sections without excluding it.
The Guardian template independently renders the same data at `view_guardian_manage.html:8-23`.
Users must reconcile a readable policy table with repeated raw sections. Remove duplicate presentation while
preserving the context contract. This is demonstrated by the loops, not a fresh rendered count.

Positive source evidence: headings separate configuration, effective policy and permission holders. Alert
dismiss buttons have translated accessible labels in `src/crud_views/templates/crud_views/tags/alert.html:5`.
Screen-level hierarchy and icon affordances remain browser checks.

### Pillar 3: Color (3/4)

**WARNING CO1 — Neutral configuration uses warning semantics.**
`src/crud_views_guardian/templates/crud_views/view_guardian_manage.html:6` wraps configuration, including the
strict-helper statement, in `cv_alert "warning"`; the equally informational policy table is unframed.
Use a neutral/informational container. The wrapper predates this phase, but the phase expanded its content.

The four scoped delete/manage templates contain **0 hardcoded hex/rgb colors** and **0 text/bg/border-primary
utilities**. The delete snippet has one error alert in each mutually exclusive blocked branch and two warning
alerts for aggregate cascade information: appropriate semantic distinctions. No rendered 60/30/10 ratio or
contrast measurement is claimed without fresh screenshots.

### Pillar 4: Typography (4/4)

**PASS T1 — No source-level typography defect found in scope.**
The four scoped templates have **0 fs-* or fw-* overrides** and **3 h4 headings**, all at
`src/crud_views_guardian/templates/crud_views/view_guardian_manage.html:5,8,27`. Table headings use
`th scope="col"`; the shared alert emphasizes its heading with `strong`
(`src/crud_views/templates/crud_views/tags/alert.html:4`). Existing Bootstrap type is inherited consistently.
This is a bounded template-consistency pass, not a font-rendering, zoom or visual-accessibility certification.
Long identifiers are scored under spacing.

### Pillar 5: Spacing (2/4)

**WARNING S1 — No narrow-screen containment.**
`src/crud_views_guardian/templates/crud_views/view_guardian_manage.html:9-22` contains three columns,
the long `cv_guardian_accept_global_perms` heading and sentence-length policy cells.
`snippets/guardian/config_table.html:2-25` includes `GuardianViewSet.get_objects_for_user()`.
Neither table has a responsive wrapper or explicit identifier wrapping. Across the four scoped templates there
are **0 table-responsive wrappers**. The old audit observed clipped mobile content; exact current clipping and
row heights are **not freshly measured**. Contain the tables, wrap identifiers and verify the viewport matrix.

Scoped spacing classes are `mb-3` on the delete group and `mb-0` on the config table; the shared alert list uses
`mb-0 mt-2` at `src/crud_views/templates/crud_views/snippets/alert/list.html:1`. No arbitrary pixel/rem
spacing was added. The score concerns access to table content, not an invented token violation.

### Pillar 6: Experience Design (1/4)

**BLOCKER E1 — Inspection can execute writes (CR-02, transferred unresolved).**
`src/crud_views/lib/views/delete.py:309` always collects through `NestedObjects.collect` at line 214,
before preview visibility is checked. POST constructs context at line 339 before validation at line 341.
The recorded reproduction at `06.2-REVIEW.md:67` demonstrates deletion/default callbacks writing on GET or
unconfirmed POST. A confirmation page must not itself authorize these writes. 6.3 DEL-01–06 owns remediation.
This audit confirms the source path; it does not claim a new reproduction.

**BLOCKER E2 — An unrelated failure can look like ordinary protection (CR-03, transferred unresolved).**
`delete.py:373-378` classifies protection exceptions; lines 351-353 render the marker as blocked.
The custom converter counterexample at `06.2-REVIEW.md:116` remains a qualification to the general propagation
claim. Fix/test the boundary in 6.3; named native-protection cases do not prove every custom error propagates.

**BLOCKER E3 — A valid deletion can be falsely blocked (CR-04, transferred unresolved).**
`delete.py:212` selects a write alias without an instance hint. The colliding-PK reproduction at
`06.2-REVIEW.md:158` shows inspection can use another database's protected rows and suppress the form.
Align inspection, write, transaction and commit-hook databases in 6.3. “BLOCKER” denotes task-completion failure
under this UI rubric; the disposition's medium false-blocking correctness characterization is retained.
No wrong-database data loss is alleged.
