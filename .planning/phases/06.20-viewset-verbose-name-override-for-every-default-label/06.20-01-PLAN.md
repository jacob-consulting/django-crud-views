<objective>
Add the two optional `ViewSet` fields `verbose_name` and `verbose_name_plural` (type `LazyStr | None`, default `None`)
and make `ViewSet.get_meta()` resolve each one instead of `model._meta` (or `Resource._meta`) when it is set,
independently for singular and plural, so that every default label built from `get_meta()` follows with no further
code. Unset fields reproduce today's dict exactly. GitHub issue #338 is the canonical specification; CONTEXT.md D-01
refines only the blank check (plain blank `str` raises at construction, lazy values are never evaluated there).

Purpose: when two ViewSets are registered on one model (the tabler-test finding 28 case: a nested `subscription`
ViewSet next to a top-level `subscriptions` list, both on `CustomerSubscription`) both say the model's name on every
header, paragraph, breadcrumb item, child button and message. One declaration on the ViewSet must rename all of them;
per-view `cv_*_template_code` stays the escape hatch for one page. The change is bounded to two fields, one validator
and one method, as CLAUDE.md "Decision Rule: Developer Maintainability" requires.

Output: `src/crud_views/lib/viewset/__init__.py` with the fields, `check_verbose_name` and the resolution in
`get_meta()`; the new test module `tests/test1/test_viewset_verbose_name.py` (9 test functions, 12 pytest cases)
covering ROADMAP success criteria 1 and 3 plus the tracer's end-to-end list-header check.

This plan carries the phase's tracer (Task 1): the thinnest path from `ViewSet(verbose_name_plural=...)` through
`get_meta()` to a rendered list heading. Plans 02 (remaining end-to-end surfaces) and 03 (docs, changelog) expand from
it; plan 03 has no code dependency and runs in the same wave.
</objective>

Noun that stays primary: the model's (or Resource's) `_meta.verbose_name` / `verbose_name_plural` remain the identity
of a ViewSet's objects; the two new fields are optional per-ViewSet display overrides read in exactly one place
(`ViewSet.get_meta()`).

Decision: `no-change`. Rationale: the override does not generalise the identity model — permission codenames, content
types, `deletion.py` summaries and the `Http404` texts keep reading `_meta` by #338's locked decision, and `None` means
"use the model's name", so nothing is promoted or demoted; adding the fields alongside `_meta` is the specified design,
not accepted debt. No invariant test beyond the SC-1 "unset reproduces today's values" tests is added.
