### Phase and plan baselines for the scope gates (`PHASE_BASE`, `PLAN_BASE`)

Two bases, each with exactly one meaning (review round 2, agreed concern 1: this plan used to re-record `PHASE_BASE`
from its own wave-2 HEAD — which already contains plans 01 and 03 — so `git diff --stat "$PHASE_BASE" -- src` was
empty and the "lists only `viewset/__init__.py`" gate could not pass; the `git merge-base HEAD main` fallback was
vacuous on `main`). The same section appears in plans 01 and 03; all three use it identically.

- `PHASE_BASE` is the commit the phase branch forked from `main`: one immutable commit for every plan, whichever wave-1
  plan ran first and however their commits interleaved. Execution runs on the `gsd/phase-06.20-…` branch
  (`branching_strategy: phase` in `.planning/config.json`; CLAUDE.md "Creating a phase worktree"), where that commit
  is `git merge-base HEAD main`. Every phase-wide gate is one self-contained command that resolves the fork point,
  refuses `main` and runs the diff, chained with `&&` — executors run each command in a fresh shell, so nothing may be
  carried over from an earlier command:

      PHASE_BASE=$(git merge-base HEAD main) && [ "$(git rev-parse --abbrev-ref HEAD)" != main ] && git diff --quiet "$PHASE_BASE" -- <paths>

  A non-zero exit is a failed gate whichever link failed: `git merge-base` found no fork point, the branch guard saw
  `main` (where the fork point is HEAD and the diff would pass vacuously), or the diff found a change. There is no
  fallback. Merging `main` into the phase branch mid-phase moves the fork point with it and the gates stay correct,
  which a SHA recorded in a file would not. The phase-wide checks in this plan (the same chain ending in
  `git diff --stat "$PHASE_BASE" -- src`, which must list only `src/crud_views/lib/viewset/__init__.py`; the
  untouched-files gate) therefore see plan 01's source change and plan 03's docs commits.
- `PLAN_BASE` is `git rev-parse HEAD` taken before this plan's first commit and recorded in the SUMMARY. It is used only
  for `git log --format=%s <PLAN_BASE>..HEAD -- tests/test1/test_viewset_verbose_name_render.py` — the list of this
  plan's commits, with the recorded SHA pasted in place of `<PLAN_BASE>` — never for a phase-wide diff. Per-commit
  scope is proven by `git diff-tree --no-commit-id --name-only -r HEAD` and `git show --stat --format= HEAD` in each
  task's acceptance criteria (this plan is alone in wave 2, so HEAD is its own commit).
