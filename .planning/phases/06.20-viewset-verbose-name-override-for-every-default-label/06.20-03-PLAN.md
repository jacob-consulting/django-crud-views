### Phase and plan baselines for the scope gates (`PHASE_BASE`, `PLAN_BASE`)

Two bases, each with exactly one meaning (review round 2, agreed concern 1: this plan used to call its own starting HEAD
"the phase-start commit", and the `git merge-base HEAD main` fallback was vacuous on `main`). The same section appears in
plans 01 and 02; all three use it identically.

- `PHASE_BASE` is the commit the phase branch forked from `main`: one immutable commit for every plan, whichever wave-1
  plan runs first and however their commits interleave. Execution runs on the `gsd/phase-06.20-…` branch
  (`branching_strategy: phase` in `.planning/config.json`; CLAUDE.md "Creating a phase worktree"), where that commit
  is `git merge-base HEAD main`. Every phase-wide gate is one self-contained command that resolves the fork point,
  refuses `main` and runs the diff, chained with `&&` — executors run each command in a fresh shell, so nothing may be
  carried over from an earlier command:

      PHASE_BASE=$(git merge-base HEAD main) && [ "$(git rev-parse --abbrev-ref HEAD)" != main ] && git diff --quiet "$PHASE_BASE" -- <paths>

  A non-zero exit is a failed gate whichever link failed: `git merge-base` found no fork point, the branch guard saw
  `main` (where the fork point is HEAD and the diff would pass vacuously), or the diff found a change. There is no
  fallback. Merging `main` into the phase branch mid-phase moves the fork point with it and the gates stay correct,
  which a SHA recorded in a file would not. In this plan the only phase-wide gate is the `docs/migrating-1.0.md`
  invariant.
- `PLAN_BASE` is `git rev-parse HEAD` taken before this plan's first commit and recorded in the SUMMARY. It is used only
  for `git log --format=%s <PLAN_BASE>..HEAD -- docs/reference/nested.md docs/reference/breadcrumb.md CHANGELOG.md` —
  the list of this plan's commits, with the recorded SHA pasted in place of `<PLAN_BASE>` — never for a phase-wide diff
  (plan 01's commits may land in between in wave 1). That this plan touched no `src/` or `tests/` file is proven per
  commit in each task's acceptance criteria by `git show --stat --format= "$(git log -1 --format=%H -- <this task's
  files>)"` — the latest commit that touched the task's files, so a plan 01 commit landing on top of it is not read by
  mistake.
