# Phase 06.20: ViewSet `verbose_name` / `verbose_name_plural` override that every default label follows (#338) - Context

**Gathered:** 2026-11-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Two optional fields on `ViewSet`, `verbose_name: LazyStr | None = None` and `verbose_name_plural: LazyStr | None = None`.
`ViewSet.get_meta()` uses each one instead of `model._meta` (or `Resource._meta`) when it is set, independently for
singular and plural, with no automatic pluralisation. Every default label built from `get_meta()` follows with no
further code. Unset fields reproduce today's dict byte for byte.

Issue [#338](https://github.com/jacob-consulting/django-crud-views/issues/338) is the canonical specification. Its
"Proposed behaviour", "Decisions (do not reopen in planning)", "Acceptance criteria" and "Out of scope" sections are
authoritative, apart from the one refinement in D-01 below (blank check on lazy values). The ROADMAP.md Phase 06.20
entry repeats the scope and success criteria.

Locked by #338 (not re-discussed):
- The override is on the ViewSet, not a per-view attribute. Resolution is strict: no concatenation, no parent fallback,
  no setting.
- Dict keys and shapes are unchanged. `capfirst()` is applied to the resolved value. `*_translate` keys are built from
  the resolved value the same way as today. A lazy override is stringified inside `get_meta()` at request time.
- Per-view `cv_*_template_code`, `cv_breadcrumb_container_label` and `cv_breadcrumb_label_template_code` still win.
- `GuardianViewSet`, polymorphic and Resource ViewSets inherit the fields. For a Resource, the override beats
  `Resource.Meta.verbose_name*`.
- Model-centric text keeps reading `_meta`: the `deletion.py` summaries, and the `Http404` messages in `ancestors.py`
  and `resource.py`. Permission codenames and content types are untouched.
- Not breaking: `### Added` changelog entry; `docs/migrating-1.0.md` untouched.

</domain>

<decisions>
## Implementation Decisions

### Blank check on lazy values
- **D-01:** A plain `str` value that is `""` or whitespace-only raises `ValidationError` at ViewSet construction, via a
  `field_validator` like the other ViewSet field validators. A lazy value (`django.utils.functional.Promise`) is
  accepted without a blank check, and the docs say so. Nothing is evaluated at import time.
  - Why: verified in-session that `str(gettext_lazy(...))` raises `AppRegistryNotReady` before the app registry is
    ready, even inside `translation.override(None)`. Evaluating at construction would break any project that builds a
    ViewSet during app loading.
  - #338 acceptance criterion 1 (`""` and `"  "` raise) uses plain strings, so it stands as written.
  - Rejected: a system check that evaluates lazy values after startup (new check ID, test and docs for an edge case)
    and evaluating lazy values at construction (the import-time failure above).
- **D-02:** `None` means "not set". A set value is stored as given (no stripping or normalisation). `capfirst()` is
  applied in `get_meta()` as today.

### Applying the override in tests
- **D-03:** The end-to-end tests apply the override with
  `monkeypatch.setattr(cv_book, "verbose_name", ...)` / `monkeypatch.setattr(cv_book, "verbose_name_plural", ...)` on
  the shared test-project `cv_book`. This follows the existing pattern in `tests/test1/test_context_action_label_mode.py`
  and `tests/test1/test_guardian_inactive.py`. No new ViewSets are registered (the registry-leak note from PR #336's
  CI), and pytest restores `cv_book` after each test.
  - `ViewSet` has no `validate_assignment`, so the assigned value is not re-validated. Use distinct plain strings
    (e.g. `"volume"` / `"volumes"`) so each assertion can only pass if the override was rendered.
- **D-04:** Lazy translation and independent singular/plural resolution are tested only in the `get_meta()` unit tests
  (#338 criterion 1). The end-to-end tests check that the override reaches each surface in #338 criterion 2:
  - list header
  - list paragraph
  - create header
  - breadcrumb container item on a book page
  - `LinkChildColumn` / `ChildContextButton` text on the publisher pages
  - a success message
  - and that a view-level `cv_header_template_code` still beats the override.

### Docs
- **D-05:** The new section in `docs/reference/nested.md` reuses the page's own models. It continues the "Sideways"
  example (books under an author, next to a top-level book ViewSet on the same model) and renames the nested ViewSet,
  e.g. `verbose_name_plural=_("titles")`. It does not bring in the customer/subscription models.
- **D-06:** It is its own `## Labels` section, placed after "Navigating between parent and child" and before "Ancestor
  authorization". It states:
  - the two fields, and that each is resolved independently, with no automatic plural;
  - precedence: per-view `cv_*_template_code`, `cv_breadcrumb_container_label` and
    `cv_breadcrumb_label_template_code` still win;
  - that model-centric text (deletion summary, 404 messages) keeps the model's names;
  - that lazy values are not checked for blanks (D-01).
- **D-07:** `docs/reference/breadcrumb.md` (the variables sentence near line 73) notes that `verbose_name*` are the
  ViewSet's names (the override when set, the model's otherwise). The `### Added` entry goes in `CHANGELOG.md`.

### Claude's Discretion
- Test file names and layout: a new `tests/test1/test_viewset_verbose_name.py`, or a unit file plus an e2e file.
- The exact override strings in the tests and the docs example, and the docs wording.
- Validator shape: one `field_validator` covering both fields is expected. Its error message wording.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `LazyStr` (`crud_views.lib.lazy`): the field type. No coercion, so lazy values stay lazy until `get_meta()`.
- Existing `field_validator`s on `ViewSet` (`context_actions_label_mode`, `form_actions_label_mode`): the model for the
  blank validator.

### Established Patterns
- Every label consumer goes through `ViewSet.get_meta()`. Verified by grep: snippets, breadcrumb, `LinkChildColumn`,
  `ChildContextButton`, cards. `crud_views_polymorphic`, `crud_views_workflow` and `crud_views_guardian` read
  `verbose_name` nowhere else, so changing `get_meta()` alone is enough.
- `get_meta()` currently imports `gettext as _` (non-lazy) and builds `*_translate` as `_(capfirst(...))`. Keep this
  order for the resolved value.
- Tests override ViewSet fields with `monkeypatch.setattr` on the shared ViewSet, never by registering new ViewSets.

### Integration Points
- Only `ViewSet` (two fields + validator) and `ViewSet.get_meta()` change in `src/`. Subclasses (`GuardianViewSet`,
  polymorphic, Resource-backed) inherit the fields with no code of their own.

</code_context>
