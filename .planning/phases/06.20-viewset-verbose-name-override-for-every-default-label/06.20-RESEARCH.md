### Blank check on lazy values
- **D-01:** A plain `str` value that is `""` or whitespace-only raises `ValidationError` at ViewSet construction, via a
  `field_validator` like the other ViewSet field validators. A lazy value (`django.utils.functional.Promise`) is
  accepted without a blank check, and the docs say so. Nothing is evaluated at import time.
  - Why: verified in-session that `str(gettext_lazy(...))` raises `AppRegistryNotReady` before the app registry is
    ready, even inside `translation.override(None)`. Evaluating at construction would break any project that builds a
    ViewSet during app loading.
  - #338 acceptance criterion 1 (`""` and `"  "` raise) uses plain strings, so it stands as written.
  - Rejected: a system check that evaluates lazy values after startup (new check ID, test and docs for an edge case)
    and evaluating lazy values at construction (the import-time failure above).
- **D-02:** `None` means "not set". A set value is stored as given (no stripping or normalisation). `capfirst()` is
  applied in `get_meta()` as today.

### Applying the override in tests
- **D-03:** The end-to-end tests apply the override with

## Summary

The change is two optional Pydantic fields on `ViewSet` plus a resolution step in `ViewSet.get_meta()`. Every label
consumer already goes through `get_meta()` — the default snippets (`templates/crud_views/snippets/**`), the breadcrumb
container item (`breadcrumb.py:147`), `LinkChildColumn` (`table/columns.py:41-44`) and the context/child buttons via
`CrudView.cv_get_dict()` → `cv_get_action_label()` — so no consumer changes. The full grep of `verbose_name` across
`src/` confirms the only other readers are the model-centric texts #338 keeps on the model (`deletion.py:169,239`,
`ancestors.py:390,503`, `resource.py:127`) and unrelated field metadata. [VERIFIED: grep `verbose_name` src/ this session]

Two facts found this session shape the implementation and the tests. (1) Today's dict for `Book` is not all `str`:
`verbose_name` is `'Book'` (`str`) but `verbose_name_plural` is a Django lazy `__proxy__` (`'Books'`, from Django's
`format_lazy("{}s", ...)` default plural), because `capfirst` is `keep_lazy_text`-decorated. "Byte for byte" therefore
means: leave the model path exactly as written and apply `str()` only to a set override. (2) In the context toolbar a
labelled button shows the *short* label (`"List"`) — the override reaches the `ChildContextButton` only in its full
label (`"List of all Volumes"`), which is the hidden text in icon mode and `get_context()["cv_action_label"]`.
Two of the six e2e surfaces are not reachable on `cv_book` as declared in the test project (no `cv_book` view has
`CrudViewBreadcrumbMixin` or `MessageMixin`); the recommended deterministic substitutes are below, each probed.

**Primary recommendation:** add `verbose_name: LazyStr | None = None` and `verbose_name_plural: LazyStr | None = None`
after `icon_header` in `ViewSet`, one `@field_validator("verbose_name", "verbose_name_plural")` that rejects a blank
`str` and passes `None`/`Promise` through, and in `get_meta()` resolve `name = capfirst(str(self.verbose_name)) if
self.verbose_name is not None else capfirst(meta.verbose_name)` (same for plural), leaving the `_translate` lines
untouched. Test with `monkeypatch.setattr(cv_book, ...)` for unit + e2e, `cv_s3file` for the Resource case,
`gettext_lazy("Delete")` under `translation.override("de")` for the lazy case.

    def get_meta(self, context: ViewContext) -> dict:
        """
        Meta data plus X for template context.
        """
        meta = self.model._meta
        data = {
            "viewset": self,
            "cv": self,
            "verbose_name": capfirst(meta.verbose_name),

    if isinstance(v, (str, Promise)):

### Pattern 1: Current `get_meta()` dict, byte for byte (what "unset reproduces today" means)

Probe output for `cv_book.get_meta(...)` today [VERIFIED: in-project probe this session]:

```
verbose_name            : str        'Book'
verbose_name_plural     : __proxy__  'Books'     # Django Options default plural is format_lazy("{}s", verbose_name)
verbose_name_translate  : str        'Book'
verbose_name_plural_translate: str   'Books'
```

And in the venv: `capfirst(gettext_lazy("delete"))` returns a `django.utils.functional.lazy.<locals>.__proxy__`
(`isinstance(..., Promise)` is True); `gettext(<that proxy>)` returns `'Delete'` as `str`. [VERIFIED: venv probe]

Implications:
- Keep `capfirst(meta.verbose_name)` / `capfirst(meta.verbose_name_plural)` verbatim for the unset branch; do not
  wrap the model values in `str()` (it would turn the lazy plural into a `str` — equal by `==` but not the same
  object type, i.e. not byte for byte).
- Unit tests comparing "unset reproduces today" must compare with `==` against the expected strings (or against a
  snapshot taken before the monkeypatch), not `isinstance(..., str)`.
- For the override branch, do `capfirst(str(value))`: `str()` resolves a `Promise` in the active language at call
  time (#338 "resolve a lazy override with `str()` inside `get_meta()`"), and the two `_translate` lines then work
  unchanged because they only see a `str`.

Recommended shape (minimal, bounded):

```python
        meta = self.model._meta
        verbose_name = str(self.verbose_name) if self.verbose_name is not None else meta.verbose_name
        verbose_name_plural = (
            str(self.verbose_name_plural) if self.verbose_name_plural is not None else meta.verbose_name_plural
        )
        data = {
            "viewset": self,
            "cv": self,
            "verbose_name": capfirst(verbose_name),
            "verbose_name_plural": capfirst(verbose_name_plural),
        }
        # the two _translate lines and data.update(context.to_dict()) stay exactly as they are
```

### Pattern 2: Validator shape (D-01/D-02)

Mirror `check_form_label_mode_map` (the `None`-guarding one). After `PlainValidator` the value is `None`, a `str` or a
`Promise`; a field validator in the default "after" mode sees that value. Pydantic does not run field validators
for the default `None` (no `validate_default`), but an explicit `verbose_name=None` does reach the validator, so
guard `None`. [CITED: docs.pydantic.dev/latest/concepts/validators/ — field validators, "after" mode; `validate_default`]

```python
    @field_validator("verbose_name", "verbose_name_plural")
    @classmethod
    def check_verbose_name(cls, value):
        """A plain str must not be blank (#338). A lazy value is not evaluated here: str() of a gettext_lazy raises
        AppRegistryNotReady while apps load, and ViewSets are built at import time."""
        if isinstance(value, str) and not value.strip():
            raise ValueError(f"must not be blank, got {value!r}")
        return value
```

- `Promise` is not a `str` subclass, so `isinstance(value, str)` already excludes lazies — no import of `Promise`
  needed in `viewset/__init__.py`. [VERIFIED: venv probe — `isinstance(capfirst(lazy), Promise)` True and it is a
  `__proxy__`, not a `str`]
- Store as given (D-02): return `value` unchanged; `capfirst("  ")` is `"  "`, so only the blank check matters.
- A failing field validator aborts construction before the `@model_validator(mode="after") register()` runs
  (lines 161-195), so `""`/`"  "` tests leave nothing in `_REGISTRY`. [CITED: docs.pydantic.dev — after model validators
  run after the whole model has been validated]
- Test pattern: `with pytest.raises(ValidationError, match="verbose_name"): ViewSet(model=Book, name="x", verbose_name="")`
  — `pydantic.ValidationError`, as in `tests/test1/test_card_action_label_mode_field.py:19-21`.

### Anti-Patterns to Avoid
- **Stringifying the model path** (`str(meta.verbose_name_plural)`): changes the plural's runtime type from lazy proxy to
  `str`; violates "byte for byte".
- **Evaluating the override at construction** (`str(value)` in the validator): `AppRegistryNotReady` at import (D-01).
- **Normalising** (`value.strip()` stored): D-02 forbids.
- **Registering a ViewSet or view class in the e2e tests**: process-global registry leak (PR #336 CI). Monkeypatch
  `cv_book`/`cv_book_bc`/`cv_s3file`; define Table subclasses, not ViewSets.
- **Asserting the ChildContextButton's visible label-mode text**: it is the short label `"List"` by design; assert the
  full label (`cv_action_label` / icon-mode hidden span).
- **Touching `deletion.py`, `ancestors.py`, `resource.py` 404 texts or any consumer**: #338 "Out of scope".

## Common Pitfalls

### Pitfall 1: "Byte for byte" and the lazy plural
**What goes wrong:** the unset path returns a `str` plural instead of today's `__proxy__`, or a test asserts
`isinstance(meta["verbose_name_plural"], str)` and fails on the unchanged code.
**Why:** Django's default `verbose_name_plural` is `format_lazy`; `capfirst` keeps lazies lazy.
**How to avoid:** branch per field, `str()` only the override, compare with `==` in tests.
**Warning signs:** diff touching the `capfirst(meta....)` lines.

### Pitfall 2: Nested create GET needs Publisher `change`
**What goes wrong:** the create-header e2e returns 403 with a `view`-only client.
**Why:** phase 06.18 ancestor authorization — Write endpoints require `change` on the nearest ancestor.
**How to avoid:** use `client_user_book_add` (grants `cv_publisher change`), as the probe confirmed.

### Pitfall 3: Strict mode icon-only child button
**What goes wrong:** rendering `PublisherDetailView` with a `ChildContextButton` to `book` raises
`ValueError: context action 'books' renders icon-only but has no icon` because `cv_book.icon_header is None`.
**How to avoid:** assert via `get_context()["cv_action_label"]`, or monkeypatch `cv_book.icon_header`, or set
`BookListView.cv_context_action_label_mode = "label"` (then only the short label `"List"` is visible — not a valid
override assertion).

### Pitfall 4: `monkeypatch.setattr` on a Pydantic field that does not exist yet
**What goes wrong:** `ValueError: "ViewSet" object has no field "verbose_name"` — the whole e2e module errors before
the fields land. Expected RED; sequence tasks so the fields are added before the e2e module is run GREEN. Do not use
`raising=False` (it would hide a typo'd field name forever).

### Pitfall 5: Translation is resolved at call time
**What goes wrong:** calling `get_meta()` outside `translation.override("de")` and asserting German.
**Why:** `_` is non-lazy `gettext`; the override's `str()` happens inside `get_meta()`.
**How to avoid:** call inside the `with` block; also assert the English value outside it.

### Pitfall 6: Validator must not catch `None` or lazies
**What goes wrong:** `ViewSet(..., verbose_name=None)` or a `gettext_lazy` value raises.
**How to avoid:** `isinstance(value, str) and not value.strip()` only.

### Pitfall 7: Registry leak from constructor tests
**What goes wrong:** a test registers a name another test (or module order under xdist) also registers → `cv_raise`.
**How to avoid:** one unique name for the Guardian constructor test; blank tests never register.
