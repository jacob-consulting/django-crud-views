## Detailed Findings

### Pillar 1: Copywriting (4/4)

- **Passing finding:** `src/crud_views/lib/viewset/__init__.py:517` resolves singular and plural independently and retains model fallback. `tests/test1/test_viewset_verbose_name_render.py:48` and `:62` assert actual response text: “Volumes”, “List of all Volumes”, “Volume”, and “Create new Volume”. The deliberate existing capitalization/grammar is preserved; changing it is outside this naming feature.
- **Passing finding:** Per-view heading precedence is covered at `tests/test1/test_viewset_verbose_name_render.py:76`; child-link text and title at `:133`; short “List” remains unchanged at `:154`. `docs/reference/nested.md:229` documents independent resolution, explicit-copy precedence, model-centric exceptions, and the lazy blank-check limitation.
- Plain blank labels fail validation (`src/crud_views/lib/viewset/__init__.py:137`). Lazy labels are deliberately not blank-checked; this is a locked compatibility decision, not an audit defect. No new generic CTA, empty-state, or error copy was introduced.

### Pillar 2: Visuals (4/4)

- **Passing finding:** The phase changes metadata values only; it retains the heading/paragraph distinction demonstrated by response assertions at `tests/test1/test_viewset_verbose_name_render.py:55` and `:69`. No extra competing focal element or icon-only control is added.
- **Passing finding:** The renamed icon-only child action keeps a hidden text label, asserted in actual response HTML at `tests/test1/test_viewset_verbose_name_render.py:156`. `src/crud_views/templates/crud_views/tags/button/action.html:8` renders this label through the existing theme slot. Breadcrumb semantics remain `nav`, ordered list, and `aria-current="page"` at `src/crud_views/templates/crud_views/tags/breadcrumb.html:2`.
- Actual visual hierarchy, clipping, focus appearance, and tooltip rendering remain unverified without a target browser capture; this score is source-scoped.

### Pillar 3: Color (3/4)

- **WARNING C1 — inherited theme concern:** `src/crud_views/lib/button_classes.py:29` maps all four context variants to the same outline-primary class; `:33` does the same for four list variants. `:40` maps card danger to secondary, and `:71` maps delete submission to primary. Destructive actions therefore receive no distinct color cue in the default table. Keep descriptive text and evaluate danger color overrides separately from this phase.
- Count: eight primary-outline entries across context/list variants, plus their two menu toggles; three primary form slots and one primary card slot. These are configuration entries, not a count of simultaneously visible elements. Their existence cannot establish a 60/30/10 rendered distribution.
- Zero new color declarations or accent elements are introduced by 06.20. Computed contrast and host-theme overrides were not measured.

### Pillar 4: Typography (4/4)

- **Passing finding:** The production diff adds zero font-size or font-weight declarations. The inspected label leaf templates (`columns/child.html:3`, `tags/breadcrumb.html:6`, `tags/button/action.html:8`) inherit host typography rather than introducing arbitrary styling.
- `src/crud_views/lib/button_classes.py:19` defines six available semantic heading classes (`h1`–`h6`), not evidence that six sizes coexist on one screen. The abstract four-size rule must not count unused library options as rendered violations. No new typography inconsistency was found; computed size/weight distribution remains host-dependent and unmeasured.

### Pillar 5: Spacing (3/4)

- **WARNING S1 — inherited responsive risk, not observed overflow:** `src/crud_views/lib/button_classes.py:41` uses button groups for context/list actions, while `:43` sets card actions to `d-flex gap-2` without explicit wrapping. Labels now accept arbitrary nonblank strings, but the rendered fixtures at `tests/test1/test_viewset_verbose_name_render.py:30` use only “volume/volumes”; the child-button rendering case exercises hidden text rather than long visible text. This leaves the expanded-name layout unverified.
- The inspected defaults use existing framework spacing (`me-2` at `button_classes.py:26`, `gap-2` at `:43`, `mb-3` at `:94`); no arbitrary pixel/rem spacing is added by the phase. The recommendation is to reproduce layout at the host level before choosing a bounded wrapping/menu adjustment, not to add label truncation or length validation speculatively.

### Pillar 6: Experience Design (3/4)

- **WARNING E1 — verification gap:** `tests/test1/test_viewset_verbose_name_render.py:90` explicitly asserts only `cv_get_message()`. The Book view lacks MessageMixin, so this does not prove an overridden label reaches the user after submission. The breadcrumb case at `:109` asserts producer titles, not its rendered navigation. This limitation is disclosed in plan 02 and its summary; it is not evidence that either flow is broken.
- **Passing finding:** Invalid plain configuration is rejected before use (`viewset/__init__.py:137`); lazy translation is resolved per call (`:517`) and tested across German/English at `tests/test1/test_viewset_verbose_name.py:100`. Existing labels and Resource fallback are tested at `:43` and `:65`.
- No asynchronous action, loading state, deletion interaction, empty state, or disabled-state implementation changes occur in this phase. Existing button disabled markup remains at `tags/button/action.html:3`. Loading/error/empty/confirmation behavior was not browser-tested and is not certified by these checks.
