Documented deviations from D-03's literal `cv_book` (RESEARCH.md "Deviation note"; recorded in 06.20-02-PLAN.md): the
breadcrumb surface monkeypatches `cv_book_bc` (only the `*Bc*` views carry `CrudViewBreadcrumbMixin`; same Book model) and
the success message is asserted on `BookCreateView.cv_get_message()` (no Book view carries `MessageMixin`; the mixin posts
exactly that string). No ViewSet or view is registered by the render module or the tracer; the registry names the unit
module introduces — `guardian_verbose_name_probe` (module-scoped fixture), `verbose_name_lazy_probe`,
`verbose_name_padded_probe` and `verbose_name_blank_probe` (constructor probes) — are each popped from `_REGISTRY` under
`_REGISTRY_LOCK` when their test or fixture finishes (review rounds 1-2, REVIEWS.md at 93aca478 and 7fb7b367).

Scope gates (`git diff --quiet <base> -- ...`, `git diff --stat <base> -- src`) compare against `PHASE_BASE`, the commit
the phase branch forked from `main` (`git merge-base HEAD main` on the `gsd/phase-06.20-…` branch) — one immutable
commit for every plan regardless of wave-1 order. Each gate is one self-contained `&&` chain that resolves the fork
point, refuses `main` (where the fork point equals HEAD and the diff would be vacuous) and runs the diff:
`PHASE_BASE=$(git merge-base HEAD main) && [ "$(git rev-parse --abbrev-ref HEAD)" != main ] && git diff --quiet "$PHASE_BASE" -- <paths>`.
Executors run every command in a fresh shell, so no gate relies on a variable set by an earlier command; a non-zero
exit from any link (no fork point, on `main`, or a diff) is a failed gate, with no fallback. `PLAN_BASE` (HEAD before a
plan's first commit, recorded in its SUMMARY) is used only for that plan's `git log` commit listing with the SHA pasted
in; the wave-1 plans (01 and 03) path-scope their per-commit subject and file-list checks to the task's files so a
sibling's interleaved commit is not read by mistake (review round 2, REVIEWS.md at 7fb7b367; checker revision 1 at
aaacb756).
