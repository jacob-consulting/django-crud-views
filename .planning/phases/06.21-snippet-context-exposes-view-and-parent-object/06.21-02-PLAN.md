Values the table documents, quoted from `ViewSet.get_meta()` (src/crud_views/lib/viewset/__init__.py:498-516):
`"viewset": self, "cv": self, "verbose_name": capfirst(meta.verbose_name), "verbose_name_plural":
capfirst(meta.verbose_name_plural)`, then `"verbose_name_translate": _(data["verbose_name"])`,
`"verbose_name_plural_translate": _(data["verbose_name_plural"])`, then `context.to_dict()` = `{"object": ...}`.
Plan 01 added in `CrudView.cv_get_meta()`: `view` (the instance) and, when `cv_viewset.has_parent`,
`parent_object = SimpleLazyObject(self.cv_get_parent_object)`.

`object` fact (review H-1/A-1, verified against source and by probe): `ViewContext.object` defaults to `None`
(src/crud_views/lib/view/context.py:25) and `to_dict()` always returns `{"object": self.object}` (lines 44-45), so the
`object` key is **always present** in the snippet dict — with the value `None` on create forms and on list/card pages
(`cv_object = False` there), and the instance on detail/update/delete/action views. On a create view the form page's
header and paragraph see `None`, while the success message rendered after the save (`CreateView.cv_form_valid` sets
`self.object`, create.py:79-82, then `MessageMixin.cv_form_valid_hook` calls `cv_get_message()`, mixins.py:144-148)
sees the created instance. Only `parent_object` is genuinely absent (on a top-level ViewSet). The docs must not call
`object` "absent" anywhere — that word is reserved for the missing `parent_object` key.

`parent_object` cost fact (review A-2): `cv_get_meta()` builds a fresh `SimpleLazyObject` per call, so on an
unguarded render (no `_cv_ancestor_state`) each snippet that references `{{ parent_object }}` performs its own
`get_object_or_404` lookup — header plus paragraph is two lookups, not one. With guard state (every dispatched
request) all of them cost zero queries.

Snippets that get the full context (D-01): `cv_header_template[_code]`, `cv_paragraph_template[_code]`,
`cv_message_template[_code]`, `cv_message_template_error[_code]`, list/card `cv_filter_header_template[_code]`.
Snippets that do not get `view`/`parent_object` (D-02): `cv_action_label_template[_code]`,
`cv_action_short_label_template[_code]`, `cv_breadcrumb_label_template[_code]`, context/row/card buttons,
`LinkChildColumn` — they render *for* a target view *from* another page via `cls.cv_viewset.get_meta(context)` or
`ContextButton.render_label`, where `context.view` is the hosting page's view, not the labelled one.
