# Phase 06.21 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.
> Snippet context (`cv_get_meta`) now exposes `view` and, on a child ViewSet, a lazy `parent_object` to
> header / paragraph / filter-header / message snippet templates (#339).

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| HTTP request → `CrudView.dispatch()` | Untrusted URL kwargs (`publisher_pk`) and user; ancestor guard and permission mixins run before any snippet renders | URL kwargs, session user (untrusted input) |
| Developer-authored `cv_*_template_code` → Django template engine | Snippet texts are class attributes set by the project developer, not request data; the engine autoescapes variable output | Template source (trusted), model/request values (autoescaped) |
| Documentation → downstream developers | Docs tell theme and app authors what `view` / `parent_object` expose | Guidance (misstatement risk) |
| Docs fences → `examples/bootstrap5/test_docs_sync.py` | Marked `cv-sync` fences are contract-checked against the example app | Code samples |
