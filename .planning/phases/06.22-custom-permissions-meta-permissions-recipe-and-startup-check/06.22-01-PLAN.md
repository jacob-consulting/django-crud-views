<objective>
Add the static, database-free half of `viewset.E269` that checks every `*PermissionRequired` view's `cv_permission`
against its ViewSet model's *declared* permission set (`Meta.default_permissions` plus `Meta.permissions` of the
concrete model, keyed exactly like `ViewSet.default_permissions`), emitted from `check_ancestor_declarations` behind the
existing `_url_configuration_loaded()` barrier. GitHub issue #341 is the canonical specification; CONTEXT.md D-01, D-02,
D-03, D-09, D-10 and D-13 bind this plan.

Purpose: a misspelled or undeclared permission key on a core ViewSet today passes `E202` (presence only) and fails
with the `assert` in `CrudViewPermissionRequiredMixin.permission_required` on the first request (tabler-test finding
24, `RunSubscriptionsView` with `cv_permission = "run"`). After this plan it fails at `manage.py check` / `runserver` /
test start with a hint that spells out the `Meta.permissions` entry to add. The change is bounded to four pure helpers,
one message builder, one wiring line and one keying call, as CLAUDE.md "Decision Rule: Developer Maintainability"
requires; no new API.

Output: `src/crud_views/lib/ancestors.py` with `_concrete_opts`, `_permission_key`, `_declared_permission_keys`,

`_permission_key`; the new test module `tests/test1/test_permission_declarations.py` (14 test functions after this
plan) covering ROADMAP success criteria 1 and 2 and the cv_permission part of criterion 4.
