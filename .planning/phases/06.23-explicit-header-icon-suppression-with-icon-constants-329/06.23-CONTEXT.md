## Implementation Decisions

### Public API and rendering
- **D-01:** Export `Icon` from `crud_views.lib.icons` with plain constants `VIEWSET_DEFAULT = None` and `NONE = ""`. Keep primitive `str | None` types; no enum, sentinel or normalization framework.
- **D-02:** `cv_icon_header` inherits the ViewSet icon only when its value is `None`. Omitted/default and `Icon.VIEWSET_DEFAULT` inherit; `""` and `Icon.NONE` suppress a non-empty inherited icon.
- **D-03:** Custom `cv_header_template` and `cv_header_template_code` do not automatically suppress the icon. Explicit suppression preserves the custom content.
- **D-04:** The shared decision applies to rendered page headers and supported modal/theme headers. Verify actual markup, not only getter results.
- **D-05:** Preserve explicit semantic icon names, registered prefixes and raw CSS-class icons, plus existing `cv_get_header_icon()` overrides returning `None` for dynamic suppression.
- **D-06:** Keep current icon type/prefix validation; constants are accepted through their primitive values and unrelated invalid values remain invalid.
- **D-07:** `Icon.VIEWSET_DEFAULT` means inheritance only in the `cv_icon_header` context. Do not add inheritance semantics to group icons or the general registry.

### Compatibility, docs and scope
- **D-08:** Deliberately change empty-string semantics from inheritance to suppression. Document migration to `None` or `Icon.VIEWSET_DEFAULT` for callers needing inheritance, in both a `### Breaking` changelog entry and `docs/migrating-1.0.md`. No deprecation cycle or compatibility flag.
- **D-09:** Document the constants, full inheritance/suppression table, custom-header example and method-override recipe; clarify generic “None means no icon” wording where it hides view-level inheritance.
- **D-10:** No new project setting, boolean flag, header-template redesign, action-icon change or icon-registry refactor. Downstream edits/releases are not required for completion; #327/#328 stay separate.
- **D-11:** Focused header/icon regression and documentation checks must pass. Broad pytest runs use multiple workers.

## Problem and current behavior

`cv_header_template` replaces heading content but does not suppress the header icon. A custom heading that includes an avatar can therefore render both the ViewSet icon and the avatar.

Currently `CrudView.cv_get_header_icon()` uses:

```python
view_icon = self.cv_icon_header
icon = view_icon or self.cv_viewset.icon_header
```

Both `None` and `""` fall back to the ViewSet. Applications must override `cv_get_header_icon()` to return `None` to suppress the icon.

The renderer already accepts `None` and empty strings as no icon; the missing distinction is at the header inheritance step. Code inspected at upstream commit `6db3f1717923db7445c38192d3b743b1d8bda06c`.

## Settled API and behavior

Export a simple constants class from `crud_views.lib.icons`:

```python
class Icon:
    VIEWSET_DEFAULT = None
    NONE = ""
```

**These are plain constants, not `Enum`/`StrEnum` members or new sentinel objects.** They deliberately keep the existing `str | None` configuration types and validation.

```python
from crud_views.lib.icons import Icon
from crud_views_object_detail.lib import ObjectDetailViewPermissionRequired


class CustomerDetailView(ObjectDetailViewPermissionRequired):
    cv_viewset = cv_customer  # Existing application ViewSet.
    cv_property_display = [{"title": "Customer", "properties": ["name"]}]
    cv_header_template = "sales/customer_header.html"
    cv_icon_header = Icon.NONE  # Custom header contains an avatar; no inherited icon.
```

All supported forms:

```python
cv_icon_header = Icon.VIEWSET_DEFAULT  # Inherit the ViewSet icon.
cv_icon_header = None                  # Same behavior; existing default preserved.

cv_icon_header = Icon.NONE             # Explicitly suppress the header icon.
cv_icon_header = ""                    # Same behavior; this literal changes meaning.

cv_icon_header = "bi:person"            # Explicit per-view icon override.
```

- Fall back to `self.cv_viewset.icon_header` **only when the view value is `None`**.
- Keep omitted/default `cv_icon_header` behavior unchanged: inherit from the ViewSet.
- Do not automatically suppress icons when `cv_header_template` or `cv_header_template_code` is configured. A custom heading can legitimately need the inherited icon; suppression is explicit.
- Apply consistently wherever the shared view header icon is rendered, including supported modal headers and theme templates using the shared API.
- Preserve explicit semantic icon names, registered prefix values, and raw CSS-class icons.
- Keep the existing `cv_get_header_icon()` override available and document it for request/object-dependent decisions:

```python
def cv_get_header_icon(self):
    return None  # Existing supported way to suppress the icon dynamically.
```

`Icon.VIEWSET_DEFAULT` means inheritance specifically on `cv_icon_header`. Because it is literally `None`, it cannot acquire magic inheritance behavior in a group icon or the general icon registry. `Icon.NONE` is literally the already-supported empty icon value. Document that context rather than adding a general inheritance framework.

## Alternatives considered and scope

- Documentation of the method override alone was considered; the chosen attribute behavior is easier for a static per-view decision.
- A real enum was proposed and discussed. The maintainer chose named constants because they provide readable intent without enum normalization, wider types, or new validation branches.
- Changing `None` to mean suppression was rejected because it is the existing view inheritance default.
- Automatically suppressing icons for custom headers was rejected; custom templates and icons remain independently configurable.
- No new project setting, additional boolean flag, header-template redesign, action-icon inheritance change, or icon-registry refactor.
- Downstream workaround removal can use this API after adoption; downstream edits/releases are not a completion dependency here.

## Compatibility and documentation

The deliberate behavior change is **`cv_icon_header=""` now suppresses instead of inheriting**. Existing callers using an empty string to inherit must use `None` or `Icon.VIEWSET_DEFAULT`.

Add the constants, inheritance/suppression table, custom-header example, and method-override recipe to the relevant icon/header reference. Update misleading generic “None means no icon” wording where it obscures the view-level inheritance distinction.

Add a `### Breaking` entry to `CHANGELOG.md` and the matching migration guidance in `docs/migrating-1.0.md`, as required before 1.0.0. No deprecation cycle or compatibility flag is requested.
