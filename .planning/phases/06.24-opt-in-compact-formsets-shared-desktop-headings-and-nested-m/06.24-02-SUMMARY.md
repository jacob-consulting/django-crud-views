# Phase 06.24 Plan 02: Compact schema and validation boundaries Summary

**Compact headings now support genuinely empty formsets without parent mutation, while strict schemas and row-owned hidden errors preserve submitted data.**

## Accomplishments

- Validate every ordinary visible field, including optional/disabled fields; reject missing declarations, nonexistent columns, identity/control columns, empty labels, heterogeneous field/widget types, labels and required state before helper/widget rendering.
- Restrict visible widgets to exact stock TextInput, NumberInput, DateInput and single Select with stock templates/input types. Reject custom subclasses, altered Select option templates, multiple selection and all unlisted widgets. Preserve attributes and legitimate model-choice widget queries.
- Reuse existing forms for populated nodes; construct only one detached metadata form for zero-total nodes, preserving kwargs/context, active translation and saved/unsaved parent identity, including UUID defaults.
- Render identity fields by role exactly once even when an application supplied a visible widget. Preserve ordinary hidden fields and only present ORDER/DELETE fields; repeated rendering stays valid.
- Expose hidden-field errors once within their owning compact row after crispy renders. Keep existing field, row and formset error owners and validation/save behavior.
- Escape plain help text before crispy's safe filter without changing explicitly safe markup. Preserve ordinary label/error escaping.
- Retain zero-total wrappers/management/headings without new Add controls, DELETE-absent extras, existing extra=0 AJAX limitations, optional/disabled fields and desktop control width. Empty control cells use existing Bootstrap display classes to remove their mobile gap.

- The existing crispy `safe` help-text behavior required compact-local `conditional_escape`; this preserves marked-safe strings and does not modify field validation or cleaned data.
