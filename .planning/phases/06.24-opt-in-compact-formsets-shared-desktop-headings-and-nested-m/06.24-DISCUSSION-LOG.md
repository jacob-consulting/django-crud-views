## Nested desktop/mobile layout

**Proposal:** Keep children within each parent row; compact desktop columns and separate child heading rows;
mobile parent cards contain smaller labelled child cards with small insets. Children remain expanded.
**User's choice:** "looks good"
**Notes:** The first nested preview was empty because the companion injected its helper at a closing-body string
inside JavaScript. The corrected version escapes that string; local Chromium checks confirmed desktop columns,
mobile stacking, two parent rows and three allocations. User approval came after that correction.
The mockup uses illustrative line/allocation data and disabled controls, not a new API or persistence design.

## Public declaration

| Option | Description | Selected |
| --- | --- | --- |
| Infer existing crispy layout | `compact=True` interprets arbitrary row helpers | No |
| Explicit columns | `compact_layout=CompactLayout(columns=[CompactColumn(...)], controls_span=...)` | Yes |

**Proposal:** A single explicit declaration replaces the compact row's crispy layout definition. Forms own labels,
widgets and validation; children use the existing `children` declaration with their own layout.
**User's clarification:** "understood. so the classic implementations stays, devs can optionally opt in for campact layout?"
**Assistant's clarification:** Classic rendering remains unchanged; each FormSet and each child opts in independently.
**User's choice:** "approved"
**Result:** Issue #347 filed with the design, exclusions, delegated details and acceptance criteria. A builder check
found "nothing important left" before filing; that was a design check, not implementation verification.
