# Cross-AI Plan Review — Phase 06.24 (Opt-in compact formsets)

## 06.24-01

**Summary.** The tracer plan picks the right seams. `XForm.helper` is the only place the row helper is chosen (`src/crud_views/lib/formsets/render_tree.py:84-92`), the classic helper is fully contained in `InlineFormSet.get_helper()` (`src/crud_views/lib/formsets/inline_formset.py:56-71`), and the template has a clean wrapper-only region before the row loop (`src/crud_views/templates/crud_views/formsets/formset.html:4-29`) with the `render_rows_only` flag already set for top-level fragments (`src/crud_views/lib/formsets/formsets.py:234`). The plan achieves a real end-to-end slice without a second renderer. The main risk is the Pydantic boundary for the frozen dataclass, which the plan describes correctly but underestimates.

**Strengths**
- Branching before either classic property is accessed is correct: the polymorphic branch returns `self.form.helper` and the ordinary branch instantiates a fresh `FormHelper` per row (`render_tree.py:88-92`, `inline_formset.py:53-57`), so a compact branch placed first leaves both byte-identical.
- Reusing `FormControl(formset=declaration)` is sound: it renders `control.html` with the declarative `FormSet` and the row form (`src/crud_views/lib/formsets/layout.py:22-30`), and `control.html` already derives Add/Delete from `edit_only` and `'DELETE' in form.fields` (`control.html:19-29`), so controls_span reserves width without new capability logic.
- The six-hook CSS surface lands in the stylesheet that real pages already receive through the settings registry (`src/crud_views/lib/settings.py:357`), so no new asset registration is needed.
- The tracer fixture is well chosen: `BookFormSet` has `extra=1, can_delete=True, can_delete_extra=True` (`tests/test1/app/views_formset.py:56-66`), so the first slice already exercises DELETE-present rows.

**Concerns**
- **MEDIUM — Pydantic will not reject dicts by annotation alone.** `FormSet` is a `BaseModel` with `arbitrary_types_allowed=True` (`formsets.py:46`). Annotating `compact_layout: CompactLayout | None` with a stdlib dataclass makes Pydantic generate a dataclass schema and coerce mapping input into it, and a `__post_init__` that normalizes `columns` to a tuple can then conflict with the declared field type during that coercion. The plan's "input guard that accepts only None or CompactLayout instances" is the right intent but the mechanism should be named: `InstanceOf[CompactLayout] | None` (or `SkipValidation` plus an after-validator). The deep copy in `FormSets.clone` (`formsets.py:539-544`) is fine for frozen instances.
- **MEDIUM — hidden policy fields must be explicit layout objects, and their side effect must precede projection.** Crispy's `render_hidden_fields` only renders fields whose widget `is_hidden` (`.venv/.../crispy_forms/helper.py:277-286`); DELETE is a checkbox and ORDER a number input by default, so they are rendered only because the classic layout uses `Field("DELETE", type="hidden")` (`inline_formset.py:76-82`), which permanently replaces the widget on the form instance (`crispy_forms/utils.py:87-88`). Plan 01 says projection is computed "after forms are built" and Plan 02 adds role classification. Because the tracer fixture already has DELETE, the role-based exclusion cannot be deferred to Plan 02; otherwise a second render in the same request classifies DELETE as hidden and the first as visible.
- **LOW — heading placement.** The strip must follow `{{ x_formset.instance|as_crispy_errors }}` (`formset.html:27`) and precede the loop; JS insertion is row-relative (`formset.js:355-358`), so a non-row sibling before the first row is safe. Worth stating in the task to prevent an executor placing it before the management form.
- **LOW — process.** Task 1 touches six files and the plan has two tasks, so with the default `inline_plan_threshold` of 2 it executes inline in the orchestrator context. That is allowed but means the heaviest task of the phase runs without a fresh executor.

**Suggestions**
- Name the Pydantic mechanism (`InstanceOf` or `SkipValidation` + `isinstance` validator) in Task 1 and add a test that a dict literal is rejected at `FormSet(...)` construction.
- Move "classify ORDER/DELETE/pk/fk by role before any crispy render" from Plan 02 into Plan 01 Task 1's action text, since the tracer fixture already needs it.
- Set `helper.label_class = "cv-formset-compact-label"`: the Bootstrap 5 field template injects `label_class` into the `<label>` class list (`crispy_bootstrap5/templates/bootstrap5/field.html:16`), which gives the approved hook without a custom field template.

**Risk Assessment: MEDIUM.** The architecture is right; the two medium items are implementation details that would surface as test failures rather than silent defects, but the Pydantic one would surface late (at `FormSets.clone`) if missed.

## 06.24-02

**Summary.** This plan closes the schema, zero-total and hidden-error edges that Plan 01 leaves open. Its central claim, that hidden-field errors vanish in the stock pack, is verified: the field template renders hidden fields as bare `{{ field }}` (`field.html:3-4`) and the errors template renders only `non_field_errors` (`errors.html:1-8`), so a compact-only error region is genuinely needed. The metadata path via `get_form_kwargs(None)` is grounded in the existing `cv_view` forwarding (`inline_formset.py:96-99`). One schema edge is missing.

**Strengths**
- The zero-total case is correctly scoped to `init()`: the fragment path always materializes `forms[0]` (`formsets.py:242`), so metadata-only construction can only arise on initial render with `extra=0` and an empty queryset.
- Query attribution split between projection and widget render is the right test design; a `ModelChoiceField` Select legitimately queries when rendered, and a whole-request count would hide a heading-time evaluation.
- Role-based exclusion of ORDER/DELETE is necessary, not optional, because of the widget mutation at `crispy_forms/utils.py:87-88`.

**Concerns**
- **MEDIUM — editable primary keys break schema uniformity between the two metadata paths.** The detached metadata form never runs `add_fields`, so it has no pk/fk/ORDER/DELETE fields. Runtime rows do. For auto PKs that difference is invisible (hidden widgets), but Django adds the pk as a visible `ModelChoiceField` when `pk_is_not_editable()` is false (an editable `UUIDField(primary_key=True)` without `editable=False`). A nonempty node would then report an omitted visible field while a zero-total node would not. The plan should either classify the pk field by role (`formset.pk_field`, already derived at `formsets.py:94-95`) regardless of widget, or document editable PKs as unsupported. Neither is stated.
- **LOW — verify selector depends on naming discipline.** `-k 'schema or metadata or classic'` only selects tests whose names contain those substrings; the "classic" tests are authored in Plan 01 Task 2 with no naming contract. State the `test_compact_classic_*` prefix explicitly.
- **LOW — "reject a metadata kwargs instance pointing to the live parent".** `BaseInlineFormSet` passes `instance` outside `get_form_kwargs`, so this guard only matters for application `form_kwargs` overrides. Harmless, but the plan should say it is a defensive check, not the primary mechanism.

**Suggestions**
- Add an explicit decision to the delegated support list: pk and fk are identity roles by `pk_field`/`fk.name`, never visible columns, and editable PKs are documented as unsupported in compact mode.
- Record the query attribution numbers in the SUMMARY as the plan already requires; that is the evidence Plan 05's docs will cite.

**Risk Assessment: MEDIUM.** The hidden-error and metadata designs are verified against installed sources. The editable-PK gap is the one place where "reject descriptively" could instead become an inconsistent accept/reject depending on row count.

**Concerns**
- **MEDIUM — the harness requires a native-theme twin for every non-tracer case.** `validateEvidence` expects `stock:<id>` and `native:<id>` for any scope other than `tracer` (`conditional-formsets.cjs:84-85`), the server generates both themes per case id (`conditional_formsets_server.py:352-370`), and the native loader replaces `formset.html` and `control.html` (`conditional_formsets_server.py:30-41`), erasing the compact hooks. A `compact-presentation` case therefore cannot pass as written. The plan's phrase "add compact-only stock expectations" implies, but does not specify, a stock-only exception in `validateEvidence` and stock-only case generation. Name both changes.
- **MEDIUM — task order invalidates Task 1's evidence.** `hashes()` includes `tests/test1/test_fragment_authorization.py` (`conditional-formsets.cjs:41`), which Task 2 edits. Task 3 then runs `--check-evidence` against the presentation JSON captured in Task 1, which fails on `Stale source hashes` (`conditional-formsets.cjs:82`). Run Task 2 before Task 1, or re-capture presentation at the end of Task 3.
- **MEDIUM — screenshots must be git-ignored or the capture throws.** The capture path is passed to `git check-ignore`, which exits 1 for a tracked path and makes `execFileSync` throw (`conditional-formsets.cjs:358`). The existing directory is covered by `.planning/ui-reviews/.gitignore` (`*.png`); the proposed `browser-captures/` under the phase directory has no such rule. Add an ignore file or reuse `.planning/ui-reviews/06.24-…/`.
- **LOW — the old runtime manifest stays mandatory.** The runner reads `06-JS-RUNTIME.json` unconditionally and includes it in the hash set (`conditional-formsets.cjs:10-11,39`). Changing the hash input set also means the historical 06.4 evidence files will no longer pass `--check-evidence`; "preserve historical evidence" should be read as "do not overwrite", and the SUMMARY should say so.
- **LOW — CDN dependency.** Bootstrap is fetched from jsDelivr (`page.html:9`); the plan's "unavailable assets fail" is the correct posture, but an offline run will fail the gate rather than degrade.

**Suggestions**
- Add to Task 1's action: extend the `expected` computation for stock-only scopes (mirroring the `tracer` special case) and generate compact cases for `mode == "stock"` only.
- Reorder tasks to 2 → 1 → 3, or add "re-run `--case compact-presentation` after all source edits" to Task 3.
- Add a `.gitignore` with `*.png` to the capture directory as part of Task 1's files list.

**Risk Assessment: MEDIUM-HIGH.** Nothing here is a design flaw, but three harness invariants will fail the gate on first run, and an executor under time pressure may be tempted to loosen `validateEvidence` instead of extending it.
