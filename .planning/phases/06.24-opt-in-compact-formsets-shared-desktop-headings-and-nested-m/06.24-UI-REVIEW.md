## Top 3 Priority Fixes

1. **Expose reversible deletion state** — a marked row retains the same icon/name and communicates its state
   through danger color. In a separately scoped control improvement, synchronize `aria-pressed` with DELETE
   and supply a visible non-color state cue, with translated text explaining that another activation unmarks it.
   Preserve current reversible semantics and theme class resolution. Findings C1/COL1.
2. **Make failed Add requests understandable** — existing failures silently insert nothing, and `extra=0`
   exposes an Add operation that returns HTTP 500. Track the retained limitation explicitly; a future lifecycle
   change should provide owner-local failure feedback and prevent unsupported Add activation or implement an
   authorized empty-form factory. This is outside the approved compact phase, not an unimplemented phase task.
   Findings E1/E2.
3. **Review dense score labels at the desktop threshold** — 768px is mechanically valid but several labels
   split into two- or three-letter fragments. Review actual application labels and use concise translated
   form-owned names where they remain unambiguous; if the eight-field layout must retain long labels, obtain
   an explicit design-contract revision before changing its fixed breakpoint/column policy. Finding T1.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1 — inherited toggle copy does not explain reversal.**
  `src/crud_views/templates/crud_views/formsets/control.html:26` fixes title and accessible name to “Delete row”.
  `src/crud_views/static/crud_views/js/formset.js:469` changes classes and the hidden value but not that name or
  a pressed-state attribute. A second activation unmarks deletion, so the unchanged name does not describe
  what happens next. The UI-SPEC deliberately retains this label; this is a follow-up quality issue, not a
  claim that the implementation missed its copy contract. No marked-state screenshot was inspected; finding
  is code-derived.
- **PASS C2 — phase-owned copy remains form-owned.** `compact_headings.html:3` uses the effective label and
  required marker; `compact.py:91` rejects blank labels. `control.html:5`–`27` retains translated group/action
  names. `formset.html:27` and `:50` preserve owner-provided validation text. The invalid screenshots show
  distinct formset, row, field and hidden-field messages. Fixture “Save”/“Cancel” and diagnostic buttons are
  host-owned and are not misclassified as new generic package copy.

### Pillar 2: Visuals (4/4)

- **PASS V1 — observed hierarchy matches the contract.** `formset.html:15`, `:18`, `:29`, `:39` and `:58`
  keep legends, independent heading strips, visible row boundaries and nested owners. Inspected desktop and
  mobile compact/compact screenshots visibly retain each child's surface within its parent card; the mixed
  desktop screenshot retains classic child labels. Invalid captures retain clearly separated correction
  owners. No row numbering, duplicate responsive input tree, sticky heading or invented summary appears.
- **PASS V2 — actions retain accessible names.** All four icon controls have translated `aria-label` and
  title in `control.html:8`, `:12`, `:20`, `:27`. A focus ring is visible on the focused title in the inspected
  presentation images. This supports the rendered focus treatment only; it does not complete a human keyboard
  or screen-reader review. The dense heading readability issue is scored under Typography, not counted twice.

### Pillar 3: Color (3/4)

- **WARNING COL1 — inherited selected deletion state uses color without a semantic state cue.**
  `formset.js:469`–`487` exchanges normal/danger classes and hidden DELETE values. The button's icon and
  “Delete row” name remain constant and no `aria-pressed` is set. Transient input highlighting does not
  communicate the persistent selected state. Address together with C1; this is one remediation, not two.
- **PASS COL2 — compact surface tokens and emphasis match.** `formset.css:52`, `:54`, `:104`, `:105` contain
  four compact-owned color declarations using three host variables (border, body background, tertiary
  background) with approved fallbacks. There are zero new compact primary/accent declarations. Neutral
  headings/cards dominate inspected populated captures; focus and page actions retain the accent. Red error
  panels have text and field invalid styling. The contract defines 60/30/10 as emphasis, not pixel coverage;
  no fabricated area percentages are claimed. Existing hardcoded animation colors at `:1`–`46` are expressly
  preserved, not newly introduced palette violations.

### Pillar 4: Typography (3/4)

- **WARNING T1 — narrow desktop heading readability is weak despite successful wrapping.** The cupping-score
  section in `compact-compact-768.png` breaks labels such as “Aroma”, “Flavor” and “Balance” into short
  fragments; required markers may occupy another line. `compact.py:138` applies the declared one-column
  cells; `formset.css:70`–`73` permits breaking anywhere. This prevents overflow and follows the explicit
  contract, but makes scanning harder. The dense 3 + seven 1 + controls 2 declaration and 768px threshold
  leave little text width. Do not fix this by shrinking type or clipping labels. Apply the bounded label/design
  review in priority 3; no generic new responsive API is recommended.
- **PASS T2 — no unapproved font system.** Compact CSS introduces no font size or family and two occurrences
  of the same 600 weight (`formset.css:61`, `:77`). Body/help/error/legend sizes remain host/pack-owned.
  Desktop label clipping at `:129` retains programmatic labels; mobile restores ordinary flow. Form-owned
  small controls in the fixture are permitted exceptions, not a violation of the reference 16px body size.

### Pillar 5: Spacing (4/4)

- **PASS S1 — spacing scale and geometry are implemented explicitly.** `formset.css:49`–`67` sets 16px root
  padding/separation and total gutter, with 8px heading padding; `:92` supplies the 4px required-marker gap.
  `:102`–`115` sets 8px local child/child-row padding and adjusts only owned child headings. `:118` gives
  mobile fields 16px gaps. Border/heading 1px compensation and the 1px clipped label box are geometry and
  accessibility details, not arbitrary spacing drift.
- **PASS S2 — mixed layouts remain local.** `render_tree.py:169`–`178` retains the classic one-column inset
  only for classic children. `compact.py:143` hides empty controls cells on mobile while retaining desktop
  width. The validated presentation evidence covers alignment/overflow at both sides of the breakpoint;
  inspected images support that result. A long mobile page is expected for expanded multi-level formsets,
  not grounds to invent collapse controls contrary to the contract.

### Pillar 6: Experience Design (2/4)

- **WARNING E1 — failed AJAX has no user-visible recovery feedback.** `formset.js:381` only debug-logs the
  failure. Users see no inserted row and no explanation or retry instruction. The lifecycle record exercises
  this no-insert behavior; UI-SPEC explicitly excludes new AJAX error/loading UI. Record as inherited
  follow-up debt; do not claim that preserving it delivers complete error-state UX.
- **BLOCKER E2 — Add cannot complete in the documented extra=0 configuration.**
  `docs/reference/formsets.md:301` documents the existing fragment factory failure; the lifecycle record
  verifies HTTP 500/no insertion. `control.html:19` gates Add on `edit_only`, not availability of an extra form.
  This blocks that specific user's Add task. It is an explicitly retained, out-of-scope baseline limitation,
  not a newly discovered compact regression or a new demand to change this phase's authorized scope. Do not
  market this configuration as supporting Add; fix before shipping an application flow that requires it.
- **PASS E3 — ordinary lifecycle and correction paths are evidenced.** Source-matched records cover actual
  parent/child insertion, retained ownership, ordering, deletion/unmarking, invalid POST and saved data.
  `compact.py:128`–`145` retains one form owner, labels, hidden payload and capability-driven controls;
  `formset.html:47`–`51` makes hidden errors visible through the shared alert. Zero-total states preserve the
  explicitly approved no-new-Add behavior. Absence of a new skeleton or destructive confirmation is not a
  defect here: deletion is reversible and the loading policy is intentionally inherited.
- **WARNING E4 — acceptance evidence still needs human judgment.** Both JSON records retain
  `humanReview: pending`. The agent's five image inspections and automated focus/identity assertions do not
  establish human grouping/focus acceptance, screen-reader behavior or physical-device quality. Review the
  existing captures and keyboard flow before recording that acceptance. This is a verification limitation,
  not proof of another UI defect and not an extra score deduction.
