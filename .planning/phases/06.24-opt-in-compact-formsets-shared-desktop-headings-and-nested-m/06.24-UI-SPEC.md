# Phase 06.24 — UI Design Contract

Optional compact formsets use shared desktop headings and labelled mobile row cards. Each child selects
its own layout and stays inside its parent row. CONTEXT.md D-01–D-18 are authoritative product decisions;
RESEARCH.md settles delegated implementation boundaries. The two references/*.html files establish grouping,
not fonts, colors, controls or production data. DISCUSSION-LOG.md supplies approval history only.

This contract covers package rendering, CSS and documentation examples. It does not add an application page,
new formset engine, new control API or downstream theme implementation. REQUIREMENTS.md FSET/COND/LIFE/THEME
contracts remain preservation obligations. Use issue #347 acceptance groups 1–8 for phase traceability;
ROADMAP.md leaves new requirement IDs TBD.

## Layout and Responsive Contract

1. **Viewport below 768px:** hide the shared visual heading strip. Each compact row is a bordered, rounded
   card containing full-width fields in declaration order, with visible labels above them. Place the existing
   controls after the row's fields, followed by its child formsets. Controls may wrap within their area.
   Use a 1px theme border and inherited Bootstrap border radius (fallback .375rem). No horizontal formset scroll.
2. **Viewport at least 768px:** show one shared heading strip per compact formset outside every data row.
   Use declared col-md-N widths for both headings and field cells, plus controls_span for the controls area.
   The same gutters/padding align heading, input and control left edges. Top-align input/control cells;
   field-local help/errors expand downward. Underfilled declarations leave trailing space without stretching.
3. Retain a visible parent-row boundary around its own fields and every child formset at both widths. Each
   compact child owns its own heading strip, legend, errors and cards. Use small local insets and neutral child
   backgrounds; no accumulated one-column offset for compact nodes. Keep children expanded.
4. Reserve the declared desktop controls width even when no controls are available. The heading cell over it
   may remain blank. Mobile control-free rows omit the empty controls block's visual gap.
5. Let long headings, help, errors and translated labels wrap. Set compact cells to min-width: 0 and permit
   long text to break as needed. Native text/select widgets remain form-owned, fit their cell, and keep normal
   native value scrolling/selection behavior. Do not truncate descriptive text or shrink type to fit columns.
6. Keep one input DOM per field; CSS changes presentation only. Resizing must preserve entered values, focus,
   identity, order and deletion state. No duplicated desktop/mobile forms or interactive-grid/table ARIA roles.

The 768px threshold follows the existing md column convention and official
[Bootstrap breakpoint definition](https://getbootstrap.com/docs/5.3/layout/breakpoints/).
The reference mockup's 600px media query is illustrative and is not the package breakpoint.

## Accessibility and Ownership

Every supported visible input must retain its own unique id and associated label for attribute. On desktop,
visually clip only labels carrying the compact label hook; never apply display:none, visibility:hidden or
aria-hidden to those input labels. Restore ordinary visible labels below 768px. Shared headings are visual
orientation, not a replacement accessible name. This follows [WAI label guidance](https://www.w3.org/WAI/tutorials/forms/labels/).

Compact mode forces label availability regardless of form_show_labels; classic mode retains its established
label behavior. A missing/empty effective label cannot meet the compact contract and must be rejected with
the formset and field identified. Required markers appear in the shared heading and associated mobile label;
do not force new native required attributes onto blank extra forms.

Preserve native keyboard order: fields, existing controls, then child formsets in DOM order. Retain visible focus,
button accessible names, page-owned form/CSRF and fieldset/legend grouping. Do not add tabindex-based ordering,
nested form tags, focus stealing or tooltip-only input names. AJAX rows must retain unique label/id links.

Field errors/help stay adjacent to their own input at both widths. Non-field form errors stay inside that row;
hidden-field errors must appear in that row's visible error region rather than disappear with the hidden input.
Formset/management errors stay at their owning formset. Preserve the pack's accessible description/error
associations and existing validation semantics; compact clipping must never target feedback containers.

The illustrative domain CTA labels from the mockups do not become package defaults.

| Loading | Preserve existing request/submit feedback; no new skeleton, loading copy or disabled-state policy |

## Theme Hooks and Bounded API

Use `FormSet.compact_layout=CompactLayout(columns=[CompactColumn("field", span=N), ...], controls_span=N)`;
export declarations from crud_views.lib.formsets. No duplicate crispy row declaration is required. Absent/None
must take the existing helper path without compact metadata work. Per-formset selection applies equally to
initial GET, invalid POST, AJAX fragments, siblings and children.

Adopt these compact-only hooks as the documented theme surface; retain existing structural classes/attributes:

| Hook / seam | Responsibility |
|-------------|----------------|
| cv-formset-compact | Mark only the opted-in formset fieldset |
| cv-formset-compact-headings | Shared strip outside all cv-formset-row elements |
| cv-formset-row-compact | Mark only opted-in rows; row boundary and padding |
| cv-formset-compact-fields | Row's own field/control grid, excluding child formsets |
| cv-formset-compact-label | Generated helper label class; responsive visual clipping only |
| cv-formset-compact-child | Mark compact child nodes for local inset; never add to a classic child |
| crud_views/formsets/compact_headings.html | Proposed overridable heading include using escaped labels and declared widths |
| Existing formset.css and control.html | Scoped layout CSS and unchanged formset:* button registry resolution |

Do not use broad ancestor-descendant selectors that hide classic child labels or change classic child margins.
Apply styles to the element's own compact hook or direct owned structure. Themes override these classes/template
through existing mechanisms; no new registry or parallel layout configuration. Keep div.cv-formset-row,
.cv-formset-form, .cv-formset-content, prefix/control attributes and the existing row-added event contract.

Top-level rows-only AJAX fragments contain no duplicate shared heading. A newly inserted parent may contain
complete child formset wrappers with their own heading strips. Existing sibling insertion and ownership remain
unchanged. Deleting/reordering the first row cannot move or delete the shared headings.

The delegated bounded support rules from RESEARCH.md apply: nonempty unique exact field names, explicit integer
spans 1–12 (not booleans), total including controls at most 12, every ordinary visible field represented once.
Hidden/identity/ORDER/DELETE fields are not visual columns and must retain their existing payload exactly once.
Do not require DELETE on extra rows where policy omits it. Standard stock text/number/date inputs and single
selects, including model-choice selects, are supported with form-owned attributes. Reject heterogeneous rows,
unlisted widgets/custom templates, custom HTML cells and arbitrary crispy objects descriptively before rendering.

Labels/schema/required metadata must be uniform across rows and request paths. Reuse existing runtime forms for
headings; zero-total metadata construction follows RESEARCH.md's query-free, index-independent constructor
boundary. Do not render widgets, evaluate choices, call arbitrary helpers or mutate parent identity for headings.
No classic path pays that cost. Document the empty/extra=0 and unsupported-widget limits with a runnable recipe.
