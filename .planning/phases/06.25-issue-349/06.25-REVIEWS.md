- **N-1 MEDIUM — choice sentinel can fire during installation, not projection.** `ChoiceWidget.choices` is a normalizing property: assignment calls `normalize_choices` (`widgets.py:861-866`), whose `Iterable` branch iterates the value to check for string-like items (`utils/choices.py:94-96`) unless the value is a `BaseChoiceIterator`. The wrapper must subclass `BaseChoiceIterator` (e.g. a `ModelChoiceIterator` subclass whose `__iter__` fails), or the test should instead `monkeypatch.setattr(ModelChoiceIterator, "__iter__", fail)` for its scope and leave the real binding in place. The test project uses `APP_DIRS: True` (`conftest.py:87`); Django raises if `loaders` is set alongside `APP_DIRS` (`template/engine.py:45`). The existing analog already handles this by flipping `APP_DIRS` to `False` and listing `app_directories.Loader` explicitly (`test_formsets_compact.py:145-151`); the plan should point to that exact recipe so the executor does not hit the error and reach for a renderer subclass (which Plan 01 explicitly deferred).
- **LOW — estimate.** 27k tokens for a ~40-case test expansion plus a renderer fixture is likely low; confidence is already marked low, so no action beyond awareness.

**Suggestions**
- In Task 2 `<action>`, replace "wrap its actual widget.choices iterator" with "install a `BaseChoiceIterator` subclass sentinel (or monkeypatch `ModelChoiceIterator.__iter__`); a plain iterable is normalized and iterated on assignment".
- Reference `test_compact_presentation_heading_include_is_overridable` (`:137-159`) as the loaders template for the custom-widget renderer test, adding `django/forms/templates` via `filesystem.Loader` DIRS or `django.forms` in `INSTALLED_APPS`.
