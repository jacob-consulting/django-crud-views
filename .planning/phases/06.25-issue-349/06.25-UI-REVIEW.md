## Top 3 Priority Fixes

1. **WARNING — Failed Add-row requests lack visible feedback.** Users cannot tell why no row appeared. In a separately scoped lifecycle follow-up, expose a row/formset-owned failure message and retry affordance using the existing alert conventions. This is code-derived, not a captured network-failure test.
2. **WARNING — Desktop heading widths hinder scanning.** “Sweetness” splits mid-word and some required markers wrap separately in the 1280 captures. Application authors should choose concise labels or a less crowded `CompactLayout`/classic layout for their actual fields; retain this intentional stress fixture and request the required human readability judgment. Do not change product CSS in this phase.
3. **WARNING — Animation colors bypass theme tokens.** A later theme-maintenance change should expose add/delete/order highlight colors as CSS custom properties with the current colors as fallbacks. Preserve current behavior here; no unsupported claim of a measured contrast failure is made.

## Detailed Findings

### Pillar 1: Copywriting (4/4)

**Positive finding:** `docs/reference/formsets.md:282` explains inherited general admission and retained schema checks; lines 289–295 explicitly assign semantics, labels, errors and dynamic initialization to widget authors and distinguish the separate checkbox issue. The marker docstring agrees (`src/crud_views/lib/formsets/compact.py:14`). No misleading visual certification is offered.

In both invalid captures, “This field is required.” appears immediately below the blank required Select, while the ordinary `browser` option label remains available in JSON observations. Icon controls have translated specific names including “Add row,” “Delete row,” “Move up” and “Move down” (`src/crud_views/templates/crud_views/formsets/control.html:8`, `:20`, `:27`). The deliberately long German label and unbroken help text are stress inputs (`tests/browser/conditional_formsets_server.py:241`), not proposed product copy. The fixture's extra native Save/Reset controls are explicitly test-only (`tests/browser/templates/conditional_formsets/page.html:45`); they are not a new product CTA defect.

### Pillar 2: Visuals (4/4)

**Positive finding:** All three 1280 images retain one shared Cupping scores heading strip, and all three 390 images retain visible row labels. Initial/invalid/added states preserve row boundaries and nested Books/Notes/Grandchild/Memos grouping. The added score row does not duplicate the shared heading strip. Invalid feedback remains attached to the first taster, not the new row.

The helper preserves associated labels (`src/crud_views/lib/formsets/compact.py:142`) and the existing heading include follows declared column spans (`src/crud_views/templates/crud_views/formsets/compact_headings.html:1`). Desktop labels are visually clipped rather than removed (`src/crud_views/static/crud_views/css/formset.css:124`). Icon controls have accessible names as cited above. This is a narrow positive assessment of the supplied fixture; nested grouping/readability still requires the user's visual acceptance.

### Pillar 3: Color (3/4)

**WARNING C1 — Inherited hardcoded highlight palette.** `src/crud_views/static/crud_views/css/formset.css:1` through line 33 contains nine literal animation color assignments using four unique colors (`#e2e0e0`, `#ff6a6a`, `#8fb7ff`, `#b3d0b3`). These do not follow host theme variables, unlike the compact body/border/child surfaces at lines 52–54 and 104–106. This is a concrete theme-maintainability gap, not a new marker defect or proven contrast failure. A future theme change can add variables with identical fallback values.

The images are predominantly white/light-neutral with restrained primary actions and red invalid feedback; the added-state green highlight is localized. There is no observed accent-overuse problem. Exact 60/30/10 pixel proportions and contrast ratios were not measured, and no palette contract mandates them. Tailwind primary-class counts are inapplicable to this Bootstrap/Django implementation.

### Pillar 4: Typography (3/4)

**WARNING T1 — Inherited desktop stress-layout word fragmentation.** In all three 1280 captures, the narrow Sweetness heading wraps inside the word; some required asterisks also wrap beneath their labels. The fixture gives taster three grid spans and each of seven other fields one span (`tests/browser/conditional_formsets_server.py:440`). `overflow-wrap: anywhere` intentionally prevents overflow (`src/crud_views/static/crud_views/css/formset.css:70`) but cannot guarantee easy scanning. The 390 layout has more readable full-width field labels. This is a visible minor issue, not hidden text or failed task completion.

The compact stylesheet introduces zero font-size overrides and one distinct weight, `600`, used for headings and row labels at lines 61 and 77. It inherits the host font scale; no new typographic proliferation is present. Choose appropriate labels/layout at the application boundary and obtain human judgment on the dense fixture rather than treating DOM visibility as readability certification.

### Pillar 5: Spacing (4/4)

**Positive finding:** Compact rows use 1rem padding/margins/gutters, children use .5rem padding, and required markers use .25rem separation (`src/crud_views/static/crud_views/css/formset.css:49`, `:59`, `:66`, `:92`, `:102`). The 1px heading margin aligns with row borders, and 1px/-1px values in the desktop label rule implement visual clipping rather than arbitrary content spacing. Mobile row gap is 1rem below 768px (line 118).

All six images retain separation between fields, help/errors and rows without overlap. The driver verifies help fits its cell and the document does not horizontally overflow (`tests/browser/compact-widget-compatibility.cjs:121`). The typography warning is not duplicated into a second spacing penalty: the spacing scale itself is consistent. Only 390 and 1280 were observed; near-breakpoint behavior is not newly certified.

### Pillar 6: Experience Design (3/4)

**WARNING E1 — Inherited silent add-request failure.** The AJAX error callback only calls `this.debug('Error:', error)` (`src/crud_views/static/crud_views/js/formset.js:381`). It does not show an error beside the formset or a retry explanation. A failed request therefore lacks user-visible recovery feedback. This finding is code-derived; the recorded driver tests successful 200 fragments, not network/server failures. Address it in separate lifecycle work rather than changing the approved marker scope.

Positive observed coverage: both widths pass keyboard focus after Tab/Shift+Tab, actual 422 invalid redisplay with owned visible errors, authenticated 200 add fragments, unique prefixed names/IDs, retained option metadata and single heading ownership. Delete toggles the added row's hidden DELETE to `1`, and unmark clears it. These are reversible pre-save marks, so an extra destructive-confirmation dialog is not required for the tested toggle. Delete/unmark have control/JSON observations only, not screenshots. The disabled overall field and optional sweetness state persist. No runtime page errors were recorded.

The existing rendering/helper remains unchanged (`src/crud_views/lib/formsets/compact.py:135`). General widget admission is not proof that arbitrary radio/checkbox/multiwidget/custom-template rendering is accessible; that is explicitly the application author's responsibility. No new SPA loading skeleton, error boundary or empty-state requirement is inferred for this bounded server-rendered marker addition. Human judgment for the six supplied images remains pending.
