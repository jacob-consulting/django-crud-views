## Design and scope

User requirement: a **new ViewSet**, not another action on cv_questionnaire. Planning choice:
cv_checklist in the existing formsets app, backed by Checklist(title) and
ChecklistItem(checklist FK with related_name="items", label, done BooleanField default=False).
Use normal models with deterministic PK ordering; ordering/reordering and nested grandchildren
are not needed to teach this single-level example. A small migration is intentional: existing
Question/Choice models have no BooleanField, while borrowing the object-detail Product model
would entangle unrelated example features and many irrelevant fields. No new Django app,
dependency, custom widget, marker, template, CSS or JavaScript is required.

Use a public CompactLayout with label span 7, done span 2 and controls_span 3 (total 12).
Set human-readable translated labels/help on the ordinary model/form fields. Done is optional;
an unchecked box means False, not a required acknowledgement. Standard model validation on
label supplies the invalid-input example. Keep the existing Questionnaire examples intact.

All changes are sequential in Wave 4. The original verification/UAT and audits describe plans
01–03 and remain historical evidence; never edit their status/fingerprint to imply coverage of
this new work. After execution regenerate phase verification and extend the consolidated visual
UAT to this real example. Do not mark existing human review passed. requirements=[] is intentional:
this phase has no assigned requirement IDs.
