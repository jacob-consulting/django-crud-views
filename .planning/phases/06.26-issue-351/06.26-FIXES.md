# Phase 06.26 Review Fixes

## WR-01 — Ordinary browser reruns overwrite retained captures

**Verified:** The original `capture()` ignored `--output`. A regression invoking the actual runner in a VM, with screenshot/filesystem writes recorded in memory, failed with `ordinary capture wrote inside the canonical evidence directory`. The probe did not change real captures.

**Resolution:** Ordinary captures now live in `<output>.captures/`, for example `/tmp/compact-checkboxes.json.captures/current-390-initial.png`. They do not require Git trackability. The existing documented `/tmp` command is now isolated without a recipe change.

Only an explicit canonical JSON destination matching the selected variant refreshes retained evidence. Those captures are staged in a unique temporary directory until all browser assertions and browser shutdown succeed, then published before the corresponding report. Failed runs preserve the canonical JSON and PNGs, write their diagnostic report under the system temporary directory, and clean staged captures. Canonical tracer outputs and mismatched variant/report paths are rejected. `--check-evidence` still validates the fixed canonical JSON/capture paths.

The regression uses the actual capture and output-publication functions; its mocks replace external I/O rather than the path-selection logic under test. No browser, package install or real evidence mutation is needed to test failure handling.
