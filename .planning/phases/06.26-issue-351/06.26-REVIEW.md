### WR-03: Cleanup waits forever after a server has already exited by signal

**Classification:** WARNING
**Status:** RESOLVED — independently verified in `dc4bf395` and final evidence `a661ffca`.
**Original file:** `/home/alex/projects/alex/django-crud-views/.planning/phases/06.26-issue-351/06.26-checklist-browser.cjs:182` at `a149553d`.
**Issue:** A child that exits by signal retains exitCode === null and sets signalCode. **Fix:** Capture the child exit promise immediately when spawning it, or check both exitCode and signalCode before attempting termination/waiting. Already-exited children should continue directly to remaining cleanup. Add a regression covering a signalled child whose exit event precedes cleanup. Keep this separate from WR-02's exception handling: catching errors cannot resolve this pending promise.

**Verified resolution:** Final runner lines 198–214 check both exitCode and signalCode. Running children get an exit listener before SIGTERM, a three-second wait, then owned-child SIGKILL and a one-second wait. Timers/listeners are removed and terminal status is recorded; any termination failure enters the continued-cleanup path. Both real-child regressions passed independently: already-emitted SIGTERM exit proceeds to reporting/removal, and SIGTERM refusal ends via SIGKILL within the bounded wait.
