## Top 3 Priority Fixes

These are follow-up improvements, not new checkbox release blockers.

1. **Improve narrow desktop score headings (inherited)** — the 768px score columns break words into several tiny lines, slowing label scanning. In a separate compact-layout improvement, give that score layout more room or retain stacked rendering until its headings fit; do not alter the approved checkbox breakpoint solely for this fixture.
2. **Clarify the fixture's primary submit action (fixture-only)** — native-looking Reset/Save controls lack the hierarchy of the Bootstrap row controls, and the nested fixture displays a second Save area. Give the fixture one clearly styled primary submission control while retaining a distinguishable test-only reset control.
3. **Tokenize lifecycle highlight colors (inherited)** — fixed red/blue/green animation values do not adapt with the surrounding Bootstrap theme. Replace them with semantic custom properties and bounded fallbacks in a separately scoped theme change.

## Detailed Findings

### Pillar 1: Copywriting (4/4)

**PASS:** `compact.py:102` requires a nonempty effective form label, and `compact.py:105` carries that label and required state into headings. `compact.py:142` preserves row labels. The long constructor-assigned German active label and required accepted label remain readable beside mobile checkboxes; desktop headings carry the same wording. `conditional_formsets_server.py:395` and `:407` define the deliberate translated fixture strings. The invalid captures show actionable feedback asking the user to confirm the conditions for this row, rather than a generic failure.

**PASS:** Ordinary help containing literal `<em>` is displayed as text, consistent with `compact.py:144–148`; it is an escaping probe, not broken product markup. Generic `Flag`, `Save`, and the language mixture belong to the fixture, not newly prescribed package copy. Row controls have specific translated titles and accessible labels (`templates/crud_views/formsets/control.html:8`, `:12`, `:20`, `:27`). No new copy defect found.

### Pillar 2: Visuals (3/4)

**WARNING — fixture-only:** `tests/browser/templates/conditional_formsets/page.html:45–46` adds plain native reset/submit buttons. In `current-1280-initial.png` they have a different visual treatment from the Bootstrap row actions. `current-768-nested.png` also shows the nested page's Bootstrap Save/Cancel area followed by the fixture Reset/Save area. This makes the page's primary action less clear. Fix the test-host presentation independently; this is not caused by checkbox CSS.

**PASS:** Actual checkbox rows have distinct bordered groups; mobile labels remain adjacent to inputs, desktop labels are accessibly clipped, and shared headings align with the checkbox columns. Icon-only row actions are named in the control template. The nested capture visibly distinguishes child groups, and `formset.html:57–60` renders children outside the owning crispy field grid. No missing-label or checkbox-grouping regression found.

### Pillar 3: Color (3/4)

**WARNING — inherited:** `formset.css:1–34` contains twelve hardcoded hex occurrences across three lifecycle animations, using four distinct colors (`#e2e0e0`, `#ff6a6a`, `#8fb7ff`, `#b3d0b3`). Unlike the row/child surfaces at `:52–54` and `:106–108`, these colors do not consult Bootstrap variables. This is a code-derived theme consistency issue; animation screenshots were not captured by this audit, and no dark-theme failure is asserted.

**PASS:** The new checkbox selector branches add zero color declarations and zero independent accents. Inspected captures use mostly neutral surfaces, blue checked/focused controls, and red field-owned invalid feedback. Error text supplements color; disabled controls have the inherited muted treatment. There is no demonstrated checkbox accent overuse. A numeric 60/30/10 area distribution was not measured and is not a locked requirement for this reusable form surface.

### Pillar 4: Typography (3/4)

**WARNING — inherited score layout:** `current-768-nested.png` shows score headings such as Flavor/Acidity/Balance breaking across short fragments. The fixture assigns most score columns one grid span (`conditional_formsets_server.py:506`), while `formset.css:70–73` allows anywhere wrapping. The result fits geometrically but is harder to scan. This is distinct from the readable new checkbox headings; retain its provenance rather than diagnosing it as a checkbox regression.

**PASS:** The audited stylesheet declares one explicit weight, 600, used for shared headings and compact labels (`formset.css:61`, `:78`), and no explicit font sizes. Other text sizes/weights come from Bootstrap and the fixture environment. No new font family, size scale or typography override was introduced. Mobile long labels and errors wrap without clipping in the inspected current/floor captures. A repo-wide Tailwind class count would not be meaningful for this Django/Bootstrap patch.

### Pillar 5: Spacing (4/4)

**PASS:** `formset.css:76–83` limits the checkbox label weight and inner margin reset to the exact owned wrapper chain. The existing grid uses a 1rem gutter, 1rem row padding/gaps, and .5rem child padding (`:49–66`, `:104–122`). The 1px label size and -1px margin at `:138–142` are intentional accessible clipping, not arbitrary layout spacing.

**PASS:** Retained measurements verify the old floor `.form-check.mb-3` inner margin becomes 0px in compact cells. Classic wrappers retain their own 16px floor or 2px current margins under the checkbox-rule isolation test. Current and floor desktop initial/invalid images show matching row geometry. Mobile labels sit beside their controls with readable wrapping; help/errors are not clipped. No checkbox-specific overflow was found in the four-width evidence. Dense score typography is recorded separately, without double-counting it as a spacing failure.

### Pillar 6: Experience Design (4/4)

**PASS:** `tests/browser/compact-checkboxes.cjs:367–381` exercises focus, Space activation, Tab/Shift+Tab and disabled inability to focus/activate. The validated records pass those checks; the desktop initial images and mobile added image visibly retain focus treatment. `:394–401` checks visible field-owned required errors. The invalid captures confirm feedback remains in the row and submitted active states survive.

**PASS:** The retained current/floor results cover optional checked/omitted persistence, disabled True/False trust, required invalid redisplay on persisted and edited added rows, unchanged untouched extras, authorized fragments, delete/unmark, and nested ordering ownership. Native form semantics remain in Django; `compact.py:84–101` changes only exact stock widget admission while preserving custom-widget checks. Successful JSON responses are a fixture convention, not the package's intended application completion screen.

The bounded patch adds no async fetch UI, destructive immediate-delete action or new empty-state surface requiring new loading/error/confirmation components. Existing row removal is staged and reversible through unmarking. This score does not certify unrelated application workflows, other browser engines, alternative themes or subjective human acceptance.
