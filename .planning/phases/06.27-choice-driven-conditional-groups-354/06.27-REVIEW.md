## Critical Issues

### CR-01: A valid inherited cleaner returning None crashes value-driven forms

**Classification:** BLOCKER  
**File:** `/home/alex/projects/alex/django-crud-views/src/crud_views/lib/conditional/group.py:221-225`  
**Related:** `/home/alex/projects/alex/django-crud-views/src/crud_views/lib/conditional/toggle.py:159`

**Issue:** Django permits `Form.clean()` to update `self.cleaned_data` without returning a replacement mapping. Its `BaseForm._clean_form()` preserves the existing mapping when the return value is `None`. The new value-group branch instead unconditionally assigns the return value of `super().clean()` to `self.cleaned_data`. A parent cleaner with an implicit `None` return therefore makes `ValueToggle.is_on()` call `None.get()`, raising `AttributeError` during `is_valid()`. This occurs for both active and inactive submissions using supported native fields and widgets.

**Reproduction:**

```python
from django import forms
from crud_views.lib.conditional import (
    ConditionalGroup,
    ConditionalGroupFormMixin,
    ValueToggle,
)

class Parent(forms.Form):
    kind = forms.ChoiceField(choices=[("a", "A"), ("b", "B")])
    detail = forms.CharField(required=False)

    def clean(self):
        super().clean()  # Legal Django cleaner; implicit None return.

class Child(ConditionalGroupFormMixin, Parent):
    cv_conditional_groups = [
        ConditionalGroup(ValueToggle("kind", ["a"]), ["detail"], required=[]),
    ]

Child(data={"kind": "a", "detail": "submitted"}).is_valid()
# AttributeError: 'NoneType' object has no attribute 'get'
```

The same failure was reproduced for `kind="b"`, and on Django 4.2.30, 5.2.19, and 6.0.10. The plain parent form accepts the same input. This finding concerns the new value-group mapping assignment; it does not assume every existing checkbox configuration already supports a None-returning parent.

**Fix:** Normalize a `None` return to the existing `self.cleaned_data` before using the result for activation, required checks, or clearing:

```python
cleaned = super().clean()
if cleaned is None:
    cleaned = self.cleaned_data
```

Keep an explicitly returned mapping authoritative, including an empty dictionary; using `cleaned or self.cleaned_data` would incorrectly discard that case. Add focused active/inactive regressions for an inherited cleaner returning None, including a parent-added validation error, and retain replacement-mapping coverage.

### WR-01: Choice fixture evidence accepts observations that contradict a passed assertion

**Classification:** WARNING  
**File:** `/home/alex/projects/alex/django-crud-views/tests/browser/conditional-formsets.cjs:126-131`

**Issue:** For `choice-widgets`, `validateEvidence()` checks the assertion IDs, `passed === true`, dimensions, and existence of `detail.observed` and `detail.expected`. It never validates those observed results against the recorded expectations. Consequently, contradictory evidence is accepted by the command intended to reject invalid evidence.

A read-only, in-memory mutation reproduced this against the final `evidence/choice-widgets.json`: first validate the unchanged record, then replace the first cell's `unload-listener-cleanup` observation with:

```javascript
{ detached: false, released: false, unchanged: false }
```

Leave its expected values all true and leave `passed` true. `validateEvidence()` still succeeds. Source hashes, assertion completeness, request statuses, and database-record presence remain intact. Thus the checker accepts a record explicitly saying the cleanup checks failed. This is a test-evidence reliability defect, not evidence that the application cleanup itself failed. The separate actual-example runner compares observations and expectations and is unaffected.

**Fix:** Make the new choice assertions independently verifiable. Either record comparable canonical observed/expected summaries and compare them in the checker, retaining larger snapshots separately, or use bounded assertion-specific predicates for the current observation shapes. Do not blindly deep-compare existing snapshots with differently shaped expectation summaries. Add a negative checker regression that changes an observed cleanup value without changing `passed` and requires rejection; apply equivalent verification to the other new choice assertion outcomes.
