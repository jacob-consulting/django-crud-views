## 06.27-01

**Summary.** The tracer slice is well grounded: every seam it names exists in the shape described, and the stock-only case mapping edit it calls for is a real requirement of the runner (`cjs:103`). Two gaps matter: the fixture row used as the controller carries a model default that is not a valid choice, and the plan does not enumerate the four `binding.checkbox` sites that a Select binding must survive. A Django 4.2 vs 5.x/6.0 seam for callable-choice detection is also unnamed here and only surfaces in Plan 05.

**Strengths**
- Correct read of the activation seam: `ToggleSource.is_on` raw fallback (`toggle.py:29-33`) is exactly what must not be inherited; the mixin calls `group.is_on(self)` only after `super().clean()` (`group.py:191-193`), so "cleaned value only" is viable without recursive cleaning.
- The "set `cv_toggle_values` to `None` on the legacy path every render" rule is necessary, not cosmetic: `layout.py:286` does `context.update(...)` on the shared crispy context, so a checkbox group rendered after a value group would otherwise inherit stale tokens.
- `validateEvidence` hard-codes which case ids are stock-only (`cjs:103`), and `selected` filters by id (`cjs:187`); the plan explicitly names the mapping change. `CV_FOCUS_NODE` bypasses the runtime manifest (`cjs:11-13`), matching the verify command.
- Existing `ToggleGroup(toggle_field: str, ...)` positional signature (`layout.py:278`) can accept a descriptor without breaking the documented keyword.

**Concerns**
- **MEDIUM — controller fixture default is not a valid choice.** The tracer declares `blank_text` as the controller, but `ConditionalPersistenceRecord.blank_text` is `CharField(blank=True, default="default text")` (`tests/test1/app/models.py:276`). A row created with defaults renders a Select with no `selected` option; the browser and `form_payload` fall back to the first option. `persisted-reopen` could then pass without proving the saved value round-trips. The seeded tracer row must carry a valid kind, and reopen should assert the selected option equals the stored value.
- **MEDIUM — four `binding.checkbox` read sites not named.** `recoverFocus` (`toggle.js:72`), `sync` (`:88`), rebind (`:141`, `:153`) and unload (`:208`) all dereference `.checkbox`. A select-only binding that changes the shape at `:164` without adapting all four throws on rebind/unload. The action says "retain focus/reset ownership" but should list these sites so the tracer does not leave Plan 03 to discover a `TypeError`.
- **MEDIUM — version seam for callable choices.** `validate_field` must inspect `field.choices` without forcing callables. Django 4.2 wraps them in `django.forms.fields.CallableChoiceIterator` (`.nox/tests-3-12-django-4-2/.../forms/fields.py:835,863-868`); 5.2 and 6.0 use `django.utils.choices.CallableChoiceIterator`/`BaseChoiceIterator` (`utils/choices.py:15,53`). Neither Plan 01 nor 02 names this, and the 4.2/6.0 runs happen only in 05-03.
- **LOW — `validate_field` is unwired until Plan 02.** Between waves, a misconfigured match never activates and never errors. Acceptable given ordering, but 01-02's acceptance text ("unsupported shapes raise") should say it is proven by direct calls.
- **LOW — six-file tracer.** Justified, but `toggle.js`, the host and the runner are each touched again by Plan 03; keep Plan 01's JS change minimal (binding shape + select resolution) so Plan 03 is an extension, not a rewrite.

**Suggestions**
- Seed the tracer row with `blank_text="wholesale"` or similar and add a `reopen-selected-matches-db` assertion.
- Name the four `binding.checkbox` sites in the action and require `binding.controls` to be the only shape by the end of 01-01.
- Add a small version-tolerant helper for "choices are callable" in `toggle.py` and a parameterized test that runs under all three series in 05-03.

**Risk: MEDIUM.** The seams are real; the risk is a tracer that passes for the wrong reason and a JS shape change that breaks lifecycle paths Plan 03 then has to repair.

## 06.27-02

**Summary.** The plan's description of the resolver, mixin ordering and checks pipeline matches the source line for line, and the `E313` id is genuinely free. One concrete defect: the new nonnullable integer fixture field has no default, which would break every bare `Record.objects.create(...)` in the suite and the browser host. A ModelForm validation-exclusion quirk also means "model validation remains authoritative" is slightly overstated for active-but-blank nonblank choices.

**Strengths**
- The locked clearing matrix is a genuine gap: model-generated choice fields are `TypedChoiceField` with `coerce=self.to_python` and `empty_value=None` when nullable (`django/db/models/fields/__init__.py:1116-1126` in 5.2), so the `scalar_pairs` branch (`group.py:112-117`, requires `forms.IntegerField`) and the text branch (`:103-107`, requires `text_forms`) currently raise. The plan's "exact stock TypedChoiceField + native to_python" rule is the minimal extension.
- Static/runtime split is preserved: `_collect_group_findings` reads `base_fields` (`checks.py:334-336`) and the mixin re-checks request-added fields in `clean()` (`group.py:187-190`), already demonstrated by `test_request_added_unsupported_field_is_configuration_error_even_when_active` (`test_conditional_group.py:112-134`).
- `ConditionalFormSet` is a Pydantic model with `arbitrary_types_allowed` (`formset.py:323-332`); a field validator is the right boundary, and the consumer calls `conditional.toggle.is_on(main_form)` directly (`formsets.py:357`), so the rejection is needed.
- Dedup via `dict.fromkeys` (`checks.py:393-395`) is the pattern to extend for `value_errors`.

**Concerns**
- **HIGH — nonnullable integer fixture field without a default.** 02-02 adds `required_integer_choice` as "required nonnullable integer choices 0/1" and does not specify `default=`. Django's `get_default()` yields `None` for a non-null `IntegerField` without default, so `Record.objects.create(parent=...)` (`test_conditional_persistence.py:73-74`, `:177`) and the browser host seeds (`conditional_formsets_server.py:678-679`) would raise NOT NULL. `required_text_choice` is safe (CharField default is `""`). D-05 explicitly allows a model default that is not a clearing instruction, so give it one and keep the "explicit value required" test.
- **MEDIUM — validation-exclusion quirk undercuts "native validation still rejects".** `ModelForm._get_validation_exclusions` excludes a `blank=False` model field from `full_clean` when the form field is not required and the value is empty (`django/forms/models.py:426-434`). Because the mixin sets `required=False` on every controlled field (`group.py:179-181`), an *active* group's nonblank choice that is not in `required` and is tampered to `""` persists `""`. This is pre-existing, but 02-02's acceptance claims inherited constraints block invalid saves; add a test that pins the actual behavior and let Plan 05 document it.
- **MEDIUM — absent-field tolerance must stay for checkbox groups.** `test_clean_skips_fields_not_on_form` (`test_conditional_group.py:53-76`) requires that a declared field missing from the form is skipped. 02-01 adds "declared controlled names exist at runtime" for value groups; state explicitly that this restriction applies only when a value group participates, or the existing test regresses.
- **LOW — callable choices in static checks.** Same version seam as Plan 01; `validate_value_groups` run from `_collect_group_findings` must not iterate a `CallableChoiceIterator`.
- **LOW — `_cv_enforce_required` uses `cleaned.get(name) in field.empty_values`** (`group.py:239`). For a nullable `TypedChoiceField`, `empty_value=None` is in `EMPTY_VALUES`, so required enforcement works; worth one explicit test with the blank `---------` option selected.

**Suggestions**
- Specify `default=` for every nonnullable fixture field and note which `create()` call sites depend on it.
- Add a "tampered blank on active, non-required, nonblank choice" test and record the outcome in the docs matrix.
- Make the overlap/controller check a pure function over `(groups, field_names, model)` and assert it performs zero queries with `django_assert_num_queries`.

**Risk: MEDIUM.** The HIGH item is a one-line fix but would otherwise fail broadly; the rest is clarification.
