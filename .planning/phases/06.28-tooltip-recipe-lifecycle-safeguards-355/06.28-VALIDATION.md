## Behavioral controls and review

- A red placement run keeps the extraction marker valid and executes the original fence body; failure must reach a
  placement assertion. A missing marker alone is insufficient.
- A lifecycle negative control backs up the current documentation bytes with mktemp and establishes EXIT restoration
  and HUP/INT/TERM exit traps before replacing only the marked body. Capture the expected assertion failure, restore
  from that backup on success or failure, and require cmp byte equality before deleting it. Do not restore historical
  Git versions or edit the file concurrently. Retain/report the backup if restoration fails; recover from it before
  continuing after an untrappable kill. Run this in one bounded shell invocation, with no retained helper or commit
  during the control, then rerun the corrected recipe green.
- Assert explicit/empty placement, other locations, omitted options, live/disposed/directly replaced identity,
  cleanup without creation, missing namespace/component (including bottom written before the no-op), late availability,
  creation count, raw-to-guard identity change on first init, and guard identity stability on repeat init.
- Review the actual fence for capture of the factory initializer and the subsequent init(el, options) call, excluding
  direct component initialization and copied guard logic. Behavioral tests alone do not prove delegation; this bounded
  source review supplies that evidence without adding syntax assertions or factory interception machinery.
- Review ordering for both loading and already-ready documents, precedence/safeguard prose and unchanged
  native/non-Bootstrap examples; inspect cumulative changes
  against execution start. Only `docs/reference/javascript.md` and `tests/js/adapters.test.js` may change as product
  files. Ordinary planning metadata and pre-existing unrelated changes are accounted for separately.
- CHANGELOG disposition: unchanged API/runtime and the existing Unreleased #202 recipe entry make an additional
  public-surface entry unnecessary. Keep CHANGELOG.md and migrating-1.0.md unchanged and record the rationale.
- No human-only UX acceptance is required. Prose/diff review is executor review, not a new approval checkpoint.
- Evidence is mocked Vitest/jsdom execution of the production factory; no new browser reproduction is claimed.
