## Accomplishments

- Configured an independent SQLite `shard` before Django setup, without TEST.MIRROR. A function-scoped router
  uses ContextVar tokens and encloses force_login, sessions, middleware and actual requests. Router restoration,
  context reset, transaction test cleanup and alias-keyed ContentType cache hygiene are scoped to fixtures.
- Added 154 database tests: 24 core lifecycle cases and 130 Guardian projection cases. Colliding Publisher,
  Book, Contract and actor PKs have distinct labels and asymmetric protection on the two actual databases.
- Actual GET/confirmed POST proves a protected row on one database neither blocks nor mutates the unrelated
  unprotected row on the other. The inverse direction preserves native blocking and unrelated children.
- Instance-aware write routing wins over the loaded read alias. Inspection ignores prefetched read-side
  relations. Actual permission/state gates see the read-alias object before the trusted selector chooses the
  same model/PK on the write alias under native using semantics; there is no second authorization lookup.
- Native and custom delete methods, both atomic modes, cooperative atomic overrides, direct processing,
  selector-once behavior after PK clearing, invalid aliases and incompatible signatures have executable controls.
  Holding the other connection's transaction proves on_commit is attached to the selected connection.
- Guardian caches by `(model, using)` and binds candidate queries to each candidate's `_state.db`. Tree and
  protected callers always supply the required keyword-only using; all existing direct callers, including
  inactive, no-view, through, proxy and polymorphic cases, were migrated without weakening their assertions.
- Before materializing candidates or taking superuser/global/through paths, validate persisted actor identity,
  User/Group/Permission/ContentType routes, auth join tables, actual related-manager routes and configured
  Guardian user/group grant managers. Enabled direct-grant candidates are enumerated from metadata before
  Guardian's target resolver can call its configured content-type hook. Through projection skips that hook.
- Authenticated actors from another database are never substituted by a colliding local PK. Configured
  anonymous resolution must return a saved active same-alias actor; absent or mismatched resolution hides labels.
- In multi-database configurations, a fresh same-alias actor discards permission/prefetch caches with unknown
  provenance on either alias, after the input identity was verified. request.user and its caches remain unchanged.
  Unrecognized global backend query paths on a non-default alias fail closed; strict object grants still work.
- Real same-alias object, group, global-user, global-group and superuser requests show the correct protected
  labels. Ninety-six independent mismatch cells cover actor, content type, both grant tables, auth models and
  joins, and instance-hinted related routes across ordinary, global, superuser and through paths on both aliases.
  Separate foreign-content-type, pre-middleware misrouted actor, anonymous and interleaved-request cases pass.
- Unsupported topology preserves native blocked state, aggregate counts and completeness while removing raw
  label objects from both tree and protected context. No new endpoint, schema or trust surface was introduced.
