# Modal focus repair proposal

This is the concrete contract for plans 18–20. It is reviewable at planning time and grants no implementation
approval. The original DESIGN/APPROVAL and GAP-DESIGN/GAP-APPROVAL remain byte-for-byte historical evidence.
Their approvals do not bind this new adapter contract. DEL-01/D-16 review happens in plan 18 before plan 19.

## Evidence and bounded scope

Current VERIFICATION reports one concrete blocker: real unchecked and stale-protection 422 responses replace the
focused node and leave BODY active; Close also leaves BODY. The original backend CR-01/02/03 and CT-01 repairs
remain verified. `17-evidence/browser.cjs`, `browser-results.json` and server.py are the actual failure record.

`cvModalInject` dispatches unload, assigns innerHTML, then dispatches loaded. `cvModalOpen` fetches before showing
the shell. `cv.adapters.modal` currently exposes only show/hide/setSize. Bootstrap can hide on Escape/backdrop
without the delegated Close handler. Calling focus immediately after hide would race its transition.
The [Bootstrap modal lifecycle](https://getbootstrap.com/docs/5.3/components/modal/#events) supplies
`hidden.bs.modal` after dismissal completes; hide itself returns earlier. Library-specific events stay inside
adapters.js. Context7 MCP/CLI were unavailable; this primary documentation and current source ground discovery.

The repair touches client focus, its adapter contract, regression proof and contract documentation. It changes no
authorization, deletion callback, database, confirmation, notice copy, CSS, layout or response-status policy.
UI-SPEC's prohibition on extra focus stealing means recovery occurs only when this operation destroys the active
dialog control, or when a finished dialog returns focus. Initial-show focus remains owned by the adapter.

## Proposed focus contract

1. Capture the actual delegated trigger before fetching, including clicks on a nested icon or text. Programmatic
   `cvModalOpen(url, size)` captures the current active element before its asynchronous work. An optional internal
   third opener argument may pass the delegated element; existing two-argument calls retain their signature.
2. During an open session, record whether focus was inside content that will be replaced. Preserve unload-before-
   replacement and loaded-after-replacement events with their existing attachment semantics. On a real 422, after
   loaded listeners run, keep any usable in-dialog focus that a listener already assigned. Otherwise, if replacing
   content destroyed active dialog focus, focus the first visible, enabled invalid field (native :invalid or
   aria-invalid=true), then the first usable dismiss control, then the shell itself with temporary tabindex=-1.
   The shell fallback keeps its existing tabindex when present and removes only an attribute added by this code
   after focus leaves. The invalid checkbox and blocked Close control are the expected stock targets.
3. A usable element is connected, has visible rendered geometry, is not hidden/inert/aria-hidden through an
   ancestor, and is neither disabled nor aria-disabled=true. Confirm the actual focus assignment succeeds before
   accepting a candidate. Do not focus hidden validation inputs, a removed node, or a disabled submit button.
4. Do not focus a newly injected hidden shell before its first show; the adapter retains show/focus-trap timing.
   Direct injection outside an active dialog session does not steal outside focus. A late 422 after the session
   has hidden or been replaced cannot move focus or inject into a newer session.
5. After completed hide, restore a still-usable captured opener. If it is unavailable, use the first visible main
   or role=main landmark outside the shell, assigning temporary tabindex=-1 if necessary; otherwise use the first
   usable focusable element outside the shell; finally focus the document body with temporary tabindex=-1.
   The main-landmark fallback is mandatory in the removed-opener browser case. BODY is permitted only as the
   explicitly documented last resort when no meaningful page target exists, never as a successful stock result.
6. Focus restoration runs once for the session, after the focus trap and modal inertness are released. Reject
   stale completion callbacks after a later open, clear opener/session references, and clean up subscriptions
   on hide, failed open and replacement. Repeated open/close cycles cannot accumulate listeners. Existing
   redirect, network-error, modified-click, Cancel navigation and native FormData submitter behavior stays intact.
   Cancellation or prevention of hide does not trigger return focus.

## Adapter lifecycle and compatibility

Add one required method: `cv.adapters.modal.onHidden(modalEl, callback)` returns an idempotent unsubscribe
function. It registers for the completed hidden lifecycle only, never calls the callback at subscription time,
and invokes it for actual completed dismissal regardless of Close, Escape, backdrop or adapter API origin.
The controller subscribes before show; it invokes the returned cleanup after consuming the session's hide.

The Bootstrap factory implements this with addEventListener/removeEventListener on `hidden.bs.modal`, filtering
the event target to the registered modal. Namespace lookup, show/hide/setSize behavior and shallow per-adapter
replacement remain unchanged. No Bootstrap name or event string is added to modal.js.

The published native-dialog adapter implements onHidden using the dialog's native `close` event, including
Escape's default close. Its showModal/close/setSize methods stay unchanged. A custom asynchronous adapter must
call the callback only after hiding and releasing its trap; a synchronous adapter may notify synchronously
after completing those actions. The test suite includes both and a prevented-hide negative control.

This is a required custom-adapter migration. Before injecting/showing fetched modal content, core checks that
onHidden exists and returns a function. A missing/malformed hook produces a descriptive error through the
existing logged full-page-navigation fallback; no broken modal is left open. Do not silently graft Bootstrap
behavior onto a theme adapter, poll visibility or introduce an observation fallback. Existing custom modal
objects must add this method immediately; Bootstrap/Tabler users of cv.bootstrapAdapters receive it automatically.
Publish the Breaking entry and docs/migrating-1.0.md change together in the implementation commit, plus the complete
native-dialog recipe in docs/reference/javascript.md. No compatibility grace period is proposed.

## Test and evidence contract

Plan 19 begins with a failing actual-browser unchecked 422 assertion before repairing source. The new permanent
runner is `tests/browser/modal-focus.cjs`; unit regressions stay in tests/js/modal.test.js and adapters.test.js.
Use the installed Node runtime from the existing 06-js-verify entry point for Vitest. The browser runner reuses
the already cached Playwright module and Chromium paths proven by 17-evidence/browser.cjs (explicit environment
overrides permitted). It starts the unchanged 17-evidence/server.py with the cached Django 6.0 interpreter,
checkout PYTHONPATH, a disposable SQLite database and loopback binding; checks readiness; stops only its own child
in finally. An occupied port or absent browser is a nonzero unavailable-evidence outcome, never a skip/pass.
No package installation or application-database access belongs to these plans.

Each browser case uses actual HTTP and rendered forms with the unchanged inspector. No fetch/response substitution
or direct focus assignment is allowed between the keyboard submission/dismissal and the observed assertion.
The runner saves actual target/id, connected/visible/focus-visible state, completed hidden event ordering, HTTP
statuses, notices/form counts and screenshots; every failed predicate exits nonzero. Record source file hashes,
revision, runtime versions, command and completed outcome; write failure records too.

Required browser cases:
- unchecked 422 → focused invalid confirmation, visible dialog and field error, one form, no callback/write;
- blocked stale 422 → focused Close, both notices, no form, no callback/write;
- Close and Escape → completed hide followed by the exact captured opener;
- removed/disabled/hidden opener → the defined usable main landmark, outside the hidden shell;
- repeated cycles and alternate triggers → current opener only, no duplicate restoration;
- existing keyboard Space/Tab, Cancel navigation and confirmed Delete 204 positive control;
- native-dialog recipe → replacement and completed Close/Escape restoration without Bootstrap involvement.

Unit cases additionally cover unload/loaded order, listener-assigned focus, hidden initial injection, programmatic
open capture, asynchronous hide, prevented hide, non-modal modified clicks, missing hook full-page fallback,
stale callbacks/responses, default/factory/custom namespace adapters and unsubscribe idempotence.
The actual published native-dialog fence must be exercised, not a separately rewritten approximation.

The browser packet uses `19-evidence/`; retain 17-evidence unchanged. Refresh only affected JS/browser/docs and
targeted request controls. Preserve the earlier source-bound three-series backend matrix as historical evidence
over unchanged backend paths; do not relabel its whole-tree digest current after changing JS/docs or overwrite
its raw captures. Re-run broader Python coverage only if backend/template changes become necessary; that would
require explicit plan/scope revision.
