## Shared Patterns

- **Authentication/authorization:** retain cooperative `CrudViewPermissionRequiredMixin` and Guardian composition;
  core `DeleteViewPermissionRequired` declares `cv_permission = "delete"` (`delete.py`, 382–383).
  Preserve POST-only deletion guard (`delete.py`, 129–146); inspection/provider changes cannot bypass these gates.
- **Error handling:** friendly output accepts only a package-owned, proven native pre-write outcome after atomic
  unwind. Existing `_cv_protection_response` is reusable; existing origin classifier is not. Unexpected inspection,
  provider, handler, converter, model, hook or commit failures propagate. Never use catch-all incompleteness.
- **Projection:** compute block/completeness independently, then redact labels through the existing tuple filter.
  Preserve aggregates unless an application's display filter redacts them. New provider data is never trusted HTML.
- **Transactions:** retain valid-write → success-hook → same-alias on-commit order, and test real commits separately
  from captured callbacks. Resolve the deletion alias once with the target instance under the reviewed contract.
- **Conventions:** absolute imports, local optional Guardian imports, `cv_` hooks, double quotes, 120-character lines;
  fixtures follow `cv_<model>`, `user_<model>_<permission>` and `client_user_<model>_<permission>`.
- **Matrix:** existing `noxfile.py` lines 3–19 already parameterizes Django 4.2/5.2/6.0. No matrix edit is implied;
  add/run the missing 5.2 environment and replay affected suites under each selected interpreter.
