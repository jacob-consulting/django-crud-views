## Resolved CR-05 and retained failure history

### CR-05: [BLOCKER, resolved] Dismissal during a pending replacement GET was lost and its late response reopened the dialog

**Current disposition:** Closed by independent re-review of `8a26b39`. The issue description,
line references, original observations and timing-control snippet in this subsection describe
the failing source at `885d8dd`, before the repair; they are retained historical evidence.

**File:** `/home/alex/projects/alex/django-crud-views/src/crud_views/static/crud_views/js/modal.js:105-113`

**Related lines:** `modal.js:123-144` installs the next hidden subscription only after the entire
response body resolves; `modal.js:129-130` also ignores completion for a session whose
`shown` flag is false. `modal.js:71-76` unsubscribes and drops the prior return target.
The actual Bootstrap lifecycle is delivered through `adapters.js:37-47`.

**Issue:** With dialog A visibly open, activating an in-dialog modal link starts replacement B.
Core immediately releases A, creates B with `shown: false, unsubscribe: null`, and leaves A's
content visible while fetching B. If the user now presses Escape or Close, there is no controller
subscription for that completed dismissal. Bootstrap hides the shell but does not restore focus;
B remains the current session. When B's response arrives, the identity check still passes and
`adapter.show()` reopens the dismissed dialog and takes focus. The corresponding late failure
path can also remain eligible for full-page fallback after dismissal.

This violates the reviewed completed-dismissal/stale-response contract and reintroduces BODY
focus for a real keyboard action. It is separate from the repaired sequence where a new open
is explicitly requested *after* a hide has begun: that intentional rapid reopen must keep working.

**Independent reproduction:** Cached Chromium 149.0.7827.55, existing Node 24.21.0 and Playwright;
unmodified then-current `modal.js`/`adapters.js` at `885d8dd`. Ran once with Bootstrap 5.3.3 and the actual stock
shell, and once with the exact native-dialog HTML/JavaScript fences extracted from
`docs/reference/javascript.md`. Bootstrap assets were the same pinned CDN version as the
fixture base template. No application server or database was used, and port 9000 was untouched.

1. Render a page with an external `#launch` button and the chosen modal shell; load the current
   production scripts and adapter.
2. Open A from focused `#launch`. A contains a normal
   `<a id="next" data-cv-modal="true" href="/next">Next</a>` and dismiss button.
3. Defer the next fetch, focus `#next`, and activate it with Enter. This starts B while A stays visible.
4. Press Escape and wait for the actual completed `hidden.bs.modal` or `close` event.
5. Resolve B's response body and observe the shell and active element.

Observed, with no focus assignment between dismissal and the assertions:

| Adapter | After completed Escape dismissal | After B resolves |
|---|---|---|
| Bootstrap 5.3.3 | hidden; active `BODY`; current session exists; no subscription | visible again; active `#cv-modal`; session active |
| Published native dialog | closed; native browser returns to `#launch`; current session exists; no subscription | open again; active replacement input `#late`; session active |

Bootstrap's actual event sequence was `shown.bs.modal, hidden.bs.modal, shown.bs.modal`.
The second show occurred without another user open action. The isolated diagnostics controlled
only fetch timing/content to establish this client race; they are not substituted backend
acceptance evidence and do not replace the genuine HTTP packet.

The timing control used by both diagnostics was:

```javascript
// After A has actually shown; then activate #next with the keyboard.
window.fetch = () => new Promise(resolve => { window.resolveNext = resolve; });

// After actual completed Escape dismissal:
console.log({
    sessionActive: cvModalSession !== null,
    subscribed: !!cvModalSession?.unsubscribe,
    active: document.activeElement.tagName,
});
// Actual result: sessionActive:true, subscribed:false.
// Bootstrap active:BODY; native active:BUTTON (#launch).

window.resolveNext(new Response(
    '<div class="modal-body"><input id="late">' +
    '<button data-cv-modal-dismiss>Close</button></div>'
));
// Actual result after the response settles: the modal is visible/open again.
```

**Fix:** Keep dismissal ownership for the displayed shell while a replacement GET/body is
pending. A pending replacement should be invalidated when that displayed session is dismissed,
and its later success/error must not inject, show, navigate or steal focus. Preserve the original
usable return target or the defined fallback through completed dismissal. One concrete approach
is to separate the displayed session from its pending replacement request and transfer lifecycle
ownership only when the replacement is committed. Merely moving the subscription earlier is
insufficient if the callback still ignores `shown:false`; preserve the intentional
hide-then-reopen case as a separate transition. Add deferred-GET and deferred-body regressions
for Escape/Close with actual Bootstrap and the published native adapter, asserting no second
show, cleared pending state and usable outside focus, plus the existing intentional-reopen control.

**Historical coverage gap:** `tests/js/modal.test.js:532-555` covers unresolved replacement followed by
another open and a late 422 after dismissal, but not dismissal while a replacement GET/body
is pending. `tests/browser/modal-focus.cjs:253-268` exercises hide-then-open, the opposite
ordering. Those passing checks did not disprove the original finding. No separate test warning was counted.
