# Phase 06.30 Plan 04: Standalone service request editor Summary

**An independent migrated service-request example uses annotated native model choices to require on-site addresses or remote URLs, clear inactive fields on save, and enforce ordinary CRUD permissions.**

## Accomplishments

- Added ServiceCategory, Service, RequestBatch and ServiceRequest in their own app. ServiceCategory.code is unique; requests optionally belong to a batch. Service labels read only their loaded name.
- Shared SERVICE_CONDITIONS declares on_site, remote and general, with general explicitly activating neither group. RequestForm annotates category codes with F("category__code"), retains generated URLField validation, and renders two explicit ToggleGroups.
- Added permission-required list/create/update views using the existing BreadcrumbMixin, CrispyViewMixin and MessageMixin conventions; list queries select the service relation.
- Task 04-01 copied all project URL patterns into a temporary test URLConf and appended the standalone ViewSet directly. Task 04-02 removed that temporary override and now tests normal project URLs.
- Generated the initial migration with an in-memory connection. Test databases run the migration and execute real GET/POST/save/reopen cases. No developer database migration was run.
