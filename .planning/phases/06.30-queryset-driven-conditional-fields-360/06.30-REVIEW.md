## Critical Issues

### CR-01: Inherited pytest options can turn the mandatory full suite into a passing one-test gate

**Classification:** BLOCKER  
**File:** `/home/alex/projects/alex/django-crud-views/tests/browser/verify_queryset_release.py:55-66`  
**Related lines:** `233-248` (positive count alone is sufficient), `271-278` (evidence validation), `298-315` (recorded environment omits pytest options).

**Issue:** `environment()` carries all of `os.environ` into the subprocess, including `PYTEST_ADDOPTS`. A normal developer setting such as `-k test_queryset_conditions_export` silently narrows the supposedly full core command. `validate_result()` requires only one passing test and does not verify that the declared selection executed. The filter is also absent from the recorded environment, so the evidence looks like the ordinary unfiltered command. With xdist, the resulting summary does not even report the deselected count.

**Reproduction:** Called the actual `command_specs(sources)[0]` through `run_command()` with `PYTEST_ADDOPTS=-k test_queryset_conditions_export`, leaving its command, cwd and source binding unchanged. The runner executed its normal `pytest tests -n 4 -q -rs -p no:cacheprovider` command and returned:

```text
RUN tests-3-12-django-5-2
RESULT tests-3-12-django-5-2: exit=0 tests=1 seconds=5.14
bringing up nodes...
bringing up nodes...
.
1 passed in 4.50s
```

`validate_result(result)` accepted that result. As a separate in-memory negative control, substituting this one-test transcript/count for the full-core command in a copy of the current acceptance record also passed the actual `check_evidence()` function with all current source hashes and remaining evidence unchanged. No saved evidence was altered.

The execution probe is reproducible from the upstream root without running or writing a complete acceptance report:

```python
import os
import runpy

review = runpy.run_path("tests/browser/verify_queryset_release.py")
os.environ["PYTEST_ADDOPTS"] = "-k test_queryset_conditions_export"
sources = review["sources_from"]()
result = review["run_command"](review["command_specs"](sources)[0], sources)
review["validate_result"](result)  # Currently accepts one test as the full core result.
```

**Fix:** Remove `PYTEST_ADDOPTS` from the runner-controlled subprocess environment (or reject a nonempty value explicitly) and record/check that effective policy in acceptance evidence and resume validation. Add a focused negative control using an inherited `-k` or `-m` filter. Do not rely solely on rejecting the word `deselected`: the actual four-worker reproduction emitted only `1 passed`. Keep legitimate explicit command selections, including the single CSP test, distinguished from this inherited filtering.

### WR-01: The complete copied-wrapper recipe omits the queryset metadata and diagnostic branches

**Classification:** WARNING  
**File:** `/home/alex/projects/alex/django-crud-views/docs/reference/conditional.md:171-193`  
**Related files:** `/home/alex/projects/alex/django-crud-views/src/crud_views/templates/crud_views/conditional/toggle_group.html:5-17`; `/home/alex/projects/alex/django-crud-views/src/crud_views/static/crud_views/js/toggle.js:183-188`.

**Issue:** The reference still calls this a complete minimal override, but its template omits `cv_toggle_kind`, `cv_toggle_guard` and `cv_toggle_diagnostic`. Its prose also incorrectly says `cv_toggle_values` is `None` except for ValueToggle. The new JavaScript reference directs theme authors to this copied-wrapper recipe. A theme following it loses the `queryset` discriminator: when the current queryset has no options for a group, its valid `[]` metadata is treated as malformed static metadata and the group remains visible and enabled. Bound coverage diagnostics disappear, and a no-fields coverage guard incorrectly emits a wrapper. This is a behavioral documentation defect, not a visual preference or a defect in the stock template.

**Reproduction:** Extracted the actual Django template fence from this section, used it as `ToggleGroup`'s template while rendering a native ModelChoiceField backed by `Publisher.objects.none()`, then ran the current `toggle.js` and `cv.initConditional()` on that HTML in jsdom. The observed group/control state was:

```json
{"values":"[]","kind":null,"display":"","disabled":false}
```

The inactive group should be hidden with its editable control disabled. Inspection of the same extracted fence confirms it has no diagnostic or guard branches, whereas the shipped template contains both.

**Fix:** Update both wrapper branches to preserve the escaped queryset kind; emit escaped diagnostics outside the wrapper; honor `cv_toggle_guard` so successful empty guards emit no container. Correct the values description to cover both ValueToggle and queryset membership. Exercise this exact copied template in the existing executable documentation checks with an empty membership and bound coverage diagnostic, so the theme recipe cannot drift from the new contract.
