## Historical Plan 10 Warning

### WR-02: A split startup record escapes the browser runner's cleanup

**Independent re-review:** Resolved at `c0ba4502`; original evidence and locations below describe the pre-fix implementation.

**Classification:** WARNING

**File:** `/home/alex/projects/alex/django-crud-views/tests/browser/formset-row-cards.cjs:112-116`
**Related lines:** `103-118` (readiness Promise), `283-300` (owned-host cleanup and evidence write).

**Issue:** The stdout listener splits the current buffer on newlines but also parses its final, potentially incomplete segment. Node stdout events do not promise complete lines. If one event ends after `{"port": 12345, "login":`, `JSON.parse()` throws before `resolve()` runs. Because this listener runs asynchronously after the Promise executor returns, that exception does not reject the readiness Promise and is not caught by `run()`'s surrounding `try`. Node can exit without reaping the owned Django server, removing its temporary database/media or recording the failure; an older passing evidence file can remain on disk. This is a concrete failure-path reliability defect in the acceptance runner, not evidence that the recorded successful run was invalid.

**Reproduction:** Extracted the actual `child.stdout.on(...)` callback from the current file, evaluated it with a stub emitter using Node's `vm`, and delivered `Buffer.from('{"port": 12345, "login":')`. It synchronously threw `SyntaxError: Unexpected end of JSON input` from the callback instead of waiting for the remainder. The probe started no server and changed no evidence.

**Fix:** Buffer stdout until a newline is available; consume only complete lines and retain the incomplete suffix. Catch parsing failures in the data callback and reject the readiness Promise after clearing the timeout, so the existing `catch`/`finally` handles cleanup. Remove readiness listeners after settlement. Add a narrow runner regression for a valid record split across two events and malformed complete JSON, verifying resolution/rejection rather than an uncaught exception.
