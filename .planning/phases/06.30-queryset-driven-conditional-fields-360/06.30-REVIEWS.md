**Cross-cutting fact that shapes several findings.** Every seam the plans intend to "reuse" in `ConditionalGroupFormMixin` is gated on `isinstance(..., ValueToggle)`:

The plans do say "reuse group cleaning", but none names these five gates. ## 06.30-01

**Summary.** A sound tracer-first slice: prove render → native POST key → cleaned object → group activation → clearing → persisted reopen on an existing fixture before adding coverage machinery. The test fixture choice is verified (`tests/test1/app/models.py:276` `blank_text`, `:294` `reference` FK to `Publisher`, nullable) and the clearing path resolves to `""` via `group.py:132-136`. The second task introduces the render-time offered-option projection, the `cv-data-toggle-kind="queryset"` marker and bound-redisplay diagnostics. The main risks are the ValueToggle gates above and the "empty ToggleGroup guard" concept, which is a two-place registration a user must remember.

**Strengths.**
- Tracer uses a real HTTP endpoint with `override_settings` ROOT_URLCONF; precedent exists (`tests/test1/test_fragment_authorization.py:1-12`, `test_ancestor_*.py`).
- The projection design is correct for the JS contract: `toggle.js:42` compares the selected option's `value` string against `binding.values`, so for queryset groups the list must be offered *selectable* tokens whose category matches, exactly as 01-02 specifies. This is why a render-time projection, not a category list, is needed.
- `ToggleGroup.render` (`layout.py:31-45`) already uses `form.add_prefix(name)` and `context.flatten()`; adding projection there keeps prefixing correct for inline rows.
- Separating `QuerysetConditionCoverageError` (subclass of `ImproperlyConfigured`) for unbound GET from a caught, escaped diagnostic on bound redisplay matches the CONTEXT "do not mask a rejected-POST error".

**Concerns.**
- **HIGH — ValueToggle gates not enumerated.** See cross-cutting note. In particular, if `_QuerysetToggle` inherits `ToggleSource.is_on` (`toggle.py:32-36`), a selected object makes `bool(cleaned["service"])` true and *every* group for that controller activates regardless of category. 01-01 says "do not call raw-data fallback" but does not say `is_on` must be overridden and must read only the final cleaned mapping via the `group.py:222-228` path, which is itself ValueToggle-gated.
- **MEDIUM — the "empty ToggleGroup guard" is a maintainability cost for a corner case.** A source whose *every* key is a no-fields key configures nothing; the only reason to render-check it is strict coverage diagnostics. The plan requires users to add `ConditionalGroup(source.when(), fields=[], required=[])` **and** `ToggleGroup(source.when())` in the layout, and then adds auto-insertion in compact (03-01), a Python test in 01-02, another in 03-01, and documentation in 06-01. Forgetting the layout guard silently skips D-05 coverage for that source. Under the CLAUDE.md maintainability rule, the simpler bounded alternative is to reject at declaration time a source with no non-empty membership (`ImproperlyConfigured`: "a QuerysetConditions source must control at least one field group") and document it as unsupported. That removes a public pattern, two tests, compact auto-insertion and a docs section.
- **MEDIUM — `ToggleGroup.render` currently has no shortcut to "invoke before".** `layout.py:32` always renders `self.inner`; the template (`toggle_group.html:6,11`) always emits a container. "Emits no conditional container on success" for an empty guard needs a new early-return branch in `render`, which must still run the projection. Fine, but the plan's wording ("invoke it before any empty-child or empty-membership shortcut") implies such shortcuts exist; they do not.
- **LOW — UUID tokens and `json.dumps`.** `ModelChoiceField.prepare_value` returns the raw PK (`django/forms/models.py:1549-1554`), and HTML emits `str()` via `ModelChoiceIteratorValue.__str__` (`:1401`). The plan says "use native prepare_value for selectable tokens" and "JSON-encode"; `json.dumps` on a UUID raises `TypeError`. Specify `str(field.prepare_value(obj))` explicitly.
- **LOW — wave gap for empty arrays.** 01-02 can emit `cv-data-toggle-kind="queryset"` with an empty array, but `toggle.js:175` still rejects `values.length === 0` until 03-02. Transitionally the group is left unbound (visible, enabled) and the server still clears. Acceptable, but 01's SUMMARY should state it.

**Suggestions.**
- Add to 01-01's action: "widen `validate_value_groups` (`group.py:47`), `clean()` (`:222`), `full_clean()` (`:243, :250`) and `ConditionalFormSet.reject_value_toggle` (`formset.py:24`) to the new membership type; override `is_on` to read only `form.cleaned_data` and return False when the controller is absent or its value is None."
- Decide the all-no-fields question before execution; recommend rejection at declaration (see concern).
- State the `str(prepare_value())` serialization and that per-render projection cost is one extra queryset evaluation per *form instance* (see 06.30-02 concern on rows).

**Risk Assessment: MEDIUM.** The tracer approach is right and the fixture exists, but the plan under-specifies the exact seams that currently exclude non-ValueToggle descriptors.
