## Top 3 Priority Fixes

1. **Contain narrow header actions and source headings** — actions and accordion chevrons protrude beyond their containers in the standalone 390px captures. Wrap/stack header actions at narrow widths; put source titles in a shrinkable, wrapping text span while preserving the chevron and accessible full name. Verify at 375/390/768 widths and increased text size.
2. **Allocate compact columns to actual option labels** — the upstream service selector clips “Technical consultation”; downstream Grind and Bag size reduce selected values to fragments. Adjust the example compact spans and downstream order layout or stacking breakpoint so the selected value can be read without opening the selector. Preserve the approved visible-disabled cell behavior.
3. **Expose conditional required status before submission** — “Visit address” and “Meeting URL” can look optional despite server rejection when active. Add concise active-state guidance and accessible required semantics through the existing conditional lifecycle, preserving inactive disabling and server authority. Keep downstream coffee fields optional.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1 — conditional required guidance is remote from the field.** `examples/bootstrap5/queryset_conditional/standalone.py:31` and `inlines.py:42` declare required address/URL groups. The standalone and compact captures show no required marker beside these labels while Service has one. The introductory prose explains “needs,” but a user entering rows must recall it. Add nearby required guidance; do not introduce required grind/bag-size business rules downstream.
- **WARNING C2 — the teaching introduction dominates the narrow first screen.** `examples/bootstrap5/project/features.py:203` supplies one long paragraph on every demonstration. In `standalone-390.png`, this block occupies roughly 400px before breadcrumbs and the editor. Shorten the lead to the current demonstration and expose the detailed comparison in a secondary paragraph/disclosure. `needs_human_review: true`: confirm a new visitor can discover all three demonstrations and explain preserve-before-save versus clear-on-save.
- Save/Cancel are appropriate established CRUD labels here; replacing every shared label would be an unrelated redesign. Messages in `standalone.py:67` and `inlines.py:129` identify the saved object. Required and quantity errors are specific and adjacent in the saved error captures.

### Pillar 2: Visuals (2/4)

- **WARNING V1 — narrow action group escapes the standalone card.** Both `standalone-390.png` and `standalone-error-390.png` show the rightmost header action extending beyond the card's right border. The long header/icon combination is supplied by `standalone.py:22`; inherited header rendering needs a wrapping/stacking layout. This is visible presentation evidence, not a measured claim that the button cannot be clicked.
- **WARNING V2 — ordinary row ownership is visually weak.** `ordinary-390.png` and `ordinary-1280.png` run one row's active field directly into the next service selector. `inlines.py:54` lays out the controller, controls and conditional fieldsets without an explicit row caption. Add a modest row separator or “Request 1” heading in the demonstration if user testing confirms ambiguity. Preserve ordinary hiding rather than converting ordinary rows into compact cells.
- Desktop heading/form/source hierarchy is otherwise clear. Compact row cards and associated labels are notably easier to scan. Existing browser assertions establish labels/focus for exercised fields; screenshots alone do not establish accessible names for every action icon.

### Pillar 3: Color (4/4)

- **PASS COLOR1 — restrained established palette.** The ten inspected captures use predominantly neutral page/card surfaces, dark typography and limited blue upstream or brown downstream action accents. Disabled fields have a neutral fill; errors add both text/icon and red, not color alone. There is no observed accent overload in the new conditional UI. The 60/30/10 principle is assessed qualitatively, not claimed as measured pixel percentages.
- No new phase-specific color palette is introduced in the example form declarations. `src/crud_views/static/crud_views/css/formset.css:49` uses Bootstrap border/background tokens with fallbacks; its earlier hardcoded transient highlight colors predate this feature. Their existence is not evidence for a phase-wide recoloring requirement.
- The source panel uses `text-body-secondary` once and two section headings (`snippet_panels.html:4`, `:6`, `:24`). The five documentation links are navigation, not five competing primary actions. Focus-ring and disabled-text contrast under alternate themes/high contrast still need human review; no numerical contrast pass is claimed.

### Pillar 4: Typography (3/4)

- **WARNING T1 — long source paths overflow narrow headings.** `snippet_panels.html:12` renders `panel.title` directly in the accordion button without a wrapping text wrapper. The conditions.py and standalone.py titles visibly push their chevrons beyond the container in the 390px captures. Use a shrinkable text span with wrapping, preserving the full filename for learning and accessible naming.
- Existing typography supplies heading/body/small-text hierarchy rather than a new Tailwind scale. Source panel section titles use `h5` twice, accordion headers use `h2`, and link icons use `small`; compact CSS explicitly uses weight 600 in two rules (`formset.css:61`, `:78`). Normal/bold emphasis is inherited. These are role-based Bootstrap styles; a mechanical four-size/two-weight redesign would not respect the existing theme.
- Saved captures show a monospaced-looking face across the page; this audit does not establish whether that is intended theme output or browser font fallback. Verify the normal supported browser/font environment during UAT before changing typography globally.

### Pillar 5: Spacing (2/4)

- **WARNING S1 — upstream desktop service column is too narrow for its own example.** `inlines.py:92` allocates three spans each to Service, address, URL and controls. In `compact-1280.png`, the selected “Technical consultation” is clipped while the controls column has substantial spare room. Rebalance these application-owned spans, retaining 12 total and narrow stacking.
- **WARNING S2 — downstream selected coffee attributes are difficult to inspect.** `/home/alex/projects/alex/tabler-test/example/sales/forms.py:152` uses spans 4/2/2/2 plus two for controls inside the order's split layout. `orders-1280.png` shows Grind and Bag size as short fragments. Widen the line-items area, adjust the desktop breakpoint or allocate additional space before reducing fonts. The existing optional field contract remains correct.
- Existing compact spacing is internally regular: 1rem row padding/margin and gutter, .5rem heading padding, 1px heading alignment (`formset.css:49`–`:67`). These are established Bootstrap-aligned values, not arbitrary phase additions. The mobile stacks retain all disabled cells as D-07 requires; their increased page length is not itself a contract failure.

### Pillar 6: Experience Design (3/4)

- **WARNING E1 — active-required state has no corresponding client required announcement.** `src/crud_views/lib/conditional/group.py:215` disarms field-level required validation and `:310` enforces active requirements server-side. `toggle.js` contains no required/aria-required synchronization. Combined with C1's visible labels, users discover the requirement only from prose or a rejected submit. Add bounded guidance/semantics, then test away/back, reset, newly inserted rows and invalid redisplay. This is a quality gap, not a bypass of server validation.
- **Evidence supports substantial state coverage.** Existing upstream JSON records 6 scenarios/87 assertions and downstream 4/47, including independent rows, ordinary hiding, compact disable-only geometry, away/back preservation, focus recovery, row insertion, reset, invalid POST, persisted clearing and zero-write rejection. The two error screenshots show readable field-adjacent messages. This audit reviewed those records and captures; it did not rerun those interactions.
- Native selection changes do not require an asynchronous loading state. Existing formset insertion behavior remains the relevant loading/error surface. No new destructive-action confirmation gap was established; row deletion keeps the existing formset/save semantics.
- **Human UAT still required:** keyboard-only traversal and recovery across ordinary/compact/inserted rows; error discovery and correction; disabled-field comprehension; long-label usability; and teaching/source navigation. Automated Tab/label/focus assertions cover selected cases, not a complete keyboard or screen-reader audit. `needs_human_review: true`.
