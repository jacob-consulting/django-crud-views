## 06.31-01 — Active group-only manage gate, hidden actions, nested preservation

### Summary
Replaces the public/debug shortcut at `src/crud_views/lib/views/manage.py:39-69` with a shared actor/mode/group predicate, forces manage to `hide`, changes the default to `yes` at `src/crud_views/lib/settings.py:34`, and re-owns the three nested-authorization test modules.

### Strengths
- **Correct projection seam.** `CrudView.cv_has_access` defaults to `True` (`base.py:483-484`); projection reads it at `base.py:861` and the hide/disable decision reads `cv_get_inaccessible_actions()` at `base.py:618`, consumed by `visibility.py:14-20`. Overriding both on `ManageView` is the smallest change that makes request and rendering agree, and `GuardianManageView` inherits it (`crud_views_guardian/lib/views.py:384`). Core stays free of Guardian imports.
- **Actor admission reuse is sound.** `_protected_actor_response` (`ancestors.py:417-425`) already denies anonymous via the endpoint's `handle_no_permission` and raises for inactive; reusing it for all-none ancestry in `_cv_ancestor_actor_response` (`manage.py:48-60`) is exactly D-08 without touching `_authorize_ancestors` (`ancestors.py:458-483`).
- **A-02 fix is non-vacuous and has a repo analog.** `conftest.py:123` forces `yes`, and `from_settings` is evaluated at class-body time (`settings.py:34`), so only an isolated process proves the new default. `tests/test1/test_import_safety.py:33` already uses the `subprocess.run([sys.executable, "-c", code])` pattern the plan asks for.
- **A-01 is explicit.** One indexed `auth_group` existence query per eligible evaluation, zero after short circuits, revocation on next request, no cache. That is the right bounded position.
- **`_check_nested_auth` accepts a class.** `_is_nested(view)` and `_require_default_alias` read only `cv_viewset`/`cv_key` (`ancestor_db.py:54-57, 66-72`), so calling it from the `cv_has_access` classmethod works, matching `CrudViewPermissionRequiredMixin.cv_has_access` (`base.py:1222-1225`).

### Concerns

**N-2 — MEDIUM — 01-03 owns `test_ancestor_auth_databases.py` but frames its changes too narrowly.**
The plan's action targets the manage routing cases (`:665-738`). However, the `events` fixture records an `("auth", model, provider)` event whenever `_auth_tables` runs inside `_check_nested_auth` (`:351-363`). Every nested page in that module renders a manage toolbar button: the fixture sets `cv_context_actions: []` (`:218`), and `register_view_class` turns that into `["manage"]` under the conftest `yes` mode (`viewset/__init__.py:346-354`); the test base template renders `{% cv_context_actions object %}` (`tests/test1/app/templates/app/crud_views.html:24` → `templatetags/crud_views.py:324-327` → `cv_get_context_action_group` → `cv_has_access`). With Plan 01's predicate, an authenticated active actor's successful render now emits an extra `("auth", <leaf model>, "model")` event and one `auth_group` query. `test_nearest_only_never_touches_the_unselected_higher_gate` (`:489-499`) asserts `_auth_events(events) == [("auth", "Book", "model")]` after a 200 by an active superuser, so it fails. Anonymous cases such as `test_plain_nested_endpoints_do_no_auth_work` (`:829-840`) survive only because the plan short-circuits unauthenticated actors before the routing check; the plan should state that ordering as a requirement, not leave it implicit.

**N-1 (shared with Plan 06) — HIGH — cost baseline and published cost record are unowned.**
`tests/test1/test_ancestor_costs.py` measures total queries per request and splits them into guard/rest (`:131-143`); for the plain provider it asserts `measured["rest"] == legacy_total` against hard-coded pre-edit numbers (`:237-248`). Its chain fixture also sets `cv_context_actions = []` (`test_ancestor_authorization.py:394-399`), so manage is appended, and its client is an authenticated active user with model view+change (`test_ancestor_authorization.py:423-427, 439`). The new membership query lands in "rest" and breaks the equality for all 12 plain cells. `.planning/phases/06.18-ancestor-authorization-for-nested-viewsets/06.18-COSTS.md` publishes those "Rest cold / warm" columns and the claim "no list or context actions" in its fixture description. Neither `test_ancestor_costs.py`, `test_ancestor_authorization.py`, nor `06.18-COSTS.md` appears in any plan's `files_modified`. Plan 01 acknowledges the A-01 cost in prose but the acknowledgment has no owner where the project actually asserts and documents costs.

### Suggestions
- In 01-01, make the predicate's evaluation order a stated contract: authenticated → active → mode (`no`, `debug_only`+DEBUG) → `_check_nested_auth` → membership query. State explicitly that anonymous/inactive/`no`/`debug_only`-off evaluations perform **no** routing check and **no** query (this is what keeps `:829-840` and `:526-533` green).
- In 01-03, add: "Successful nested renders by authenticated actors now emit one extra `("auth", <leaf>, "model")` event and one `auth_group` query from manage projection; update exact-event assertions (`:497` and any sibling) to account for it, or set `cv_context_actions` to exclude manage where the test's subject is ancestor routing, not projection."
- Assign N-1 to a task (see Plan 06 suggestions).

### Risk
Medium. The core design is right; the risk is the two unowned/misframed assertion surfaces, which would otherwise surface only in Plan 06-03's blanket "repair anything found" clause.
