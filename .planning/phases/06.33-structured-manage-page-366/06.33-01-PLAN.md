## Shared data contracts (new in this phase)
Use ordinary ordered dictionaries/lists, not a new framework. Every new Python presentation builder has explicit (viewset, user) arguments; get_manage_hierarchy adds keyword-only route_kwargs=None. No builder reads self.request or synthesizes a request. The web adapter alone passes the actual request user and kwargs after existing admission/ancestry. Resolve guarded auth data against the supplied ViewSet's registered manage class. These builders prepare diagnostics; they do not impersonate or replace request admission. Any path reading permission/auth/grant data requires the supplied ViewSet's registered manage class; absence raises ImproperlyConfigured('Manage diagnostics require a registered manage view') before diagnostic reads. Pure configuration/route projections may run without that class.

- get_manage_permissions returns columns [{key, permission, codename}], actor (same row shape), groups, users (empty when hidden), show_users, superusers {count,names}, and user overflow information. Row: {id,label,member_count,cells}; each column-aligned cell has {key,model:bool,object_count:int|None}. Permissions rows carry no configuration provenance; is_default/source apply to configuration entries, not grants. Core object_count=None; Guardian count 0 is distinct from unavailable. The actor row includes effective grants; holder rows are direct. Zero counts render a dash unless model is true; model and positive object badges may coexist.
- get_manage_views returns [{key,class_path,route_name,route,requirement,parent_requirement,guardian_policy,sections}]. Requirement: {kind,value,ancestor_applies}; parent_requirement is None or {key,permission}; requirement_metadata_error is None or a translated unavailable-metadata message; no access-result boolean. Guardian policy None on core, otherwise {applicable,accept_global_perms,effective_policy}.
- Each section {key,label,entries,default_count}; entry {key,value,source,is_default,unknown}. Values are display-ready escaped by templates (never mark_safe), sources are independent of is_default. Counts are Python-prepared and pluralized in rendering.
- get_manage_facts returns identity entries; get_manage_routes returns [{key,name,route,route_error}], with route=None and an explicit translated metadata error only for expected display-resolution failures. get_manage_hierarchy returns {parents:[{name,model,url,route_name,route}],children:[{name,model,is_resource,route_name,route}]}; parents may have url=None when explicit coordinates are absent, children never have links.
- get_manage_presentation returns {sections,set_count,default_count,buttons}; button {key,type,target,label,template}, display-only no get_context call. get_manage_ancestor_policy retains distinct as_ancestor and requests groups with effective/source/inherited entries; legacy ancestor_policy shape stays separate.
- get_manage_checks returns {count,messages:[{id,severity,message,hint}]}; count counts only viewset.checks objects. get_manage_guardian returns strict helper metadata or absent core content.
- New context keys are manage_permissions, manage_views, manage_facts, manage_hierarchy, manage_routes, manage_presentation, manage_ancestor_policy, manage_checks, manage_guardian, manage_docs_base_url. Legacy cv/data/views/permission_holders/show_users/ancestor_policy/guardian_config keep their old contracts.
- Whole-card blocks: permission_holders, ancestor_policy, guardian_config remain; new manage_views, manage_presentation, manage_viewset, manage_hierarchy, manage_urls, manage_checks. One manage_checks block can wrap conditional alert/strip locations with child output at the correct grid position; do not duplicate evaluation.
- Stable docs base: https://django-crud-views.readthedocs.io/en/stable/reference/manage/. Approved anchors are system-checks,permissions,views,presentation,viewset,hierarchy,url-names,ancestor-policy,guardian,templates-and-actions,label-modes.
