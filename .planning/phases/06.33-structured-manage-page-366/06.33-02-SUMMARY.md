## Accomplishments

- Added public `CrudView.cv_get_requirement()`, `CrudViewPermissionRequiredMixin.cv_get_requirement()` and `ManageView.cv_get_requirement()`. Each returns `{kind,value,ancestor_applies}`. The base describes none, the permission mixin the declared key, and manage the configured group. No method reads `permission_required`, dispatches, loads an object or calls an authorization predicate.
- Added bounded `_cv_requirement_is_custom()`: an effective `has_permission` owner before the effective description owner in the MRO produces custom. Inherited project gates and mixins remain custom; harmless subclasses inherit the known description; explicit descriptions remain authoritative. Arbitrary dispatch/get_object/get_queryset changes are intentionally outside detection.
- Added `get_manage_routes(viewset,user)` as the shared display projection, returning `{key,name,route,route_error}` from actual generated URL patterns. Named regex groups become readable placeholders. Empty registries return before URL generation. Expected route metadata `ImproperlyConfigured`/`ViewSetError` failures yield named unavailable rows. Summaries copy these routes and expose `name` as `route_name`.
- Added internal `_manage_requirement(viewset,user,view)`. Parent metadata reuses `_validate_ancestor_structure`, `_operation_requirements` and `_selected_gates`; provider-none intermediate ancestors are skipped, all-disabled ancestry and None nearest keys produce no badge. Exact action entries remain authoritative. Permission-map reads retain supplied-manage and ancestor routing guards.

Auth/permission-map exceptions remain outside the catch. Malformed endpoint requests retain their original assertion/configuration failures.
- Native closed `details#cv-view-<key>` summaries contain key, actual class path, generated route and registry-backed nonlink badges. Summary elements contain no nested controls. Titles/data-cv-tooltip, hidden text and `aria-describedby` preserve keyboard-readable meaning. Real AutoManageView wrappers remain visible even when a project base is configured. Core `guardian_policy` is None until the Guardian owner enriches it.
- Core inventory covers plain/protected list/card, CRUD, ordered actions, ActionView, both custom-form families, RedirectChildView and ManageView. Request cases pair missing/present grants, collections, redirect behavior, exact custom-action ancestry and disabled action state with descriptions. Existing manage-group tests continue to deny nonmember staff/superusers.
- Extension inventory covers plain/protected WorkflowView, ObjectDetailView and five polymorphic families (fourteen concrete classes). Tests exercise actual GETs, selector POST and contributed content-type create route, nested selector write ancestry, workflow state rejection and independent transition permissions.
