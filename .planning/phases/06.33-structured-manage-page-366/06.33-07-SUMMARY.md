## Accomplishments and Contract Inventory

- New external `manage.js` exposes `cv.initManageDefaults(root)` and internally uses `updateDefaults(root, show)`. A per-page WeakSet prevents duplicate listeners and preserves the current checked choice on reinitialization. It supports DOMContentLoaded, late loading, explicitly supplied roots and the existing modal-loaded event. It neither invokes third-party globals nor duplicates tooltip initialization.
- The single initially hidden `data-cv-defaults-control` label contains an unchecked `data-cv-show-defaults` switch in the Views header, before help. Its `aria-controls` names both cards. Only after listener binding does initialization hide `data-cv-default-row` rows and reveal the control. Missing controls or binding failure leave all values visible. Zero defaults is harmless; unrelated controls do nothing; focus stays on the switch.
- Section counts remain pretranslated server markup. Only sections whose configuration rows are all hidden reveal their count; section headings and set rows remain visible. There are no storage calls, generated HTML, inline events, styles, scripts or javascript URLs.
- The existing `row g-3` carries `data-cv-manage`. CSS scopes typography, wrapping, minimum child widths, 192px nonwrapping config keys, 160px minimum values, 44px summary targets, wrapping 8px header gaps and 32px round help targets. Group badges use the registered magenta class; other badge colors continue through the registry. No opacity dimming is introduced. The host page-heading shell remains host-owned; card headings now follow its h1 with h2, and subsections use h3.
- Every responsive table wrapper has a translated accessible label, region role and keyboard tabindex. All default rows resolve `manage:row-default`; values are muted through the stock default class, allowing theme replacement. Help links have `data-cv-manage-help`, visible question marks, documentation labels, new-tab titles and the existing approved URLs. Public blocks, stable view/ancestor IDs, native summaries, requirement descriptions and Guardian/ancestor authorization paths remain intact.
- Presentation retains `details#cv-manage-presentation`, direct summary and sibling help. Scoped `::details-content` visibility keeps help available when collapsed; a separate closed-body rule keeps diagnostics folded. A real isolated Chromium probe reproduced the initially hidden link and then verified a visible 32×32 help target with the body still hidden. Native folding semantics are described by the [HTML rendering standard](https://html.spec.whatwg.org/multipage/rendering.html#the-details-and-summary-elements).
- Settings append manage.js/manage.css after existing assets, preserving adapters first and the current theme-path mechanism. All five independently pinned inventories now expect eight core scripts/five styles, correct nonce totals, extras, source ordering and resolver offsets. Real JavaScript and CSS bundler tests include the new files; CSS packaging expectations are now independent literal paths rather than values derived from the collector.
