## Pattern Assignments

### A. Core manage data and web adapter

**Analog:** `src/crud_views/lib/views/manage.py`, 1–207. Applies to core builders, admission preservation and explicit-input APIs.

Imports (3–8) keep internal imports absolute; auth/model-specific imports inside legacy methods defer app-model loading:

```python
from django.contrib.auth.mixins import PermissionRequiredMixin
from django.views import generic
from crud_views.lib.ancestor_db import _check_nested_auth
from crud_views.lib.settings import crud_views_settings
from crud_views.lib.view import CrudView
```

Existing class-based guard accepts an explicit actor (39–51):

```python
@classmethod
def _cv_manage_allowed(cls, user) -> bool:
    # Existing enabled-mode and active/authenticated checks precede this.
    _check_nested_auth(cls, actor=user, model=cls.cv_viewset.model)
    return user.groups.filter(name=crud_views_settings.manage_group).exists()
```

Existing request ordering (31–37):

```python
response = self._cv_ancestor_guard()
if response is not None:
    return response
return super().dispatch(request, *args, **kwargs)
```

Copy the guard ordering, not its implicit ViewSet dependency into new builders. **Every new data method accepts ViewSet/user explicitly and never reads `self.request`**; route kwargs arrive explicitly where needed. Resolve the target registered manage class for `_check_nested_auth` using the supplied ViewSet. Guardian validates its provider before any core diagnostic query. Web admission/ancestor enforcement remains in the existing request adapter.

Core direct-holder query shape (89–92):

```python
for group in Group.objects.filter(
    permissions__codename=codename,
    permissions__content_type__app_label=app_label,
).order_by("name"):
```

This identifies direct assignment, unlike `user.has_perm()` in the actor row (108–111). New matrices batch/pivot memberships, key by holder PK, and aggregate member counts; do not reproduce legacy per-permission holder queries. SHOW_USERS controls querying/rendering names, including superuser names.

Existing ancestor-policy shape (148–162) separates `as_ancestor` from `requests` and uses effective-policy helpers; preserve that distinction. Existing `get_view_data` (165–207) supplies ordered sections. Preserve legacy shape/order with only the class-path fix: the current `str(view.__class__)` at 172 reports the metaclass; use the actual class's module/qualname.

**Compatibility:** `get_context_data` currently eagerly invokes old methods (112–119). Introduce request-local Django `SimpleLazyObject` wrappers, preserving overridable legacy method signatures. Stock cards must consume new keys exclusively, including heading/empty-state tests. Lazy wrappers are a researched new seam, not an existing implementation to copy.

**Errors:** preserve existing denial/route exceptions; never convert auth/database failures to empty cards or clean checks.
