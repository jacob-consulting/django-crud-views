## Layout and Interaction Contract

- Use Bootstrap `row g-3`, main `col-12 col-lg-8`, side `col-12 col-lg-4`; stack below
  992px. Main order: failing-check alert, Permissions, Views, Presentation. Side order: clean-check
  strip, ViewSet, Hierarchy, URL names, Ancestor policy, Guardian (Guardian only).
- At 390px and desktop (1280px), the document has no horizontal overflow, with disclosures both
  closed and open. Every table scrolls within its own responsive wrapper. Set grid/card children
  `min-width: 0`; wrap summaries, routes and class paths with `overflow-wrap: anywhere`.
  Key/value tables reserve a 192px nonwrapping key column and at least 160px for values; horizontal
  overflow remains inside the wrapper. No ellipsis truncation of keys, routes or class paths.
- Permissions: single column vocabulary from `viewset.permissions`, including custom permissions.
  Header key + codename sublabel; actor first, then Groups, conditional Users. Model and object badges
  may coexist. Actor results are effective; holder results are direct. Display group sizes and active
  superuser count. Names follow SHOW_USERS, including superuser names. Never render hidden names into
  attributes or hidden markup. Fold users after exactly 20; put remaining rows in a valid table inside
  the `+ n more` disclosure, repeating column headers. Never nest details directly inside tbody.
- Views: stable `cv-view-<key>` native disclosures, all closed on initial navigation. Summary contains
  key, readable route, real dotted class path, own/parent requirement and applicable Guardian policy.
  Summary contains no links or nested controls. Badge details are also available as hidden descriptive
  text associated with the summary, so keyboard users do not need hover.
- Expanded rows follow D-10/D-25: Navigation, Templates, Icons, Guardian when applicable, Other.
  Preserve row order regardless of set/default status; omit `cv_` in displayed keys. Other is
  alphabetical, data-only, excludes `cv_viewset`, marks unknown names, and shows annotation-only
  values as not declared. Render classes as dotted paths and other values as escaped repr shortened
  to 200 characters plus an ellipsis; preserve list/tuple syntax. This bound applies only to diagnostic
  repr, not routes, labels, permissions or class paths.
- The one labeled Show defaults checkbox/switch controls Views and Presentation. JS initializes it
  unchecked and hides defaults only after its listener is ready; hidden rows leave the accessibility
  tree. A section with only hidden rows shows the translated count. Without JS every row is visible;
  keep the nonfunctional switch hidden until enhancement succeeds. No persistence or asynchronous load.
- Presentation is native details, closed initially, with D-21 count summary and sections. Place its
  header help link as a sibling of summary (visually at the right), never within summary. Include
  static target descriptions for all five built-in context-button types and the custom fallback.
  Child/sibling targets are unlinked. Its section help links follow D-24.
- Ancestor policy keeps `id="cv-ancestor-policy"`, its two labeled parts and complete effective
  cascade/read/write/actions facts with inherited markers; no third declared column. Hierarchy links
  only upward with existing URL kwargs; no object sampling. Resource children have a note, not a route.
- Scoped warnings/errors replace the clean strip with the main alert; each message has severity,
  check ID and text. Honor silencing and include the separate collectors. Clean count includes only
  `viewset.checks()` entries (D-17).
- Card headings follow the inherited page heading semantically. Table column and row headers use
  scope; responsive scroll regions have an accessible label and keyboard focus when scrollable.
  Keep native summary disclosure markers and focus outlines. Switch Space and disclosure Enter/Space
  work; focus remains on the activated control. No custom arrow-key model or animation.
- Every help link has visible ?, `aria-label="Documentation: <card/section>"`,
  `target="_blank" rel="noopener"`, and title/hidden text announcing a new tab. Header actions wrap
  at narrow widths; the help control follows Show defaults. Requirement badges have title,
  `data-cv-tooltip` and hidden permission/group prefixes; they are not links.

nested object views retain both. Do not label requirement badges as an access verdict. Guardian strict
counts retain the existing helper's superuser behavior (RESEARCH caveat), documented beside the legend.
A failed HTTP request keeps the existing host error response/browser retry; do not render false clean
checks or fabricated zero grants. Missing optional metadata gets the documented fallback, not a spinner.
