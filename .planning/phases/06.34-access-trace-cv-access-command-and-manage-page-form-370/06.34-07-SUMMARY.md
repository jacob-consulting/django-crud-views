# Phase 06.34 Plan 07: Manage Access check Summary

**Core and Guardian manage pages now offer opt-in GET access diagnostics with fresh target actors, complete route inventories and escaped shared traces.**

## Accomplishments

- `CrudViewsSettings.manage_access_trace` reads `CRUD_VIEWS_MANAGE_ACCESS_TRACE`, default False. The always-present
  `manage_access_trace` context value is None while disabled. `_manage_access_query` branches before reading GET,
  resolving users or invoking diagnostic reversal/tracing. Existing manage admission, ancestor guards, viewer
  builders and lazy legacy context remain authoritative and unchanged.
- `get_manage_access_trace(viewset, user, *, mode, object_pk=None, path=None, route_kwargs=None)` is independent
  of `self.request`. Both GET forms use `resolve_trace_user`, including nonnumeric usernames, real PKs and
  username-over-other-PK collision precedence. Empty/unknown users, unsupported modes, missing paths and malformed
  URLs produce escaped feedback without trace results. No picker, anonymous control, session substitution or
  viewer mutation is introduced. The shared runner creates its own fresh actor and synthetic request.
- Arbitrary-path mode leaves the matrix actor unchanged and can inspect a target whose ancestors the viewer
  cannot access. Tests prove the hosting ancestor and group gates still deny unauthorized viewers. Target object
  names never enter card output; traces retain scalar identity, source, exception class/message and limitations.
- ViewSet mode enumerates `get_all_views()` in registration order, including backend and POST-only entries.
  Reversal uses only declared parent coordinate names from hosting kwargs; supplied own PK is used only when
  `cv_object` requires it, under the ViewSet's actual `pk_name`. Missing own PK says `needs an object pk`;
  contributed child/polymorphic/custom coordinates and malformed converter values say `use the path field`.
  No object-derived ancestry, fabricated URL or omitted row is used. The tests include two-parent nesting,
  custom own-PK names, tampered extra GET coordinates and visible POST-only limitations.
- Successful ViewSet selection invokes the existing polymorphic `get_manage_actor_row` once for the selected
  actor and replaces only `manage_permissions.actor`. Guardian retains strict object counts. Both matrix layouts
  say `(checked below)` for successful selected-self and selected-other results; disabled, unsubmitted, invalid,
  unknown and arbitrary-path queries preserve `(you)` exactly. Nonactor matrix data and request/session identity
  remain unchanged.
- The `manage_access_trace` block sits after the complete `permission_holders` block and before `manage_views`.
  Guardian inherits it without a fork. The shared partial accepts `trace`, `step` or `result`, with automatic
  escaping, translated labels, header/plan/numbered steps, source/permission/provider/object identity, zero-aware
  counts, deciding step and limitations. Native details have no nested interactive controls. The two GET forms
  have unique associated input labels. The help link honors `manage_docs_base_url#access-check` and existing
  new-tab accessibility contracts. There are no new scripts, inline handlers or inline styles.
- Ten declared `manage:trace-*` keys use the specified Bootstrap defaults, and all ten pass sentinel override
  tests. Existing `form:submit` and `manage:help` keys style controls. Scoped CSS wraps arbitrary diagnostic text
  and badge labels and permits fieldset shrinkage. New totals are 121 core / 139 combined / 19 manage keys;
  inventory/documentation synchronization remains plan08-owned.
