## Boundary decisions and probes

- D-18 governs sequencing: first task is the real authorization-to-trace tracer; command follows recorder/fidelity, form follows command. No premature UI slice.
- Inactive/plain and Guardian-list shorthand yields to actual gates under D-11/D-20; no policy changes.
- POST-only whitelist receives GET only on the diagnostic instance, with a visible method/handler limitation; custom method-sensitive dispatch is an explicit unsupported error. Real GET parity uses GET-capable family representatives.
- Fixed synthetic origin is http://localhost; a bounded HttpRequest subclass supplies get_host. No supplied URL host is trusted and no global ALLOWED_HOSTS mutation occurs.
- Non-login redirect, early success without stub, 405/5xx or nonresponse yields error. Only actual response identity observed at real login middleware, inherited Django AccessMixin, or the direct ancestors._deny_anonymous redirect_to_login branch counts as login redirect.
- Default savepoint always rolls back; exception normalization occurs outside it. Memory session/messages never save to a configured backend. Other DB/external/cache effects are documented limits.
- D-08 custom steps identify the actual observed bound class/method in source, how=observed_boundary, and explicit unknown inner origin in message. Instance wrapping cannot observe each super frame; library outer boundaries and multiple project overrides are tested without choosing an unseen project culprit. This implements the locked opaque-method/class/result promise, not an inner-code analysis feature.
