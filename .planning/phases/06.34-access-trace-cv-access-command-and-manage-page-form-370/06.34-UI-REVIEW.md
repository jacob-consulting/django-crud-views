## Top 3 Priority Fixes

1. **WARNING — Make collapsed result rows explain the outcome.** `view_manage.html:124` shows only key, badge and optional step number. Add a short, escaped summary derived from the recorded deciding step, or list counts for list results. Preserve full native disclosure. This restores the useful at-a-glance explanation in D-14 and mockup lines 96–133 without recomputing authorization.
2. **WARNING — Surface the arbitrary-path outcome before lengthy detail.** `includes/access_trace.html:31` starts with metadata and only renders the outcome at line 41, after plan/steps. In both 390px path captures the answer is far below long class/source text. Add a compact outcome/deciding-step summary above the metadata while retaining the complete trace and limitations.
3. **WARNING — Associate validation feedback with the submitted form.** `view_manage.html:119` puts a plain alert after both forms; inputs at lines 105/114/115 have no invalid/error description association. Put feedback with the relevant form, add an error ID and conditional `aria-describedby`/`aria-invalid` on the offending input. Preserve submitted values and server-rendered no-JavaScript behavior.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1:** `src/crud_views/templates/crud_views/view_manage.html:86` says “your row includes effective permissions and reachable objects” even when the selected actor is someone else. The desktop captures correctly label reader as “checked below”, making the contradictory explanatory sentence apparent. Use actor-neutral “the access row” wording and update its German translation. Existing Guardian explanation at line 87 similarly says “Guardian actor counts” accurately and need not change.
- **WARNING C2:** `src/crud_views/templates/crud_views/includes/access_trace.html:42` repeats the allowed/handler-phase boundary that also appears in `trace.untraced` at line 44. The path captures repeat essentially the same sentence consecutively. Keep one prominent explanation and avoid duplicating it in the human-facing limitations list; preserve structured trace data.
- Positive finding: visible outcomes, unknown-user feedback, needs-PK/path guidance and the “may open the page” limitation are specific and honest. “Check” is the approved contextual CTA; it is not penalized merely for being short. Raw method names and stable diagnostic values are appropriate to this developer tool, not automatically translation defects.

### Pillar 2: Visuals (3/4)

- **WARNING V1:** Priority fix 2. Metadata, plan and steps have the same visual precedence before the primary answer (`access_trace.html:31–44`). The long-input mobile screenshots demonstrate a real scanning cost, although no text is lost. This is a hierarchy recommendation, not a claim that the approved trace ordering itself is forbidden.
- Positive finding: Access check follows Permissions in the main column (`view_manage.html:93`), the two query modes have legends, and the help control has an accessible name and new-tab description (line 98). Historical desktop/mobile images show the expected cards and responsive stacking. No icon-only unlabeled control was found in the new card.

### Pillar 3: Color (4/4)

- **PASS finding:** `src/crud_views/lib/button_classes.py:145–154` defines exactly ten required trace keys: two success, one danger, five warning-with-dark-text, and two secondary. The shared partial at lines 3–13 resolves all result badges through the registry; unavailable reuses not-evaluated deliberately. Words distinguish states independently of hue.
- The inspected images are predominantly neutral surfaces/text with small semantic badges and two primary submit buttons. No accent-overuse defect was observed. There is no numeric 60/30/10 contract for this Bootstrap diagnostic surface, and pixel-area proportions were not measured. Existing CSS fallbacks/group-magenta (`manage.css:75`, `:133`) are established theme behavior, not newly invented trace colors. Custom downstream themes were not visually certified.

### Pillar 4: Typography (4/4)

- **PASS finding:** `src/crud_views/static/crud_views/css/manage.css:1–4`, `:51–80` use 16px body/headings, 14px secondary/table/badge content, weight 400 and weight 600. Code inherits font size/color; metadata remains distinguishable through semantic labels and monospace identifiers. The new partial uses the existing h6 hierarchy instead of adding arbitrary sizes.
- Captures show readable wrapping rather than clipped path/class/error blocks. Exceptionally long fixture identifiers do create dense paragraphs, but no unsupported type-scale defect was established. This is not a human certification of actual-size readability or zoom behavior.

### Pillar 5: Spacing (3/4)

- **WARNING S1:** `view_manage.html:110–120` gives the second form no bottom margin/result separator. The unknown-user capture places “Unknown user” directly against the Check button; successful path captures do the same with “Checking access for”. Add one scoped Bootstrap spacing interval (for example `mt-3` on a result wrapper) between controls and feedback. This is separate from linking feedback to its field.
- Other spacing is consistent: card/form `mb-3`, field `mb-2`, and scoped 8px summary padding/header gap (`manage.css:21–26`, `:83–87`). Native summaries have 44px minimum height. Fieldsets can shrink and badges wrap (`:142–152`). Existing fixed table dimensions support local scrolling; they are not evidence of page overflow. No blanket “arbitrary px” penalty is appropriate for this established CSS design.

### Pillar 6: Experience Design (3/4)

- **WARNING E1:** Priority fix 1. Current summary markup contains neither `counts` nor the deciding step's requirement/message. Allowed list rows can read only “list Allowed”; denied rows require opening and searching for a numbered step. The approved mockup explicitly displays “sees 4 of 25 objects”, object grants and required permissions in collapsed rows. Add only a bounded projection of recorded facts, not a second gate evaluator.
- **WARNING E2:** Priority fix 3. `role="alert"` gives feedback semantic importance but does not associate the server-returned error with either of the two identical user controls. The visible error exists and task completion remains possible; this is not classified as a blocker.
- Positive findings from code: separate labeled GET forms retain input; shared builder/adaptor (`src/crud_views/lib/views/manage.py:740`, `:781`) preserve viewer/actor separation, default-off behavior and per-row missing-coordinate guidance. Guardian inherits the core template. Native details need no custom script, and errors are escaped. These are synchronous read-only queries, so asynchronous spinners and destructive confirmations are not missing requirements.
- Historical plan-10 receipt supports keyboard disclosure, copied result URLs, labels/focus, CSP and no overflow at 390/1280px, across both locales and page variants. Those observations are historical; this audit neither executed nor re-certified them on current source.
