## Top 3 Priority Fixes

These are nonblocking polish recommendations, ordered by practical impact. They are not newly required phase acceptance work.

1. **W1 — Long holder labels overwhelm the permission matrix (WARNING).** The German mobile stress case reaches 16 lines in a holder cell, repeated across 20 visible users. If improving this shared component later, give long labels an accessible compact/full-text disclosure inside the existing row; retain complete names, row ordering, the current overflow behavior and keyboard access. Do not silently truncate identities or redesign Resource-only cards.
2. **W2 — Horizontal scrolling is visually understated (WARNING).** Narrow configuration tables show only the beginning of values. Add a small localized scroll hint or edge cue when a region actually overflows, retaining the existing focusable, labeled scroll region and fixed configuration-key widths.
3. **W3 — Child-opening instructions appear on childless Resource leaves (WARNING).** Render the instruction at `view_manage.html:322` only when `manage_hierarchy.children` is nonempty. Preserve the explicit “No child ViewSets” state and real upward parent links.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **W3 — WARNING, inherited conditional-copy issue.** `src/crud_views/templates/crud_views/view_manage.html:320` renders “No child ViewSets”, immediately followed by unconditional child-navigation advice at line 322. This appears in the English and German nested-empty images even though Resources are leaves. It adds an irrelevant instruction; it does not invent a clickable child or prevent navigation. The bounded remedy is the conditional described above.
- **Positive finding:** Lines 79–94 distinguish “No Resource permissions declared” from no direct holders and explain separate developer/ancestor/custom restrictions. The mapped legend explicitly denies per-item grants. Empty/None/no-holder captures show different, accurate states in both languages. The model branch retains its own guidance.
- **Positive finding:** The Resource caption at line 294 and metadata source in `src/crud_views/lib/views/manage.py:311` distinguish backing metadata from URL fields. `resource_permissions` remains in the existing Presentation section (`manage.py:524`). The trace forms retain labeled “This ViewSet”/“Any URL” fieldsets, user/path feedback and a contextual “Check” action (template lines 110–128); a generic-label grep alone would misclassify that action.

### Pillar 2: Visuals (3/4)

- **W1 — WARNING, inherited stress-case density.** `src/crud_views/static/crud_views/css/manage.css:44` deliberately bounds holder labels to 120–192px and wraps arbitrary names. `view_manage.html:59` displays the first 20 users before the native overflow disclosure. In `resource-layout-de-390.png`, the retained DOM evidence reports a maximum of 16 holder-label lines; the image shows very tall repeated rows before subsequent cards. `core-normal-390.png` and `guardian-normal-390.png` show the same weakness, so this is not a Resource regression. Full identity remains available and the document remains usable.
- **Positive finding:** Permissions provide the first focal point, card headers group diagnostics, and the existing `col-12 col-lg-8` / `col-12 col-lg-4` grid retains desktop main/side columns and mobile stacking (`view_manage.html:9`, line 277). Empty-state desktop captures retain this hierarchy without overlapping headers. Question-mark documentation links have explicit accessible names and new-tab descriptions, for example line 25; they are not unlabeled icon-only controls.

### Pillar 3: Color (4/4)

- **Positive finding:** `src/crud_views/lib/button_classes.py:137` declares exactly `badge bg-info text-dark`. Four template sites resolve `badge-resource` through the registry (lines 39, 47, 61, 71), preserving actor/group/user/overflow semantics and overrides. The German mobile mapped case contains 27 such badges, all with `rgb(13, 202, 240)` background and `rgb(33, 37, 41)` text in the recorded browser facts.
- **Positive finding:** The inspected pages are predominantly white/neutral surfaces, gray borders and text, with compact semantic accents. This is a qualitative distribution assessment, not a measured 60/30/10 pixel claim. The repeated badges exceed a generic ten-element accent heuristic because they encode required matrix cells; removing them would contradict D-05. Their visible text independently communicates meaning.
- **Positive finding:** The harness computes foreground/background contrast for visible text before and after disclosure/default changes (`tests/browser/manage-presentation.cjs:414`–469). The retained German mobile opened Resource case has minimum text contrast **6.57:1**. Existing CSS fallback colors and the magenta group badge (`manage.css:75`, 101, 106, 132) predate this change and have semantic roles; no arbitrary new Resource color is introduced. No color defect found in the reviewed stock theme.

### Pillar 4: Typography (4/4)

- **Positive finding:** `manage.css:1`, 51, 68 and 78 define 16px body/header text, 14px table labels/badges/small text, and 400/600 weights. The retained `resource-layout-de-390` opened DOM contains exactly `(14,400)`, `(14,600)`, `(16,400)`, `(16,600)`. The host heading uses the existing responsive Bootstrap h4/600 role, separately bounded to 20–24px by the harness.
- **Positive finding:** German captions wrap without obscuring controls in the inspected captures. Technical keys and class paths remain literal developer-facing identifiers; they are not untranslated interface prose. Code inherits the content size and color (`manage.css:63`). The tall arbitrary-name wrapping is recorded under W1 rather than counted again as a separate font-scale defect.

### Pillar 5: Spacing (3/4)

- **W2 — WARNING, inherited discoverability issue.** `manage.css:33` keeps configuration keys at least 192px and values at least 160px. The responsive wrappers at `view_manage.html:201`, 237 and 292 correctly allow local scrolling, but mobile captures reveal clipped right-side content without a persistent textual/edge cue. Eight wrappers overflow in the opened German mobile mapped case. The harness confirms they can scroll, have accessible labels, `role="region"` and `tabindex="0"`; this is an affordance weakness, not inaccessible or lost data.
- **Positive finding:** Template spacing uses `g-3` once, `mb-3` twelve times, `mb-0` ten times, `mb-2` four times and `mt-3` three times. CSS uses 8px gaps/padding, 32px help controls, 44px minimum summary height and a deliberate 56px reservation for the sibling help control. These are existing coherent shared dimensions, not new arbitrary Resource offsets. Captures show consistent card separation, and recorded document width equals viewport width at 390/1280. No 375/768/1440px capture is claimed.

### Pillar 6: Experience Design (4/4)

- **Positive finding, source plus retained interaction evidence:** `manage.js:29`–43 binds the defaults control before hiding rows and only then reveals it. Without JavaScript, diagnostics remain visible. Native disclosures and the labeled switch remain keyboard-operable. The prior harness explicitly opens details, toggles defaults with Space and records the opened state for each Resource case (`manage-presentation.cjs:649`–687); this audit did not repeat those interactions or produce new interaction captures.
- **Positive finding, code/render-test evidence:** The trace is default-off, inputs have explicit labels, invalid fields are associated with errors, and errors use `role="alert"` (`view_manage.html:103`–139). The included renderer labels outcomes, deciding steps, plans and limitations (`includes/access_trace.html:41`–58). C07/C08/C12 receipts cover input failures and complete UI/CLI parity. Enabled Resource trace forms were not visually inspected in the eight screenshots; their assessment here is source/render-test based.
- **Positive finding:** Zero-column maps, no direct holders, hidden users, overflow, absent views and failed checks have explicit states. This is a server-rendered diagnostic page with native navigation, not an asynchronous card loader: a missing custom spinner is not a defect. No destructive action handler is executed by access tracing, so adding a destructive-action confirmation is not warranted. Core/Guardian screenshots retain model/object labels, and existing fallback behavior is preserved. No interaction defect found within this evidence boundary.
