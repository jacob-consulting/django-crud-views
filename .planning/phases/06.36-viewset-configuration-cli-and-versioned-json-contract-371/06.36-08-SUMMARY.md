**2. [Rule 3 — Blocking issue] Recursive FormSet field types.** Existing `Self` fields were treated as arbitrary values at the floor and emitted startup warnings that broke real pipe/PTY stderr assertions. Explicit `FormSet` forward references restore recursive validation without suppressing warnings. Seven new behavioral cases prove invalid parent/child/grandchild values are rejected and mixed base/subclass nodes work. Before correction, three floor admission cases and two primary mixed-node cases failed; afterwards the broader formset selection passes **431** on each runtime. On newer Pydantic this intentionally permits base/subclass relationships where `Self` previously required the same subclass. The reference and Fixed changelog describe this bounded semantic change. Files: `formsets.py`, the new declaration tests and release/reference docs; commit `1558c737`.

**3. [Rule 1 — Bug] Resource inheritance before the subclass hook.** Independent review found that old Pydantic rejected a real descendant `pk` before the hook could neutralize its inherited alias. The private alias and neutralizer now raise AttributeError for class lookup, keeping normal instance `row.pk`, static marker discovery and the existing PK algorithm. The existing test additionally covers grandchild inheritance and an explicit default. Primary/floor Resource and import checks pass **33 each**, and the final installed selection passes 40. The [independent reviewer receipt](06.36-REVIEW-GAP-08.md) retains the frozen-byte failure and both-runtime recheck. Files: `resource.py`, `test_resource.py`, CHANGELOG; commit `0876d769`.
