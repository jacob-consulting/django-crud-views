## Bounded compatibility correction and superseded receipts

The first focused Django 4.2 run produced 321 passes and one failure: the new serializer assumed `_args`/`_kw` on exact known Django translation proxies, while the installed 4.2 runtime uses name-mangled storage. A new regression covers gettext/pgettext, positional/keyword arguments and English/German output; its intentional assertion failure was machine-validated and committed as `ab800334`. Fix `6eb55c18` reads the two known storage layouts only after exact-type identification, retaining plain-string argument validation before translation. Existing hostile-object/custom-Promise rejection tests remain unchanged and pass. This is **Rule 1 — Bug**, narrowly extending plan07 ownership to `src/crud_views/lib/manage_report.py` and `tests/test1/test_manage_report.py`.

Bounded follow-up review proved a hook-safety defect in the first compatibility fallback: harmless alternate storage keys could conceal hostile real translation arguments. Intentional sentinel RED `d033ddca` failed on `Hostile.__str__`; final fix `4846f729` selects argument names from a fresh Django-created prototype, then reads those exact attributes only after the exact-type gate. It retains the original plain-string checks, rejects hostile real arguments despite spoofed safe fields, accepts valid real arguments despite hostile alternate fields, and avoids mapping `.get` hooks. No new serializer abstraction, dependency, state or query was added.

After completing this bounded review, the six command/report/export/preservation/docs/locale modules pass **354 tests on each of Django 4.2, 5.2 and 6.0**; report models alone contain **57** tests. Earlier source/installed full runs each passed 15,593 tests plus one skip, and the first-correction normal runs passed 15,594 plus one skip, but those receipts are **superseded**, not final acceptance. Source and installed recorder runs of the first correction were explicitly interrupted (3573 and 1830 tests had passed) to finish the proved safety fix before restarting broad verification. The frozen source adds six regressions to the original baseline. Final build, installed-byte, schema and quality checks are repeated, followed by all four full modes. Strict MkDocs evidence is retained because every docs/catalog/schema-asset byte is unchanged; its input fingerprints and successful asset comparison still apply.
