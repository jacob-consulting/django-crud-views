**Summary.** Catalogue tracer plus full core inspection through the registered manage class, with the complete wire contract fixed up front. The contract text is the strongest part of the phase: it pins every A-02 vocabulary verbatim and types every existing public inventory field.

**Strengths.**
- Guardian kind detection without importing the extension is implementable exactly as written: `GuardianViewSet._ancestor_provider = "guardian"` is class metadata (`src/crud_views_guardian/lib/viewset.py:62`), and core `ViewSet` declares `"model"` (`src/crud_views/lib/viewset/__init__.py:72`).
- "Include manage when web mode is no" is grounded: registration builds `AutoManageView` unconditionally (`src/crud_views/lib/viewset/__init__.py:213-214`); only `register_view_class` consults the mode (`:359`).
- Validating the view selector against `get_all_views()` rather than `get_view_class()` is right; the latter aliases `list` to `card` (`:375-379`).
- Making only the actor call conditional is the correct seam: `get_manage_permissions` already runs the guard and holder queries before `"actor": self.get_manage_actor_row(viewset, user)` (`src/crud_views/lib/views/manage.py:197-235`), and `_check_nested_auth` already tolerates a non-model actor while still checking every table manager (`src/crud_views/lib/ancestor_db.py:157-170`).

**Concerns.**
- MEDIUM: The plan declares an instance-only `_manage_export_enabled` flag, but three of the owner branches it must enrich are `@staticmethod`: `_manage_display` (`manage.py:292`), `_manage_view_entry` (`:651`) and `_manage_check_messages` (`:714`). A static method cannot read instance state, so the plan as written cannot capture pre-display values or numeric check levels "at the owner" without changing those methods to instance methods or threading the flag through parameters. All current call sites go through `self.` (`manage.py:303,347,412,418,455,637,746`; `src/crud_views_guardian/lib/views.py:402`), so a static→instance conversion is call-compatible, but the plan should say so explicitly; it is the single biggest unplanned refactor in task 01-02.
- MEDIUM: `_url_configuration_loaded()` swallows the exception and returns `False` (`checks.py:193-194`). Treating `False` as `collection_failed` is correct, but the structured error can carry no `exception_class` or message, so a broken included URLconf yields "discovery failed" with no cause. Research recommended a raising traversal; plan 01 does not own `checks.py`, so this is either a conscious trade-off to document or a one-line ownership addition.
- LOW: With `user is None`, the builder returns `"actor": None` where the documented page contract promises a dict (`docs/reference/theme.md:850,862-863`). Fine for the command, but the docs plan should state that `None` is a new input value with a new return shape.
- LOW: `tests/test1/test_manage_docs.py:103-104` asserts the exact set of `get_manage_*` names on `ManageView`/`GuardianManageView` equals the documented table. The plan's `manage_export()` name is safe; any helper accidentally named `get_manage_…` breaks that guard.
- LOW: `ParentViewSet` and `ContextButton` instances reach `_manage_field` as raw values (`manage.py:325-332,411`). The contract lists `ConfigEntry` button fields but no explicit projection for the `parent` fact; without one the normalizer will label it `unsupported`. See plan 02.
