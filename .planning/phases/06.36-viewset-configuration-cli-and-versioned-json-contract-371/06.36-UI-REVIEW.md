## Detailed findings

### C1 — Sparse command help (WARNING)

`src/crud_views/management/commands/cv_manage_view.py:201` registers `viewset`, `view`, `--list`, `--user`, `--as-json` and `--schema` without help text. A direct configured `Command.print_help("manage.py", "cv_manage_view")` probe confirmed that all six appear with blank descriptions, while inherited Django options have descriptions. The overall description at line 199 is accurate but does not explain what either selector accepts or the diagnostic-only role of the actor. The reference provides these details (`docs/reference/manage.md:209`, `:226`, `:257`); bring concise versions into the command help. Update the German message inventory when adding translated descriptions.

### C2 — Generic recovery message for conflicting modes (WARNING)

`src/crud_views/management/commands/cv_manage_view.py:213` merges three invalid-input cases; line 227 always emits “Choose --list, --schema or a ViewSet name.” A direct `Command.handle(list_viewsets=True, schema=True)` probe emitted that message and exited 2. It correctly failed, but did not explain that the chosen modes conflict. A user supplying `--list --user alice` would likewise not be told to remove the user or select a ViewSet. Use a small explicit selection of human messages without changing the machine error vocabulary or parser boundary. Documented restrictions already establish the intended correction (`docs/reference/manage.md:226`).

### Relevant strengths and limits

The terminal renderer labels selected-view versus ViewSet-wide scope, preserves all validated leaves and explains direct/effective grants and hidden-holder visibility (`cv_manage_view.py:54`, `:94`, `:98`). Empty arrays/nulls remain explicit rather than disappearing. Dynamic text escapes nonprintable characters before intentional heading styling (`:46`, `:66`, `:69`). JSON/schema bypass styling (`:229`, `:279`), and incomplete status takes precedence over severe checks (`:122`). The existing process, PTY, locale and rendering tests recorded in plan04/06 and final acceptance support these behaviors; they were not rerun by this bounded audit.

Runtime probe used `PYTHONPATH=src:. .nox/tests-3-12-django-5-2/bin/python -c 'from tests.test1.conftest import pytest_configure; pytest_configure(); from crud_views.management.commands.cv_manage_view import Command; c=Command(); c.print_help("manage.py", "cv_manage_view"); c.handle(list_viewsets=True, schema=True)'`. Exit 2 was the expected invalid-input outcome, not a test-suite failure. No browser focus, hover, loading, keyboard or responsive state was captured or claimed.
