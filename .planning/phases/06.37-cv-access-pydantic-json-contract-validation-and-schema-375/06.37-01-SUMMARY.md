# Phase 06.37 Plan 01: cv_access version-1 export contract Summary

**cv_access now runs every trace through strict internal Pydantic models before either formatter, which keeps valid output byte-identical and turns malformed facts into one escaped returncode-2 diagnostic. A new exclusive `--schema` flag prints the plain validation-mode JSON Schema generated from the same models.**

## Performance

- **Duration:** about 11 min
- **Started:** 2026-11-16T19:14:47Z
- **Completed:** 2026-11-16T19:25:55Z
- **Tasks:** 3/3
- **Files modified:** 6 (2 created, 4 modified)

## Accomplishments

- `crud_views.lib.access_trace_export` holds the strict models: `TraceUser`, `ObjectIdentity`, `TraceException` (`class` alias), `Counts`, `PlanRow`, `Step` and `AccessTraceExport`. It also defines the closed `Outcome`/`Kind`/`StepResult`/`Provider` sets and provides `validate_export()` and `export_schema()`. It imports only `typing` and `pydantic`, and a subprocess test confirms that loading it pulls in no Django module.
- `cv_access` validates `trace.to_dict()` right after `trace_access()`, ahead of the color logic, the no_such_route stderr line and both formatters. A failure prints only `Output validation failed (ValidationError): <escaped loc paths>`, raised as a CommandError with returncode 2. Through Django's real `run_from_argv` this gives empty stdout and exactly one stderr line, with no traceback, no raw ESC and no input values.
- `cv_access --schema` (also accepted with `--as-json` and `--force-color`) prints the uncolored schema. It runs before user resolution and tracing, and the tests use no `django_db` mark, with `explode` spies on both runner entry points. Combining it with a path, user or `--anonymous` gives returncode 2, and so does a missing path.
- The German catalog covers all four new msgids, and the `.mo` was recompiled with polib.
