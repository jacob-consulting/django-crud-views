# Phase 06.37 Plan 03: cv_access contract documentation and #375 changelog Summary

**`## cv_access` now publishes the version-1 trace contract. A new `### Schema and compatibility` subsection covers `cv_access --schema`, the D-12 versioning rule, validation failures (stderr, exit 2, not an outcome) and the not-public model note. A second streams table documents the exit codes, and the Step fields vocabularies now equal the model Literals, `model` provider included. Docs tests bind every new statement to real command behavior, and a CHANGELOG Added entry for #375 points to the new anchor.**

## Accomplishments

- The intro bash block gains `python manage.py cv_access --schema`. The actor rule now reads "For tracing, supply a user or `--anonymous`, never both; `--schema` takes neither." The color paragraph speaks of trace JSON and trace output and adds "`--schema` output is always plain." The `DJANGO_COLORS` sentence is kept.
- `### Outcomes and streams` has a second table `| Invocation or failure | Exit | Streams |` with a blank line before it. Its rows are `--schema` (0), Output validation failure (2) and Unknown user or wrong invocation (2). The paragraph after the tables now lists validation failure alongside the unknown-user convention.
- `### Schema and compatibility` sits between Step fields and Custom method boundaries and contains no JSON block. It covers:
  - schema access and exclusivity: no path, user or `--anonymous`, exit 2 when combined; `--as-json` is redundant and the output stays plain under `--force-color`;
  - no trace, user or database read, and no static schema file;
  - authority, and why `{}` and plan-row keys are not required;
  - regenerating a saved schema after upgrading;
  - the D-12 rule;
  - validation failure, including the `cv_get_requirement()` non-string case and the fact that the manage page does not validate;
  - D-14: the models are not a public Python API.
- The `user` row ends with "or `{}` before actor resolution."
- In Step fields the provider row reads "`core`, `guardian`, `model` or `none`, or null", and "Step results are" replaces "include". A new sentence calls outcomes, kinds, step results and providers closed sets in version 1, links the compatibility rule, and says plan rows use the same kinds and only `unavailable`.
- The CHANGELOG has a first Unreleased Added bullet, **Access trace contract** (#375), linking `docs/reference/manage.md#schema-and-compatibility`.
