## Fixed Issues

### WR-02: `TraceUser` accepts partial and null-valued actors, so gate and schema are weaker than the documented contract

**Files modified:** `src/crud_views/lib/access_trace_export.py`, `tests/test1/test_access_trace_contract.py`
**Commit:** da9e018f
**Status:** fixed: requires human verification (validation logic change)
**Applied fix:** Added the review's `model_validator(mode="after")` `_empty_or_complete` to `TraceUser`. `{}` still
validates. Any non-empty user must now set all four keys (`pk`, `username`, `active`, `anonymous`), and `active`
and `anonymous` must be booleans, not null. The fields stay optional and nullable, so the generated `--schema`
output is byte-identical (same sha256 before and after), and the docs tests did not need changes.
`docs/reference/manage.md` already describes this shape ("boolean `active` and `anonymous`, or `{}`"). The schema
still lists the user keys as optional and nullable. Expressing "empty or complete" in the schema would need the
`anyOf` change the review describes, which rewords D-05 and was not part of this fix.
Regression tests: five new `test_malformed_exports_are_rejected` cases (`user-partial`, `user-key-removed`,
`user-active-null`, `user-anonymous-null`, `user-null-flags`), each failing with `value_error` at `("user",)`, and a
new `anonymous-user` round-trip case (`pk`/`username` null, booleans set).
