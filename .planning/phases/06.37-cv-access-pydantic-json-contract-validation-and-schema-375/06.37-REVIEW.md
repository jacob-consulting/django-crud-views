## Warnings

### WR-05: The documented way to detect a validation failure also matches an unknown user, a wrong invocation and a text-mode `no_such_route`

**File:** `docs/reference/manage.md:550-552`
**Issue:** The new sentence says "scripts should detect the failure by exit `2` with empty stdout, not by the
text". That signal is shared with three other documented cases. Real-process runs of the CLI fixture
(`tests.test1.access_trace_cli_fixture`) at HEAD, plus the validation failure through `run_from_argv`:

```text
/plain/ nobody --as-json            exit 2, stdout empty   CommandError: Unknown user: nobody
/plain/ sam --anonymous --as-json   exit 2, stdout empty   CommandError: Supply either a user or --anonymous, but not both.
--as-json                           exit 2, stdout empty   CommandError: Supply a project path, or use --schema.
/nope/ --anonymous                  exit 2, stdout empty   No such CRUD view route: /nope/
(malformed trace)                   exit 2, stdout empty   CommandError: Output validation failed (ValidationError): steps.0.result
```

A script that follows the sentence reports a mistyped username as an output validation failure. In text mode it
also cannot tell the failure from the `no_such_route` outcome, although the same paragraph says the failure "is
not an outcome". The table at `manage.md:435-439` lists these cases as separate rows with the same exit code, so
the page already shows that the rule cannot separate them.

A locale-independent part of the line exists: the class name in `(ValidationError)` comes from
`type(exc).__name__` (`cv_access.py:227`) and survives translation, as the German line
`CommandError: Ausgabevalidierung fehlgeschlagen (ValidationError): steps.0.result` shows.

The wording follows the fix suggested for IN-04 in the first review, so the imprecision comes from that
suggestion and not from the fix commit.

A related, older limit of all three stderr rows: Django's standard `--traceback` flag re-raises the
`CommandError`. Measured with an unknown user, the process then exits 1 with a 15-line traceback and empty
stdout. Mentioning it is optional.
**Fix:** State what the signal means and name the stable token. Replacement for the sentence at lines 550-552
(all lines stay under 120 characters, and "no trace document" stays in the section for
`test_documented_validation_failure_is_not_an_outcome`):

```markdown
field locations, never their values, and the command exits `2`. The message is translated (German:
`Ausgabevalidierung fehlgeschlagen`), so scripts should not match its text. Exit `2` with empty stdout means
only that no trace document was written: an unknown user, a wrong invocation and a text-mode `no_such_route`
look the same. The class name `(ValidationError)` in the line is not translated.
This is not an outcome and adds no document shape.
```
