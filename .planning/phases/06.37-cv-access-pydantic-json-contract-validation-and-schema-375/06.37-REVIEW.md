## Warnings

### WR-06: "A login redirect is a `denied` step" is false when project code turns a recorded 404 into the redirect

**File:** `docs/reference/manage.md:515-516`; `tests/test1/test_access_trace_docs.py:118-119`
**Classification:** WARNING
**Issue:** The reference says "A login redirect is a `denied` step with the `login_redirect` outcome". The diff
adds an assertion for it: for the `login_redirect` case, the deciding step must be `denied`. That case is an
anonymous request to a stock `DetailViewPermissionRequired`, where the ordinary permission gate records the
`denied` step.

The statement does not hold for a project override that catches a 404 and refuses instead. Probe view, registered
like the test's own view and traced through `call_command("cv_access", path, "--anonymous", "--as-json",
"--no-color")` with a missing pk:

```python
class Hide(DetailViewPermissionRequired):
    def has_permission(self):
        try:
            self.get_object()
        except Http404:
            return False
        return super().has_permission()
```

Real output (exit 1, empty stderr, the document passes the validation gate):

```text
outcome=login_redirect decided_by=2
  1 route          passed
  2 object_lookup  not_found    CrudView.get_object
  3 custom_gate    not_reached
  4 action_state   not_reached
```

The deciding step is `not_found`, and the trace contains no `denied` step at all. A consumer that follows the
sentence and expects `steps[decided_by - 1].result == "denied"` for a login redirect gets a wrong answer.

The cause is in the runner, outside this review's file list. The handler observer adds its `denied` step only
when no terminal step exists yet (`access_trace_runner.py:285`), and `decided_by` is the last terminal step
(`access_trace_runner.py:461`). The same view with an authenticated user does get an extra `custom_gate`
`denied` step, through the exception branch at `access_trace_runner.py:442`. Keeping the instrumented step as
evidence is consistent with "Custom method boundaries" (`manage.md:566-567`), so the reference sentence is the
part that overstates.

The sentence came in with `02ce753e`, and the previous review judged it accurate from stock traces only. The
assertion added in this diff has the same limit. The claim "never emits `login_redirect` on a step" is not
affected.
**Fix:** Qualify the sentence. Changing the runner would add a step to existing traces, which conflicts with
the phase promise that valid output bytes are unchanged. Replacement for `manage.md:515-516` (all lines under
120 characters):

```markdown
on a step; they are reserved. A login redirect normally has a `denied` deciding step with the `login_redirect`
outcome. If project code answers an earlier recorded refusal with the redirect (for example a `has_permission()`
override that catches a 404), that step stays the deciding one. `unavailable` is planning metadata on plan rows.
```

Bind the new wording after `test_access_trace_docs.py:116`:

```python
    assert "A login redirect normally has a `denied` deciding step" in " ".join(step_section.split())
```

Verified in the scratch copy with every fix proposed in this review applied: the docs tests pass (44 passed
with `test_manage_docs.py`), `ruff` is clean, and changing `denied` to `not_found` in the new sentence then
fails 6 tests.

### IN-09: "A wrong invocation" does not always exit 2: Django's own option errors exit 1

**File:** `docs/reference/manage.md:439,442-443,552-553`; `tests/test1/test_access_trace_docs.py:396`
**Classification:** WARNING (Info tier)
**Issue:** The new sentence lists "a wrong invocation" among the cases that look like exit 2 with empty stdout,
as the older table row and paragraph do. Two wrong invocations exit 1 instead, measured in real processes:

```text
/plain/ sam --no-color --force-color   exit 1, stdout empty, 1 stderr line
                                       CommandError: The --no-color and --force-color options can't be used together.
/plain/ nobody --as-json --traceback   exit 1, stdout empty, 15 stderr lines (traceback)
```

The repository already pins the first case at exit 1 (`tests/test1/test_access_trace_command.py:314`), so the
reference and the test suite disagree. Exit 1 is the code the outcome table gives to `denied`, `not_found` and
`login_redirect`. The docs test at line 396 compares the table's number with the literal `2` and runs no wrong
invocation. Most of this text is older than the diff; the new sentence repeats it. The previous review mentioned
`--traceback` as optional. The `cv_manage_view` section already makes this exception
(`manage.md:311-312`).
**Fix:** Add the same exception after `manage.md:444`:

```markdown
Django's own option handling is outside this table: `--no-color` with `--force-color` exits `1`, and `--traceback`
turns any `CommandError` into a traceback with exit `1`.
```

Verified in the scratch copy: the docs tests still pass with this paragraph.
