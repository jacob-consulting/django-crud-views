## Setup and categories

- Both destination types use real `ListViewPermissionRequired.cv_has_access`, with the actor's Book model view grant.
- Plain parent: shipped plain Book/Publisher ViewSets, default Read nearest `view`, and Publisher model view grant.
- Mixed parent: core destination on `links.child`, Guardian Publisher parent, `CHANGE_READ` nearest `change`,
  and `world`'s matching real object change grant. No Publisher view grant is needed in this lane.
  This differs from the alternate-child core preservation case: its default Read is `view`, so that separate
  case adds an object view grant on only `parents[0]` and continues to deny `parents[1]`.
- Fresh actor: fetched from the database outside each measured block. Warm actor: a fresh actor has passed
  `has_perm("app.view_book")` outside the block, populating Django's model-permission caches.
- Cold vocabulary: both ViewSets' `_default_permissions`, Django ContentType cache and Guardian content-type
  cache reset after actor warm-up. Warm vocabulary: both permission maps read after reset, outside measurement.
- The own-access baseline and integrated renderer each start from independently reset, equivalent cache states.
  The baseline calls the destination's existing `cv_has_access` directly. It is not a full page or request baseline.
- `P` counts outer SELECTs from `auth_permission`, including vocabulary and model/object grant joins;
  `C` counts outer SELECTs from `django_content_type`. Totals count actual captured SQL.
- Every integrated row below has **one** helper invocation on the exact supplied actor/parent, versus **zero**
  in its own-access baseline. All have **zero parent-row, child/relation-row, actor and other SQL queries**.
  Actor refetch, grants and host setup are outside measured SQL.
