## CR-01: Historical Coverage Gap and Correction

The earlier audit's zero-gap conclusion was incomplete. Its anonymous/inactive matrix used default backends,
whose permission denial masked a missing protected-parent actor prerequisite. A supported custom backend can
grant `app.view_book` to an anonymous or inactive actor; provider success alone did not establish the required
actor admission. The initial runtime could emit an enabled child link while its immediate protected parent's
request guard rejected that actor. This was an uncovered D-02/plan-01 actor requirement, not an approved
farther-ancestor limit. The prior passing suites and fingerprint did not prove that edge satisfied.

Independent [REVIEW resolution](06.39-REVIEW.md#resolution-verification--2026-11-18t124057z) records CR-01 fixed
at runtime `3e699221db7dddc3499cca9e202b0f2dd3a9da83`, with regression
`16ad5f02bd432e100d3123b123b0b4faa7af29f6`. This refresh read the actual backend, all new regression assertions
and corrected hook, together with the review's resolution evidence. It does not change implementation or
claim to have rerun the tests independently.

`test_plain_child_link_backend_grant_cannot_waive_actor_rule` adds **24 cases**: context/card × hide/disable ×
anonymous/inactive/inactive-superuser × protected/none. The tests first prove that the real configured backend
grants the parent permission and own access allows. Actual destination GETs then return 302 to login for
anonymous protected actors, 403 for inactive protected actors, and 200 for provider-none controls. Rendered
protected links hide or disable without a usable URL; provider-none links remain enabled. Each case verifies
one helper call, no parent-row read, and own-denial short-circuiting with no helper or SQL work. The test-local
inactive backend inherits `AllowAllUsersModelBackend`, retaining inactive sessions so request tests do not
silently substitute an anonymous actor.

The corrected core hook keeps own denial and top-level early returns, calls the existing parent helper once,
then requires authenticated active actors unless the immediate provider is none. Keeping the helper first
preserves reached configuration errors, missing-parent denial and provider-none ordering. Source inspection
confirms no farther-parent traversal, second permission check, renderer gate or change to the Guardian
standalone/create adapters.

Result: **exit 0; 68 passed in 1.93 seconds, no skips**. All 24 new cases passed; the remaining 44 exercise
