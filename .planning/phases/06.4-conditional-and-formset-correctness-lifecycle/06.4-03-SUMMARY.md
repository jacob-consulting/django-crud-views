# Phase 06.4 Plan 03: Clearing Configuration Diagnostics and Invariants Summary

**Unsupported conditional clearing reports E312 across declared main/inline forms and raises ImproperlyConfigured before saving request-created fields, while explicit native values and application/model invariants remain authoritative.**

## Accomplishments

- Replaced W320's null/blank heuristic with E312. Diagnostics identify the form, toggle/group and field, with an explicit empty_values hint. Standard supported Boolean, blank text and M2M pairs avoid obsolete warnings; disabled fields remain exempt. Existing E310/E311/W321 semantics remain covered.
- Registry traversal inspects main forms and each form class reachable through all formset descendants, including custom native BaseInlineFormSet subclasses. It never constructs request-dependent forms. Class-identity deduplication avoids rechecking shared declarations. Each form computes its own declared/injected namespace; valid inline-only names pass, and names belonging only to the main or a sibling form cannot satisfy inline references. Reversed traversal order yields the same findings.
- Runtime clean validates configuration before inherited clean regardless of submitted toggle state. Fields added after the mixin's constructor are included; unsupported active and inactive submissions raise ImproperlyConfigured before model save, rather than an end-user validation error.
- Non-null numeric/FK, TypedChoiceField, MultiValueField, JSON/custom form/model fields and overridden save_form_data hooks require explicit native values. Tests execute the custom persistence hook and refresh a real database row for False, None, empty string and empty list without reinterpretation. Plain Forms remain independent of ModelForm hooks.
- Inherited nonfield invariants survive ordinary conditional field-error suppression. Model clean and uniqueness checks still see final state and can reject saving. Server-disabled validation errors and trusted values remain preserved.
