# Phase 06.4 Plan 04: Mandatory Formset Row Policy Summary

**Package and custom native inline formsets reject edit-only additions and invalid submitted identities before any save, while retaining conditional clearing, authorized edits/additions, selected database and inactive aggregate behavior.**

## Accomplishments

- Mandatory XFormSet validity traversal runs normal Django/custom clean before policy, irrespective of whether the declaration inherits package InlineFormSet. Edit-only changed/DELETE/nested-only extras receive translated `Additions are not allowed.` / `cv_additions_not_allowed`. Untouched extras and existing edits remain valid. Repeated validity calls retain one nonform error per policy code and avoid repeating membership queries.
- Existing-row intent derives from initial positions, submitted IDs and persisted bound instances. Native model PK conversion, membership in `instance.get_queryset()` on its selected database, and equality with the actual persisted instance are all required. Missing, malformed, nonexistent, foreign-parent, same-parent-filtered and misbound IDs receive `Invalid row.` / `cv_invalid_row`, including DELETE-marked rows. Existing IDs in extra positions cannot become replacement inserts; negative/impossible management counts also reject.
- Isolated registered create/update routes cover both package and direct Django BaseInlineFormSet adapters. Real GET and valid POST controls prove the adapters reach runtime policy. Save spies cover main/sibling/nested models, and policy-call spies prove negative requests fail at the mandatory gate. Native custom clean calls and errors survive. Additional direct tests cover UUID conversion, legitimate blank-ID/default-UUID additions, mismatched bound instances and a queryset explicitly selected on the independent shard while the ambient router returns to default.
- The main form participates in the second validity pass, retaining errors added by child clean without entering ModelForm.save. Unbound parent forms used for standalone runtime trees remain supported. Inactive trees skip active policy; parameterized edit_only/can_delete combinations preserve managed-queryset purge and default skip. Existing genuine save-failure rollback and unchanged scalar/file/image-reference/M2M clearing regressions pass.
