# Phase 06.4 Plan 06: Formset Controls and Modal Submission Summary

**Form-scoped formset initialization keeps identical prefixes independent, enforces native action capabilities, and cancels modal requests when prior listeners or child reorder reject submission.**

## Accomplishments

- Public `cv.initFormsets(root = document)` accepts Document, Element and DocumentFragment roots, includes a root form and resolves the owning form of content/row/control roots. Page readiness, late script execution, modal loaded and outer row-added all use it. A private WeakMap retains one controller per actual form, with delegated native action handling and a form submit listener. Repeated initialization does not bind again, including recursively inserted nested content. Missing jQuery retains deferred window-load retry, one diagnostic and explicit supported late retry. jQuery AJAX and existing internal class test seams remain; the page-global `cv.formsetController` is no longer used.
- Every dynamic prefix/name lookup uses fixed structural selectors plus exact attribute/name equality within the owning form: content, rows, management, DELETE, reorder fields, new-row initialization, highlighting and event targets. Integer and UUID parent keys and deep hyphenated declaration/ancestry prefixes are tested with identical forms and near-match management/row/suffix decoys. `FormSets.check_keys` still rejects punctuation-bearing declarations.
- Stock Add is absent for edit-only formsets. Real package formset instances/forms render the shipped template across all eight edit-only/Delete/Reorder combinations, retaining native type, labels, row prefix and registry classes. The test models the supported absence of optional ordered-model startup validation; it does not replace the template or formset runtime with handwritten markup. Custom Add cannot bypass edit-only, and action activation rechecks live capabilities, can_delete_extra, disabled controls/fieldsets, hidden/inert/aria-disabled ancestors and native type=button semantics. Closed modal controls and stale detached Add responses do not mutate live content.
- Form submission reorders only its owner before the document modal handler constructs FormData. The complete formset traversal now returns false after any malformed child instead of losing false inside jQuery.each. Modal handling honors earlier defaultPrevented and issues no fetch after cancellation or reorder failure. ORDER is selected by its exact row name; orderable nondeletable formsets work without a DELETE input.
- Tests load the actual formset, toggle and modal scripts together. Open/422/close/open keeps the old unload event attached before replacement, initializes live replacement controls once, disposes old control handlers and conditional observation, preserves management submission and one outer event with exact `{prefix, rows}` detail. Nested widgets/actions initialize without a second nested event. Existing focus, Cancel, native submitter and stale-session tests all pass; modal injection/focus/session implementation remains intact apart from the document submit guard.
