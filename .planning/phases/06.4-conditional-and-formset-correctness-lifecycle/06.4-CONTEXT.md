<decisions>
## Implementation Decisions

### Theme compatibility and toggle binding

- **D-01:** Corrected toggle identity may require immediate migration of existing template overrides before 1.0.
  Establish an unambiguous contract and provide documented, tested migration examples. Do not make preserving
  all old markup or a temporary legacy compatibility layer a prerequisite for the repair.
- **D-02:** If outdated custom markup leaves multiple possible toggle matches, do not guess. Leave the affected
  group unchanged and report a diagnostic. Do not hide/disable it as a fallback or fail the whole form's
  initialization. Server-side conditional rules remain authoritative.
- **D-03:** Isolate ambiguous-binding handling to the affected group. Correctly bound groups, including those in
  other forms, continue working. This does not authorize bypassing a correctly bound ancestor's disabled state.

### Visibility, disabled controls and focus

- **D-04:** Use immediate native visibility for 1.0. No theme visibility/animation adapter is required in this phase;
  a compatible presentation hook can be considered later.
- **D-05:** When hiding a group would strand focus inside it, move focus to its controlling checkbox. If necessary,
  use a visible, enabled ancestor toggle. Leave focus elsewhere untouched. Preserve the accepted Phase 6.3 modal
  focus contract and avoid unnecessary focus movement on initialization or resynchronization.
- **D-06:** Preserve unsaved entries across off→on toggles before submission. Do not clear values merely because
  the client hides a group. Submitting with the group off still applies the server-side policy, including D-09.
- **D-07:** Disable action buttons inside inactive groups along with their data fields, including formset Add,
  Delete and Reorder controls. Restore them when active while preserving independent disabled reasons and all
  enclosing conditional states. Retain the existing management-input exception required for valid POST/re-render.

### Inactive field clearing

- **D-08:** Provide automatic field-aware clearing defaults for supported field types. Honor explicit
  `empty_values`; require explicit configuration for unsupported cases. Clearing a FileField reference must not
  imply deleting the stored file. Research must define and test the supported field/persistence matrix.
- **D-09:** Preserve fields explicitly disabled on the server even when their conditional group is off. Switching
  the group off must not change a field the application made non-editable. This is an exception to the general
  off-group clearing rule, not a grant of authority to client-side disabled attributes.
- **D-10:** If no supported automatic clearing value exists and no explicit value is supplied, raise a descriptive
  configuration error identifying the group and field. Report it at startup where detectable, otherwise before
  saving. Do not turn this programming/configuration problem into an end-user form validation error.

### Edit-only and dynamic rows

- **D-11:** A nonblank extra row submitted to an active edit-only formset rejects the whole submission with a
  formset validation error explaining that additions are not allowed. Save nothing; do not silently discard the
  extra row while saving other edits. This does not change the separately documented inactive aggregate purge policy.
- **D-12:** A submitted existing row with a missing ID or an ID outside the formset's authorized queryset rejects
  the whole submission with a generic invalid-row error and no saves. Do not reveal whether that ID belongs to
  another parent, ignore the row while saving others, or create a replacement row. Distinguish submitted existing
  rows from legitimate new rows in formsets that permit additions.
- **D-13:** Provide a documented, repeat-safe initializer for a supplied content root, usable by themes inserting
  content themselves or adding a toggle widget after its group. Library-managed page, modal and added-row
  lifecycle events invoke the same supported initialization behavior automatically. Its concrete name/signature
  is for research/design; no private controller constructor or wiring flag is the public integration contract.
- **D-14:** Repeated initialization resynchronizes current state: retry unresolved bindings and update visibility
  and disabled state without duplicate handlers, lost entries or unnecessary focus changes. Include supported root
  elements themselves as well as their descendants. Missing-toggle retries must not be blocked by marking failed
  initialization successful.

### Carried-forward requirements and compatibility

- **D-15:** Retain all A1–A7 roadmap acceptance: sibling/nested row identities, shared suffixes, prefixed and multiple
  forms, both nesting orders, baseline disabled ownership, cancellable native reset, management POST/re-render,
  initial load, modal/422 replacement, nested added rows, scripts loaded after DOMContentLoaded and real
  add/delete/order/submit/widget lifecycle. Test stock and minimal non-Bootstrap templates and keyboard/focus
  behavior. Document inherited clean/model validation accurately; conditional field-error suppression must not
  bypass application/model invariants.
- **D-16:** Repair A19's non-first sibling child-fragment indexing and prove rendered-prefix/management/POST
  round trips while preserving Phase 6.2's authorization and ancestry checks. Its existing characterization test
  is not successful round-trip evidence. Reconcile the old first-declared-child limitation only after verification.
- **D-17:** Preserve fragment request coordinates and `{html, rows}` responses, row-added event detail
  `{prefix, rows}` and one event per outer inserted row. Document a usable formset template-data projection without
  declaring internal rendering-tree classes public merely because templates consume their data.
- **D-18:** Keep jQuery in this phase; the #210 port remains deferred. Preserve server authorization, parent denial,
  restricted querysets, existing atomic/rollback boundaries, default skip and opt-in aggregate purge semantics.
  Rejected submissions in D-11/D-12 must fail validation before any part is saved, not rely solely on rollback.
- **D-19:** Preserve completed form-leaf, label-mode, escaping and cancel-link contracts and the accepted modal
  focus behavior. Document changed template/DOM, clearing and validation contracts; pair every Breaking changelog
  entry with `docs/migrating-1.0.md`. Hand all newly supported public names to Phase 7's inventory.

### Agent's Discretion and Planning Notes

- No additional product choices were explicitly delegated. Concrete helper/API names, diagnostic IDs/messages,
  supported-field analysis, implementation placement, test organization and precise documentation wording are
  research/planning responsibilities within these decisions.
- D-02's diagnostic mechanism must not turn ambiguity into a page-wide failure. Distinguish ambiguity from a
  temporarily missing toggle and preserve retry behavior. Do not treat an unresolved group as a reason to enable
  descendants disabled by another owner.
- Define how repeated initialization composes baseline, nested and independently changed disabled reasons;
  resynchronization must not capture the library's own temporary disabling as a permanent baseline.
- Account for formset actions rendered through custom markup: hiding alone is not the D-07 disabled guarantee.
  Document required semantic hooks and preserve accessible labels and management inputs.
- D-09's trusted server-disabled preservation takes precedence over off-group clearing, including configured
  empty values. Client-side disabling is not trusted evidence of this server configuration.
- Establish field-aware defaults and explicit-value persistence semantics together. Cover FileField, Boolean,
  M2M and custom fields without assuming that `None` always means clear; preserve application/model validation.
- The existing source audit and passing historical suites are starting evidence, not proof that every finding
  still reproduces or that repairs pass. Reproduce against current source and use discriminating regressions,
  supported Django-version checks and real browser lifecycle/focus evidence appropriate to the changed contracts.
- If no usable controlling or ancestor toggle exists, the precise focus fallback remains a design detail to
  resolve consistently with the existing modal contract; do not invent a user-approved fallback here.

</decisions>

- `tests/js/toggle.test.js`, `tests/js/formset.test.js`, the `tests/test1/test_conditional_*.py` and

### Established Patterns

- Python validation/persistence owns authority; templates and JavaScript do not authorize writes. Resolve
  conditional presentation centrally so themes retain semantic hooks without copying server enforcement.
- Public events initialize injected content; the initializer should unify those paths and custom-root use rather
  than forcing themes to fabricate events or use undocumented constructors.
- Use existing Django system-check/configuration-error conventions, accessible control semantics and paired
  Breaking/migration documentation. Codebase maps are historical orientation, not current-source proof.

### Integration Points

- `src/crud_views/lib/formsets/render_tree.py` individually saves changed forms and nested rows; validation must
  enforce edit-only and existing-row identity before this save traversal can write anything.
- `src/crud_views/lib/formsets/formsets.py` and `src/crud_views/lib/formsets/mixins.py` connect declarations,
  fragment generation, authorized requests, management prefixes and save/validation order. A19 crosses initialized
  sibling indices and fragment generation; keep ancestry and request coordinates intact.
- `src/crud_views/templates/crud_views/conditional/toggle_group.html` and
  `src/crud_views/templates/crud_views/formsets/control.html` connect corrected identities and action capabilities
  to stock/custom template contracts.
- `src/crud_views/static/crud_views/js/modal.js` owns the existing replacement/focus lifecycle; automatic formset
  initialization and conditional visibility must compose with its loaded listeners and focus recovery.

<specifics>
## Specific Ideas

- Two rows each contain `active`; each group follows its intended row's toggle. Ambiguous copied markup produces
  a diagnostic without changing that group or preventing other groups from initializing.
- A user types text, switches the group off and back on, and sees the same unsaved text. Off at submission applies
  the server policy; a server-disabled field retains its existing value.
- Hiding a group containing the focused input returns focus to a usable controlling toggle. Hiding another group
  does not move focus. Inactive Add/Delete/Reorder controls cannot remain enabled solely because they are buttons.
- An active edit-only formset with a nonblank forged extra, or an existing row outside its authorized queryset,
  rejects the entire submission before saving the main form or any siblings.
- A theme inserts a group, then supplies its checkbox later and calls the documented initializer again. Binding
  succeeds without duplicate handlers; reinitializing already-bound content resynchronizes current state.

</specifics>
