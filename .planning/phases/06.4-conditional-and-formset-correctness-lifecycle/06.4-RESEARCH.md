### Theme compatibility and toggle binding

- **D-01:** Corrected toggle identity may require immediate migration of existing template overrides before 1.0.
  Establish an unambiguous contract and provide documented, tested migration examples. Do not make preserving
  all old markup or a temporary legacy compatibility layer a prerequisite for the repair.
- **D-02:** If outdated custom markup leaves multiple possible toggle matches, do not guess. Leave the affected
  group unchanged and report a diagnostic. Do not hide/disable it as a fallback or fail the whole form's
  initialization. Server-side conditional rules remain authoritative.
- **D-03:** Isolate ambiguous-binding handling to the affected group. Correctly bound groups, including those in
  other forms, continue working. This does not authorize bypassing a correctly bound ancestor's disabled state.

### Visibility, disabled controls and focus

- **D-04:** Use immediate native visibility for 1.0. No theme visibility/animation adapter is required in this phase;
  a compatible presentation hook can be considered later.
- **D-05:** When hiding a group would strand focus inside it, move focus to its controlling checkbox. If necessary,
  use a visible, enabled ancestor toggle. Leave focus elsewhere untouched. Preserve the accepted Phase 6.3 modal
  focus contract and avoid unnecessary focus movement on initialization or resynchronization.
- **D-06:** Preserve unsaved entries across off→on toggles before submission. Do not clear values merely because
  the client hides a group. Submitting with the group off still applies the server-side policy, including D-09.
- **D-07:** Disable action buttons inside inactive groups along with their data fields, including formset Add,
  Delete and Reorder controls. Restore them when active while preserving independent disabled reasons and all
  enclosing conditional states. Retain the existing management-input exception required for valid POST/re-render.

### Inactive field clearing

- **D-08:** Provide automatic field-aware clearing defaults for supported field types. Honor explicit
  `empty_values`; require explicit configuration for unsupported cases. Clearing a FileField reference must not
  imply deleting the stored file. Research must define and test the supported field/persistence matrix.
- **D-09:** Preserve fields explicitly disabled on the server even when their conditional group is off. Switching
  the group off must not change a field the application made non-editable. This is an exception to the general
  off-group clearing rule, not a grant of authority to client-side disabled attributes.
- **D-10:** If no supported automatic clearing value exists and no explicit value is supplied, raise a descriptive
  configuration error identifying the group and field. Report it at startup where detectable, otherwise before
  saving. Do not turn this programming/configuration problem into an end-user form validation error.

### Edit-only and dynamic rows

- **D-11:** A nonblank extra row submitted to an active edit-only formset rejects the whole submission with a
  formset validation error explaining that additions are not allowed. Save nothing; do not silently discard the
  extra row while saving other edits. This does not change the separately documented inactive aggregate purge policy.
- **D-12:** A submitted existing row with a missing ID or an ID outside the formset's authorized queryset rejects
  the whole submission with a generic invalid-row error and no saves. Do not reveal whether that ID belongs to
  another parent, ignore the row while saving others, or create a replacement row. Distinguish submitted existing
  rows from legitimate new rows in formsets that permit additions.
- **D-13:** Provide a documented, repeat-safe initializer for a supplied content root, usable by themes inserting
  content themselves or adding a toggle widget after its group. Library-managed page, modal and added-row
  lifecycle events invoke the same supported initialization behavior automatically. Its concrete name/signature
  is for research/design; no private controller constructor or wiring flag is the public integration contract.
- **D-14:** Repeated initialization resynchronizes current state: retry unresolved bindings and update visibility
  and disabled state without duplicate handlers, lost entries or unnecessary focus changes. Include supported root
  elements themselves as well as their descendants. Missing-toggle retries must not be blocked by marking failed
  initialization successful.

### 1. Bound identity, including formset wrappers

**Recommendation:** keep the existing marker attribute but change its documented value to the exact bound HTML name, emitted with form.add_prefix(toggle_field) (equivalently BoundField.html_name). Resolve by equality among checkbox controls owned by the nearest actual form; do not use suffix matching. Use name equality rather than concatenating unescaped CSS selectors. Explicitly support prefixed forms and identical field names in different forms. Duplicate exact names within one form are ambiguous and must not be guessed. An old unprefixed marker that cannot resolve is diagnostic/retryable, not grounds to hide. D-01 permits immediate migration. [CITED: 06.4-CONTEXT.md D-01–03,D-13–15; https://docs.djangoproject.com/en/4.2/ref/forms/api/#django.forms.BoundField.html_name]

The existing context is quoted as "cv_toggle_field", "cv_toggle_css", "cv_toggle_legend", "cv_toggle_inner"; the wrapper uses "cv-data-toggle-group" and "cv-data-toggle-field". The formset wrapper currently obtains its name from the declaration, so fixing only ToggleGroup.render is insufficient. [VERIFIED: src/crud_views/lib/conditional/layout.py:25-35; src/crud_views/templates/crud_views/conditional/toggle_group.html:3-10; src/crud_views/templates/crud_views/formsets/formsets.html:3-10; src/crud_views/lib/formsets/render_tree.py:195-198]

Keep unresolved bindings separate from successful bindings. An ambiguous group contributes no new conditional owner; it does not release a correctly bound ancestor's ownership. Store successful element-to-checkbox binding privately and retry missing/ambiguous bindings on explicit reinitialization. Repeated initialization must also refresh already-bound groups and newly inserted descendants. [CITED: 06.4-CONTEXT.md D-02–03,D-13–14]

### 2. Disabled ownership and reset

**Recommendation:** use one per-control ownership model, with an independently maintained baseline and the set of currently inactive ancestor groups. Compute effective disabling from both. Recompute the relevant owning form rather than writing the last changed group's Boolean across descendants. This avoids dependence on outer-first versus inner-first initialization. Native disabled fieldsets remain independent browser owners; do not rewrite them. Preserve input values on client hide. [CITED: 06.4-CONTEXT.md D-03–07,D-14–15]

Do not merely snapshot once and blindly restore forever. An application can disable a widget after initialization or while a group is off. Distinguish external disabled-attribute changes from the library's own writes, with observed mutations and explicit self-write suppression, or provide a small documented reason-owner API if observation cannot satisfy the tested cases. **Preferred plan:** prove the mutation-observer approach with a focused spike test before committing to its mechanics; drain pending mutations before synchronous resync and never recapture library-owned true as baseline. Test external true→false changes while active and while inactive, including assignment of true when already conditionally disabled. An undocumented assumption that widgets never change disabled state would violate D-14. This implementation choice is within the explicit planning discretion. [CITED: 06.4-CONTEXT.md Agent's Discretion and Planning Notes]

Include native buttons, selects, textareas and inputs. Keep management controls out of conditional ownership, but never forcibly enable management controls disabled by an independent owner. The existing management names are quoted as "TOTAL_FORMS", "INITIAL_FORMS", "MIN_NUM_FORMS", "MAX_NUM_FORMS". Do not disable an entire enclosing fieldset when it also contains management controls: inherited disabling cannot be undone on an individual management input. Require native button semantics for formset actions in custom templates, or explicitly implement and test equivalent keyboard/disabled semantics for a supported non-button hook. [VERIFIED: src/crud_views/static/crud_views/js/toggle.js:8-30] [CITED: https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#enabling-and-disabling-form-controls:-the-disabled-attribute; 06.4-CONTEXT.md D-07]

Use immediate native hidden/display behavior; no animations. When a hide actually strands current focus, try the group's usable checkbox then the nearest visible enabled ancestor checkbox. For the no-usable-toggle case, recommend a temporary programmatically focusable visible form container, staying inside the current modal when applicable; validate actual focus success and remove only attributes introduced by the helper. Never move focus merely because init/resync ran. This fallback is a research design recommendation, not a prior user choice. [CITED: 06.4-CONTEXT.md D-04–05 and discretion; src/crud_views/static/crud_views/js/modal.js focus helpers]

Observe native reset on each owning form, defer resync until after default reset completes, and check event.defaultPrevented at the deferred point. A later listener may cancel it. Do not reset another form, clear entries yourself, rewrite management totals, or detach/recreate rows as an unrequested reset policy. The standard dispatches cancelable reset before control resetting. [CITED: https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#resetting-a-form]

### 3. Public root initialization and formset scoping

**Recommended public additions (design, not existing API):** cv.initConditional(root = document) and cv.initFormsets(root = document). Each supports a Document, Element or DocumentFragment root; include root.matches(...) plus descendants. Page readyState startup, modal load, outer row-added, and direct theme calls must invoke these same entry points. Keep them independently loadable; no dependency of native conditional handling on jQuery. A root holding only a late checkbox should also cause unresolved groups in its owning form to be retried. [CITED: 06.4-CONTEXT.md D-13–15,D-18]

Use one controller per form, retained in a WeakMap, with idempotent namespaced listeners or delegated handlers. Scope row lookup, management input lookup, add insertion, reorder and submit to that form. Current lookup helpers start from global jQuery selections and the constructor installs handlers on every matching form, so a global "already started" flag alone cannot satisfy two independent forms or modal replacement. [VERIFIED: src/crud_views/static/crud_views/js/formset.js:52-55,127-130,172-182,278-281,473-489,609-615]

Resolve capabilities from the action's own formset before executing. Stock Add must not render when edit-only, and a custom Add control must not initiate an add for edit-only. Enforce inactive action blocking in the handler as well as native disabled markup so synthetic/custom activation cannot bypass the UI promise; server validation still owns write authority. [CITED: 06.4-CONTEXT.md D-07,D-11,D-18] Current stock Add has no edit-only predicate, while the page-wide control lookup supplies a universal non-edit-only capability. [VERIFIED: src/crud_views/templates/crud_views/formsets/control.html:18-22; src/crud_views/static/crud_views/js/formset.js:540-570]

Audit submit ordering against the existing modal listener. It builds FormData in a document submit listener and does not presently check a previous listener's defaultPrevented flag. The formset's submitted form must finish reorder before serialization; if reordering genuinely fails, a later modal handler must not continue the submission. Test the actual listener combination rather than either module in isolation. [VERIFIED: src/crud_views/static/crud_views/js/modal.js:165-177,227-234; src/crud_views/static/crud_views/js/formset.js:473-489]

Preserve public events exactly: "cv:modal:loaded", "cv:formset:row-added", detail "{prefix, rows}", one event per outer inserted row. Do not synthesize additional nested events. Initialize nested controls from the outer root and leave widget listeners their established event. Modal unload must allow observers/widget teardown while old nodes remain attached; loaded listeners run before replacement-focus recovery. [VERIFIED: src/crud_views/static/crud_views/js/toggle.js:57-65; src/crud_views/static/crud_views/js/formset.js:359-380; src/crud_views/static/crud_views/js/modal.js:90-105]

### 4. Supported clearing and persistence matrix

**Recommended initial support policy:** recognize standard Django form/model pairs and explicitly enumerate their clear semantics. Unknown/custom field classes or unusual persistence hooks require explicit empty_values; do not infer support from an arbitrary subclass's name. The entries below are proposed repair behavior under D-08–10, to be proved by persistence tests before documentation calls them supported. Django distinguishes optional form empty values by field type, and FileField persistence has a separate no-change sentinel. [CITED: https://docs.djangoproject.com/en/5.2/ref/forms/fields/; https://raw.githubusercontent.com/django/django/stable/6.0.x/django/db/models/fields/files.py]

| Field shape | Recommended automatic off value | Persistence/validation proof |
|---|---|---|
| Any field with server Field.disabled=True | Preserve its trusted cleaned/initial value; explicit empty_values does not override this | Tampered input and absent POST both preserve existing value, including file and relations |
| Nullable text-like model field | None, preserving existing nullable text semantics | Refresh DB; test omitted input with a model default |
| Non-null text-like model field permitting blank | Empty string | Refresh DB; no accidental default restoration |
| Plain Django CharField family | Its declared empty_value | Form clean contract; nullable model backing takes precedence above |
| Non-null BooleanField | False | Existing true becomes false; do not store NULL |
| Nullable Boolean / NullBoolean form field | None | Database null allowed; model clean still runs |
| Nullable number, date/time, duration, UUID, ordinary nullable FK | None | Refresh DB; FK uses normal model field save_form_data; app/model validators still authoritative |
| Non-null scalar/FK with no valid empty representation | Configuration error unless explicit value supplied | No save invocation; descriptive group + field message |
| Standard FileField / ImageField | False | Reference becomes empty; storage.delete never called; off upload discarded |
| Standard M2M / ModelMultipleChoiceField | Empty collection | After normal save/save_m2m, relation is empty; protect disabled relation |
| Plain MultipleChoiceField | Empty list | Cleaned result is empty; no model-persistence promise |
| Typed choices, MultiValueField, JSON/custom model fields or custom save_form_data | Require explicit empty_values initially | Prove actual declared pair before broadening automatic support |

D-08 does not require automatic defaults for every conceivable Django/custom field. The supported matrix should remain precise and extensible without claiming that all JSON null/empty-container semantics or custom relation managers are interchangeable. [CITED: 06.4-CONTEXT.md D-08,D-10]

**Explicit values:** treat dictionary membership, not truthiness, as the override test. Preserve supplied false/empty collection/empty string/null values. Document them as native form/model persistence values: in particular explicit FileField None remains Django's no-change instruction, while False clears the reference. Do not silently reinterpret an explicit value or delete a storage object. Clearly distinguish this intentional override from the automatic off default. Runtime programming errors must be descriptive configuration errors, not add_error calls that blame a user. ## Common Pitfalls

- **Green old tests hide missing cases.** Current focused suites pass despite the probes below; add tests that distinguish correct persisted values and true row-local behavior. [VERIFIED: session baseline commands]
- **Defaults defeat cleaned-data-only clearing.** Test omission, explicit empty payload, tampered payload and existing/default values independently. [CITED: Django construct_instance source above]
- **Server-disabled exception implemented too late.** Preserve the field before suppression/clearing and before explicit overrides. [CITED: D-09]
- **Local InlineFormSet guard leaves other declarations unprotected.** The allowed superclass is broader. [VERIFIED: src/crud_views/lib/formsets/formsets.py:60,88-89]
- **Changing event counts to initialize nested rows breaks widgets.** Keep one outer event and recurse inside the initializer. [VERIFIED: src/crud_views/static/crud_views/js/formset.js:359-380]
- **Repeated startup rebinds every form or captures temporary disabling.** Track actual owners/controllers; test modal open→422→close→open and two same-prefix forms. [CITED: D-13–15]
- **A canceled reset still resynchronizes.** Recheck cancellation after dispatch/default-action timing. [CITED: WHATWG reset algorithm above]
- **UI-only add blocking is not edit-only enforcement.** Real POST must fail before any save. [CITED: D-11,D-18]
- **Cleanup steals focus from the modal owner.** Conditional focus recovery runs only for a genuine newly hidden active descendant; modal replacement remains owned by modal.js. [CITED: D-05,D-19]
- **Rewriting skip/purge or commit=False while nearby.** Preserve aggregate policy; A8 remains outside scope. [CITED: D-18; Deferred Ideas]
