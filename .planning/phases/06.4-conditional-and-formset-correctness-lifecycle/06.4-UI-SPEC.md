## Interaction and Visibility Contract

### Exact binding and root lifecycle

Use `cv-data-toggle-group` and `cv-data-toggle-field` with the exact bound checkbox HTML name, including the
form/row prefix. Match by name equality among controls belonging to the group's actual form, including explicit
HTML form ownership; never suffix matching or raw-name interpolation into CSS selectors. Preserve
`cv_toggle_field`, `cv_toggle_css`, `cv_toggle_legend` and `cv_toggle_inner`; the field's meaning is now bound.
Top-level conditional formsets project the main form's bound name. Old copied templates require the plan 09
migration; no legacy guessing layer is promised (D-01–D-03).

Missing bindings remain retryable. Multiple exact matches leave that group's own state unchanged and produce
the local diagnostic. Other groups/forms continue; unresolved groups cannot release a bound ancestor's disabled
ownership. Corrected markup plus reinitialization can recover without duplicate handlers.

The supported APIs selected in plans 01/06 are `cv.initConditional(root = document)` and
`cv.initFormsets(root = document)`. Accept Document, Element and DocumentFragment roots; include matching roots
and descendants, and find the owning form from a row/control/late-checkbox root. Repeated calls retry unresolved
groups, refresh current states and newly inserted content, preserve entries and avoid duplicate listeners.
There is one scoped formset controller per actual form, even when two forms use identical prefixes.

Page readiness, late script load, `cv:modal:loaded` and `cv:formset:row-added` invoke the same supported behavior.
Retain jQuery and its diagnostic/retry path. Controller constructors, WeakMaps, observer state, wiring flags and
`cv.formsetController` are not the public theme integration API (D-13–D-15, D-18).

### Visibility, disabled state, values and reset

| State/change | Required result |
|--------------|-----------------|
| Bound group active | Show through immediate native visibility; only remove that group's own conditional disabled reason |
| Bound group inactive | Hide immediately; disable descendant inputs/selects/textareas/native action buttons through composed ownership |
| Nested groups | Effective disabled state is independent baseline OR any inactive bound ancestor, in either nesting order |
| Independently disabled widget | Preserve externally changed disabled state, including a same-value true write while conditionally disabled and later false writes |
| Off then on before submit | Preserve unsaved field values and file selections; client hiding does not clear data |
| Management fields | Exclude TOTAL_FORMS, INITIAL_FORMS, MIN_NUM_FORMS and MAX_NUM_FORMS from conditional disabling; never force-enable an independent disable |
| Native reset allowed | After the native default reset, resynchronize only the owning form in a queued task; defaults, visibility and disabled state agree |
| Native reset cancelled | Including a later listener's cancellation, leave values and presentation untouched |

Do not disable an entire enclosing fieldset to implement group state: it would disable management inputs through
inheritance. Existing native disabled fieldsets remain independent owners. Reset does not remove/recreate dynamic
rows or rewrite management totals; it does not replace Cancel navigation (D-04, D-06–D-07, D-14–D-15).

### Focus and keyboard

When a transition actually hides the focused descendant, try the visible enabled controlling checkbox, then
the nearest usable ancestor checkbox. Plan 05 already specifies the remaining fallback: the visible owning
form with temporary `tabindex=-1`, inside its active modal where applicable. Check successful focus and reject
disconnected, hidden, inert, aria-hidden, disabled or aria-disabled targets/ancestors. Remove only the temporary
attribute introduced by the helper on blur. This is the plan's concrete D-05 design detail, not a new claim of
explicit user approval.

Leave focus outside the hidden group unchanged; initialization/resynchronization alone must not steal focus.
A hidden modal shell receives no premature focus. Preserve the accepted Phase 06.3 ownership: adapter handles
initial show; unloaded listeners run while old content is attached; loaded listeners run before destroyed-node
replacement recovery; usable listener-assigned dialog focus survives; otherwise the existing invalid-field,
dismiss-control, shell fallback applies. Completed hide restores the current opener through the existing
`onHidden` contract and fallback chain; stale responses/callbacks remain guarded (D-05, D-19).

Keep native checkbox labels, Space/Tab operation, keyboard activation of native row/reset controls and existing
focus indicators. Supported custom row controls remain native `button type="button"` with accessible names,
existing action classes and bound row-prefix hooks. Disabled/inactive controls must also be rejected by action
handlers, including synthetic activation. No extra live region or focus trap is introduced.

### Row capabilities, submission and persistence

Stock edit-only formsets omit Add; custom Add activation also respects the owning formset's edit-only flag.
Delete/Move controls retain their own can_delete/can_order capabilities and existing row marking/reorder behavior.
All actions, management lookups, inserted rows and event targets remain scoped to the actual owning form, using
exact dynamic prefix/name equality. Preserve supported lowercase/hyphenated declaration keys and integer/UUID
coordinates; this repair does not broaden key or PK grammar (D-07, D-11, D-15–D-18).

Finish reorder before the modal submit listener serializes FormData. A prevented or failed reorder/submit must
not fetch. On invalid submission, render the existing formset nonform-error location before its rows. Reject
nonblank edit-only extras, including deleted/nested-only extras, and missing/malformed/unauthorized existing IDs
before any main, sibling or nested save. Preserve normal existing edits, untouched blank extras and legitimate
new rows when allowed. A client control's visibility/disabled state grants no write authority (D-11–D-12, D-18).

Off-group submission uses plans 02/03's supported field-aware clearing matrix and explicit native empty_values;
the client does not perform persistence clearing. Trusted server-disabled fields retain their values before
suppression or overrides. File/ImageField reference clearing does not delete stored files; explicit None retains
Django's no-change meaning while False clears the reference. ImageField evidence is reference-only; uploaded
image-byte decoding is not claimed. Preserve inherited form/model/uniqueness invariants, default inactive
formset skip, opt-in managed-queryset aggregate purge and existing authorization/atomic boundaries (D-08–D-10,
D-15, D-18). This document does not expand the supported persistence matrix beyond plans 02/03.

### Dynamic rows and template projection

Preserve request coordinates `template`, `pk`, `num`, `formset_parent_prefix_key`; responses remain `{html, rows}`.
Use the selected declaration's sibling index for non-first/deeper child fragments without weakening ancestry
checks. Raw full/rows-only fragments must have balanced wrappers before browser repair. Management totals and
rendered prefixes must bind the intended rows through POST and database refresh (D-16–D-17).

Dispatch one bubbling `cv:formset:row-added` per outer inserted row with detail `{prefix, rows}`; initialize nested
descendants from that root without additional nested events or duplicate widget setup. Preserve existing modal
unload cleanup and initialize new 422 content once. No success is inferred from a substring-only fragment test.

Document the existing projection in plan 09: title/key/prefix, management form, nonform errors, rows, form/helper,
nested formsets and capabilities; retain existing JSON keys and their distinct formset-versus-row PK meaning.
Consuming template data does not make XForm/XFormSet constructors or save methods public. Pair every Breaking
entry with migration guidance and hand exact supported names to Phase 7 (D-17, D-19).
