# Phase 06.40 Plan 04: Protected Tenant and Customer example Summary

**An independent navbar example uses strict Tenant Guardian grants, model-level Customer CRUD permissions, and two Customer detail destinations with stable identity and active sections.**

## Accomplishments

- Added owned Tenant and Customer models with explicit ordering, translated names and Customer notes. Business models are not imported from another example. Local forms and tables follow existing examples without extra module layers.
- Registered `navbar_tenant` and `navbar_customer`; the parent edge explicitly maps `attribute="tenant"`. Tenant list/detail use strict Guardian object grants. Customer views use existing protected core compositions and cascading ancestor authorization. Object views attach one shared `NavbarMixin`; Customer list/create do not.
- Details and Notes are separate GET views of the same Customer. Tests exercise the lazy context and real navbar tag, asserting identical owner/link PKs and distinct active labels. Notes renders the stored text. Noncolliding Tenant/Customer PKs prevent accidental identity substitution from passing.
- Published `/object-navbar/` and `navbar-demo-home`. Its authenticated entry redirects to the filtered Tenant list, without accepting a selected Tenant shortcut. All declared links resolve through the project URLconf. Shared base-template placement, explanatory landing page, feature registration and expanded hierarchy remain plan 05's explicit work.
- Proved actual cross-Tenant reads/writes return 403 despite model permissions; mismatched authorized-parent/foreign-Customer reads return 404. Both Customer operation permissions and Tenant change grants are required for writes. Create/update ignore injected parent fields, bind to the authorized Tenant and need no Customer object grants. Successful create/update/delete and anonymous-entry redirects are covered.
- Generated the app-local initial migration using the supported example environment. It has no external business dependencies, matches current models, and applies/reverses/reapplies in an isolated in-memory database.
