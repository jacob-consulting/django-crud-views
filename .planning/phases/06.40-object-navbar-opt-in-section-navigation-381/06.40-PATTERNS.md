## Shared Patterns

### Owner identity, routes and errors

`src/crud_views/lib/ancestors.py:576-585`:

```python
def _resolved_ancestor(view: CrudView, name: str) -> Model | None:
    """The ancestor of ViewSet ``name`` resolved by a successful guard on this request, or None (no guard state,
    or ``name`` is not in the view's ancestry). Lets request helpers reuse the resolved identity."""
    state = getattr(view, "_cv_ancestor_state", None)
    if state is None:
        return None
    for (_, ancestor), obj in zip(_walk_ancestors(view.cv_viewset), state.objects, strict=True):
        if ancestor.name == name:
            return obj
    return None
```

Use page object on owner pages and this request state on descendants; no new ancestor fetch. `_walk_ancestors` (89-121) supplies bounded nearest-first metadata and configuration errors. Determine the direct child below the owner using that path, irrespective of intermediate mixins.

`src/crud_views/lib/viewset/__init__.py:372-388` shows literal registration membership, but get_view_class/get_router_name transparently substitute card for missing list. Check explicit keys literally **before** calling those helpers. For omitted child key only, select list then card by membership. Use declared parent kwargs (`get_parent_url_args`, 295-303), owner PK and Django reverse; never descendant current PK or URL slicing. Reached configuration failures propagate during rendering.
