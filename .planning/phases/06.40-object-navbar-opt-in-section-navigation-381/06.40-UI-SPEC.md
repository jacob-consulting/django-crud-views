# Phase 06.40 — UI Design Contract

## Scope and Decision Sources

Implement the opt-in object navbar using the existing Bootstrap theme. This contract adds no UI implementation.
The authority is `06.40-CONTEXT.md` D-01–D-16 and `06.40-ISSUE-381.md` acceptance criteria 1–9.
`06.40-RESEARCH.md` supplies source-grounded implementation guidance. ROADMAP lists requirements as TBD;
use the issue's acceptance numbers for traceability rather than inventing requirement IDs.

Locked: layout B, plain owner identity, unchanged view header/actions, ordinary full-page links, wrapping,
per-view attachment, permission/state filtering, active-section rules, no-output states, three override levels,
the dedicated tenant/customer example, and the documented surface's stability at 1.0.
Issue A-01–A-07 remain proposals. Specific markup, template context names, spacing choices and example copy below
are design defaults or recommendations for planning, not additional maintainer approvals.
The planner may refine these proposals with a recorded reason while preserving all locked behavior.

Preserve existing context buttons and byte-identical nonparticipating pages. Do not introduce a navigation library,
new layout/location setting, global menu, dropdown, badge/count, nested menu, animation or JavaScript tab behavior.
Retain A-05's proposed zero-new-class-key approach: templates are the styling seam. No schema/API changes are made
by this document. Maintainability and the established theme/stability policy apply.

## Spacing Scale

Use existing Bootstrap rem utilities at the example's default 16px root. These are phase usage values, not a new
token registry. Preserve inherited responsive container/card gutters.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px / .25rem | Icon-to-label gap; space between adjacent/wrapped link boxes (`gap-1`) |
| sm | 8px / .5rem | Identity-to-items gap; link vertical padding |
| md | 16px / 1rem | Link horizontal padding; navbar-to-existing-card gap |
| lg | 24px / 1.5rem | Existing section/container spacing only |
| 2xl | 48px / 3rem | Existing major section spacing only; unused inside navbar |

No new 32px/64px utilities are required. All declared values are multiples of four.
With 24px text line-height and 8px vertical padding, ordinary links have 40px minimum height; retain at least
24px target width for short labels. Icons never create independent touch targets. No fixed navbar height.
An absent navbar contributes no margins, empty wrapper or gap. Existing border widths are not spacing tokens.

## Typography

Three nominal sizes and two weights, inherited from Bootstrap. The navbar itself uses 16px text.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / section link | 16px / 1rem | 400 | 1.5 |
| Owner identity | 16px / 1rem | 500 | 1.5 |
| Supporting example copy | 14px / .875rem | 400 | 1.5 |
| Existing page heading | 28px / 1.75rem nominal | 500 | 1.2 |

The existing page heading uses `cv_heading`, level 1, size 3. Preserve its Bootstrap responsive sizing and theme
overrides; do not force 28px at every viewport or change its semantic level. Owner identity is ordinary text,
not a second H1. Labels remain visible beside optional decorative icons, including on small screens.
Existing typography elsewhere on the page is outside this contract.

## Color

Use inherited Bootstrap variables/utilities. The 60/30/10 split describes visual emphasis within the existing
page, not a demand to recolor it or cover exactly ten percent in blue.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff`, existing body/card surface | Page and navbar background |
| Secondary (30%) | Existing neutral surfaces; card header uses translucent black over white, approximately `#f7f7f7` | Existing cards and boundaries; no additional filled navbar panel |
| Accent (up to 10%) | Existing primary `#0d6efd`, hover `#0a58ca` | Section-link text, selected pill fill, existing primary action |
| Text | Existing body `#212529`; active pill text `#ffffff` | Identity, prose and selected link |
| Destructive | Existing danger `#dc3545` | Existing destructive actions only; navbar adds no destructive action |

Accent reserved for section-link text, selected-section background, keyboard focus treatment and existing primary
page actions. Do not color the identity as another primary action. Active state combines a filled shape and an
accessible current marker; color alone is insufficient. Preserve visible keyboard focus, normal-text contrast of
at least 4.5:1 and identifiable focus/selected boundaries in actual theme rendering.

Default values are grounded in [Bootstrap 5.3.3 variables](https://raw.githubusercontent.com/twbs/bootstrap/v5.3.3/scss/_variables.scss);
consumer themes retain their own palette.

## Layout and Interaction

Default example order: existing example information, breadcrumb, navbar identity, navbar items, existing page card
with its original heading/icon/actions/content. Insert the opt-in tag in an example-owned block immediately before
the card; nothing about navbar use requires moving or retitling that card's header.

Identity shows the owner ViewSet header icon and `str(owner)` as plain text. Never infer a caption link from the
first visible item. Escape caption and label text, including a model caption returned as a safe-string value.
Missing/suppressed icons leave readable text without an empty icon placeholder. Use the existing icon renderer
and honor its element/host conventions; decorative icon output must not replace or duplicate the accessible name.

Items appear in declaration order after admission. An owner item selects its exact registered object view;
a child item selects its configured GET-capable no-child-object destination. Omitted child keys use list then
card only when list is unregistered. Never substitute another destination because the selected one is denied.
Owner labels use the destination's short action label; child labels/icons use its ViewSet plural name/header icon.
Explicit item overrides win, including intentional empty-icon suppression. Keep labels visible rather than
introducing an icon-only mode.

Use a `<nav>` landmark labelled with translated `Sections for %(object)s`, substituting the escaped owner caption,
and a list of ordinary anchors. Link order equals visual, reading and Tab order. Enter follows the normal URL;
browser open-in-new-tab behavior works. Do not add tablist/tab/tabpanel roles, roving tabindex, aria-selected,
Bootstrap tab toggles, AJAX, intercepted navigation or unsaved-change warnings.

Keep the active link clickable. Highlight a matching visible owner view key on owner pages; highlight the visible
direct-child section on all of that child's descendant pages. If the matching item is hidden or absent, no item
is active; do not select the first visible item. Set `aria-current="true"` on the single active link and omit it
elsewhere. This proposed refinement to A-05 avoids claiming that an Orders collection link is the current page
while viewing an Item. It preserves D-12 and needs no extra public context field.
[Bootstrap's static navigation guidance](https://getbootstrap.com/docs/5.3/components/navs-tabs/#base-nav)
allows a current-item marker independently of dynamic-tab semantics.

Wrap links naturally at every viewport using flex wrapping; do not introduce a narrow-screen menu, carousel,
scrolling strip, clipping or ellipsis. Use natural-height items with `max-width: 100%` and allow flex children to
shrink (`min-width: 0` where needed). Both captions and link labels must wrap, including an unbroken long token
using `overflow-wrap: anywhere` or an equivalent scoped rule. Preserve full accessible and visible text.
Put any necessary rules in existing stylesheet delivery, not inline script/style or a new class registry.
The nav occupies its parent's width; ordinary links retain natural widths and do not expand into equal columns.

## Template Override Contract — Concrete Proposal for Planning

D-08 locks global wrapper/partial overrides, split placement and `NavBar(template=...)`; D-16 makes the final
documented template contract stable at 1.0. The following exact context shape is proposed, not yet implemented.
The planner may rename fields before implementation if it updates plans, tests and reference/stability docs
consistently. Do not expose builder/resolver classes as public API merely to support templates.

| Template expression | Proposed meaning |
|---------------------|------------------|
| `cv_navbar` | One shared lazy result for the participating view/request; absent or None on nonparticipants/modals; evaluates to None if no visible items |
| `cv_navbar.object` | Resolved owner object, identical for all placements on this request |
| `cv_navbar.label` | Plain owner caption derived from `str(owner)` |
| `cv_navbar.icon` | Owner ViewSet header icon value consumed through the existing renderer, or no icon |
| `cv_navbar.items` | Ordered visible-item sequence, already admitted and resolved; templates never filter permissions |
| `item.label` | Plain visible label |
| `item.icon` | Resolved/overridden icon value or no icon |
| `item.url` | Complete registered destination URL preserving owner and higher ancestor PKs |
| `item.active` | Boolean active-section result; at most one true |

The wrapper and both partials receive the same named `cv_navbar` value. Each independently guards on that value
before emitting any HTML or spacing, so direct partial inclusion is safe on empty/nonparticipating/modal pages.
The items partial owns the nav landmark and computes its translated accessible name from `cv_navbar.label`;
it must not depend on a neighbouring identity node or generated DOM ID. This keeps split placement independent.

Global customization overrides the theme-selected `tags/navbar.html`, `tags/navbar_identity.html` or
`tags/navbar_items.html` path. Default core paths start with `crud_views/`. Split placement includes the identity
and items templates directly in the project's base template using its existing context. The default wrapper is
then omitted. A per-bar `template=` affects the wrapper used by `{% cv_navbar %}`; its custom wrapper receives
the same context and may reuse the partials. Direct split includes intentionally choose their own templates.

First actual template use performs one build; later tag/partial accesses reuse its result. Context creation,
an omitted navbar tag/partials, and every modal response perform zero navbar builder/permission calls.
Rendering tag plus split partials is not the layout example: use one placement strategy to avoid duplicate UI.
Test repeated access for shared-result correctness without advertising repeated bars as a supported layout.

Document layout A only as a project wrapper override arranging identity and items on one wrapping row. Ship only
layout B. Template authors retain responsibility for accessible naming, text wrapping and guarded empty output.
The stable public inventory must name the final tag, templates and documented context fields explicitly.

## Copywriting Contract

Navbar items are destination labels, not action buttons. Do not add a primary CTA to the bar merely to satisfy a
generic template. Existing page CRUD actions remain in their original header and retain their behavior.

| Element | Copy / behavior |
|---------|-----------------|
| Primary example-entry CTA | `Explore object navigation` on the dedicated landing page; opens the example's existing customer navigation entry flow |
| Customer navbar labels | `Details`, `Notes`, `Orders`, `Addresses`, in that order; use explicit overrides where short-label defaults differ |
| Owner identity | Exact plain `str(customer)`; seed example caption such as `Acme Coffee` is illustrative, not a reserved name |
| Navbar accessible name | Translate `Sections for %(object)s` with current owner caption |
| Empty navbar heading | No copy and no HTML; hide identity and items when every item is denied/state-disabled |
| Empty navbar body | No placeholder, explanation or retry link |
| Empty Orders collection | Preserve the existing collection's empty-state rendering and available Create action; keep the Orders link visible; no count or badge |
| Example explanation for empty Orders | `This customer has no orders yet. Orders stays available because you can open the section.` |
| Example explanation for Charlie | `Charlie can read customers, orders and items in Alice's tenant. Addresses and write actions are unavailable.` |
| Notes without text | Reuse the existing detail-view empty-value treatment; do not hide the Notes section |
| Navbar error state | No inline error/retry UI; configuration errors propagate through existing diagnostics; destination failures use existing request error responses |
| Example explanation of denied navigation | `A visible section link does not guarantee access. The destination checks its permissions when you open it.` |
| Documentation link | `Object navbar reference` |
| Reciprocal live-example link | `Try the object navbar example` |
| Destructive confirmation | None added; section links never perform a write or deletion; existing delete pages keep their confirmation flow |

New library-owned accessible text is translatable. Example descriptions use existing translation conventions.
No custom 403 screen is required. A copied URL or higher-ancestor denial must not redirect users to an unrelated
tenant or silently replace the selected section with another page.

## Dedicated Example and Acceptance Evidence

Use one self-contained example app with Tenant → Customer → (Order → Item, Address). Keep shared login, styling
and index infrastructure. Add discoverable Charlie login instructions alongside Alice/Bob in the example's own
intro or shared account help; no permission-management interface is introduced. Do not import another example's
business models or require cross-app scenario navigation.

| Scenario | Required observable result |
|----------|----------------------------|
| Alice and Bob in their own tenants | Customer bar contains Details, Notes, Orders and Addresses; existing CRUD actions reflect their full business-model access |
| Charlie on Alice's Customer | Details, Notes and Orders visible; Addresses absent; direct Address and write requests denied |
| Customer Details / Notes | Same Customer caption and tenant-aware URLs; only corresponding owner item active; Notes displays the Customer text field |
| Order / Item pages | Same Customer identity/URLs; Orders active and clickable even if an intermediate view omits the mixin |
| Accessible empty Orders | Link stays visible and GET succeeds; collection uses existing empty rendering |
| Unlisted owner view | No active item unless that owner key was explicitly declared; header/action behavior unchanged |
| Cross-tenant copied descendant URL | Destination rejects unauthorized tenant access independently of navigation visibility |
| No attached bar, all items hidden, or modal | No navbar markup; no additional work for nonparticipants or modals; all-hidden case performs admission once |
| Global, split and per-bar overrides | Render intended placement and caption/items; split partials share exactly one build |

Browser evidence must cover desktop (1280px), a narrow 320px viewport and a 200% zoom/reflow check using the live
example. Inspect both normal four-link copy and stress content: a caption of at least 120 characters, an unbroken
80-character token, and a long multiword item label. Assert document scroll width does not exceed client width
(allow 1px rounding), visible link boxes remain within the content width, all text is reachable, and no items are
hidden to satisfy width. Capture a wrapped state, selected section, keyboard focus and header placement.

Use Tab/Shift+Tab and Enter to verify all visible links, including the active one; captions/icons are not separate
focus stops. Confirm nav naming, one current marker or none as appropriate, absence of tab roles, and actual
destination URLs. Include a markup-bearing caption/label render test and missing-icon case. HTML snapshots alone
cannot establish wrapping or no horizontal scrolling.

Map rendered/override tests to acceptance 1/2/7, permission/no-output tests to 3/4/5, configuration diagnostics to 6,
browser evidence to 8, and dedicated example plus reciprocal `Feature.docs`/`DocRef` links to 9.
Measure builder/hook counts separately from SQL; do not label an unmeasured navbar query-free.
