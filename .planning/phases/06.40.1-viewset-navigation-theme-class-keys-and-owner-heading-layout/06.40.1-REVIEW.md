## Warnings

### WR-01: The link-spacing recipe lacks a layout that applies its gap

**Classification:** WARNING
**File:** `/home/alex/projects/alex/django-crud-views/docs/reference/theme.md:862`
**Related:** `/home/alex/projects/alex/django-crud-views/docs/reference/navbar.md:277-278`; `/home/alex/projects/alex/django-crud-views/tests/test1/test_theme_adoption_docs.py:55-77`; `/home/alex/projects/alex/django-crud-views/src/crud_views/templates/crud_views/tags/navbar_items.html:3`
**Issue:** The copyable registration promises link spacing but registers `nav-link mw-100 text-break gap-2`. Stock Bootstrap's `.nav-link` is `display: block`; none of the other listed classes makes the anchor a flex/grid container. The parent `ul.nav` being flex does not make the anchor's icon and caption flex children. Consequently, `gap-2` adds no icon-to-caption spacing when this recipe is copied into the stock Bootstrap theme. The existing executable documentation assertion checks only the emitted class string and therefore passes despite the ineffective utility. This is confirmed by [Bootstrap 5.3.3's nav source](https://github.com/twbs/bootstrap/blob/v5.3.3/scss/_nav.scss#L21-L23) and its [gap utility documentation](https://getbootstrap.com/docs/5.3/utilities/spacing/#gap).
**Fix:** Make the example self-contained by including an appropriate display/layout utility, for example `nav-link d-flex flex-wrap align-items-center mw-100 text-break gap-2`, and update the executable recipe expectation. Alternatively, explicitly document and demonstrate the consumer CSS prerequisite instead of promising that the current string supplies link spacing. Preserve full caption wrapping and ordinary link semantics when choosing the layout.
