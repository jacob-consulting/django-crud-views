## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1:** `docs/reference/navbar.md:298` retains the obsolete no-new-keys sentence immediately after the per-bar recipe. Readers comparing it with the new registration guidance receive conflicting instructions. Fix as priority 2.
- **WARNING C2:** `docs/reference/theme.md:1222` gives the pre-phase totals. The new six defaults in `src/crud_views/lib/button_classes.py:100` and executable inventory in `tests/test1/test_theme_adoption_docs.py:48` establish the new inventory. Fix as priority 3.
- **PASS:** `navbar_items.html:1` retains translated “Sections for …” naming, and line 3 retains visible item labels. `docs/reference/navbar.md:266` explicitly describes fallback, retained actions and equal-title behavior. No new generic CTA, destructive action or form/error copy is introduced.

### Pillar 2: Visuals (4/4)

- **PASS:** Phase-base diff shows only class lookup substitutions in the three leaves; wrapper, identity, landmark, list and anchors are retained. `docs/reference/navbar.md:245` and `:253` explicitly establish owner h1 followed by view h2, with the title, actions and paragraph preserved below navigation.
- **PASS:** Icons accompany text rather than replacing labels; `tests/test1/test_navbar_docs.py:88` checks the decorative icon, and `:120` checks actual breadcrumb/title/navigation/action order. There is no evidence of a new unlabeled icon control or broken source hierarchy.
- **Limit:** Visual balance, focus visibility and mobile overflow were not observed. This passing score applies to preserved structure and explicit hierarchy only.

### Pillar 3: Color (4/4)

- **PASS:** The six entries at `src/crud_views/lib/button_classes.py:100` introduce zero literal color values and zero new primary-color utility occurrences. The single active-class slot is conditional in `navbar_items.html:3`; `aria-current` is separately conditional and survives empty styling.
- **PASS:** Defaults exactly preserve the former `nav-pills`/`active` presentation; the optional documentation switches to `nav-tabs` without introducing a palette. No new accent overuse is evidenced by this delta.
- **Limit:** A 60/30/10 page-wide color distribution and rendered contrast cannot be measured from these class substitutions. Neither is claimed to have been verified.

### Pillar 4: Typography (4/4)

- **PASS:** One explicit navbar weight utility, `fw-medium`, and zero explicit font-size utilities appear in the six defaults. The owner recipe uses two semantic heading levels with a single h1 fallback (`docs/reference/navbar.md:245`, `:253`, `:266`). There are no new arbitrary font-size values or expanded weight scale.
- **PASS:** Guidance at `docs/reference/navbar.md:272` correctly assigns content-heading coordination to the theme rather than suggesting that global header settings infer navigation presence. `tests/test1/test_navbar_docs.py:36` covers both default and configured header levels.
- **Limit:** Actual typeface, line-height and rendered size relationships remain consumer-CSS concerns, unobserved here.

### Pillar 5: Spacing (3/4)

- **WARNING S1:** `docs/reference/theme.md:862` adds `gap-2` to a link with no flex/grid display utility, while `:868` describes selecting spacing. The leaf (`navbar_items.html:3`) also supplies no display context. Gap alone does not guarantee icon/text spacing on a conventional block link. A consumer theme may supply the necessary display rule, but this prerequisite is not stated. This is a source-derived recipe caveat, not a captured visual failure; fix as priority 1.
- **Evidence limitation:** `tests/test1/test_theme_adoption_docs.py:55` asserts exact class strings and semantics, so its passing result cannot establish actual spacing.
- **PASS:** The stock six-key spacing vocabulary is unchanged: `mb-3`, `mb-2`, `gap-1`; the owner recipe adds standard `gap-2` on an explicitly flex container and retains `mb-3`. No arbitrary pixel/rem spacing is introduced. Stock `flex-wrap`, `mw-100` and `text-break` remain present, and the recipe calls for narrow-width validation at `docs/reference/navbar.md:277`.

### Pillar 6: Experience Design (4/4)

- **PASS:** `navbar_items.html:3` retains ordinary clickable hrefs and independent current-state semantics, including when classes are replaced/cleared. `tests/test1/test_navbar_templates.py:120` and `:131` cover full/component/include resolution, project precedence, empty/null values and hostile class strings.
- **PASS:** All three leaves independently guard absence. `tests/test1/test_navbar_docs.py:39` covers present/missing/unconfigured/hidden/modal states while preserving actions and content; `:98` checks inherited blocks and equal titles; `:120` verifies real action links and order. No asynchronous interaction or destructive control is added, so new loading/error/confirmation UI is not warranted by this change.
- **Limit:** These are source/DOM findings and previously recorded test results. Keyboard operation and post-interaction appearance were not freshly captured.
