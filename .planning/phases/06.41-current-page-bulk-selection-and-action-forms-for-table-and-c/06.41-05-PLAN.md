Destination behavior already implemented by plans 01 and 02 (read the module first):

- `_read_ids(post, field)` normalizes each submitted value through the primary-key field's `to_python`, keeps
  string transport, deduplicates in order and raises `BadRequest` for malformed or overlapping IDs.
- `_selection_queryset()` raises `ImproperlyConfigured` when the ViewSet queryset or `get_queryset()` is not an
  unsliced `QuerySet` of the ViewSet model on the default database, applies `_scope_child_queryset` and returns
  the intersection.
- `_review_selection(candidates, excluded)` raises `ImproperlyConfigured` when `cv_get_db_alias()` is not the
  default alias or an object's state database or write route is not the default; it lists every submitted ID as
  eligible or blocked.

ASVS level 1; block on high severity.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Submitted IDs to scoped queryset | any ID can be named; only the intersection of ViewSet, destination and parent scope may resolve |
| Review page to user | the page must not confirm that a record outside the user's scope exists |
| Request routing to database alias | a router may send reads or writes to an alias the feature does not support |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.41-14 | Elevation of Privilege | nested and tenant-scoped destinations with a broader `get_queryset()` | critical | mitigate | Task 02 tests that `_selection_queryset` keeps `ViewSet.get_queryset(view)` and `_scope_child_queryset` as mandatory bounds; a broader destination queryset cannot widen them. |
