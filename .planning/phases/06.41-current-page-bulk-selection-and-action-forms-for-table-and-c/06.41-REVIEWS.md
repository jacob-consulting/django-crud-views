## 06.41-01

Tracer is the right cut: one table path through the form leaf, real dispatch, scoped resolution, and the origin return. Names and the no-JS `formaction` choice match the leaves that exist today.

**Strengths**
- `ListViewTableMixin.get_table_kwargs` returns `{"view": self}` and does not call `super()` (`src/crud_views/lib/views/mixins.py:302-303`), so "mixin first" is a real constraint, not folklore.
- The form leaf already emits `type`, `name`, `value`, and `{{ cv_flat_attrs }}` (`src/crud_views/templates/crud_views/tags/button/form.html:2-3`). `formaction` needs no leaf change. D-29 is implementable.
- `cv_permission = None` is rejected by `CheckAttribute` (`src/crud_views/lib/check.py:79-81`), so the ungated-twin ban is enforced by an existing check.
- `_cv_ancestor_operation` is the real family marker (`src/crud_views/lib/ancestors.py:244-249`). Custom-form views are not in the family table, so the write marker is required.
- Count-before-parse, NUL-before-`to_python`, and `OverflowError`/`DataError` only around queryset evaluation are the right order for T-06.41-04. The simulated `DataError` branch is an honest residual.

**Concerns**
- MEDIUM: Pattern 1 says `render_to_string` returns safe markup and the toolbar prints `{{ button }}`. `render_to_string` returns a plain `str` (`src/crud_views/lib/crispy/buttons.py:201` uses it only inside crispy, which marks layout HTML safe). `{{ button }}` will escape `<button` unless the property returns `mark_safe`. The flow test will fail until that is explicit. Safe to mark safe only because the leaf already escapes `cv_label`.
- MEDIUM: `get_form_kwargs` must call `super()` and then drop `data`/`files`. `CrispyViewMixin.get_form_kwargs` is what injects `cv_view` (`src/crud_views/lib/crispy/form.py:180-184`). Replacing the method drops it and every crispy button breaks.
- LOW: Hidden `cv_bulk_blocked_ids` are specified without `|unlocalize`, while eligible IDs use it. If `item.pk` is an int and thousand separators are on, the execute POST will 400. Store the normalized transport string, or unlocalize both.

**Suggestions**
- State `mark_safe` on each rendered button, and `super().get_form_kwargs()` before popping `data`/`files`.
- Pin blocked-id transport as the same string `_read_ids` produced.

**Risk: MEDIUM.** The path is proven in outline; the two rendering/form-kwargs traps are easy to miss and the acceptance tests will catch them only after a red run.

## 06.41-02

Confirmation outcomes, the cancel-only form, and the in-transaction check are the right completion of the tracer. `get_form_actions` already drops a `None` submit (`src/crud_views/lib/crispy/form.py:57-60`), so D-28 needs no new tag. `Contract` is a real `PROTECT` child (`tests/test1/app/models.py:84-85`).

**Strengths**

- `django_db(transaction=True)` for `in_atomic_block` is correct. The default fixture already holds a transaction, so the flag would always be true.
- Escaping is decided on response text, not lxml. That matches how lxml reparents nested forms. `cv_alert` escapes heading/items in `alert_data` and renders the body in the caller context (`src/crud_views/templatetags/crud_views.py:488-501`).

**Concerns**
- HIGH: The hook-order test compares the bulk destination with a plain custom form and expects one sequence. Those sequences cannot match. Stock `post` checks, hooks, validates, then `cv_form_valid_process` checks again and only then opens `cv_get_atomic()` (`src/crud_views/lib/views/mixins.py:42-64`). - LOW: `cv_atomic = False` still calls `transaction.on_commit` inside `nullcontext()` (`src/crud_views/lib/view/base.py:381-390`). On Django 4.2 and 6.1 that runs the callback immediately in autocommit, so it is not a 500. Worth one sentence so nobody "fixes" it into a raise.

**Suggestions**
- Pin the bulk sequence on its own. Assert only that it contains the stock hook names and that `_review_selection` runs inside `cv_get_atomic()` before `cv_form_valid`. Do not require identical order with `CustomFormNoObjectView`.
- Use `django_capture_on_commit_callbacks(execute=True)` for the on-commit assertion.

**Risk: MEDIUM.** Behavior coverage is strong. The hook-order acceptance criterion contradicts D-06 and the mixin it cites.
