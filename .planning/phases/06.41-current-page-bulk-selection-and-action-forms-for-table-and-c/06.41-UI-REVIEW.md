## Top 3 Priority Fixes

1. **Increase unchecked checkbox contrast (C1)** — Selection affordances are hard to locate on white cards. Add a darker theme border through the existing `bulk:checkbox` and `bulk:card-select` class entries, then inspect checked, unchecked, focus and disabled states.
2. **Enlarge selection hit targets (S1)** — Small row/card boxes demand precise pointing. Provide a padded associated label or enlarge the checkbox through the existing class entries; preserve top-left placement, accessible names and independent card actions. Verify keyboard focus and touch selection at 375 px.
3. **Use native-link cancellation in the example/theme where JavaScript-off navigation matters (E1)** — The visible Cancel button otherwise does nothing without JavaScript. The existing `form:cancel-tag: "a"` option supplies a bounded solution without a bulk-specific leaf or lifecycle changes. This is an opt-in improvement to an accepted limitation, not a requirement to change package defaults.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING W1:** `examples/bootstrap5/bulk_selection/views.py:69`, `:90` and `:122` interpolate a count into fixed plural sentences. Processing one document produces “1 documents deleted”, “1 documents archived”, or “Owner assigned to 1 documents.” Use translated singular/plural templates for the example messages and refresh the synchronized documentation excerpts/catalog entries. Code-derived; retained browser scenarios use two records and therefore do not expose this.
- The core copy is substantially sound: explicit Archive/Assign owner labels, counted blocked/eligible groups, actionable empty/limit warnings (`src/crud_views/lib/bulk/__init__.py:347`), and a changed-selection instruction (`:379`). `snippets/bulk/blocked.html:2` already pluralizes correctly. Generic Confirm and Cancel are approved shared-form wording, not deviations to fix.

### Pillar 2: Visuals (3/4)

- **WARNING V1:** The retained `06.41-13-card.png` renders only document names in all six cards. The example card configuration (`examples/bootstrap5/bulk_selection/views.py:38`) uses the stock title-only card (`src/crud_views/templates/crud_views/tags/card.html:6`, empty `card_content` at `:7`). Users cannot see which document is locked, already archived or assigned before selecting Archive/Assign owner. Add concise status, lock and owner text in an example-specific card-content override. Do not add source permission queries or hide configured actions; D-03 deliberately defers authoritative checks to the destination.
- Retained mixed-review captures show the intended hierarchy: action title, warning with reasons, eligible count and plain names, then form actions. Checkbox accessible names exist for both sources (`view_card.content.html:9`, `columns/bulk_select.html:1`); the shared form leaf supplies hidden text in icon mode (`tags/button/form.html:3`). No record links, collapse control or danger-button variant is recommended: these were explicitly excluded or deferred.

### Pillar 3: Color (2/4)

- **WARNING C1:** Unchecked card boxes in `06.41-13-card.png` are barely distinguished from the white card/background; selected blue boxes and their focus halo are much clearer. Both new checkbox class defaults rely on Bootstrap's unmodified `form-check-input` (`src/crud_views/lib/button_classes.py:110`, `:113`). Improve the unchecked border with a theme token/class shared by these two entries. This is a visual-observation finding, not a claimed measured contrast ratio or formal accessibility conformance result.
- No hardcoded hex/RGB colors occur in the bulk templates or script. Bulk actions reuse one `form:submit` primary class entry (`button_classes.py:69`), intentionally per D-29. The retained card image has two filled action buttons, two checked boxes and one filled current-page indicator; neutral surfaces dominate. The warning uses the shared warning alert and text/icon, so it does not communicate the blocked state by color alone. No exact 60/30/10 pixel distribution is asserted from these captures.

### Pillar 4: Typography (3/4)

- **WARNING T1:** `src/crud_views/templates/crud_views/snippets/bulk/eligible.html:2` hardcodes `<h3>` instead of the package's existing `cv_heading` renderer. The stock card already uses that renderer (`tags/card.html:6`), and heading size keys exist in `button_classes.py:19`. Consequently a theme's heading-size mapping does not reach “To process”. Use `{% cv_heading level=3 %}` with the same translated content; no new typography abstraction is needed.
- No explicit font-size or font-weight utilities are introduced by the bulk templates. The inspected review uses body text, a stronger alert heading and larger action/count headings; no excess size/weight palette was found. The demo's inherited monospace appearance is not a new phase defect. Theme-customized typography and zoom are not visually verified.

### Pillar 5: Spacing (3/4)

- **WARNING S1:** Individual selectors are bare inputs with an `aria-label` but no associated visible/padded label (`view_card.content.html:9`, `columns/bulk_select.html:1`). The retained screenshot shows approximately 16 px checkbox squares, and the card selector is positioned across the card corner by `translate-middle` (`button_classes.py:113`). Plan-13 center hit-testing proves that the controls are not covered; it does not prove a generous pointer/touch target. Enlarge the hit area without making the entire card intercept its own actions. This is a usability finding, not a formal minimum-target compliance determination.
- **WARNING S2:** The selection/count row uses `d-flex align-items-center gap-3 mb-2` without wrapping (`button_classes.py:108`), whereas the action row explicitly has `flex-wrap` (`:111`). Long translated labels or larger text can squeeze the count. Add `flex-wrap` to the existing controls class and inspect narrow/zoomed output. This risk is code-derived, not observed overflow: no relevant mobile/tablet screenshot is available.
- The seven bulk class entries use existing Bootstrap spacing: `mb-3`, `gap-3`, `mb-2`, `mb-0`, `gap-2`; blocked list markup uses `mb-0 mt-2`. No arbitrary pixel/rem spacing was introduced. The retained desktop layout has consistent card gutters and separation between the two toolbar rows.

### Pillar 6: Experience Design (3/4)

- **WARNING E1 — accepted limitation:** `button_classes.py:92` defaults `form:cancel-tag` to `button`; `tags/button/form.html:3` carries the cancellation URL as a data attribute. Without JavaScript this visible Cancel control does not navigate. `docs/reference/bulk_actions.md:249` expressly documents the limitation, and plan 13 excludes Cancel from its JavaScript-off acceptance flow. Prefer the existing native-link theme/example option where this mode matters (`docs/reference/buttons.md:764`). This review did not independently click Cancel; the finding is code-derived. Navigation remains available through the surrounding page/browser, so this is not classified as a newly discovered task-completion blocker.
- State coverage is otherwise strong: zero-selected disabled actions, select-page indeterminate state, empty-page select-all disabling, and browser-history refresh are in `bulk.js:21–44`; the count has `aria-live="polite"` (`bulk_toolbar.html:12`). JavaScript reveals enhancements only after setup; native submission remains available without it.
- Review errors retain selection, newly blocked candidates require another confirmation, and all-blocked reviews use a cancel-only form (`lib/bulk/__init__.py:337`, `:371`, `:379`). Deletion reviews before execution; immediate Archive is an approved application choice. Server-rendered navigation supplies the loading mechanism; an SPA skeleton/error-boundary framework is not warranted for this bounded Django flow.
- The retained runner/JSON record all six planned browser groups passing, including native action submission with JavaScript off, required-owner errors, preserved origin ordering/page, and corrected Enter handling. This review does not report those interactions as newly captured or independently rerun.
