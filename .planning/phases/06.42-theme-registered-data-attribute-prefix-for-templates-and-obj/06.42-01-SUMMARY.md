# Phase 06.42 Plan 01: Native component data-prefix registration Summary

**Themes can register one validated native attribute prefix, read by four real component paths while preserving every default markup byte.**

## Accomplishments

- Added `crud_views.lib.register_data_prefix(prefix: str) -> None`, explicitly re-exported from the stdlib-only `data_prefix` module. Private `_data_prefix` defaults to `bs`; internal `get_data_prefix() -> str` reads it. Invalid types and strings raise `ValueError` before assignment; valid calls use last-call-wins semantics.
- Added argument-free `cv_data_prefix() -> str` in the existing tag library. Actions menu, language dropdown, vertical tabs and accordion groups read it at render time, including separate inclusion/group contexts.
- Added `isolate_data_prefix` fixture, `render_data_prefix_component` helper and seven named `_RAW_DEFAULT_COMPONENTS` captures. Captures are inline, revision-provenanced and frozen; no generator, normalization or snapshot framework was added.
- Source guard retains its allowlist and nonempty gate while recognizing static `data-bs-` and exact dynamic `data-{% cv_data_prefix %}-` syntax. Both allowed and forbidden synthetic trees are exercised.
