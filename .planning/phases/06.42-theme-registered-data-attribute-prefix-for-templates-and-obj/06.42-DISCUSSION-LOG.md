## Default-page compatibility

**Question:** Which interpretation should planning use for byte-identical default pages versus adding a
prefix attribute to `#cv-config`?

| Option | Description | Selected |
|--------|-------------|----------|
| 1. Always emit the prefix (recommended) | Emit the attribute for both bs and coreui. Preserve component markup and behavior, with this single exception to byte-identical page output. | Yes |
| 2. Emit only nondefault prefixes | Omit the attribute for bs and rely on the JavaScript fallback, preserving exact default page output. | No |

**User's choice:** `1`

**Outcome:** D-06 in CONTEXT.md records unconditional attribute emission, including bs. This is the sole
exception to the blanket byte-identical page requirement. Missing-config/attribute fallback remains intact.
The agent recommended option 1 because it gives the simplest explicit template contract.
