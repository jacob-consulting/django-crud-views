# Issue #393: Breadcrumb class keys and accessible sort state in the stock table header (U9/U10)

Source: https://github.com/jacob-consulting/django-crud-views/issues/393
Captured: 2026-11-21
GitHub updatedAt: 2026-11-21T08:26:19Z

**Date:** 2026-11-21
**Status:** design approved by the maintainer on 2026-11-21; issue handover, not implementation authorization.
**Scope:** CoreUI theme upstream findings U9 (the breadcrumb has no class key) and U10 (the stock table header has
no `aria-sort`). This document does not schedule a phase or authorize product implementation.

## Problem / motivation

**U9.** `crud_views/templates/crud_views/tags/breadcrumb.html` hard-codes `ol.breadcrumb`, `li.breadcrumb-item` and
`active`; the class registry has no `breadcrumb:*` key. A theme that places the breadcrumb in a header row (CoreUI's
layout does) needs `breadcrumb my-0` and today works around it with a CSS rule cancelling `.breadcrumb`'s bottom
margin. #384 solved the same problem for the navbar with class keys.

**U10.** In `crud_views/templates/crud_views/table/bootstrap5.html`, block `table.thead`, a sortable `<th>` shows the
`table-sort-asc` / `table-sort-desc` icon but carries no `aria-sort`, so assistive technology does not learn which
column is sorted or in which direction. Downstream CoreUI and Tabler themes each copy the whole `table.thead` block
to add one identical attribute (a block cannot add an attribute to upstream's `<th>`), and keep drift tests on the
copies.

The icon condition also has a bug: it compares `request.GET.sort` with the column name, which hard-codes the
parameter name `sort`. A table with a `prefix` (parameter `<prefix>sort`) never shows its sort icon.

Goal: themes drop the breadcrumb CSS workaround and both `table.thead` copies; the stock header becomes accessible
and the prefix bug goes. Developer maintainability is a hard constraint: template and registry work only, through
existing mechanisms; no new API, setting or rendering path.

## Proposed solution

Three breadcrumb class keys in the existing registry with unchanged defaults, and a sort state in the stock header
taken from django-tables2's bound column (`column.is_ordered`, `column.order_by_alias.is_descending`) for both the
icon and a new `aria-sort` attribute. The approved contract is recorded in `gsd-handover` below.

## Alternatives considered

1. **Class keys plus sort state from the bound column — selected by the maintainer.** Reuses the registry and the
   stock template; matches the attribute both downstream themes already render, so their copies can be deleted.
2. **Keep the icon on the URL parameter (fixed for the prefix) and derive `aria-sort` from it too — not selected.**
   No visible change, but a table with a default ordering (`Meta.order_by`) would report itself unsorted to
   assistive technology while it is sorted.
3. **Finer template blocks for themes to override — not selected.** Themes would still copy markup that drifts.
4. **Compute `aria-sort` in Python through the table's `th` attrs — not selected.** More indirection than one
   template attribute, and harder to trace.

## gsd-handover

Carry these approved decisions and the acceptance criteria into GSD planning. Filing this issue does not create a
phase, schedule work, or authorize implementation.

### D-01 — Bounded scope: U9 + U10

Breadcrumb class keys and the table header sort state, nothing more. Out of scope: the breadcrumb `nav` element's
untranslated `aria-label="breadcrumb"`, breadcrumb item content and links, the card list's sorting UI, pagination,
the `--bs-*` CSS properties (U5), and any new setting or API.

### D-02 — Breadcrumb class keys (U9)

Three ordinary keys in `crud_views/lib/button_classes.py`. Names and defaults were proposed by the assistant and
approved with the design.

| Key | Default | Element |
|---|---|---|
| `breadcrumb:list` | `breadcrumb` | `<ol>` |
| `breadcrumb:item` | `breadcrumb-item` | every `<li>` |
| `breadcrumb:item-active` | `active` | added to the last (current-page) `<li>` only |

- No `breadcrumb:nav` key: nothing needs it, and an empty default would need empty-`class` handling.
- Follow existing registry precedence (defaults < `register_button_classes()` < `CRUD_VIEWS_BUTTON_CLASSES`) and
  empty-value behaviour, as for the navbar keys of #384. Keep no hard-coded copies of these classes in the template.
- `aria-current="page"` on the last item stays independent of styling.
- With default keys the rendered breadcrumb is byte-identical to today.

### D-03 — Header sort state (U10)

In block `table.thead` of `table/bootstrap5.html`, for orderable columns only:

- `aria-sort` on the `<th>`: `ascending` / `descending` when `column.is_ordered` (direction from
  `column.order_by_alias.is_descending`), else `none`. This is exactly the attribute both downstream themes render.
- The sort icons use the same condition instead of `request.GET.sort`, so icon and `aria-sort` always agree and
  tables with a `prefix` show their icon.
- Non-orderable columns are unchanged: no `aria-sort`, no icon.

Visible change (accepted): a table ordered by default (`Meta.order_by`, or an `order_by` passed to the table) now
shows its sort icon on first load without `?sort=`. Not breaking; record it under CHANGELOG `### Changed`.

### D-04 — Acceptance and documentation

- Breadcrumb: existing breadcrumb output and goldens unchanged; tests that each key is overridable through theme
  registration and project settings and lands on the right element (`item-active` on the last item only).
- Table header: tests for a URL-sorted table (ascending and descending), a default-ordered table without `?sort=`,
  a table with a `prefix`, an unsorted orderable column (`none`) and a non-orderable column (no attribute, no icon),
  each checking icon and `aria-sort` together.
- Docs: list the three keys in `docs/reference/buttons.md` / `docs/reference/theme.md` next to the navbar keys and
  mention them in `docs/reference/breadcrumb.md`; state in the table docs that the sort icon and `aria-sort` follow
  the table's effective ordering. CHANGELOG: `### Added` (breadcrumb keys, `aria-sort`), `### Changed` (icon on
  default ordering), `### Fixed` (icon on prefixed tables). Not breaking, so `docs/migrating-1.0.md` is untouched.
- Downstream note, not upstream work: once released, the CoreUI theme can drop its `.header-breadcrumb .breadcrumb`
  rule (setting `breadcrumb:list` to `breadcrumb my-0` instead), and the CoreUI and Tabler themes can delete their
  copied `table.thead` blocks.
