### Concerns
- **HIGH — `aria-sort` cannot be a `render_attrs` keyword.** `render_attrs` is a `simple_tag`. Django 4.2 `parse_bits` accepts keyword arguments only through `token_kwargs`, whose key pattern is `\w+`. `aria-sort="ascending"` is not a keyword; it is an unparsable positional bit. The only working call in this template is `{% render_attrs table.attrs class="table" %}` (`bootstrap5.html:8`) because `class` is a word character. Upstream `render_attrs` does start with kwargs and then `update(attrs)`, so a caller value would win and a duplicate would be avoided — but that Python behavior is unreachable from the template for a hyphenated name. The plan also forbids appending a literal attribute after `as_html`, which is the D-01-compatible way to emit the attribute. Following the plan either fails template compilation or adds a helper D-01 forbids.
- **LOW — Header class assertions must tolerate serializer-injected classes.** `BoundColumn.attrs` already folds `orderable`, and `asc`/`desc` when ordered, into `th` class before `as_html`. Exact equality with only the caller class will fail even though ordinary attrs are preserved. Quote escaping is `format_html_join` in `AttributeDict.as_html`, not something the plan needs to reimplement.

### Suggestions
For orderable columns only, keep `{{ column.attrs.th.as_html }}` and add one literal `aria-sort` whose value is `ascending`, `descending`, or `none` from the same `is_ordered` / `is_descending` branches as the icon. Leave non-orderable columns on the current `as_html` path. Document that a caller-supplied `aria-sort` can duplicate and is unsupported; do not add a filter or claim the icon matches that caller value. Assert custom class/data tokens are present alongside existing `orderable`/`asc`/`desc` classes. Append release notes to the existing Unreleased Added/Changed/Fixed sections.
