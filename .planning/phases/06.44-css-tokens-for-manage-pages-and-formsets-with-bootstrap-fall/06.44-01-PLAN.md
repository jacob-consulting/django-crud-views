## Browser contract

The new runner contains one small synthetic fixture exercising every affected selector, with a light document and a nested `data-bs-theme="dark"` section. No new Django application/server is required. Use real Chromium and the existing exported `preflight()` from `manage-presentation.cjs`; use `runtime()` from `cancel-navigation.cjs` with the same cache candidates as the manage runner. Load the SRI-validated Bootstrap 5.3.3 bytes, followed by upstream CSS; prohibit network fetches. Keep the original and changed documents isolated and otherwise identical. Original rows have the original class lists; changed rows use the class strings read from the current template/helper, without editing baseline CSS. Match exactly one expected class-string source and fail if extraction is empty or ambiguous. Existing Python tests separately prove actual emitted markup.

Measure twelve consumers per section: manage th color, default td color, outlined help foreground; card border color/radius/background; compact row radius/background; bordered compact row border color; child background/border color/radius. Measure both row gutters, alignment, child left/right padding, row margins and representative row/column bounding boxes. Keep 16px root text and deterministic content. At narrow width, explicitly assert hidden headings and compare computed spacing; at wide width assert visible headings and nonzero row/column boxes. Require dark backgrounds to differ from light before accepting parity. Assert all twelve property records and both row records are present in every stock case; a zero-match query is an error.

`--case all` requires exactly eight unique passed case IDs: `stock-light-1280`, `stock-dark-1280`, `stock-light-390`, `stock-dark-390`, `cv-precedence`, `legacy-bs`, `literal-fallback`, `theme-root-mapping`. The first four compare all properties and geometry before/after. `cv-precedence` sets distinct valid values for all six cv tokens with conflicting Bootstrap values and checks every consumer, including actual help foreground. `legacy-bs` sets element-scoped Bootstrap properties with no cv tokens and compares baseline/current for all consumers. `literal-fallback` omits Bootstrap and cv declarations and asserts all twelve consuming values against the six approved literals; for help, add only fixture glue `color: var(--bs-btn-color)` to make its preserved component-variable bridge observable without Bootstrap. `theme-root-mapping` maps all six synthetic library variables at outer and nested theme roots and verifies independent nested values plus a root-only control that retains outer values. Both modes are exercised in the latter cases where inheritance applies.

`--case manage` is the tracer selection: the same first four stock IDs and `cv-precedence`, checking the three manage consumers; it must report exactly five cases and identify its narrower scope. It cannot satisfy final phase acceptance. Implement the full runner in Task 1; Task 2 enables its full acceptance after formset changes.

Every report includes status, expected/actual case count, each actual/expected measurement, baseline revision/bytes/hashes, current four-source hashes, runner hash, Bootstrap hash, browser version/runtime paths and timestamps. `validateEvidence` checks the exact ID set, unique IDs, passed status, required measurements, hash equality to currently tested files, and nonempty observations before success. Exit nonzero for missing cases, failed assertions or unavailable infrastructure; write failure evidence and close Chromium in `finally`. Do not build an evidence framework or claim synthetic fixture coverage for downstream theme integration.
