Help buttons use `btn btn-sm btn-outline-secondary` plus the stock data attribute. Do not extract class strings from Python/template source: existing Django rendering tests prove the actual emitted classes, while this fixture measures their CSS effects.

The selection determines its measurements. In `manage`, measure exactly three consumers per section: manage th color, default td color and actual outlined-help foreground; no formset or grid records are required. In `all`, measure those three plus card border color/radius/background, compact row radius/background, bordered compact row border color and child background/border color/radius (twelve total). Also measure both row gutters, alignment, child left/right padding, row margins and representative row/column bounding boxes. Fix root text to 16px and use deterministic content. At 390px assert headings hidden; at 1280px assert visible headings and nonzero boxes. Zero-match selectors fail. In both selections require a measured light/dark difference before accepting baseline parity (manage text; full formset backgrounds).

Both selections run four stock IDs: `stock-light-1280`, `stock-dark-1280`, `stock-light-390`, `stock-dark-390`. Each compares its selection's measurements before/after. Both also run `theme-root-mapping`: map all six cv tokens through synthetic library variables on outer and nested theme roots, using distinct valid values conflicting with Bootstrap. Assert selection-appropriate consumer values and a root-only control retaining the outer value. This combines token precedence and nested mapping proof in one case. The full selection additionally runs `literal-fallback`: omit Bootstrap and cv declarations and assert all twelve consumer values; for help add only fixture glue `color: var(--bs-btn-color)`. Compare independently expected computed equivalents, not literal CSS spellings: #6c757d → rgb(108, 117, 125), #495057 → rgb(73, 80, 87), #fff → rgb(255, 255, 255), #dee2e6 → rgb(222, 226, 230), .375rem → 6px at the fixed root, #f8f9fa → rgb(248, 249, 250). Apply the same computed-value normalization to synthetic override expectations.

Thus `manage` requires five cases with three consumers per stock case; `all` requires six with twelve consumers and two row records per stock case.
