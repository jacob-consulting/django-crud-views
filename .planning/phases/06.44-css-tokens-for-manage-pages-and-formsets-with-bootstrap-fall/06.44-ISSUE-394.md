# Issue #394: CSS tokens (`--cv-*`) for the manage page and formsets, with Bootstrap fallbacks (U5)

Source: https://github.com/jacob-consulting/django-crud-views/issues/394
Captured: 2026-11-21

**Date:** 2026-11-21
**Status:** design approved by the maintainer on 2026-11-21; issue handover, not implementation authorization.
**Scope:** CoreUI theme upstream finding U5 (upstream CSS reads `--bs-*` custom properties). The same gap in
django-crud-views-extensions (U12, typeahead skins) is a separate issue in that repository and follows this one.
This document does not schedule a phase or authorize product implementation.

## Problem / motivation

`crud_views/static/crud_views/css/manage.css` and `formset.css` read six Bootstrap custom properties (12
`var(--bs-…)` references, each with a hard-coded fallback) and set two Bootstrap component variables:

| Property | Read in |
|---|---|
| `--bs-secondary-color` | `formset.css` (row card border), `manage.css` (dimmed default cells) |
| `--bs-secondary-text-emphasis` | `manage.css` (table headers, help button colour) |
| `--bs-body-bg` | `formset.css` (row card, compact row) |
| `--bs-border-color` | `formset.css` (bordered compact row, compact child) |
| `--bs-border-radius` | `formset.css` (row card, compact row, compact child) |
| `--bs-tertiary-bg` | `formset.css` (compact child) |

| Set | Where |
|---|---|
| `--bs-btn-color` | `manage.css`, `[data-cv-manage] [data-cv-manage-help].btn-outline-secondary` (contrast fix) |
| `--bs-gutter-x: 1rem` | `formset.css`, `.cv-formset-compact-fields, .cv-formset-compact-headings` |

A Bootstrap fork that renamed its properties (CoreUI defines `--cui-*`) leaves the read properties undefined: the
manage page and formsets fall back to the light hard-coded values and do not follow dark mode. Its components never
read the two set variables. None of this is documented; a downstream theme today finds the list by reading
upstream's CSS and re-defines the `--bs-*` names itself.

That re-definition has to be scoped to upstream's own elements (`[data-cv-manage]`, `.cv-formset-row-card`,
`.cv-formset-row-compact`, `.cv-formset-compact-child`): a custom property that references another is resolved
where it is declared, so a mapping on `:root` alone would freeze at the page's colour mode and ignore a nested
dark-mode section. The scoping works but couples the theme to upstream's selector list — a new upstream rule breaks
it silently — and re-defining Bootstrap's names can leak into other Bootstrap-aware CSS.

Goal: a documented, crud_views-owned set of CSS tokens that a theme maps once on its own theme roots, without
knowing upstream selectors. Stock Bootstrap rendering is unchanged. Developer maintainability is a hard constraint:
CSS and documentation work only, no new Python API or setting.

## Proposed solution

Upstream reads six `--cv-*` tokens through a fallback chain to the Bootstrap property and the current hard-coded
value; it never declares the tokens itself. The compact-row gutter moves to Bootstrap's `gx-3` class; the
help-button contrast fix stays a Bootstrap-specific rule and is documented. The approved contract is recorded in
`gsd-handover` below.

## Alternatives considered

1. **Own `--cv-*` tokens with Bootstrap fallbacks — selected by the maintainer.** One documented contract, mapped
   once by a theme on its theme roots; no coupling to upstream selectors; no re-definition of Bootstrap names.
2. **Document the `--bs-*` names as the contract — not selected.** No CSS change, but themes keep re-defining
   Bootstrap's names scoped to upstream's selectors, so every new upstream rule can break them.
3. **Upstream declares the tokens on `:root` (`--cv-x: var(--bs-x)`) — rejected.** The value would resolve once at
   `:root`, breaking Bootstrap's own nested `data-bs-theme` sections that work today.

## gsd-handover

Carry these approved decisions and the acceptance criteria into GSD planning. Filing this issue does not create a
phase, schedule work, or authorize implementation.

### D-01 — Bounded scope: U5

The six read properties, the gutter, and documentation of the help-button rule, in `manage.css` and `formset.css`.
Out of scope: django-crud-views-extensions (U12, separate issue using the same token names), new tokens beyond these
six, other CSS files, class-key changes, Python changes.

### D-02 — Token names and fallback chains

Names mirror Bootstrap's, so a theme's mapping is a 1:1 rename. Proposed by the assistant and approved with the
design.

| Token | Every use reads |
|---|---|
| `--cv-secondary-color` | `var(--cv-secondary-color, var(--bs-secondary-color, #6c757d))` |
| `--cv-secondary-text-emphasis` | `var(--cv-secondary-text-emphasis, var(--bs-secondary-text-emphasis, #495057))` |
| `--cv-body-bg` | `var(--cv-body-bg, var(--bs-body-bg, #fff))` |
| `--cv-border-color` | `var(--cv-border-color, var(--bs-border-color, #dee2e6))` |
| `--cv-border-radius` | `var(--cv-border-radius, var(--bs-border-radius, .375rem))` |
| `--cv-tertiary-bg` | `var(--cv-tertiary-bg, var(--bs-tertiary-bg, #f8f9fa))` |

- Upstream only reads the tokens and never declares them (see alternative 3).
- Fallback values stay exactly today's.
- A theme that still re-defines the `--bs-*` names on upstream's elements keeps working through the fallback, so
  existing themes need no change and can switch when convenient. Not breaking.

### D-03 — Component variables upstream sets

- **Gutter:** drop the `--bs-gutter-x: 1rem` rule. Add Bootstrap's `gx-3` class (the same 1rem) to the two rows:
  `crud_views/templates/crud_views/formsets/compact_headings.html` and the crispy `Row(...)` in
  `crud_views/lib/formsets/compact.py` (`css_class`). Keep `cv-formset-compact-fields` /
  `cv-formset-compact-headings` on those elements. Existing tests that match the class attribute's ending may need
  the class order considered.
- **Help button:** the `--bs-btn-color` contrast fix stays as is — a rule bound to Bootstrap's
  `.btn-outline-secondary`, active only with the stock `manage:help` class — but reads
  `--cv-secondary-text-emphasis` through its chain. A token cannot cover it, because every library names its button
  variables differently. Document that a theme either keeps the stock class and hands the value to its own button
  variable, or sets its own `manage:help` class.

### D-04 — Acceptance and documentation

- A test parses `manage.css` and `formset.css` and fails on any `var(--bs-…)` that is not the fallback inside one
  of the six `--cv-*` chains, on any declaration of a `--cv-*` token, and on any `--cv-*` token missing from the
  docs table. The only `--bs-*` declaration allowed is the help button's `--bs-btn-color`.
- Stock rendering is unchanged (computed styles in light mode and in a `data-bs-theme="dark"` section; formset and
  manage page tests and goldens pass, apart from the added `gx-3` class).
- Docs: a "CSS tokens" section in `docs/reference/theme.md` with the token table, a mapping example on a theme's
  roots (`:root, [data-<lib>-theme] { --cv-body-bg: var(--<lib>-body-bg); … }`), why mapping on `:root` alone
  freezes the value in nested colour-mode sections, and the help-button note. Link it from
  `docs/reference/formsets.md` (CSS classes table) and the manage page docs. CHANGELOG `### Added` (tokens) and
  `### Changed` (`gx-3` on compact rows). Not breaking, so `docs/migrating-1.0.md` is untouched.
- Downstream note, not upstream work: once released, the CoreUI theme can replace its element-scoped `--bs-*` block
  and its gutter hand-over with one token mapping on its theme roots, and drop its upstream-CSS parsing test in favour
  of the documented list; the Tabler theme can do the same for its two re-mapped properties.

Formatting of the CSS chains, the parser used by the test, and placement of the docs links.
