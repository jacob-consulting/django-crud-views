## Detailed Findings

### Pillar 1: Copywriting (4/4)

Positive finding: `docs/reference/theme.md:44` provides exactly six token/fallback pairs; lines 73–98 explain computed-before-inheritance behavior, nested colour modes, legacy mappings, the help-button bridge and the standard Bootstrap spacing-scale limitation. This is useful actionable copy for the actual audience, theme developers. `src/crud_views/templates/crud_views/formsets/control.html:8` and lines 12, 20, 27 retain specific translated accessible names (“Move up”, “Move down”, “Add row”, “Delete row”). No new generic CTA or error string is introduced. Fixture-only “Save” and synthetic validation messages are not new package-copy defects.

### Pillar 2: Visuals (3/4)

**WARNING V1, existing limitation:** The inspected core-normal-390.png has extensive vertical expansion for adversarial long permission-holder identifiers. `src/crud_views/static/crud_views/css/manage.css:43` constrains holder columns to 120–192px while wrapping anywhere. This prevents text escape but makes the permission section dominate the mobile page. The receipt records document width 390px, so this finding is about scanning effort, not a claim of whole-page horizontal overflow. The relevant selector is unchanged from the immutable baseline.

Positive findings: nested compact panels are visibly distinguished from parent rows; invalid field and formset feedback remain prominent in invalid-390.png. Icon-only row controls have aria-label/title pairs in `control.html:8`. The new tokens do not change hierarchy or selectors.

### Pillar 3: Color (4/4)

Positive finding: three reads in `manage.css:75`, 102 and 106 and nine reads in `formset.css:53`, 54, 55, 75, 76, 80, 131, 132 and 133 use the exact approved chains. No upstream --cv declaration is introduced. The sole Bootstrap declaration remains the scoped help-button --bs-btn-color at `manage.css:102`.

The complete retained `evidence/css-tokens.json` contains six passing cases: stock light/dark at 1280/390, theme-root mapping, and literal fallback. All twelve computed consumer values match the pinned original source in each stock case; mappings override conflicting Bootstrap values and root-only mappings provide a negative control. White/neutral surfaces dominate the inspected light captures with restrained action/status accents. A numeric 60/30/10 area distribution was not measured and is not a requirement of this compatibility change.

Existing literal animation colours (`formset.css:1`) and the group badge (`manage.css:133`) remain outside the six-token scope. Their presence is not grounds to demand additional tokens contrary to D-01.

### Pillar 4: Typography (3/4)

**WARNING T1, existing limitation:** The dense cupping-score headings in saved-1280.png split “Sweetness” across lines. `compact_headings.html:3` uses caller-defined Bootstrap spans and `formset.css:98` allows wrapping anywhere. This preserves content but impairs quick column scanning. Adjust the consuming layout's span/label choices for this case; do not change the approved token patch to suppress wrapping globally.

The scoped sheets use four explicit size spellings (14px, 16px, 1rem and .95rem; 16px and 1rem coincide under the stock root) and two weights, 400/600. `manage.css:2`, 55, 70 and 79 establish the hierarchy; `formset.css:63` and 68 style legends. No typography declaration changed in this phase. The wrapping issue is not a new gx-3 regression.

### Pillar 5: Spacing (4/4)

Positive finding: `compact_headings.html:1` and `compact.py:175` both emit gx-3 and retain component hooks. `formset.css:90` preserves flex-start alignment. The retained stock comparisons record 1rem gutters, 8px column side padding, matching margins and row/column boxes at both widths and colour modes. The 390px capture preserves nested insets and stacked labels; the desktop capture retains shared headings.

Spacing is predominantly .25/.5/1/1.25rem in formsets and 8px increments in manage controls. Existing 1px heading margins are border compensation, not newly introduced arbitrary spacing. The responsive rules remain at 767.98/768px (`formset.css:153`, 164). Their exact transition was source-reviewed, not newly captured.

### Pillar 6: Experience Design (4/4)

Positive finding: the production diff changes only CSS reads and constant row classes, preserving existing task paths. The retained compact receipt has one passing lifecycle case with 19 assertions; its invalid capture visibly contains field, row, formset and hidden-field feedback. The saved desktop capture retains nested values. Retained automated assertions cover dynamic lifecycle/persistence and state handling; they are not a fresh audit execution or a substitute for human acceptance. The historical `humanReview: pending` field was not rewritten.

The real manage receipt contains passing Core, Guardian and ordinary-denial cases. No new async operation, destructive action or loading state is introduced that requires new UI machinery. Accessible control names are confirmed from source. Keyboard focus/hover/open states were not newly captured because interaction capture is off; no claim of a complete accessibility or interaction audit is made.
