### `src/crud_views/lib/js_config.py` and `src/crud_views/lib/__init__.py`

**Analog:** `src/crud_views/lib/data_prefix.py`, lines 3–21. Copy the minimal standard-library validation/state pattern, with the approved namespace regex and placement vocabulary substituted:

```python
import re

_data_prefix = "bs"


def register_data_prefix(prefix: str) -> None:
    """Register a theme's prefix at startup; the last valid call wins.

    Invalid values raise ValueError without changing the previous registration.
    """
    global _data_prefix
    if not isinstance(prefix, str) or re.fullmatch(r"[a-z][a-z0-9]*(-[a-z0-9]+)*", prefix) is None:
        raise ValueError("Data prefix must match ^[a-z][a-z0-9]*(-[a-z0-9]+)*$")
    _data_prefix = prefix


def get_data_prefix() -> str:
    """Return the current prefix for internal rendering consumers."""
    return _data_prefix
```

Namespace default is `bootstrap`; do not derive it from prefix `bs`. Namespace validation is string type plus full match of `[A-Za-z_$][A-Za-z0-9_$]*`. For placements, validate the dictionary and every key/value before assignment, then replace with a copy. Return a copy from the internal mapping getter. The scalar analog demonstrates assignment ordering; mutable input/output isolation and whole-map replacement require the new bounded implementation described in RESEARCH.md, not an existing registry framework.

**Export analog:** `src/crud_views/lib/__init__.py`, line 1:

```python
from .data_prefix import register_data_prefix as register_data_prefix
```

Use the same explicit re-export style for both public registrations. No setting, authentication, database, logging or request-specific state is required here. Invalid registration raises `ValueError` and retains previous state.
