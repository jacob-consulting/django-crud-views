### WR-01: Accepted N6-01 — lazy presentation failure can suppress the toolbar after selection is enabled

**Classification:** WARNING

**File:** `/home/alex/projects/workspaces/cv-phase-06-46/django-crud-views/src/crud_views/lib/bulk/__init__.py:122-143`  
**Related locations:** `src/crud_views/lib/bulk/__init__.py:116-119,145-157`; `src/crud_views/templates/crud_views/view_list_table.content.html:3`; `src/crud_views/templates/crud_views/view_card.content.html:3,8`.

**Issue:** Context preparation evaluates only the effective destination keys in Python. Button labels and URLs remain evaluated by the lazy `cv_bulk_buttons` property when Django resolves a template guard. An admitted destination whose label/URL hook raises `ObjectDoesNotExist` or another exception marked `silent_variable_failure` can therefore make that guard false. The table column was already injected from the admitted keys, leaving selection controls without their toolbar. On cards, a failed `cached_property` calculation is not cached, so the same presentation failure is retried by the toolbar guard and each card guard. This is a presentation/diagnostic robustness issue, not an authorization bypass; destination admission and POST checks remain independent.

**Evidence:** An in-memory reproduction against the current `BulkPublisherListView` and `BulkPublisherCardView` classes used an already-admitted `("archive",)` effective tuple and a short-label hook raising `ObjectDoesNotExist`. No source files or database records were changed. The actual mixin and Django template engine produced:

```text
table: rendered='', selection_columns=['cv_bulk_select'], label_calls=1, buttons_cached=False
card, 2 rows: rendered='', label_calls=3, buttons_cached=False
```

This directly confirms the accepted failure mechanism. It was a focused template/property reproduction, not a full HTTP presentation-error regression. The full GET gate-error tests cover a different boundary: access/state/resolver errors are forced in Python before template evaluation and must not be described as fixing this presentation case.

**Fix:** In a separately authorized follow-up, evaluate `self.cv_bulk_buttons` in Python after cooperative `get_context_data()` preparation, so a presentation failure aborts before template guards can suppress it. Add real table/card GET regressions for silent-variable label/URL failures, including empty and populated pages, and retain the existing gate-call and context-order guarantees. Preserve the accepted lazy behavior for this phase.
