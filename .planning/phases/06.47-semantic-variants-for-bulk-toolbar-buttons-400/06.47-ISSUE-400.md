# Issue #400: Semantic variants for bulk toolbar buttons (C11, amends phase 06.41 D-19 and D-29)

Source: https://github.com/jacob-consulting/django-crud-views/issues/400
Captured: 2026-11-21

**Date:** 2026-11-21
**Status:** design approved by the maintainer on 2026-11-21; issue handover, not implementation authorization.
**Scope:** theme-tracker finding C11 (AdminLTE and CoreUI demos): a destructive bulk action cannot be styled apart
from a harmless one. This amends decisions D-19 and D-29 of phase 06.41 (#387). The Confirm button of the review
page and #399 (which actions the toolbar offers) are out of scope.
This document does not schedule a phase or authorize product implementation.

## Problem / motivation

Bulk toolbar buttons render through the form leaf as the `submit` kind, so every one carries `form:submit`
(`docs/reference/bulk_actions.md`: "These are form submit buttons styled by `form:submit`", "There is no per-action
map and no variant"). In the Acme Roasters demo "Mark roasted" and "Cancel orders" are both `btn btn-primary`; the
package's own bulk delete example has the same look as its archive action.

Single-record actions have semantic variants: every view has `cv_action_variant` (`primary`, `secondary`,
`tertiary`, `danger`; check `viewset.E209`), and themes map `context:*`, `list:*` and `card:*` class keys. The
toolbar ignores the destination's variant.

This was decided, not overlooked. D-19 ruled out variants for bulk buttons, and D-29 chose the unchanged form leaf
with the recorded cost "bulk buttons look like other form submit buttons and a theme cannot style them apart",
noting that a dedicated leaf can be added later without breaking. The research record names that leaf as the
fallback "if the maintainer wants bulk-specific styling" (`06.41-RESEARCH.md`, Option C).

Bulk actions (#387, PR #392) are unreleased, so the rendering can still change without a migration.

Goal: a theme can style bulk toolbar buttons by the destination's semantic variant. Stock Bootstrap output is
unchanged.

## Proposed solution

A dedicated bulk button leaf whose class comes from four new class keys `bulk:<variant>`, selected by the
destination's existing `cv_action_variant`. The approved contract is recorded in `gsd-handover` below.

## Alternatives considered

1. **Dedicated bulk leaf with four variant keys — selected by the maintainer.** The form leaf and its finite
   contract stay untouched; this is the fallback the 06.41 research named.
2. **Teach the form leaf a second class source.** One name fewer, but it changes the form-leaf contract, and a
   theme with a copied form leaf would silently keep `form:submit`. Not selected.
3. **Danger only, through the existing `form:delete` key.** No new name: a `danger` destination renders as the
   `delete` form kind. Offered as the cheaper path; the maintainer chose full variants. Not selected.
4. **Extend the action leaf.** Ruled out in 06.41 (no native submit, breaks copied theme leaves). Unchanged.
5. **A per-action class map on the source view.** D-19 ruled out per-action maps; that part stands. Not selected.

## gsd-handover

Carry these approved decisions and the acceptance criteria into GSD planning. Filing this issue does not create a
phase, schedule work, or authorize implementation.

### D-01 — Amendment of 06.41 D-19 and D-29, bounded

Replaced: D-19's "no `primary`/`secondary`/`tertiary`/`danger` variants" and D-29's "no bulk button class key or
leaf path enters the 1.0 surface", with D-29's choice of the form leaf for toolbar buttons. Kept: icon from the
destination's `cv_icon_action`, labels per D-20, the `bulk` label-mode floor (default `both`), no per-action maps
on view, ViewSet or setting, the action leaf untouched. The all-blocked Cancel button (D-28) and every real form
keep the form leaf; `crud_views/tags/button/form.html` and `FORM_LEAF_KEYS` do not change.

### D-02 — Variant source

The toolbar button of an action takes its variant from the destination's `cv_action_variant`. No new attribute and
no override on the source view. The default is the inherited `secondary`, as for every other action; a destructive
destination sets `cv_action_variant = "danger"`.

### D-03 — Four class keys

`bulk:primary`, `bulk:secondary`, `bulk:tertiary`, `bulk:danger`. Stock default for all four: `btn btn-primary`,
the value `form:submit` has today, so stock Bootstrap toolbars do not change. This follows `context:*` and
`list:*`, whose stock values do not distinguish variants either.

`bulk` joins the variant locations, so a mode key such as `bulk:danger:icon` is accepted by `crud_views.W362` and
preferred when present, exactly as for the other locations. This lifts the "do not read a mode key for bulk" note
of the 06.41 research.

Consequence, to document: bulk buttons no longer follow a project's `form:submit` override.

### D-04 — The leaf

A new template `crud_views/tags/button/bulk.html` renders toolbar buttons: a native
`<button type="submit" name="cv_bulk_stage" value="review" formaction=…>`, working without JavaScript as today.
Besides the leaf path and the four keys of D-03 it adds no name: it reuses `form:hidden-label` and
`form:icon-host` and keeps `data-cv-tooltip="form"`, so no tooltip location is added (relevant to #398).

With stock classes the rendered toolbar is byte-identical to today's. Whether the leaf is fed by
`cv_button_data` (lifting its `location == "bulk"` refusal) or by a smaller helper is the builder's call; the
contract keys it reads are documented either way, because themes may copy the leaf.

### D-05 — Acceptance and documentation

- Stock: existing bulk source tests and goldens pass unchanged (same markup, same classes).
- New: with the four keys overridden in `CRUD_VIEWS_BUTTON_CLASSES`, each destination's button carries the class of
  its `cv_action_variant`, on table and card sources; a destination without the attribute gets `bulk:secondary`;
  a `bulk:<variant>:icon` key wins in icon-only mode; overriding `form:submit` does not change a bulk button;
  overriding `form:hidden-label` does; `W362` accepts a `bulk:<variant>:<mode>` key and still rejects an unknown one.
- Unchanged: the review page (Confirm stays `form:submit`), the all-blocked Cancel button, `E209`.
- Inventories (06.41 research, Pitfall 2): `EXPECTED_KEYS` and the literal key counts in
  `tests/test1/test_button_classes.py`, the key count sentence and the bulk table in `docs/reference/buttons.md`,
  the stability inventory for the new leaf path.
- Docs: `docs/reference/bulk_actions.md` section "Toolbar buttons" (replace "styled by `form:submit`" and "no
  variant"; keep "no per-action map"), `docs/reference/buttons.md` (keys, variant locations),
  `docs/reference/theme.md` (the four keys a theme sets, the copyable leaf). CHANGELOG: amend the unreleased #387
  entry. No `docs/migrating-1.0.md` entry, because the feature is unreleased.
- The package's bulk example sets `cv_action_variant = "danger"` on its delete action.
- Downstream note, not upstream work: the CoreUI, Tabler and AdminLTE themes add the four keys (and `:icon`
  variants where they use them); the demos set `danger` on "Cancel orders".
