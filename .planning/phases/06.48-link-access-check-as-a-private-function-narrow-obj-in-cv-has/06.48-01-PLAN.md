Create `tests/test1/test_link_access_matrix.py`. It records, for one cell at a time, what the user would see, as one of four strings: `hidden`, `enabled`, `disabled:permission`, `disabled:state`. The private helper `_outcome(raw)` produces that string from a ctx dict by calling `cv_resolve_action`: `None` gives `hidden`, a dict with `cv_disabled` true gives `disabled:` followed by its `cv_disabled_reason`, any other dict gives `enabled`. A navbar child item has no ctx dict; its outcome is `enabled` when the item is present in the built navbar data and `hidden` otherwise. A cell that raises records `raises:` followed by the exception class name. URLs and primary keys are never part of the outcome.

A case id is the string `control/composition/target/actor/state/mode`. The dimensions of this task are:

- control: `child-button` (a `ChildContextButton` rendered on the parent detail page object), `card-child` (a child `CardAction` on a parent card row), `navbar-child` (a `NavItem` with `child=` on the host page).
- composition: `plain` (core parent ViewSet, core child ViewSet), `guardian` (Guardian parent, Guardian child), `mixed` (Guardian parent, core child).
- target: `list` and `create` of the child ViewSet.
- actor: `anonymous` (`AnonymousUser`), `inactive` (an inactive user holding the model permissions and the object grants of the other actors), `superuser`, `model` (Django model permissions view, add, change, delete on the parent and child models), `direct` (Guardian object grants view and change on the parent row, no model permission), `group` (the same object grants through a group), `direct-view` (object grant view only on the parent row). Build them with `_make_actor` or the helpers in `tests/lib/helper`; re-fetch each user so Django's per-instance permission cache is empty.
- state: `on` or `off`, by monkeypatching the target's `cv_action_enabled` to return that value.
- mode: `hide` or `disable`, by setting the target's `cv_inaccessible_actions`.

Reuse the existing isolated ViewSet scaffolds by import instead of copying them: `rendered_data` with the `links`, `plain_links` and `core_links` fixtures for the two button renderers, and `permission_routes` with `navbar_routes` for the navbar. Where a composition has no existing scaffold, build it inside this module with unique ViewSet names and the cleanup pattern of the `links` fixture (registry entries removed, `check_module._VOCAB_CACHE` restored, URL caches cleared in a `finally`).

Capture the outcomes once, on the unchanged tree, into `tests/test1/link_access_matrix_baseline.json`: a JSON object with `source_revision` (the output of `git rev-parse HEAD` at capture time), `interpreter` (Python and Django versions) and `cells` (case id to outcome string, keys sorted).
