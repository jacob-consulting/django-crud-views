## Decision taken by this plan (CONTEXT.md, consequence of D-25: "the own-child argument is the planner's to settle")

`cv_has_access` on a nested Guardian create answers `False` for every argument (the research's option G1). A create
has no own object, so under D-11 and D-15 no argument other than `None` is inside the hook's contract, and `None`
must stay `False`. Only "allowed" answers become "denied". This is also the direction that stays open: relaxing it
after 1.0 would be compatible, tightening a tolerant hook later would be breaking.

## What the docstrings of the two hooks must say

These are facts about the code as it stands after plan 06. The wording is the executor's; nothing beyond these
facts is claimed.

| Hook | Fact |
|------|------|
| `cv_has_access(user, obj)` | `obj` is this view's own object, or `None` for a view without one (list, create). The package never passes a parent or a page object of another kind. |
| `cv_action_enabled(user, obj)`, the object | `obj` is the object the request passes, as `cv_get_action_object` defines it: the view's own object, the immediate parent for a nested view without an own object (list and create alike), otherwise `None`. A package link passes that same object. One exception: on a view that did not run the ancestor guard, a nested list receives `None`. |
| `cv_action_enabled(user, obj)`, the order | For the request, and for the links the private link check decides (child context buttons, card child actions, object navbar child items, and every link to a nested Guardian create), the hook runs only after permission passed. Context buttons, row actions, the parent button, the sibling button and non-child card actions still evaluate it independently of the permission result. An override must not rely on permission having passed. |

The exception of the second row is decision D-36. The docstring states it in plain words and cites no decision
number.

The present first sentence of the `cv_action_enabled` docstring says the gate is evaluated only after
`cv_has_access` has passed. That is true for the request and untrue for the controls of the last row; correct it.
Do not write that a link always evaluates state after permission, and do not write that every link passes the same
object without the exception.
