## The one cost that changed

Stated once, so that the reference page, the after-record and the summary say the same thing.

The three controls that hold the parent in hand (child context button, card child action, object navbar child
item) asked own access first and the parent gate second. An actor whose own access was denied never reached the
gate. The link check asks the gate first (concept 5.2). For such an actor two things follow:

- the control now runs one parent gate, with the queries that gate costs;
- a malformed parent policy (an undeclared key, a nested endpoint without operation requirements, authorization
  records on another database) now raises `ImproperlyConfigured` for that actor too, where the control was simply
  hidden.

Nothing changes for an actor whose own access is allowed, and no rendered result changes for a well-formed policy.

| Control | Moved in | Before-value | Evidence after |
|---------|----------|--------------|----------------|
| child context button, card child action | plan 04 | zero queries and no gate call, asserted by `test_query_denied_actors_and_custom_do_no_permission_work` | the query count the same test reports with `layer="own_denied"`; `test_plain_child_link_errors` raises in the own-denied branch |
| object navbar child item | plan 02 | no gate call, shown by `test_reached_policy_errors_propagate` with `allowed=False`, which rendered an empty navbar under a malformed policy | the same test raises for `allowed=False`; no navbar test measures the queries of an own-denied actor, so the record states one parent gate and no number |
