### L1 — List-page overwrite (D-34)

The maintainer decided on **2026-11-23** to keep this in stage 1: a Guardian list page resolves a context
button's `key_target` (or action key) in its own ViewSet and, when that key is its Guardian create, overwrites
the button's access/state with the page's own create result. This affects both a parent create button and a
sibling button registered under `create`, while URL/label/icon retain the real target. A parent button runs
two gates; the sibling exception runs only the overwrite's gate. Removing this changes a rendered result;
concept section 3 assigns the list-page rewrite to stage 3. Plan 08 published it as F11.

Frozen `parent-button/guardian-3/{list,detail}/parent-create/{near-change,far-change}/on/disable` cells show
the opposite grant results on list versus detail pages. Named pins are
`test_parent_button_reaches_nested_guardian_create_through_the_check` and
`test_sibling_button_under_create_key_gets_page_create_result` in `test_link_access.py`.

### L2 — Nested Guardian create actor rule (D-35)

The maintainer decided on **2026-11-23** to keep this in stage 1: nested Guardian create denies an inactive
actor, but an anonymous actor under a model-provider parent receives that provider's answer, so a backend
grant can show the link. The core adapter's signed-in rule never applied to this path. Removing the exception
changes a rendered result; the unchanged request gate still refuses the click.

Frozen `child-button/core-guardian/parent/create/anonymous-backend/on/disable` and
`card-child/core-guardian/parent/create/anonymous-backend/on/disable` cells are enabled, while their inactive
counterparts deny. `test_actor_rule_for_protected_ancestry` pins the rule.

### D-36 — Unguarded nested-list state object

nested list's state hook receives `None`. Core controls do not disappear. This is pinned by
`test_page_action_object_follows_request_definition` and `test_unguarded_view_keeps_core_controls`, and
