## Pattern Assignments

### `src/crud_views/lib/link_access.py` (utility, request-response)

**Primary analog:** `_cancel_target_available`, `src/crud_views/lib/view/base.py:76-88`. This is the existing
function that already has the narrowed argument rule (D-11, D-15), permission before state (D-19) and the action
object of the request (D-13). The new function generalizes it.

**Core pattern** (`base.py:76-88`):
```python
def _cancel_target_available(target, user, obj, rendering_view):
    """Evaluate the concrete destination's access and state hooks, including overrides."""
    target_obj = obj if target.cv_object else None
    if not target.cv_has_access(user, target_obj):
        return False
    if target.cv_object:
        return target._cv_action_enabled_for_rendering(user, target_obj, rendering_view)
    action_obj = None
    if target.cv_viewset.has_parent:
        action_obj = rendering_view._cv_cancel_parent_object()
        if action_obj is None:
            return False
    return target._cv_action_enabled_for_rendering(user, action_obj, rendering_view)
```
Differences the new function must have: the parent comes from the handed ancestor list, not from
`rendering_view._cv_cancel_parent_object()` (that helper reaches `cv_get_parent_object`, whose fallback at
`base.py:1184-1188` is `get_object_or_404`, a database read that D-04 forbids for a link); step 3 calls
`target.cv_action_enabled(user, action_obj)` directly, not the adapters (RESEARCH.md Pitfall 8); the result is
three-valued, not a bool.

**The request's action-object rule to mirror** (`base.py:568-575`):
```python
def cv_get_action_object(self) -> Model | None:
    if self.cv_object:
        return self.get_object()
    if self.cv_viewset.has_parent:
        return self.cv_get_parent_object()
    return None
```

**Parent-gate composition analog:** `_immediate_parent_access`, `src/crud_views/lib/ancestors.py:654-686`. Compose
it, do not rewrite it. Its early-return order is pinned by tests:
```python
if parent_obj is None:
    return False
viewset = view_class.cv_viewset
((_, parent_vs),) = _walk_ancestors(viewset, first_only=True)
if rendering_view is not None:
    resolved = _resolved_parent(rendering_view)
    if resolved is not None and resolved is not parent_obj and _same_row(resolved, parent_obj):
        parent_obj = resolved
provider = _effective_provider(parent_vs)
if provider == "none":
    return True
_check_nested_auth(view_class, actor=user, model=parent_vs.model, obj=parent_obj, provider=provider)
key = _operation_requirements(view_class).nearest
permission = _permission_name(viewset, parent_vs, key, _registered_key(view_class))
return parent_vs._ancestor_has_permission(user, permission, parent_obj, view=rendering_view)
```

**Import pattern (load-bearing).** The gate must be reached through the module attribute, because
`parent_spy` monkeypatches `_immediate_parent_access` on `crud_views.lib.ancestors`,
`crud_views_guardian.lib.mixins` and `crud_views_guardian.lib.views`
(`tests/test1/test_guardian_child_link_visibility.py:615-630`). A `from crud_views.lib.ancestors import
_immediate_parent_access` at the top of a new module would hold the unpatched function. Two existing forms work:

- module access, as the tests do (`tests/test1/test_ancestor_helpers.py:30`, `:183`):
  ```python
  from crud_views.lib import ancestors
  ...
  ancestors._immediate_parent_access(helpers.book.List, viewer, data.penguin)
  ```
- import inside the function body, as `base.py:533` does:
  ```python
  from crud_views.lib.ancestors import _effective_provider, _immediate_parent_access
  ```

`parent_spy` also calls `monkeypatch.setattr(module, "_immediate_parent_access", gate)` on both Guardian modules.
`setattr` raises when the attribute is missing, so `crud_views_guardian/lib/mixins.py:11` and
`crud_views_guardian/lib/views.py:11` must keep their module-level import of that name even if a refactor removes
its last use in one of them.

**Module header convention** (`src/crud_views/lib/ancestor_db.py:1-40`, `src/crud_views/lib/ancestors.py:1-65`):
a module docstring that states the rule and names the callers, then
```python
from __future__ import annotations

from typing import TYPE_CHECKING
...
if TYPE_CHECKING:
    from django.db.models import Model

    from crud_views.lib.view import CrudView
    from crud_views.lib.viewset import ParentViewSet, ViewSet
```
Private module functions carry a leading underscore and a docstring that lists their early returns as bullets
(`ancestors.py:657-671`).

**Outcome vocabulary** (`src/crud_views/lib/view/visibility.py:14-20`). The consumer reads two dict keys and knows
two reason strings, `"permission"` and `"state"`:
```python

if usable:
    return {**ctx, "cv_disabled": False}
if ctx.get("cv_inaccessible_actions") != "disable":
    return None
reason = "permission" if ctx.get("cv_access") is not True else "state"
return {**ctx, "cv_disabled": True, "cv_url": None, "cv_disabled_reason": reason}
```
Reuse those two strings for the denials; `visibility.py` itself needs no edit.

**Reading resolved ancestors without a query** (`ancestors.py:570-585`):
```python
def _resolved_parent(view: CrudView) -> Model | None:
    """The immediate parent resolved by a successful guard on this request, or None."""
    state = getattr(view, "_cv_ancestor_state", None)
    return state.parent if state is not None else None
```
`_resolved_ancestor(view, name)` (576-585) is the by-name variant. Both return `None` without guard state and
never touch the database. These are the sources for sibling-page sites (D-27).

### `src/crud_views/lib/view/base.py` (per-target seam; sites A1, A9, B2)

**Analog for the seam:** the adapter it replaces or re-specifies, `base.py:527-541`:
```python
@classmethod
def _cv_child_link_has_access(cls, user, parent_obj) -> bool:
    """Access for a child link whose URL uses the supplied immediate parent."""
    access = cls.cv_has_access(user, parent_obj)
    if not access or not cls.cv_viewset.has_parent:
        return access
    from crud_views.lib.ancestors import _effective_provider, _immediate_parent_access

    if not _immediate_parent_access(cls, user, parent_obj):
        return False
    # A backend grant cannot waive protected ancestry's actor rule. Keep the helper's
    # configuration errors and provider-none bypass, without consulting farther ancestors.
    return (user.is_authenticated and user.is_active) or _effective_provider(
        cls.cv_viewset.parent.viewset
    ) == "none"
```
What to keep: the lazy import, the gate called with no `rendering_view` (so the provider receives `view=None`,
RESEARCH.md Pitfall 3), and the D-18 actor rule in the last statement. What changes: `cls.cv_has_access(user,
parent_obj)` on line 530 is the AC-1 violation; the own-access call receives the target's own object or `None`,
and it moves after the parent gate (concept step order, RESEARCH.md Pitfall 6).

**Analog for a classmethod that delegates to a module function** (`base.py:990-992`):

This is the existing shape of "module function owns the rule, classmethod is the override point that Guardian
mixins wrap with `super()`". The link seam follows the same shape in the opposite direction: the function calls
the classmethod.

**Site A9/B2**, `_cv_get_action_context`, `base.py:909-916`:
