### Pillar 6: Experience Design — 3/4, code-derived

**Preservation evidence:** `tests/test1/test_link_access_matrix.py:462` compares live outcomes with the frozen JSON. Its completeness test at line 467 requires exactly 1,178 unique cells and a closed set of hidden/enabled/permission-disabled/state-disabled/filter/page-status outcomes. At lines 438–452, refused pages must record no fabricated controls and served pages must record matching controls. The JSON is unchanged from `bc4510a6` (fresh diff exited 0). This establishes characterized behavior, not all possible downstream overrides or browser interactions.

`src/crud_views/lib/link_access.py:68` denies missing immediate parents and separates own objects from supplied ancestors. Lines 80–90 evaluate state after permission and map permission/state outcomes into the existing visibility fields. `tests/test1/test_link_access.py:969` requires nonempty request and rendering recordings for action-object parity; line 1055 checks package call sites individually. The inspected navbar/button/card/filter/Guardian diffs route the declared sites through this logic and preserve the other sites' bounded paths.

**WARNING — accepted existing navigation inconsistency:** A link may remain enabled while a farther ancestor or a queryset-only composition causes its request to return 403. The matrix explicitly pins both halves at `tests/test1/test_link_access_matrix.py:477`; `docs/migrating-1.0.md:109` explains the limit. Users can reach a refused destination despite an enabled control. D-26/D-30 explicitly preserve this in stage 1; any later correction must deliberately change both rendering and its frozen expectations. It is not a phase blocker.

**WARNING — accepted existing control inconsistency:** The list-page create overwrite can make a parent/sibling button use the page's own create permission result, while the detail-page counterpart uses its target's result. The matrix at `tests/test1/test_link_access_matrix.py:497` pins opposite-grant parent-button cases; documentation begins at `docs/migrating-1.0.md:113`. D-34 preserves this for the later list-page rewrite. Likewise the filter can remain False where a toolbar create control is available (migration lines 94–98; matrix lines 488–496). These limitations justify withholding 4/4 without treating approved preservation as a new regression.

**Migration risk, addressed:** Custom overrides using a parent/page object in `cv_has_access`, or assuming a non-null rendering view in `cv_create_has_access`, must migrate. Incorrect overrides can hide controls or raise while rendering. The paired release/migration guidance names these cases; default-hook matrix preservation is not a promise that old custom overrides keep working.

Loading/empty states, keyboard focus, hover, modal transitions, destructive-action confirmation and screen-reader behavior were not exercised. No captured interaction state is claimed.
