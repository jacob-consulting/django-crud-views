# Phase 06.5 Plan 07: Removed card label alias Summary

**CardAction rejects removed `no_label` inputs with explicit migration guidance; card rendering uses `label_mode`, and obsolete template context is ignored.**

## Accomplishments

- Added `reject_removed_no_label`, a model-before validator checking exact membership only on `Mapping` inputs. True, False, None, empty string, zero and arbitrary strings fail through constructor, mapping and JSON entry points, alone or alongside each supported mode.
- Removed the alias field, combination validator branch and runtime alias branch. Model fields, JSON schema and dumps no longer expose it. Unrelated extras, near-spelling/Unicode keys, valid existing instances and invalid non-mapping Pydantic errors retain their behavior.
- Migrated positive app/render/menu/variant fixtures to `label_mode="icon"`; retained accessible hidden labels, title text, explicit action precedence, request-local settings and menu semantics.
- Removed the obsolete `cv_no_label` template guard. Forty-eight cases show stray context does not affect current modes or output and does not mutate the input.
- Updated active reference tables, examples and precedence to three steps; preserved singular/plural API names, the heading table/count and form documentation. No templates or golden files changed.
