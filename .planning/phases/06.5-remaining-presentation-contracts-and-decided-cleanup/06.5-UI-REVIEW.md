## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING C1 — small contract drift:** `src/crud_views/lib/view/card.py:24` says `CardAction.no_label has been removed; use label_mode="icon" for icon-only actions` rather than the contract's `CardAction.no_label was removed; use label_mode="icon" for icon-only actions.` The migration is still clear and actionable; this is not a functional blocker.
- **WARNING C2 — technical diagnostic instead of the specified explanation:** `src/crud_views_object_detail/lib/presentation.py:34–36` supplies the correct regex, field label and rejected value, but omits the requested plain-language ASCII-token rule. Add that explanation; do not relax the full-match grammar. Duplicate diagnostics at lines 64–78 already name the conflicting identity and require distinct identifiers.
- **PASS finding:** Modal `Close` remains translated and accessible (`src/crud_views/templates/crud_views/modal/content.html:5`). Group titles remain escaped supplied text in the tab and accordion templates; the badge template uses the mapped label or original escaped value (`types/default/badge.html:1`). Zero groups introduce no invented workflow or empty-state copy.
- The accordion's literal `properties` suffix (`layouts/accordion/group.html:12`) is inherited copy. Its lack of plural translation is outside this phase's preserve-existing-copy contract, so it is not charged as a new regression. Generic action labels elsewhere are likewise not grounds to reopen D-15.

### Pillar 2: Visuals (3/4)

- **WARNING V1 — visual evidence gap:** no relevant server was running at the audit's default ports. The service on 8080 returned Svelte module entry points and is not this Django package; capturing it would be misleading. Desktop, mobile and tablet screenshots were therefore not captured or inspected. All three requested widths remain unverified visually.
- **PASS finding:** The page title is one semantic heading with explicit size 3 (`tests/test1/app/templates/app/crud_views.html:14–21`; actual example at `examples/bootstrap5/project/templates/project/crud_views.html:17–23`). Modal titles retain `modal-title`; split-card and striped-row title icons now belong to their headings (`layouts/split-card/group.html:8–9`, `layouts/striped-rows/group.html:4–5`). Interactive icons belong to the actual tab/accordion button, not an adjacent decorative host.
- `cv_heading_icon` returns either a host class or one inline icon (`src/crud_views/templatetags/crud_views.py:341–350`). Existing browser case `mixed-heading-icons` records 120 passing assertions for placement, sizing, titles and names. That supports the structure and glyph availability, not perceptual balance or responsive wrapping.
- Icon-only detail controls retain `aria-label` and tooltip text (`layouts/card-rows/property.html:6`). No missing accessible label was found in the changed controls.

### Pillar 3: Color (4/4)

- **PASS finding:** Across all 16 shipped layout templates, the direct primary-accent class scan finds exactly one `bg-primary` occurrence: the intentionally preserved striped header (`layouts/striped-rows/group.html:3`). Selected tab accents come from Bootstrap's `nav-pills`/`active` classes (`layouts/tabs-vertical/object_detail.html:6–9`); passive headings introduce no new accent. No literal hex/rgb color declarations occur in these templates.
- Semantic badge data is derived from the same resolution result (`src/crud_views_object_detail/lib/resolvers.py:201–216`), with text preserved by `types/default/badge.html:1`. Native browser evidence exercises custom/hostile semantic color names and escaped values without Bootstrap markup.
- The contract expressly makes 60/30/10 descriptive, permits existing primary delete styling and semantic colors, and excludes recoloring. No pixel-distribution or contrast measurement is claimed; no new color deviation was found in the audited source.

### Pillar 4: Typography (4/4)

- **PASS finding:** `CvHeadingNode.render` independently selects semantic level and size, then escapes and joins size/caller/icon contributions (`src/crud_views/templatetags/crud_views.py:362–384`). The registry retains all six `h1`–`h6` defaults (`src/crud_views/lib/button_classes.py:16–21`). The actual demo retains `mb-0` while adopting explicit `size=3`.
- Layout scan: six `level=5` sites, one `level=2` accordion wrapper; seven `fw-medium` occurrences, one `fw-semibold`, and 15 `small` tokens (including semantic tags). These are existing Bootstrap roles and exceptions, not an unauthorized expansion of the four-role reference table. No new font or fixed pixel typography was introduced.
- Existing browser records prove replacement/removal of heading-size classes and independent heading semantics. They do not measure all computed responsive font metrics; native themes are explicitly not required to reproduce Bootstrap metrics.

### Pillar 5: Spacing (4/4)

- **PASS finding:** The 16 layout templates retain the documented utility scale: `mb-0` 11, `mb-3` 7, `mb-1` 4, `mb-2` 3, and `mb-4` 1 occurrences. Remaining padding/margin tokens use steps 0–4, including `ps-md-4` and `pe-md-3`/`ps-md-3`. No arbitrary pixel/rem spacing was added to these templates.
- `heading:icon-inline` defaults to `me-2`, with empty page/modal overrides (`src/crud_views/lib/button_classes.py:23–25`). `_heading_class` resolves configuration layers before location and respects explicit suppression (lines 184–195). The modal retains its literal title separator (`modal/content.html:4`).
- Responsive layout structure remains `col-md-*` and `col-sm-*`, with existing borders and natural wrapping. The legacy 10px property margins, intrinsic unbroken-value/badge overflow and component-internal padding are explicit exceptions; normalizing them would violate scope. Their visual behavior at the three requested widths remains unobserved, covered by V1 rather than invented spacing defects.

### Pillar 6: Experience Design (4/4)

- **PASS finding:** First trigger/panel selection is shared through `presentation.selected`; inactive triggers have `tabindex=-1`, panels carry `role=tabpanel`, reciprocal IDs and `tabindex=0` (`layouts/tabs-vertical/object_detail.html:9–16`, `group.html:2–5`). Accordion controls begin collapsed and point to component-scoped panels/parents (`layouts/accordion/group.html:5–18`).
- `tabs.js:23–57` initializes only marked stock lists without calling `show()` or taking focus, initializes modal content, and disposes existing instances before replacement. Native/unmarked roots do not read Bootstrap. Existing source-matched browser evidence covers first arrow-key activation before clicking, mouse switching, wrapping/Home/End, exact Tab destinations, siblings, page/modal isolation and reopen behavior.
- **Evidence:** `09-browser-results.json` has 12 passing cases / 297 passing assertions, empty page/console error lists, all five required assets successfully loaded and successful fixture/browser cleanup. All 52 recorded source hashes were independently compared with disk during this audit: zero mismatches. `09-existing-lifecycle.json` has two passing cases / 20 assertions and 35 source hashes: zero mismatches. These are retained runtime records, not interaction screenshots captured by this audit.
- Modal pending/error behavior remains the existing fetch/injection/full-page-navigation lifecycle (`src/crud_views/static/crud_views/js/modal.js:133–162`, 173–199). No local tab loading state, new confirmation dialog or new form state machine is required. Prior accepted validation, deletion and conditional/formset contracts are not reopened.
- **WARNING E1 — bounded accessibility evidence:** screen-reader announcements and visible focus appearance remain unverified. No native tab widget or full alternative-theme certification is claimed. This limitation is expressly allowed by D-16 and does not deduct from implemented interaction behavior.
- The separate security audit's T17 fixture-cleanup failure path is not hidden by successful runtime cleanup. It remains a security/fixture finding, not a demonstrated user-facing tab failure; see `06.5-SECURITY.md` for its disposition.
