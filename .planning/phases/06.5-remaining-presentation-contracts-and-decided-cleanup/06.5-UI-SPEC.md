# Phase 06.5 — UI Design Contract

Visual and interaction contract for the existing Django presentation surface. Scope is PRES-01–PRES-06 and
CONTEXT decisions D-01–D-17. The nine reviewed PLANs settle implementation names and behavior; the research's
earlier proposals and baseline defects are historical where those plans or completed source supersede them.
This contract creates no new screens and does not redesign the stock theme.

Plans 01 and 06 have completed their producer/modal and semantic-badge work. Their SUMMARY evidence is bounded
to those contributions. Other consumer migrations, real-browser acceptance and phase-wide verification remain
outstanding. This file is a design contract, not evidence of implementation, human approval or phase completion.

## Typography

Four reference sizes and two reference weights describe the phase's main stock title/body roles. Keep their
existing selectors and responsive sizing rather than writing fixed pixel overrides.

| Role | Size at stock root | Weight | Line Height |
|------|--------------------|--------|-------------|
| Body and tab/accordion button label | 16px / 1rem | 400 | 1.5 |
| Supporting description | 14px / .875em of body | 400 | 1.5 |
| Modal and ordinary group title | 20px / 1.25rem | 500 | 1.2 |
| Page title, explicit `size=3` | 28px / 1.75rem before responsive reduction | 500 | 1.2 |

Preservation exception: this table does not cap the reusable library's existing typography. All six semantic
heading levels and all six `heading:size-N` mappings remain supported; existing property-label emphasis,
`fw-semibold`, `dt` and badge typography retain their inherited weights/sizes. Restricting those existing styles
to this four-role sample would violate D-01/D-15 and require unrelated CSS changes. Native themes may replace
or omit size classes; they are not required to reproduce Bootstrap font metrics.

The existing page or modal title is the primary visual anchor, followed by group headings or the selected
tab/accordion control, then property labels and values. This clarifies the inherited hierarchy without redesign.

### Heading contract

- `cv_heading` keeps semantic `level` and render-time header-level behavior. Explicit literal `size=1..6`
  selects the corresponding theme sizing key even when semantic and visual levels match. Without explicit
  size, use the original template level's size key only when the semantic level changes.
- `heading:size-1` through `heading:size-6` default respectively to `h1` through `h6`. Clearing a size key
  removes that contribution only; preserve caller utility/structural classes, including the demo's `mb-0`.
- Compose independently escaped size, caller `class`, and projected `icon_class` contributions in that order.
  Do not strip classes by prefix. Page title wrappers must not nest headings; retain the `cv_header` body block.
- `cv_heading_icon(value, location="page"|"modal"|"group")` supplies `host_class` and `inline_html`.
  Place host classes on the visible-title heading, or the actual accordion/tab button. An element library
  supplies one decorative child icon. Empty or disabled icons retain the title and never create a fallback duplicate.
- Shared slots are `heading:icon-host` and `heading:icon-inline`; each location supports the corresponding
  `heading-page`, `heading-modal`, or `heading-group` override. Resolve project location, project shared, theme
  location, theme shared, builtin location, builtin shared. Explicit empty/None stops fallback.
- Resolve each header icon hook once and render each element icon once. Keep `cv_header_icon` callable for
  standalone icons; it is superseded specifically as the host-aware heading recipe, not removed.

Sources: plans 01/02/03, completed 01-SUMMARY and current heading source. Bootstrap sizing/weight references
were checked against its [versioned variables](https://raw.githubusercontent.com/twbs/bootstrap/v5.3.3/scss/_variables.scss)
and [heading class definitions](https://raw.githubusercontent.com/twbs/bootstrap/v5.3.3/scss/_type.scss).

native themes map supported names themselves. `badge_color` and `badge_pill` augment existing `badge_css` and

## Interaction Contract

### Tabs and accordion

| State / interaction | Required behavior |
|---------------------|-------------------|
| First render, zero groups | No trigger/panel pair and no active selection; initialize as a no-op |
| First render, one or more groups | Exactly the first tab and its panel share `selected=true`; trigger active, `aria-selected=true`, `tabindex=0`; panel active/show. Other tabs have `aria-selected=false`, `tabindex=-1`. |
| Pairing | Tablist role/orientation remain vertical; each tab's control target and `aria-controls` equal its panel ID, and the panel's `aria-labelledby` names that tab |
| Mouse selection | Activate the clicked tab and its panel; deactivate only the previous pair in the same component |
| ArrowUp / ArrowDown | Move focus and automatically activate together, wrapping within this tablist; a one-tab list retains its only selection |
| Home / End | Use Bootstrap's first/last-tab behavior; do not add a competing keyboard state machine |
| Tab exit | Stock panels retain `tabindex=0`: from selected trigger, Tab reaches selected panel; next Tab reaches its first link or the following control if content is plain text. Hidden panels are not focus stops. |
| Accordion | Retain initially collapsed state and normal native button/Bootstrap collapse behavior; control, panel and parent references belong only to the enclosing component |
| Standalone group | Allocate local identity; omit references to absent roots/controls. A standalone tab panel uses the escaped title as its label, not a dangling `aria-labelledby`. |

For theme copies, the panel reading stop is the stock choice: a theme may omit it when its leading meaningful
content is already focusable, but must retain an accessible destination for plain content and test its focus order.
The planned browser checks must test plain and link-bearing panels and assert exact focus targets.

`data-cv-od-tabs` identifies stock-owned tablists. `cv.initObjectDetailTabs(root=document)` includes root itself
and descendants, uses only triggers owned by each nearest marked tablist, and calls Bootstrap's existing
`Tab.getOrCreateInstance`. Initialize normal/late page loads and `cv:modal:loaded` before the first keypress.
Initialization must not call show/focus, reset selection or install duplicate listeners. Dispose existing removed
instances on `cv:modal:unload` while content is attached. Keep page siblings and accepted modal focus restoration
unchanged. No Bootstrap access for native/unmarked layouts; absent Bootstrap preserves server selection safely
but does not establish working stock switching. No new generic tab adapter, hash activation or selection persistence.
Source: plans 03/05/08/09 and the verified
[Bootstrap 5.3.3 tab implementation](https://raw.githubusercontent.com/twbs/bootstrap/v5.3.3/js/src/tab.js).

### Identity and projection

Use one immutable per-render component with `id`, `tablist_id`, `content_id`, and `groups`. Each entry retains
the original `group` plus `control_id`, `panel_id`, and `selected`. Pass `component` and `presentation` through
`render_group`, preserving original `groups`, `group`, `prop`, `value`, `layout` and `od_settings` where applicable.
The generic group-only fallback must reuse this projection rather than allocate another namespace.

Supply a component token through `render_object_detail(..., component_id=...)` or the view's
`cv_object_detail_id` / `cv_get_object_detail_id()` and `object_detail_id` context. Group configuration exposes
optional `id`, retained on `ResolvedGroup`. Supplied values must full-match `[A-Za-z][A-Za-z0-9_-]*` without
coercion, trimming, title slugging or suffixing. Omission generates a component token `g` plus UUID4 hex.

For token `C`, the base is `cvod-c{len(C)}-{C}`; root/tablist/content append `-root`, `-tabs`, `-content`.
Each group appends either `-s{len(G)}-{G}` for supplied group token G or `-i{zero_based_index}` for omission,
then `-control` or `-panel`. Explicit component and group tokens remain stable across translations and reorder;
omitted group tokens promise positional identity only. Generated component tokens change between renders.

Detect duplicate supplied groups/final IDs within the shared outer render, including includes, inheritance and
explicitly transported library nested contexts. Fresh backend renders without scope transport and independent
HTTP/modal responses are separate boundaries; applications must choose distinct namespaces when assembling them.
The documented request-aware hook uses `cv_is_modal_request(self.request)` and `X-CV-Modal: true` to choose
`author-page` versus `author-modal`; further repeated instances require their own tokens. No request/global registry,
mutated resolved groups or promise of cross-response collision detection. Sources: plans 03/04/09, D-05–D-08.

### Badge and removed-alias preservation

Resolve badge color once: callback, otherwise nonempty map, otherwise fixed color. None property values bypass
the callback; a map miss or callback returning None renders an ordinary value. An empty map retains fixed-color
fallback; an empty resolved color string retains its existing `text-bg-` result. Unresolved semantic defaults
are `badge_color=None`, `badge_pill=False`. A resolved badge still precedes a property's explicit template.
Native recipes read semantic fields and original value/context without parsing CSS or repeating model resolution.

Reject exact Python `no_label` presence before normal extra-field handling; omission and unrelated extras retain
their established behavior. Remove the obsolete template rejection guard while never restoring `cv_no_label`
to produced data. Replacement icon-only actions retain accessible labels. Both singular/plural label-mode APIs
remain unchanged. Sources: completed plan 06, pending plan 07, D-09–D-15.
