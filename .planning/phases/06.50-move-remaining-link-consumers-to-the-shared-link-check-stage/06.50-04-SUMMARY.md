**The permission filter checks known ancestors without state; core Cancel checks both target shapes using its existing parent hook and known higher ancestors.**

## Accomplishments

- `cv_context_has_permission` preserves its existing target lookup and explicit Guardian seam result, otherwise aligns known ancestors and calls `_link_permission`. It supplies the target-own object or None and the real view only for the same ViewSet. No state hook or new lookup is used; permission/configuration failures remain outside the lookup catch.
- Core `_cancel_target_available` calls `_link_access == _LINK_ALLOWED`. Every nested target obtains its immediate parent from `_cv_cancel_parent_object`; higher objects come only from guard state. Object targets retain the exact target-own object for permission/state, while collection permission receives None and collection state receives the hook parent.
- Guarded Cancel reuses the exact guard parent with zero domain fetches. Unguarded Cancel performs its existing single Book fetch without fetching Publisher. A built-in missing row is unavailable; custom Http404, KeyError and DatabaseError reach callers for both target shapes. The request override reaches the existing shallow owner copy and its actor without mutating the source view.
- Guardian ParentPermission Cancel retains one immediate gate and can still allow a destination whose higher request gate denies. Queryset-only Cancel retains its immediate-gate exception but now checks a known higher ancestor. Both differences have real request checks. No Guardian/request implementation changed.
