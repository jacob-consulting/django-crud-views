## Recommendation

Use the existing private `_link_access` / `_link_permission` pipeline at each enumerated consumer.
Add one bounded private helper for target-aligned known ancestors; reuse `_walk_ancestors` and
`_resolved_ancestor` in `src/crud_views/lib/ancestors.py`. Match by the target's declared ancestor
ViewSet, not tuple position in the rendering page's ancestry. Preserve unknown levels as `None`.
No ancestor fetch, queryset membership query, synthetic rendering view, or new cache is needed.
The helper's name and placement remain planner discretion; no public API is introduced.

For own-ViewSet targets obtain parents from guard state. For child targets seed the immediate parent
with the object/row used to construct the URL, then align higher levels. For parent/sibling/navbar
owner targets align afresh to the actual target. Supply the real rendering view only when
`target.cv_viewset is rendering_view.cv_viewset`; otherwise supply `None`. This identity check is
independent of whether the consumer is labelled child/owner/context.

`_cv_page_link_ancestors` retains its Guardian create override. At existing seam consumers, a tuple
remains the exception-specific ancestor list; the core `None` result means use aligned known state,
not the former split permission/state branch. Do not route navbar child items through this seam.
Delete `_page_action_object` after all callers migrate. Keep both state adapters and their overrides:
nested Guardian Cancel remains a production consumer until 3b.

## Resolved navbar overlap: D-55

A Guardian Publisher → Book → BookNote probe renders a Book-owned navbar on BookNote list. Its child
item targets BookNote create, hence target and rendering page belong to the same ViewSet. Publisher
`view` without `change`, Book `view` plus `change`, and a stricter create higher-level write policy
produce a permitted page but a denied full-chain link.

The maintainer selected the full-chain interpretation and committed D-55. The immediate-parent-only
exception belongs to the existing seam and rewrite, not every consumer on the same page. The navbar
child item must be denied by its higher gate even when the context create button retains its exception.
Pin this distinction explicitly; do not extend the exception or remove the retained mechanisms.

The baseline probe was independently rerun before implementation: **1 passed in 0.83s**. Its observed
results were same_viewset=True, baseline_items=1, aligned_result=permission,
immediate_only_result=allowed, existing_page_seam=(). This is characterization evidence, not phase
acceptance or a performance result. Its source is preserved below for reproduction.

## Reproducible probe source

Copy this to the temporary path in the command above.

```python
from types import SimpleNamespace

import pytest

from crud_views.lib import ancestors
from crud_views.lib.link_access import _link_access
from crud_views.lib.navbar import NavBar, NavItem, _build
from crud_views.lib.viewset import AncestorPermissions, AncestorPolicy
from tests.test1 import test_ancestor_helpers as fixture_source
from tests.test1.app.models import BookNote
from tests.test1.test_ancestor_authorization import _user
from tests.test1.test_ancestor_helpers import _bound, _grant

helpers = fixture_source.helpers
data = fixture_source.data


@pytest.mark.django_db
def test_own_viewset_navbar_create(helpers, data, monkeypatch):
    actor = _user("navbar_own_target_probe")
    _grant(actor, helpers.pub, "view", data.penguin)
    _grant(actor, helpers.book, "view", data.book)
    _grant(actor, helpers.book, "change", data.book)
    note = BookNote.objects.create(book=data.book, note="Probe")
    _grant(actor, helpers.note, "view", note)
    monkeypatch.setattr(helpers.note.vs, "ancestor_policy", AncestorPolicy(write=AncestorPermissions(nearest="change", higher="change")))
    view = _bound(helpers.note.List, actor, **{
        helpers.book.vs.parent.get_pk_name(): data.penguin.pk,
        helpers.note.vs.parent.get_pk_name(): data.book.pk,
    })
    view.request.resolver_match = SimpleNamespace(url_name=helpers.note.vs.get_router_name("list"))
    assert view._cv_ancestor_guard() is None
    view.cv_navbar = NavBar(viewset=helpers.book.vs.name, items=[NavItem(child=helpers.note.vs.name, key="create")])
    known = (ancestors._resolved_ancestor(view, helpers.book.vs.name), ancestors._resolved_ancestor(view, helpers.pub.vs.name))
    baseline = _build(view)
    seam = helpers.note.Create._cv_page_link_ancestors(view, None)
    result = {"same_viewset": helpers.note.Create.cv_viewset is view.cv_viewset,
              "baseline_items": len(baseline["items"]),
              "aligned_result": _link_access(helpers.note.Create, actor, None, known, rendering_view=view),
              "immediate_only_result": _link_access(helpers.note.Create, actor, None, known[:1], rendering_view=view),
              "existing_page_seam": seam}
    print(result)
    assert result == {"same_viewset": True, "baseline_items": 1, "aligned_result": "permission", "immediate_only_result": "allowed", "existing_page_seam": ()}
```
