## 06.52-01

### Summary

The plan adds a regular `Enum` and one validating wrapper beside the private check, with a test module that covers the six D-54 cases, compatible instances and unsaved own objects. The mechanisms it relies on all hold in the source. Its weak points are the undecided non-list `known_ancestors` input and unsaved-object tests that only exercise a path where the object is never read.

### Strengths

- **Validation must come first, and the plan puts it there.** `_link_permission` returns `False` for a missing nearest parent before it looks at any farther slot (`src/crud_views/lib/link_access.py:72-74`), and `_higher_ancestor_gates` silently ignores slots beyond the chain (`link_access.py:49`). Without the wrapper's own pass, D-54 cases 1 and 5 would be denials or no-ops.
- **`_validate_ancestor_structure(viewset, relations=False)` is the right reuse** (`06.52-01-PLAN.md:36`). It walks the registry only, rejects Resource ancestors and raises its own `_AncestryError` (`src/crud_views/lib/ancestors.py:124-146`), so every ancestor level has a model.
- **`isinstance` against `_meta.concrete_model` is necessary, not a preference.** A model-permission parent ignores the object entirely (`src/crud_views/lib/viewset/__init__.py:507-509`), so without the type check any object counts as a known parent.
- **The delegation spy will work.** The wrapper calls the module-global `_link_access`, so a `monkeypatch` on the module proves no private call for invalid input.
- **No existing test pins the module in a way the new symbols break.**
  - The signature test covers only the private functions (`tests/test1/test_link_access.py:259-272`).
  - The source scan looks for retired names only (`test_link_access.py:204-212`).
  - The cost receipt checks hash length, not current hashes (`tests/test1/test_link_consumer_costs.py:835-836`).
- **Unsaved objects do not trip the database guard.** `_check_nested_auth` skips an object whose `_state.db` is `None` (`src/crud_views/lib/ancestor_db.py`, `_check_nested_auth`), so P52-08 produces no misleading "another database" error.
- **Not stringifying instances in error messages** avoids `__str__` side effects and keeps validation free of queries.

### Concerns

- **MEDIUM: `known_ancestors=None` and non-list inputs are undecided.** The plan documents "a finite ordered list/tuple" and puts everything else "outside the contract" (`06.52-01-PLAN.md:79`), with no test.
  - `check_link_access(BookList, user, known_ancestors=None)` is a natural call next to `obj=None`. The private function tolerates `None` (`link_access.py:72`), but a wrapper that counts slots raises a bare `TypeError`. That is the same kind of accidental error P52-07 removes for a missing ViewSet.
  - `known_ancestors=publisher` (a single instance) fails the same way.
  - `known_ancestors=Publisher.objects.filter(...)` is evaluated by `len()` or indexing and reads the ancestor table. That contradicts the documented "loads nothing".
  - Whatever happens here is frozen at 1.0 by accident unless the plan picks it.
- **MEDIUM-LOW: the unsaved "real acceptance path" never reads the object.** The plan uses "ordinary core behavior for the real acceptance path" (`06.52-01-PLAN.md:135`), but core `cv_has_access` ignores `obj` (`src/crud_views/lib/view/base.py:1346-1353`). The only path where an unsaved instance reaches a backend is Guardian: `checker.has_perm(codename, obj)` (`src/crud_views_guardian/lib/mixins.py:202-216`). From reading guardian 3.5.2, a `pk=None` object does not raise and yields no grants, and all unsaved instances of one model share a cache key. No test pins this, and it is the case the P52-08 caveat ("does not promise an allowed result") is about.
- **LOW: unsaved ancestors are neither tested nor documented.** D-54 does not reject them, so `known_ancestors=[Publisher()]` counts as a known immediate parent. Under a model-permission parent the gate passes and the state hook receives a row that does not exist. This is consistent with "membership is not checked", but the reference should say it.
- **LOW: the multi-table child under `isolate_apps` leaks a descriptor.** The repo precedent is a proxy (`tests/test1/test_ancestor_resolution.py:457-466`). A non-proxy child adds a `publisher_ptr` one-to-one, and Django sets the reverse accessor on the real `Publisher` class for the life of the xdist worker. I expect this to be harmless, but it is not the same isolation the precedent has.
- **LOW: frontmatter `requirements: [AC-1, …]` breaks precedent.** All seven 06.51 plans use `requirements: []`. `execute-plan.md:513-526` passes these IDs to `requirements.ready-ids` and `requirements.mark-complete`, and they do not exist in `REQUIREMENTS.md`. Best case this is a no-op; worst case it stalls close-out.

### Suggestions

- Decide the non-list case now and test it. My recommendation: accept only `list` or `tuple`, raise the prefixed `ImproperlyConfigured` for anything else including `None`, and document it as one more input rule. If the maintainer prefers `None` to mean "no ancestors", that works too; either way, pin it.
- Add two Guardian unsaved cases to `test_public_unsaved_own_objects`: an ordinary user (denied, no exception) and a superuser or `cv_guardian_accept_global_perms` view (allowed).
- Add one test and one reference sentence for an unsaved ancestor.
- State in the plan that `.value` of the enum members is not part of the contract, and have plan 03 say so in the reference. Otherwise `"allowed"`, `"permission"` and `"state"` are public in practice.
- Set `requirements: []` in all three plans and keep the AC labels in the body, as 06.51 did.

### Risk Assessment

**LOW-MEDIUM.** The production change is small and every mechanism it relies on checks out. The risk is the unpinned input edge becoming permanent at 1.0, not a wrong decision by the function.
