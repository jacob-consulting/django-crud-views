# Phase 06.6 Plan 05: Form request ownership Summary

**Workflow now uses the shared page-owned form boundary; enforced-CSRF requests prove stock, parent and extension ownership without expanding modal support.**

## Accomplishments

- Replaced workflow's direct crispy invocation with `cv_render_form` and removed its unused crispy tag load. Kept its choice branch, heading, non-form errors, implicit current-page POST target and outer token.
- Added 25 request tests covering eight actionable surface/mode combinations, forbidden users, protected deletion, separate workflow no-choice branches, rejected create/update modal opt-in, plain forms and polymorphic selection.
- Reused plan 01's raw event scanner before DOM inspection, with auxiliary sibling forms/tokens. The guard counts all raw nested starts, including unclassed forms; it checks the target owner's token rather than whole-document token totals. Fields and submitters are associated with the target form.
- Enforced CSRF uses extracted rendered tokens and real cookies. Missing/invalid tokens produce 403 without writes; valid tokens with invalid payloads retain ownership and errors; valid writes preserve create/update fields, confirmed deletion and workflow state/history.
- Cancel controls retain their actual `type="button"` and `data-cv-cancel-url`, with no submit/reset control substitution. Browser navigation/focus remains plan 07's gate.
- Removed only `PublisherFormSetForm.helper` and example `QuestionnaireForm.helper`, plus the newly unused example import. Parent create/update preserve management fields, nested child/grandchild persistence and token suppression. W292 detects missing parent submit icons without instantiating a form.
- Plain custom and plain polymorphic selection use local routes with actual library view classes, existing viewsets and no copied processing logic. Forms remain without helper attributes after GET and invalid POST. The existing crispy polymorphic selection route independently preserves native selection/submitter/redirect behavior.
- Approved UI-SPEC governs the ownership and workflow branch assertions; the plan's historical statement that no UI-SPEC exists is superseded.
