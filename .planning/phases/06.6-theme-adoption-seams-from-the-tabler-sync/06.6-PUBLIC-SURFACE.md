## Theme label floors

Import `register_label_mode_defaults` from `crud_views.lib.view.label_mode`.
Signature: `register_label_mode_defaults(defaults: dict[str, str]) -> None`.
The argument must be a dict; keys are exactly `context`, `list`, `card`, `form`, and values are
`label`, `icon`, `both`. Invalid registration raises `ValueError` before publishing any value.
Input is copied; later registrations merge per key, with the later value winning. Startup/AppConfig order
therefore matters. Atomic publication prevents readers observing half a registration.

The effective floor is package → theme → live `CRUD_VIEWS_LABEL_MODE_DEFAULTS` per key. Package defaults remain
context/list=`icon`, card=`both`, form=`label`. Explicit view/ViewSet/button modes retain their existing higher
precedence; whole-owner form maps are selected, never merged across owners. No singular/plural API was renamed.
Project settings are reread through `override_settings`; invalid configuration still triggers E108.
Non-strict invalid settings log once per location/value and use theme, then package. Strict mode raises;
an invalid owner retains first-error authority over an invalid setting. W292 uses the effective theme floor.

Implementation: `src/crud_views/lib/view/label_mode.py`, `src/crud_views/checks.py` and
`src/crud_views/lib/view/button_data.py`. Evidence: `tests/test1/test_theme_label_modes.py`, existing label-mode
and form-check suites. Recipes: [theme registrations](../../../docs/reference/theme.md#register-theme-defaults),
`docs/reference/settings.md`, `docs/reference/action_menus.md`, and
`docs/migrating-1.0.md#theme-defaults-and-additive-utilities`.

## Four class keys

All four are base-only utility keys, with no mode suffix or variant grammar. `register_button_classes()` and
`CRUD_VIEWS_BUTTON_CLASSES` retain package → theme → project precedence, including explicit empty/None values.
W362 and the full 88-key registry inventory recognize them.

| Key | Core default | Consumer |
| --- | --- | --- |
| `form:actions` | `""` | Library ordinary/delete `get_form_actions()` group |
| `form:filter-actions` | `""` | Library filter helper's independent action group |
| `alert:dismissible` | `alert-dismissible fade show` | Dismissible alert frame only |
| `alert:close` | `btn-close` | Close button inside the alert frame |

Group values supplement the selected pack's classes and structure. They are escaped and resolved each render;
the source layout/helper remains unchanged. Custom layouts are not rewritten. A custom `get_form_actions()`
can call `super()` and customize the resulting group; a wholly replaced group must opt into the documented
key lookup. Existing trailing filter hidden inputs and custom action replacement/removal remain intact.

The internal Bootstrap bridge is confined to `bootstrap5`, the installed distribution's resolved origin,
and exact audited crispy-bootstrap5 2023.10 source. Current Bootstrap packs and the actual native Tabler
pack forward group classes themselves. Custom loaders, other packs and provider overrides retain ownership;
no global crispy template replacement or universal pack-support promise is introduced.

Alert semantics, accessible Close name, `type="button"`, and `data-cv-alert-dismiss` remain unchanged.
Default Bootstrap bytes are unchanged. Empty/None dismissible values add no separator; empty close classes
retain `class=""`. Nonempty whitespace is not normalized. Core adapters retain their established behavior.

Implementation: `src/crud_views/lib/button_classes.py`, `src/crud_views/lib/crispy/form.py`,
`src/crud_views/lib/views/list.py`, `src/crud_views/lib/crispy/actions.py`, and `tags/alert.html`.
Evidence: `test_theme_action_groups.py`, `test_alerts.py`, complete class inventory/check suites and
native browser group/dismissal records. Contracts: `docs/reference/buttons.md`,
`docs/reference/theme.md#action-group-classes`, and `#custom-alert-frame`.

## Page form ownership and selected helper

`cv_render_form` selects the helper once and supplies `cv_form_helper` to the replaceable
`crud_views/tags/form.html`. A copied inner template must use `{% crispy form cv_form_helper %}`.
An absent/None helper gets a nonwrapping default. Render-local adaptation suppresses only crispy CSRF output;
source helper/layout state and custom bound hooks remain unchanged. A helper property need not support copying
or mutable `disable_csrf`. Computed and falsey helpers retain their supported semantics.
For a formset, crispy's render-local hidden-field request retains unmentioned row identity fields after
the source-bound custom layout hook runs. This preserves model-formset POST identity without mutating
the caller's helper flag or layout; ownership tests cover ordinary/custom hooks and a real CSRF POST.

Page templates own method, action, id, classes, enctype and novalidate. These are not transferred from helper
settings. Stock create/update/custom/delete and actionable full-page workflow render one outer form and one
CSRF input. No-choice full-page workflow omits its owner. Raw HTML scans reject nested forms before browser
repair; auxiliary sibling forms have independent ownership/tokens. Valid POST, invalid response, multipart,
authorization and submitter semantics remain unchanged.

| Configuration | Result through `cv_render_form` |
| --- | --- |
| `form_tag=True` | `ImproperlyConfigured` in both strict modes; set `form_tag=False` immediately |
| Nonempty raw `form_action`, `form_id`, `attrs`, `form_class`, or non-`post` `form_method` | Warning outside strict mode; `ImproperlyConfigured` in strict mode |
| Ordinary helper defaults, layout/field/media options | No unused-wrapper warning |

The diagnostic identifies attribute names without resolving/exposing action values. It cannot distinguish an
explicit assignment equal to the ordinary default, and copied templates that ignore `cv_form_helper` bypass
suppression without automatic diagnosis. These are runtime ownership diagnostics, not new numbered check IDs.
Custom helper overrides retain their existing static W292 inspection boundary; inherited library providers
recover inspection when redundant parent overrides are removed.

Full-page workflow retains `crud_views_workflow/view_workflow.content.html` and `view_workflow.action.html`.
Modal workflow retains the inherited `crud_views/view_custom_form.content.html` on GET/invalid POST/no-choice;
the eight branch records prove those distinct origins. Custom/delete/workflow modals retain replacement/focus
behavior. Create/update remain nonmodal and E251 rejects opt-in.

Library helpers now use `form_tag=False`, so standalone callers of library forms must supply their own wrapper.
Direct standalone crispy rendering retains its CSRF token; do not add a duplicate token to that wrapper.
Application-owned standalone crispy helpers and the GET-filter policy are unchanged. Executable
recipes cover computed helpers, escaped page attributes, selected inner helpers, copied workflow bodies and
standalone library wrappers in `tests/test1/test_theme_adoption_docs.py`; request ownership is covered by
`test_theme_form_ownership.py` and `test_theme_form_requests.py`.

## Private mechanisms and limits

`_PageFormHelper`, `_prepare_form_helper`, `_diagnose_form_wrapper`, the theme registry/locks and private
action-group/Bootstrap bridge machinery are implementation mechanisms, not new public constructors or hooks.
The documented selected-helper context and class keys do not expose those internals.
The evidence utility and temporary HTTP/browser routes are test infrastructure, not shipped product APIs.
The independent UI audit observes that the unchanged native nested FormActions wrapper can retain 0px
row spacing between wrapped mobile controls despite the new outer gap utilities. The contract promises
additive class consumption and pack preservation; it does not certify every pack's inner spacing. See
[06.6-UI-REVIEW.md](06.6-UI-REVIEW.md). The user explicitly accepted this W1 appearance in
[06.6-UAT.md](06.6-UAT.md), which records all seven scoped human checks passing. Browser/version was not
supplied and no assistive-technology claim is inferred.

Final exact commands, source/runtime/asset identities and historical exclusions are in
[09-REGRESSION.md](09-REGRESSION.md) and [09-final-evidence.json](09-final-evidence.json).
Human visual observations, independent security/code review and canonical phase verification remain separate
acceptance gates. No final stability freeze, universal browser/AT claim or later-phase implementation is made.
