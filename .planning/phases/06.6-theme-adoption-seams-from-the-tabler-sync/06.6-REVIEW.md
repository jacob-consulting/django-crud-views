### CR-01: BLOCKER — Render-local helper loses formset hidden fields (resolved)

**File:** `/home/alex/projects/alex/django-crud-views/src/crud_views/templatetags/crud_views.py:486-495`

**Issue:** When `cv_render_form` receives a Django `BaseFormSet` with a nonwrapping helper and a
field-selective layout, crispy sets `helper.render_hidden_fields = True` before rendering its rows.
That assignment lands on `_PageFormHelper`, but its unconditional delegation reads the source
helper's flag and returns `render_layout` bound to the source. Thus crispy's request to render
unmentioned hidden fields never reaches layout rendering. Hidden identity fields disappear;
a model formset that needs its hidden PK to update existing objects will submit without that field.

This is a behavioral regression from the prior direct crispy boundary, not the intended
wrapper/token correction. The inline parent-formset fixture uses another rendering path and
does not cover passing a formset directly to this public tag.

**Reproduction:** On the cached Python 3.12 / Django 5.2 / crispy 2.7 runtime, configured using
`tests.test1.conftest.pytest_configure()`:

```python
from django import forms
from django.template import Context, Template
from crispy_forms.helper import FormHelper
from crispy_forms.layout import Layout

class Row(forms.Form):
    name = forms.CharField()
    identity = forms.IntegerField(widget=forms.HiddenInput)

def build():
    rows = forms.formset_factory(Row, extra=0)(
        initial=[{"name": "A", "identity": 42}]
    )
    rows.helper = FormHelper()
    rows.helper.form_tag = False
    rows.helper.layout = Layout("name")
    return rows

for source in (
    "{% load crispy_forms_tags %}{% crispy form form.helper %}",
    "{% load crud_views %}{% cv_render_form %}",
):
    rows = build()
    rendered = Template(source).render(Context({"form": rows}))
    print('name="form-0-identity"' in rendered)
```

Observed output: direct crispy **True**, `cv_render_form` **False**.
The source helper's `render_hidden_fields` stays false through the new boundary.

**Fix:** Preserve crispy's render-local hidden-field request without mutating the caller's
helper or rebinding arbitrary custom methods in a way that breaks `super()`. One bounded
approach is a render-local `render_layout` wrapper that delegates the original hook and then
renders only still-unrendered hidden fields when crispy requested formset hidden-field rendering.
Use crispy's `render_field`/`form.rendered_fields` contract, preserving the active pack and
already-rendered hidden fields. Add direct formset and model-formset regressions, including a
successful existing-row POST, custom helper hooks, caller immutability, repeated rendering,
and current/floor crispy versions.

**Disposition:** Reported to orchestrator and plan 09 executor; confirmed by executor.
Correction requires a source-owning execution agent. No reviewer source edits.

### CR-02: BLOCKER — Passing companion runs bypass the collection-shrink guard (resolved)

**File:** `/home/alex/projects/alex/django-crud-views/tests/browser/theme_adoption_sources.py:494-499`

**Issue:** `compare_suite_failures` returns immediately when the candidate has no reported
failures. Baseline parsing and the existing `result["count"] >= original["count"]` guard run
only for failing candidates. A collection regression that removes tests, including the failing
tests, therefore becomes an accepted passing result. Both `prepare` and `verify_replay` use
this function, so the supposedly protected full-suite comparison can accept reduced coverage.

**Reproduction:** Supplied command records with correct `log_sha256` values through the real
`suite_result` parser: baseline output `Ran 109 tests in 1s` plus
`FAIL: test_old (pkg.tests.Case.test_old)`, exit 1; candidate output
`Ran 1 test in 1s\nOK`, exit 0. Calling
`compare_suite_failures(candidate, baseline, {}, {})` returned:

```python
{"retained_failures": [], "outcome": "passed"}
```

It should reject with `companion test collection shrank`.
This demonstrates a validator defect; it does not assert that the currently retained real
companion runs have reduced collection.

**Fix:** Whenever a baseline is supplied, parse it and enforce the collection-count guard
before the passing-result early return. Keep the existing missing-baseline requirement for
failing candidates. Add regression cases for reduced passing collection and unchanged/increased
passing collection, preserving source checks for retained failing tests.

**Disposition:** Reported to orchestrator and plan 09 executor; executor confirmed and owns the
utility fix and regression.
