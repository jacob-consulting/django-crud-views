### Pillar 5: Spacing (2/4)

- **WARNING W1, native pack integration limitation:** Companion `src/crud_views_tabler/buttons.py:40–41` correctly registers exactly `d-flex flex-wrap gap-2` and `d-flex flex-wrap gap-1`. However, companion `src/django_tabler/templates/crispy_tabler/layout/formactions.html:4` puts them on the outer `.form-footer`, while lines 9–10 put all controls in a single inner div. The actual flex container therefore has one child; its gap cannot separate the buttons.
- Fresh 375px `filter-pinned-mobile.png` and `workflow-mobile.png` show touching wrapped button rows. Read-only computed-style inspection confirms outer `display:flex` with 4px/8px gap respectively, and inner `display:block` with `gap:normal`. Class-presence acceptance therefore overstates visible spacing effectiveness. Add a geometry assertion for wrapped controls, not merely another class-string assertion.
- Measured filter button bounds are y=414–454 and 454–494; workflow bounds are y=616–656 and 656–696. Both inter-row gaps are **0px**, confirming the screenshot finding numerically.
- This is **not newly introduced wrapper damage**: the native pack structure is preserved, as required. It is an unresolved practical limit of the selected additive spacing adoption. Keep the exact class registrations and pack ownership; address it with scoped theme CSS only if approved for follow-up. Core custom layouts must remain opt-in.
- All 33 captured states have `documentElement.scrollWidth === innerWidth`. Ordinary 375px create/custom/parent actions fit; the three-column Author layout collapses on mobile. No new arbitrary spacing values were introduced. This positive evidence does not negate the wrapped-action failure.
