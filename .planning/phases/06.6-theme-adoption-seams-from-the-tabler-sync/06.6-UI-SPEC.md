## Interaction Contract

### Page-owned forms and helpers — D-01–D-04, D-16

- An actionable target content region contains one raw owning form, no nested form start tag and one owned CSRF
  input. Auxiliary sibling forms retain their independent tokens. Whole-document form/token counts cannot prove
  this contract; parser-repaired DOM alone cannot prove absence of nesting.
- Page templates retain method, action, enctype, novalidate, IDs and other outer attributes. Create/update/custom
  forms keep POST to `request.get_full_path` and multipart encoding; delete retains its existing POST attributes;
  full-page workflow retains its implicit current-page target. Do not transfer wrapper settings from helpers.
- Select `form.helper` once, by presence rather than truthiness. Absent/None obtains a nonwrapping default;
  existing falsey helpers retain selection and their existing hook semantics. Pass `cv_form_helper` explicitly
  through the replaceable inner template. Preserve context tiers and restore context on success or exception.
- Library helpers set `form_tag=False`. Application `form_tag=True` always raises `ImproperlyConfigured`, including
  non-strict mode. For compatible helpers, nonempty raw action, form_id, attrs, form_class and nondefault method
  warn non-strict and raise strict. Ordinary defaults are quiet; default-valued explicit assignment is not
  promised detectable. Field/label/media/layout settings are outside these wrapper diagnostics.
- Suppress inner CSRF only at `cv_render_form`, without mutating caller helpers/layouts or changing custom hooks.
  Completed plan 01 uses a private forwarding adapter; copying is not a required public mechanism.
- Standalone crispy rendering of library forms now loses its helper-owned wrapper while retaining its existing
  token. A caller-owned wrapper around that path must not add another token. Standalone custom helpers and GET
  filter policy retain their existing behavior. This differs from the page-render path, whose page emits the token.
- Copied inner templates must consume `cv_form_helper`; copied workflow action templates must use `cv_render_form`.
  Legacy copies bypassing that boundary can emit duplicate tokens and cannot be reliably auto-diagnosed. Do not
  rewrite HTML or global crispy templates to conceal that migration requirement.

cannot write. Retain accepted conditional clearing, field-aware persistence, reset, fragment authorization,
dynamic row management, modal replacement and focus behavior from prior phases.

### Label modes, native controls and cancel — D-05–D-07, D-15/D-16

Package floors remain context=icon, list=icon, card=both, form=label. The new
`crud_views.lib.view.label_mode.register_label_mode_defaults(defaults: dict[str, str]) -> None` validates the
entire input before publishing a copied per-key merge; later registration wins. Invalid registration always
rejects without changing prior values. Live project settings override theme then package per key; explicit
button/view modes remain above those floors. Preserve owner-first selection of a whole form map; never merge
different owners' maps. Invalid project values warn and fall back to theme then package non-strict, raise strict;
E108 and effective W292 diagnostics remain operative. Do not rename accepted singular/plural owner APIs.

| Mode | Visible / accessible result |
|------|-----------------------------|
| both | Native icon plus visible escaped label |
| icon | Native icon plus translated hidden label through `form:hidden-label`; existing title and `data-cv-tooltip="form"` |
| label | Visible escaped label without the inline SVG/icon |

Retain missing-icon diagnostics/fallback policy. Required companion acceptance cannot pass by disabling icons,
using text-only defaults, substituting Font Awesome, or rendering empty/unrelated SVG paths.

The companion registers exactly `{"form": "both"}` from AppConfig. Its native action mapping is:

| Action kind | Native type / label | Semantic icon → companion definition |
|-------------|---------------------|--------------------------------------|
| submit | submit / Save or application label | save → tabler:check |
| delete | submit / Delete | delete → existing tabler:trash |
| cancel | button or eligible native link / resolved Cancel | cancel → tabler:arrow-left |
| filter-submit | submit / Apply Filter | filter → existing tabler:filter |
| filter-reset | reset / Reset Filter | filter-reset → tabler:filter-x |

All five kinds must be exercised under both/icon/label, project overrides, explicit owner/kind overrides and
restoration to the theme floor. Preserve actual name/value/id, disabled semantics, filtering GET behavior and
native reset without submit. Workflow retains its separate existing workflow semantic icon.

Cancel remains eligible for a native link only for semantic cancel with native type button, a usable URL and
no disabled state. Submit/reset never become links. Eligible links have one authoritative escaped href and no
button-only attributes; disabled or URL-less cases fall back to a native type=button, without href.

| Cancel destination | Preserved rendering and activation |
|--------------------|------------------------------------|
| Usable URL | Existing selected button/link navigates to its resolved destination without submit/reset; preserve modal dismissal/origin semantics |
| Absent/None | Native button even when anchor requested; omit `data-cv-cancel-url`; click/Enter/Space cause no navigation, submit or reset and preserve the edited value |
| Explicit empty string | Native button even when anchor requested; retain `data-cv-cancel-url=""`; unchanged handler performs a real same-URL document GET; zero submit/reset or POST; do not promise edited values survive navigation |

For both URL-less states test requested button/anchor, each label mode and click/Enter/Space separately. Record
attribute presence/value and actual outcome. Empty-destination evidence must include the completed GET and new
document; intercepting navigation or substituting None cannot pass. This preserves Phase 6.1, not a new behavior.
