- Private module src/crud_views/lib/view/cancel.py owns effective_cancel_keys(owner) returning a fresh tuple, navigation_params() returning the existing origin name plus its derived cancel/restore names, capture_cancel_state(view, origin) returning a token or None, read_cancel_state(view) returning CancelCapture or None, and clean_navigation_query(querydict) returning a mutable cleaned copy. CancelCapture is an immutable record with origin and query fields; validity is distinct from query="".
- Keep CrudView.cv_cancel_keys=None for non-form base classes. CrudViewProcessFormMixin.cv_cancel_keys="auto" enables automatic form behavior; polymorphic selector adopts the same value in plan 03. This string is the explicit, JSON-readable automatic representation, not a list entry. Effective auto keys are registered list/card and, for cv_object=True, registered detail; list aliases card only when list is absent. Honor MRO and instance overrides. Explicit lists are copied, None/[] return no origins. Existing metadata exposes "auto", never an unserializable object. Existing E252 accepts auto/None/list and validates explicit list keys/types; E253 stays success-only.
- Parameter names are derived at use time from crud_views_settings.origin_param: existing key channel (default cv_from), plus cv_from_cancel and cv_from_restore. No additional setting. A changed origin_param changes all three names. Reserve and strip all three in captured/restored/session query state.
- Token uses django.core.signing.Signer(salt="crud_views.cancel.v1").sign_object(payload, compress=False); unsign_object uses the same salt. Use non-timestamp Signer for deterministic URLs and no arbitrary expiry. Signing adds integrity, not confidentiality or authorization. Payload has exactly v=1 (integer), origin (registered key), query (QueryDict.urlencode string), viewset=[cv_viewset.app or "", cv_viewset.name], parents={every get_parent_url_args() name: str(current kwargs value)}. There is no target path, user grant, source object PK or session record in it.
- Bound before decoding: token at most 16384 ASCII bytes; uncompressed decoded JSON at most 12288 bytes; query at most 8192 UTF-8 bytes and 128 total key/value pairs; origin at most 128 characters; each viewset identity member at most 256 characters; at most 16 parent fields, each key/value at most 512 characters. Reject compressed-token prefix before unsign_object so a signed compression bomb cannot allocate unbounded data. Validate exact field set, concrete types, version, signature, duplicate request scalar parameters, matching origin channel, current ViewSet and exact current parent coordinate map. Validate query pair count with parse_qsl(max_num_fields=128, keep_blank_values=True) before QueryDict, then clean internal fields. Use only narrow signature/JSON/Unicode/value decoding catches. Hook, database and programming failures propagate.
- Emission outside the limits omits the cancel capture; a present but invalid/oversized token forces configured fallback and never degrades into a trusted key-only origin. A missing token may use the existing validated key-only origin behavior, without claiming captured empty state. When emission cannot encode a cancel origin, omit its key unless unchanged dynamic-success behavior independently needs that key. Explicit static cancellation does not emit cancel state. Preserve existing success-key selection and origin channel semantics.
- Public CrudView.cv_get_cancel_url(self, obj=None, user=None, request=None) returns str or None. Defaults come from self.object and self.request; a request is required when neither supplied nor bound (raise ImproperlyConfigured). A supplied request supplies user unless explicitly passed. No-object owners ignore supplied/form-instance objects for origin eligibility. Object origins require a saved model instance (not _state.adding), while existing Resource objects retain their existing support. Reverse only through self.cv_get_url using current object/current parent kwargs. Captured query is appended to an accepted origin only, never to fallback or success URLs. Append the derived restore scalar with value 1 for accepted list/card captures, including empty query.
- New private target classmethod _cv_cancel_target_available(cls, user, obj, rendering_view) is the extension seam. Core checks cls.cv_has_access(user, target_obj) before cls.cv_action_enabled(user, action_obj): target_obj is saved form object only for object destinations, otherwise None; action_obj is saved object, current URL parent for nested no-object destinations, otherwise None. Do not dispatch a target request or call mutation hooks. Plan 02 adds Guardian's implementation and the diagnostic matrix without changing this signature.
- Existing get_cancel_button_context keeps a dictionary with cv_url (str or None) and translated cv_action_label. Crispy get_cancel_button_kwargs keeps its dictionary customization contract. get_cancel_button returns Button or None based on the resolver outcome before invoking customization; get_form_actions and CrispyDeleteForm.helper filter None before constructing _ThemedFormActions. Do not change the standalone Button leaf's URL-less/disabled behavior. Avoid caching across requests or on classes.
- Existing cv_get_cancel_key remains available as key resolution only; update it for effective defaults but remove its old cancel-template recommendation. It is not the new URL/permission contract. No unrelated public API is removed.
