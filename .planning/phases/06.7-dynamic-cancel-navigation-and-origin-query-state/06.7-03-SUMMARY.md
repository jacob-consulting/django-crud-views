## Accomplishments

- `PolymorphicCreateSelectView.cv_cancel_keys="auto"` makes selector cancellation follow the standard no-object default. Successful type selection still reverses the selected content-type route.
- The handoff validates the original bounded capture, concrete allowed keys, same-ViewSet registration and no-object destination eligibility. Valid legacy input is encoded with `query=None`; captured empty query remains empty and receives restoration semantics. Invalid supplied state becomes the bounded `invalid` marker. Static concrete forms receive no cancel state.
- Only the cancel token is forwarded. Shared `cv_from`, arbitrary query/form fields and raw return URLs are not forwarded. The sixteen selector/concrete cancel/success configuration combinations preserve pre-existing concrete save fallback; direct concrete requests retain explicit dynamic-success behavior.
- Repeated invalid selector and concrete POSTs, repeated selections, list/card origins, parallel selector instances and actual session-memory changes retain the original destination. Tampered, oversized, duplicate/mismatched shared keys, token-only handoff, explicit allowed/rejected keys and detail-to-create exclusion are covered.
- Public signature: `cv_cancel_url(context, obj=None) -> str | None`, registered with `takes_context=True`. It normalizes unresolved/empty template arguments, defaults to the authoritative view object, and calls `view.cv_get_cancel_url` with the current context request/user. Missing context and fallback configuration errors propagate; it never calls generic action-link capture.
- The migrated template contract is `{% cv_cancel_url as url %}{% if url %}<a href="{{ url }}">Cancel</a>{% endif %}`. Tests execute the Django template engine and normal autoescaping, including hostile raw resolver URL characters and decoded repeated/empty query values.
- All five form families retain capture across two invalid POSTs with both native anchors and buttons. Supported modal delete/custom-object/workflow responses retain capture across 422 replacements. Workflow page inheritance, omitted page action, single form/CSRF ownership, submit controls, protected-delete omission and create/update E251 remain intact.
- Custom `get_form_actions` and delete-helper subclasses filter `get_cancel_button() is not None` before layout construction. Accessible destinations preserve kwargs customization; denied destinations omit controls and skip kwargs hooks in both rendering modes. Exact save `Location` and supported modal `X-CV-Redirect` values remain unchanged.
