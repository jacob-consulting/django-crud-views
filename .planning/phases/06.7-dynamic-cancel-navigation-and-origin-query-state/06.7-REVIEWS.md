## 06.7-01

**Summary.** The plan correctly identifies every seam it must change: the static defaults at `src/crud_views/lib/view/base.py:81-82`, the key-only emitter at `base.py:808-815`, the user-ignoring cancel context at `base.py:817-824`, the bare-list restoration at `src/crud_views/lib/views/mixins.py:391-397`, and the crispy action group at `src/crud_views/lib/crispy/form.py:57-58,138-149`. The interface block is unusually precise and the signed, bounded transport is a sound fit for the project's security enforcement. Two things are missing: the plan has no consumer for the restore marker on card pages, and it does not acknowledge that the new default changes four committed goldens and at least fourteen exact-link assertions in test files its verify commands never run.

**Strengths.**
- `cv_cancel_keys="auto"` on `CrudViewProcessFormMixin` lands on exactly the form family D-02 names: `create.py:12`, `update.py:9`, `delete.py:51`, `form.py:10,40` all put the mixin before `CrudView`, and `WorkflowView(CustomFormView)` at `src/crud_views_workflow/lib/views.py:18` inherits it. List, card, detail and action views stay at `None` (`base.py:82`).
- The existing F2 rule at `base.py:803-805` already prevents an object page from sending an origin to a no-object target, so D-04 (no detail → create capture) holds without new code.
- The plan calls out the two places where a string sentinel would be silently iterated: `base.py:523-525` would check `is_view_registered("a")` and fire E252, and `base.py:796` would splat `"auto"` into four one-character keys. Both are named in the interface block.
- `ViewSet.app` exists (`src/crud_views/lib/viewset/__init__.py:71`), so the proposed `viewset=[app or "", name]` binding is implementable as written.
- Restoring explicit-empty state before the stored-query redirect is placed correctly: `mixins.py:395-397` is the only branch that revives old filters, and `session.py:71-80` persists only on clean exit, which the plan relies on for "no write when disabled".
- Reserving three derived names from `origin_param` (`settings.py:38-39`) avoids a new setting and keeps `test_custom_origin_param_name` (`test_cancel_origin.py:369-379`) meaningful.

**Concerns.**
- **HIGH. Card origins have no restore-marker consumer, so the marker leaks and accumulates.** `CardListView(CardOrderMixin, CrudView, generic.ListView)` at `src/crud_views/lib/views/card.py:17` does not include `ListViewTableFilterMixin`, yet the interface says to append the restore scalar "for accepted list/card captures". On a card page the marker would survive in `request.GET`, be copied into the order form's hidden inputs by `mixins.py:271-279`, and into every pagination link by `templatetags/crud_views.py:557-569`. A later row action would then capture a query the plan promised to clean only "on capture", and the browser URL keeps the marker across order changes. The plan's only consumption point is `ListViewTableFilterMixin.get`.
- **HIGH. The default change alters committed goldens the plan does not mention.** `tests/test1/golden/action_menus/{list_full,toolbar_detail_full,cards_author_full,toolbar_publisher_list}.html` contain hrefs to update/delete/create. They are rendered from `cv_author` and `cv_publisher` (`test_action_menus_golden.py:88,106,118,132,142`), whose form views have no explicit keys (`test_cancel_origin.py:47-53` asserts `cv_cancel_keys is None` on `cv_author`'s update view). Under `auto`, those links gain `?cv_from=…&cv_from_cancel=<signed token>`. PROJECT.md's byte-identical rule allows exceptions only "where a phase says so", and neither ROADMAP nor this plan says so. The token is deterministic under the fixed `SECRET_KEY="django-testing"` (`tests/test1/conftest.py:46`), but a golden containing a signature tied to a salt and secret is brittle, and Plan 05 later forbids "blindly regenerating goldens". A decision is needed here, not in wave 4.
- **MEDIUM. Blast radius of the default is discovered too late.** Fourteen exact `href="{…create|update|delete…}"` assertions exist across seven files (`test_guardian_parent_none.py`, `test_authorization_templates.py`, `test_authorization_matrix.py`, `test_sibling_context_button.py`, `test_core_nested_create_state.py`, `test_inaccessible_actions_resolve.py`, `test_action_menus_groups.py`). At least the card-page ones break: `test_guardian_parent_none.py:875` asserts `row["cv_url"] == create_url` on a card page, and `card.py:77` routes that URL through `cv_get_link_url`, so a nested create (auto, `card` registered) now carries an origin. Plan 01's three verify commands run none of these files; the full suite first runs in Plan 05-02. Plan 02's verify then runs `test_guardian_parent_none.py` and will fail on a Plan 01 change it does not own.
- **MEDIUM. The "tracer" is not thin.** Task 01-01 touches five production files and asks for "the complete bounded parser at its creation" plus the core target adapter, the crispy omission path and list restoration. That is the whole architecture in one task, which defeats the tracer's purpose as an early integration checkpoint and makes the red-first test a poor diagnostic when it fails.
- **LOW. Token bound exceeds practical URL limits.** A 16384-byte token and 8192-byte query sit above common defaults (nginx 8k header buffers). Emission only omits capture above the plan's limits, so URLs between roughly 8k and 16k would be emitted and then rejected with 414 by the front end. Research explicitly declined to invent a browser limit; a lower practical default or a documented note is still warranted.
- **LOW. `cv_cancel_key=None` semantics.** `cv_get_cls(None)` resolves to the current view (`base.py:501-502`), so "cancel to self" is what the plan preserves. Fine, but the docs in Plan 04 should state it, because D-09's missing-fallback error must not fire for this legal value.
- **LOW. Performance.** For nested no-object destinations the target adapter resolves the URL parent via `cv_get_parent_object` (`base.py:864-876`), one extra `get_object_or_404` per form render. Acceptable, but the form view already resolved that parent in Guardian dispatch; caching per request would avoid a duplicate query.

**Suggestions.**
- Strip the three navigation names at one request-level seam shared by list and card views (a small mixin, or in `CrudView.setup`), and let only `ListViewTableFilterMixin.get` do the session work. Add a card round trip to `test_cancel_state.py` that asserts the order form hidden inputs and pagination `base_qs` contain no `cv_from_*` names.
- Decide the golden policy now and write it into the plan and CHANGELOG: either regenerate the four action-menu goldens as the phase's declared markup change, or make `test_action_menus_golden.py` normalize `cv_from_*` query parameters before comparison. Do not leave this to Plan 05.
- Add `tests/test1/test_action_menus_golden.py tests/test1/test_guardian_parent_none.py tests/test1/test_authorization_templates.py tests/test1/test_authorization_matrix.py` to task 01-02's verify, and list those test files in `files_modified` if their exact-link assertions are to be migrated to path-plus-parsed-query assertions.
- Split 01-01: tracer = emit key plus token, resolve, render through crispy, visit, assert same records. Move the full bound/limit matrix and the session clear-on-empty behavior into 01-03 where its tests already live.

**Risk Assessment: HIGH.** The design is right, but the plan under-reports its own blast radius (goldens, card pages, cross-suite exact links), and the omissions land on later plans that do not own the files.

## 06.7-01

The vertical slice is the right shape: one signed per-form capture, sibling reversal only, and an explicit empty-query marker before `ListViewTableFilterMixin` restores session memory. It will not work if `"auto"` is stored on `cv_cancel_keys` and the existing key helpers are left as they are.

**Strengths**
- Emission already goes through `cv_get_link_url` for row, context, and card actions (`src/crud_views/lib/view/base.py:712`, `src/crud_views/lib/view/buttons.py:103`, `src/crud_views/lib/views/card.py:77`). A tracer that follows a rendered Update link will exercise the real path.
- Invalid POST already keeps the query: create, update, custom, and delete templates post to `request.get_full_path`.
- Session writes already go through `SessionData.__exit__` (`src/crud_views/lib/session.py:71-80`), so clearing `filter_query_string` inside the existing `with` block will persist.
- Detail identity stays on the form object. `cv_get_url` puts `obj.pk` in the path (`base.py:541-542`); keeping the PK out of the token matches that.

**Concerns**
- **HIGH** — `"auto"` is not a key list, and the current helpers iterate it as one. `cv_get_link_origin_key` unpacks `cls.cv_cancel_keys or ()` (`base.py:796`). A non-empty string unpacks to characters, so `self.cv_key in keys` is false for `"list"` and no origin is emitted. `cv_get_allowed_origin_cls` uses `origin not in keys` (`base.py:745`), which is a substring test: a one-letter key such as `"a"` is in `"auto"`. `cv_origin_keys_registered` likewise iterates the string (`base.py:518-524`). The plan says E252 must accept `"auto"`, but it never names these three call sites. The tracer fails until all three resolve `effective_cancel_keys()` first.
- **MEDIUM** — Disabled persistence returns before any cleaning (`src/crud_views/lib/views/mixins.py:364-365`). The task says to strip navigation fields in that branch too, but the failure statement only requires the session blob to stay unchanged, so a leftover `restore=1` in `request.GET` can still pass.
- **MEDIUM** — Card lists do not use `ListViewTableFilterMixin` (`src/crud_views/lib/views/card.py:17`). URL capture can still restore a card query, but no task follows a filtered card link. CAN-02's card half is untested.
- **LOW** — `request.GET` is cached from `QUERY_STRING`. Cleaning one and not invalidating the other leaves the restore marker in django-filter and pagination links.

**Suggestions**
- In the same change that sets `CrudViewProcessFormMixin.cv_cancel_keys = "auto"`, route `cv_get_link_origin_key`, `cv_get_cancel_key`, and E252 through `effective_cancel_keys()`. Never pass the raw string to `in` or `for`.
- Add one filtered card → update → Cancel request next to the list tracer.
- Assert the disabled-persistence response query no longer contains the restore or cancel parameter.

**Risk: MEDIUM.** The transport and session rules match the code. The `"auto"` string is a real foot-gun in the helpers the plan relies on, and the tracer should catch a missed emission fix only if those helpers are actually updated.

## 06.7-02
