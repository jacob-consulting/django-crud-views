# Phase 06.7 — UI Design Contract

This contract implements CONTEXT D-01–D-16 and CAN-01–CAN-07 through existing form and navigation surfaces.
Preserve the accepted Phase 06.6 theme, typography, action rendering, form ownership and modal contracts.
The change is the destination and availability of Cancel; no screen, visual redesign or confirmation dialog is added.

Status boundary: plan 01 is complete. Its summary reports CAN-01–CAN-03 complete, a 189-test focused superset
and 918-test migration selection passing. Those are recorded upstream results, not tests rerun for this document.
Plans 02–05 remain pending, including Guardian integration, the template tag, selector forwarding, migration
documentation and browser acceptance. Requirements below describe the required final behavior, not completed
implementation or human visual acceptance. Current plans/source supersede research's earlier proposed names
and its historical statements that requirement IDs and automatic-default representation were unsettled.

## Copywriting Contract

Keep translated and application-provided labels. The existing Save label is the primary CTA; do not rename it
to meet a generic verb/noun convention. Navigation metadata never becomes visible end-user copy.

| Element | Copy / required behavior |
|---------|--------------------------|
| Ordinary primary CTA | Existing translated `Save`, or the application's current submit label |
| Cancel | Existing resolved translated `Cancel`; do not substitute a destination name or Back |
| Delete CTA and confirmation | Existing translated `Delete` and required `Confirm deletion` checkbox; Cancel never triggers either confirmation or submission |
| Filter actions | Existing translated `Apply Filter` and `Reset Filter`; preserve their IDs and GET/reset semantics |
| Empty form heading/body | No new empty-state message; render existing blank fields, help and actions |
| Empty returned card list | Existing translated `No items found.`; keep filter/reset controls where already available |
| Empty returned table list | Preserve the active table/application empty text and existing filter/reset affordances; no replacement universal heading |
| No accessible Cancel destination | Render no Cancel control, explanation, disabled substitute or empty placeholder; retain the usable submit action |
| Invalid origin input | No new banner; use the accessible configured fallback or permission omission |
| Invalid form submission | Preserve actual translated field/non-field validation messages and entered values under existing conditional rules; users correct fields and resubmit through the existing CTA |
| Modal load/submission transport failure | Preserve the existing full-page fallback to the requested/form URL; no new toast, retry control or error panel |
| Missing/structurally unusable configured fallback | Developer-facing diagnostic names the owning view and effective `cv_cancel_key`, and directs the developer to configure an existing usable destination; runtime `ImproperlyConfigured`, planned startup `viewset.E256` |
| Protected deletion | Preserve existing protection/generic notices and omitted confirmation form; introduce no Cancel control on that branch |

Keep all translated labels, object names and query values escaped. Do not display captured query payloads,
signatures or private diagnostic data in the form. Configuration faults remain distinct from permission denial
and ordinary invalid request input. Protected-object labels retain existing permission filtering.

## Interaction Contract

### Destination selection and the five routes — D-01–D-04, D-09–D-11

| Entry path | Cancel result |
|------------|---------------|
| List → Update | Original list and captured query |
| Detail → Update | Current saved form object's detail and accepted captured query |
| List → Create | Original list and captured query |
| List → Delete | Original list and captured query; object remains |
| Detail → Delete | Current saved form object's detail; object remains |

Automatic standard-form configuration is `cv_cancel_keys="auto"`. Create and no-object custom forms accept
registered usable list/card origins. Object-based update/delete/custom forms also accept registered detail.
Detail uses the form's saved object, never another captured object's identity. Detail → Create uses fallback.
Explicit lists allow their configured custom keys; `cv_cancel_keys=None` and `[]` retain static selection.
`cv_cancel_key` remains the configured fallback, default `"list"`, including list-to-card resolution. Singular
`cv_cancel_key=None` retains current-view routing semantics; it is not the plural static-selection setting.

Resolution order is an allowed, usable, accessible origin, then the accessible configured fallback. If both
registered destinations are inaccessible, omit Cancel entirely and keep authorized form submission usable.
Never render an empty href, disabled Cancel or a third arbitrary destination. Missing/malformed/disallowed/
unusable request origin safely selects fallback. If fallback is needed but its configured route is missing or
structurally unusable, report the configuration error; do not disguise it as omission. A missing current parent
at the built-in lookup is runtime unavailability, not a missing registration. Unexpected custom-hook errors
remain errors. A valid origin need not resolve an unused fallback.

Evaluate each target's existing core/Guardian object, parent, actor and state policy; current-form permission
does not grant destination access. An authorized empty Guardian list remains eligible. Preserve target request
authorization even after a link was rendered, including permission changes between render and click.

### Captured query and independent forms — D-05–D-08

- Capture the actual originating URL's filters, sorting, pagination, repeated values and blank values. Preserve
  per-key value order, not arbitrary interleaving between different keys. Reverse within the same ViewSet and
  current parent coordinates; no caller-supplied return path is accepted.
- Each open form owns its capture. Tab B changing ordinary remembered filters does not change Tab A's Cancel.
  Tab A returning to Adams after Tab B stores Pratchett must show Adams; later bare-list visits remember Adams
  when persistence is enabled. Tab B's already captured return remains unchanged.
- Explicitly empty captured query restores an unfiltered list and clears only its remembered query when
  persistence is enabled. Absent/legacy uncaptured state is different: preserve ordinary fallback/bare-list
  behavior. Disabled persistence renders restored state without writing or clearing session memory.
- Update memory on the returned list visit, never merely by rendering a form or resolving Cancel. Clean reserved
  navigation fields before list filtering, ordering, pagination, hidden controls and subsequent action links.
  Apply restoration to explicitly allowlisted custom-key list-family destinations without making them automatic.
- Invalid submissions retain the original capture across create/update/delete and both custom-form families,
  including repeated invalid submissions and supported modal 422 replacement. Do not recapture the form page.
- Polymorphic selection retains the original allowed list/card capture through the selected concrete create
  form and invalid creation. Preserve content-type routing, each view's independent auto/static choices and
  unchanged success behavior; the selector must not become the origin or newly forward success-origin state.
- Bounded invalid or excessive capture uses safe fallback when Django receives the request. Parser bounds do
  not guarantee full request-line acceptance by proxies/servers; do not promise fallback for upstream rejection.

### Controls, forms and modal behavior — D-12, D-15–D-16

Use `cv_get_cancel_url(obj=None, user=None, request=None)` as the shared URL-or-None contract. Crispy button,
eligible native anchor, supported modal and migrated template must expose equal decoded URLs or all omit
Cancel for the same request/object. Keep ordinary customization hooks on accessible outcomes and filter None
before custom FormActions/layout construction. Do not change standalone URL-less Button behavior globally.

The stock button remains native `type="button"`, navigating through `data-cv-cancel-url` and the current delegated
handler; clicks on nested text/icons behave identically. Configured native anchors retain a single escaped href,
native browser link behavior and no button-only submit attributes. Cancel never submits, saves or deletes,
including dirty or browser-validation-invalid forms. Retain native keyboard activation and visible focus styling;
hidden Cancel has no focusable remnant. Form omission must not disable, intercept or remove Save/Delete.

Preserve all label modes: label is visible text; both adds the semantic icon; icon retains translated hidden
text via `form:hidden-label` and the existing title/tooltip. Preserve selected theme floors and caller overrides.
Do not replace native Tabler icons with stock Font Awesome in theme integrations.

Keep one owning raw form and one owned CSRF input per actionable target region, existing method/action/enctype
and pack structure. Create/update/custom/delete retain their current full-path POST action. Preserve conditional
and formset lifecycle behavior, raw ownership checks, literal escaping and existing submitter identity.

Supported delete/custom/workflow modal paths retain existing loading, 422 replacement, focus and dismissal
lifecycle. Cancel follows the resolved destination; it is not redefined as modal dismissal. Create/update,
including their formset variants, remain unsupported for modal opt-in and retain E251. Protected deletion keeps
its absent-form branch. Existing workflow no-choice branch differences between page and modal stay unchanged.
Save, successful deletion, `cv_success_keys`, Location and modal redirect headers retain their existing behavior.

### Immediate template migration — D-13–D-14

Plan 03 adds the context-taking tag `cv_cancel_url(context, obj=None)`, which delegates to the view resolver.
The required template recipe loads `crud_views`, resolves `{% cv_cancel_url as cancel_url %}`, and renders the
existing escaped Cancel anchor/control only inside `{% if cancel_url %}`. Preserve existing theme classes and
translated label; do not use `safe` or generic action-link generation to rebuild the URL. The tag must not swallow
configuration failures. Its object argument follows the existing empty/unresolved-to-None convention.

The old `{% cv_context_url view.cv_get_cancel_key as url %}` recipe is immediately unsupported for cancellation.
Retain the underlying key helper for other callers; do not advertise reduced-function compatibility. Custom form
action/helper code must filter an omitted `get_cancel_button()` before layout construction while retaining submit
and ownership. Publish executable recipes, defaults/static overrides, session effects, permission omission and
diagnostics, paired with CHANGELOG Breaking and `docs/migrating-1.0.md`. Plan 04 owns publication and examples.

## UI Considerations

Applicable state considerations resolved: pending the orchestrator's post-checker probe. No probe has run for
this draft; the following surfaces and authored requirements are its input, not a claim of probe approval.

| ID | UI surface | Element kinds |
|----|------------|---------------|
| E1 | Standard create/update/delete and object/no-object custom form, fields, validation and action group | form, interactive-control, static-content |
| E2 | Cancel button/native link and guarded custom-template navigation, including permission omission | nav, interactive-control |
| E3 | Origin and restored list/card collection, filter form, sorting and pagination controls | list-collection, form, nav, interactive-control |
| E4 | Existing object detail page and its sibling navigation into update/delete | static-content, nav, interactive-control |
| E5 | Polymorphic type-selection form and handoff into concrete creation | form, nav, interactive-control |
| E6 | Supported modal form, invalid replacement, Cancel and existing close control | form, nav, interactive-control, static-content |
| E7 | Protected-delete notice and related-object preview where the confirmation form is absent | static-content, list-collection |

State requirements for probe extraction:

- **Empty and partial forms (E1/E5/E6):** keep real blank/optional fields, labels and help. Invalid or incomplete
  submissions preserve values under existing conditional rules and retain original Cancel capture. Never add a
  placeholder form, synthetic object identity or empty-state heading. Selector choices remain the existing allowed
  choices; preserve its current required-field validation if no selection is made.
- **Empty/zero-one-many collections (E3/E7):** preserve the Copywriting Contract's existing empty output and
  permission-filtered content. A zero-row authorized list is not a denied destination. One or many records keep
  existing row/card layout, ordering, pagination and counts; restoration changes state, not collection rendering.
  Related-object previews retain current zero/one/many and incomplete-preview branches and count wording.
- **Populated/partial collections (E3/E7):** display current authorized records at the restored filter/order/page,
  not snapshots of records captured earlier. Preserve optional values and current pagination/error behavior if
  underlying data changed. Do not invent records, replacement pagination policy or exhaustive preview claims.
- **Loading (E1–E6):** keep native page navigation and existing modal pending behavior. No independent capture
  fetch, spinner, skeleton, optimistic write or new disabled-control policy is introduced. Preserve modal content
  and existing focus lifecycle while requests are pending; browser navigation handles native request progress.
- **Errors (E1–E6):** use existing field/non-field feedback and modal full-page failure fallback. Invalid origin
  input selects fallback without a banner; denied destinations cause omission; bad configured fallback remains
  developer-facing. A destination rejected after render follows normal authorization/error behavior. No new
  collection retry UI, generic alert or alternate destination is invented.
- **Overflow and long text (E1–E7 where applicable):** retain full escaped translated labels, object names, values
  and notices with the current pack/theme wrapping, table scrolling and responsive structures. Preserve existing
  action-group wrapping; add no fixed-height box, ellipsis, truncation or label derived from a URL. Captured query
  is an attribute value, never a visible long label. Existing nowrap/unbroken-text limitations remain preservation
  limits; this phase does not certify arbitrary host CSS containment at every viewport.
- **Keyboard/accessibility (E1–E6):** preserve native names, focus styling and tab order. Verify keyboard Cancel
  on both button and anchor, omitted Cancel with usable submission, and focus after supported modal replacement.
  No autofocus jump is added to compensate for omission. Human focus/assistive-technology acceptance remains
  pending until recorded; automated DOM checks are not a substitute for those observations.

No independent media surface, real-time/offline/optimistic state, new RTL policy or animation is introduced.
Icons remain existing decorative control content with preserved accessible names. Browser-only input, scroll
position, history stacks, cross-ViewSet returns and unsaved-input restoration are excluded by D-16.
