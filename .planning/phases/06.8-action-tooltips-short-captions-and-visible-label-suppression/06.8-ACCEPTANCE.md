## Investigation and repair

D-05's confirmed defect was long icon-only action tooltip captions in stock and an unidentified application.
The stock/custom mixed-mode investigation found visible inline controls already obey the intended suppression
contract. This report does not claim a separately reproduced visible-label inline defect or identify the
external application. The context-menu native-title removal is the explicit D-07 behavior change.

The new live modal acceptance exposed a separate existing Bootstrap 5.3.3 lifecycle race: its queued show/hide
transition callbacks dereferenced nulled instance state after synchronous disposal during fast replacement.
[Original failing evidence](06.8-browser-before-lifecycle-fix.json) retains the real stacks and source hashes;
[validated regression RED](06.8-03-lifecycle-red.json) independently demonstrates the stale callback.
The orchestrator explicitly authorized the minimal necessary repair. `cv.bootstrapAdapters().tooltip.init`
now guards each initialized instance's queued completions by current instance identity. Disposal remains
synchronous before detachment; live callbacks preserve arguments, receiver, return values and errors.
Animations are not disabled and browser errors are not filtered out.

Compatibility limit: this narrowly uses Bootstrap's private `_queueCallback` seam, verified against the cached
5.3.3 implementation. The guard is conditional when that method/getInstance are present, and does not claim
universal compatibility with future internals or independently initialized third-party tooltip instances.
Custom adapters continue to own their behavior. Independent phase code review remains required.

Fixture corrections during development registered ContextButton objects via `cv_context_buttons`, retained
modal focus using Shift+Tab/Tab rather than a backdrop-dismissing body click, and paired response waits with
their triggering actions so errors reach owned cleanup. Asset response bytes are hashed on first load before
navigation invalidates Chromium response handles. These corrections did not alter production action behavior.

## Review follow-up: startup failures and actual fonts

WR-01 was reproduced with `CV_CANCEL_PYTHON=/tmp`: Node exited on an unhandled `EACCES` event and left
a seeded passing report untouched. The runner now rejects a directory override, handles asynchronous
child-process launch errors immediately and passes the original error through the failed-report writer.

wait for a nonexistent process exit. Real subprocess regressions cover an executable with a missing shebang
interpreter (OS `ENOENT` after validation), a directory override, and a fixture exiting before readiness.
They require fresh failed JSON, replacement of stale success where applicable, bounded termination and
absence of the owned PID after exit. [Validated RED evidence](06.8-03-spawn-red.json) retains the initial failures.

not repeated for this runner/test-only follow-up; their earlier results above remain historical evidence.
