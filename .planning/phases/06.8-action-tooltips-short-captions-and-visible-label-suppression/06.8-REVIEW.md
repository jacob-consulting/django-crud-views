### Resolved finding: WR-01 — Fixture spawn errors bypassed the failed-evidence writer

**Original classification:** WARNING — **RESOLVED in `5af66b8`; excluded from open counts.**  
**Original file/lines:** `/home/alex/projects/alex/django-crud-views/tests/browser/action-tooltips.cjs:74-86`  
**Related:** `tests/browser/action-tooltips.cjs:355-364`; imported runtime/termination helpers in `tests/browser/cancel-navigation.cjs:72-84`.

**Issue:** `cp.spawn()` reports operating-system launch failures through the child's asynchronous `error` event. `startServer()` attaches only stdout/stderr listeners and polls exit state; its surrounding `try/catch` does not catch that event. The unhandled event terminates Node before `main()` reaches its catch/finally and writes the failed JSON. The shared runtime check accepts existing searchable directories because it checks existence and `X_OK`, so this is reachable through the supported `CV_CANCEL_PYTHON` override. Other spawn failures can reach the same path even with a file. A reused output path can consequently retain an earlier passing report after the new run failed.

**Reproduction:** From the checkout, with the existing cached prerequisites:

```bash
CV_CANCEL_PYTHON=/tmp \
CV_CANCEL_ASSETS_DIR="$HOME/.cache/django-crud-views/cancel-assets-06.7" \
node tests/browser/action-tooltips.cjs --case smoke \
  --output /tmp/cv-068-review-spawn-error.json
```

Observed exit code 1 with `Unhandled 'error' event` / `spawn /tmp EACCES`; the requested output file did not exist afterward. No browser or fixture server was started. The existing missing-runtime test exercises validation before spawn and therefore misses this failure path.

**Fix:** Handle the child's `error` event immediately after spawning and reject the awaited startup operation so `main()` records the original error. Preserve owned-child cleanup for failures after a successful spawn; do not introduce an unconditional wait for an `exit` event on launch failure. Add a bounded subprocess regression using an existing directory as `CV_CANCEL_PYTHON`, requiring a fresh failed JSON report and normal termination; also check that an old passing output is replaced. Rejecting directories during runtime validation is useful, but does not replace handling asynchronous OS spawn errors.

**Resolution verified:** The child now has an immediate error listener, startup polling throws the captured error, failed startup records owned-process state, and `main()` writes failed evidence. Directory validation runs inside the reporting try/finally. A focused replay of the missing-shebang-interpreter, directory/stale-report and early-exit tests passed (3/3), including after WR-02's test isolation. The OS failure report replaces seeded success, and the early-exit test verifies the owned PID has disappeared. No runtime repair defect remains from WR-01.
