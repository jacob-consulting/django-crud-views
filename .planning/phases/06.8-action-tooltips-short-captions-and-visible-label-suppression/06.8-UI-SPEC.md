## Interaction and Caption Matrix

| Surface / condition | Required rendering and behavior |
|---------------------|---------------------------------|
| Context/list, effective icon, nonempty full and short | Emit short title and data-cv-tooltip location; retain exact full hidden span and full accessible name |
| Short absent, None or empty | Use full-caption fallback for title; no whitespace stripping or new definition of empty |
| Short equals full | One action and one hidden caption; no duplicate visible caption |
| Both captions empty, real icon | Preserve effective icon mode and empty hidden span; no generated title, marker, tooltip instance or invented accessible name |
| Full empty, short nonempty, real icon | Preserve forced effective icon mode and empty hidden span even if configured label/both; emit short title/marker. Existing Bootstrap hydration supplies the short aria-label/name for this otherwise empty control |
| Icon missing, full nonempty, non-strict | Existing fallback selects visible label mode; no generated title or marker; retain warning |
| Icon missing, full empty, short nonempty, non-strict | Preserve effective icon mode, empty hidden span and short title/marker; do not invent a visible icon, visible short fallback or server aria-label; retain existing warning. Python edge coverage suffices per plan 01 |
| Icon missing in strict effective icon mode | Preserve existing configuration exception; do not silently substitute another icon or mode |
| Effective label/both | Preserve visible short label and icon behavior; no generated title, marker, Bootstrap instance or tooltip bubble |
| Context/list/card overflow item | Visible resolved short caption; no generated title or marker regardless of inline mode, even when normalized data contains cv_title |
| Card inline action | Preserve explicit card label → short caption → full caption → key precedence; card title uses that resolved caption |
| Form control | Preserve separate resolved-caption path and caller-owned extra attributes; do not globally remove title/data-cv-tooltip |
| Disabled action | Preserve disabled tag/state, omit href/submit/modal hooks as before. Icon controls may retain short title/marker and initialized instances; do not require a displayed disabled tooltip |
| Active/denied action | Preserve active state and aria-current; unauthorized hidden actions remain absent; disable-policy controls retain their existing disabled semantics |

Keep links as links and POST actions as their existing targeted submissions. Preserve modal triggers,
action order, grouping, zero/one/many menus, icon-host classes and label-mode owner/theme/project precedence.
Repeated and independent request renders must not mutate caption inputs or share projected state.

The existing tooltip adapter owns initialization, hover/focus, click hide and disposal. Keep
DOMContentLoaded and dynamically loaded modal/formset initialization; dispose old modal instances before
replacement; initialize new nodes on replacement/reopen. No production JavaScript change is needed solely
for caption shortening. No placement, delay, focus navigation or keyboard redesign is authorized.

Bootstrap relocates title during initialization, so an absent hydrated title alone cannot prove tooltip
suppression. Browser acceptance must inspect raw title/marker, actual instances and shown tooltip text.
Nonempty full accessible names remain exact. The explicit empty-full edge above follows existing Bootstrap
behavior; do not add a server-generated aria-label to make it resemble the nonempty case.

Keep Django escaping for plain/lazy strings and untrusted values interpolated into caption templates.
Quoted/Unicode/markup-shaped text must display literally without attribute/element injection. Existing
trusted template literals and arbitrary SafeString inputs retain their trust boundary; no new sanitization
claim is made. Sources: CONTEXT.md D-01–D-11; plans 01 and 03; current button_data.py and action/menu leaves.

## Migration and Acceptance Contract

Copied action/menu templates must adopt this behavior immediately. There is no supported temporary legacy
tooltip path. An action copy already consuming guarded cv_title and full hidden cv_label needs no markup
edit but must adopt the changed field semantics. A copied menu must remove automatic title/marker emission.
Raw ContextButton templates must use the existing normalizer/tag before assuming flat leaf fields.
Retain full-caption/helper APIs and app-owned attributes; add no diagnostics or caption settings.

Plan 02 owns the paired Unreleased Breaking entry and docs/migrating-1.0.md action-tooltips guidance,
including links from both existing markup and silent-break checklists. Canonical complete action/menu/raw
recipes live in docs/reference/buttons.md and are executed from their exact fence bodies. The action and
menu copies carry their own root recipe identities and preserve all normal action hooks; they must not
delegate to stock leaves. Plan 03 uses those same exact bytes and hashes for browser custom fixtures.

Real-browser acceptance covers stock Bootstrap and migrated custom templates, with short hover/focus
tooltips, independent full names, mixed icon/label/both actions, visible missing-icon fallback, every menu
location, caption edges, permission/disabled states, real link/POST/modal flows, and nonzero hide/disposal/
reinitialization observations across modal replacement. Keep the scoped non-strict specimen isolated.
Record stock/custom/stock template isolation and current source/runtime/assets/recipe identities.

Retain six phase-owned screenshots for stock/custom tooltip, menu and modal cases with relative paths and
hashes in browser evidence and links in acceptance. Human review remains pending until actually performed;
browser accessible-name checks do not establish screen-reader testing. Plan-01 passing focused tests are
reported in its SUMMARY, not newly executed by this specification. Later plans must record actual browser,
documentation and full-suite results and their runtime limits.

The confirmed defect is long icon captions. Report the actual visible-inline investigation result honestly;
do not claim a separately reproduced visible-label defect from the menu change. External-application
verification is not a completion gate. Informational property-detail tooltips, filter toggles, formsets,
card-order controls and unrelated golden output remain outside the changed caption rule.
