## 06.9-02

### Summary
Plan 02 is the authorization plan and remains the most intricate. The Guardian fixture reachability problem (A03) is solved concretely with a scoped registry copy plus a temporary Guardian Contract ViewSet, which works because the registry is keyed by name and already tolerates duplicate models. The actor/parent/grant alias topology gap (A04) is addressed by reusing an existing private helper that really exists with the stated signature. The query-cost bound (A02) is now numeric. Three small clarifications remain, none blocking.

### Strengths
- **A03 is implementable as written.** `_REGISTRY` is an `OrderedDict` keyed by ViewSet name (`viewset/__init__.py:43, 146-151`); `cv_publisher` and `cv_guardian_publisher` already share a model (`tests/test1/app/views.py`), so a temporary `GuardianViewSet(model=Contract)` registers cleanly, and excluding existing Contract ViewSets from a copied registry lets the unmodified default hook (`delete.py:190-191`) select it. `delete.py:187` imports `_REGISTRY` at call time, so either in-place or attribute patching works; the in-place pattern exists at `test_delete_migration_docs.py:44-192`.
- **Composition-error semantics correctly separated.** `GuardianParentPermissionMixin._cv_cancel_target_available` raises `ImproperlyConfigured` before any auth (`mixins.py:249-251`); the plan keeps lookup-before-availability and tests absent-child and eligible-child outcomes separately, which is exactly the distinction Gemini asked for.
- **A04 reuse target exists.** `_PermittedPks._projection_actor(model, *, using)` (`views.py:136-185`) certifies actor alias, routes and reloads a same-alias actor; using it only as a predicate, not `__call__`, avoids enumerating grants. Parent alias equality via `_cv_cancel_parent_object` (`base.py:835-847`) is the right seam.
- **A11 covered.** Spying separately on source and target `cv_action_enabled` catches the re-evaluation that `has_permission` (`base.py:1072-1082`) already performed once.

### Concerns
- **LOW (new) — "Reuse the single parent lookup" needs its mechanism named.** The unchanged Guardian hook calls `rendering_view._cv_cancel_parent_object()` (`mixins.py:257`), which calls `self.cv_get_parent_object` with no cache (`base.py:841-845, 1023-1035`). With shared edits forbidden, the only way to honour "a single destination-parent lookup" is an instance-level shadow of `cv_get_parent_object` on the fresh destination; `base.py:842`'s override predicate will then treat the shadow as an application override and skip the `Http404` catch, which is fine because the shadow returns an already-resolved object. The plan should either name that instance-shadow mechanism or accept two parent reads and size the budget accordingly.
- **LOW (new) — A02 constants are unmeasured hypotheses.** `Q(N) <= N` and `Q(N) <= 12*N + 4` were written without a run. If stock cost is, say, 14 per Guardian candidate, the executor faces a bound failure with no sanctioned path except a deviation, and the forbidden path is "optimise shared Guardian code". The linearity ratio `3*(Q(8)-Q(4)) <= 4*(Q(4)-Q(1))` is the real invariant and holds with equality for exactly linear growth. Also, "keep a deliberately failing excess-query control in the regression design" is ambiguous: a permanently failing test cannot live in the suite; presumably a mutation-style check is intended.
- **LOW (new) — Unparented core fixture is unnamed.** `Q(N) <= N` for "unparented core candidates" needs a core detail destination for a protected relation without a parent; the test app has none (`Contract` is nested under Publisher, `tests/test1/app/models.py:79-80`, `views.py:485`; `Royalty` has no ViewSet). 02-01 specifies registry isolation for its Guardian fixture, but 02-02 (in `test_delete_databases.py`) does not say how its unparented core destination is created.

### Suggestions
- In 02-02, state that the parent object is reused via an instance attribute on the fresh destination (or drop "single lookup" and budget two reads).
- Reword A02 constants as initial bounds: record measured values in SUMMARY and allow a documented constant adjustment while keeping the ratio check mandatory; replace "deliberately failing control" with "a mutation check that an injected per-candidate extra lookup violates the bound".
- Name the unparented core fixture (e.g., a temporary unparented `ViewSet(model=Contract)` under the same registry isolation as 02-01, or an `isolate_apps` blocker).

### Risk Assessment
**MEDIUM.** The design is correct and every mechanism exists; residual risk is implementation friction from three unstated details, not design error. A02, A03, A04, A11 are closed as planning findings.
