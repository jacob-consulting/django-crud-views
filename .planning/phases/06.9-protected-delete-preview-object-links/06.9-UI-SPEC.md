## Interaction and State Contract

| Condition | Required rendering and interaction |
|-----------|------------------------------------|
| Preview and linking enabled; eligible visible blocker | One li with ordinary a href containing the complete escaped label |
| Visible blocker without an eligible URL | One li with escaped plain text; no anchor, empty href, tabindex or synthetic disabled control |
| Linking disabled | Same ordered obj/url entry shape, every url=None; plain text and zero protected URL work |
| Preview disabled | Existing limited context; omit detailed collections/URLs; blocking remains independent of visibility |
| Zero visible blockers but unfiltered blockers exist | Existing generic blocked heading/body; entire confirmation form absent |
| One or many visible blockers | One list item per filtered entry, original order, no deduplication for equal names or PKs |
| Mixed link/text/hidden records | Render permitted links and visible text fallbacks together; hidden rows never reach URL generation or markup |
| Protected and cascade data together | Preserve existing alert ordering and cascade summary/tree behavior; never treat a linked blocker as deletable |
| Page link activation | Native full-page detail navigation to the emitted href; current browsing context, not a new tab |
| Modal link activation | Native full-page detail navigation exits the delete modal, even for a modal-capable detail destination |
| Keyboard activation | Anchor participates in ordinary Tab order; Enter activates that exact focused anchor; retain focus styling |
| Delete submission while blocked | Existing server protection and response behavior; no form or added Cancel action in blocked UI |
| Permission or row changes after preview | Actual destination request remains authoritative; existing redirect/403/404 handling applies |
| Application/operational failure | Preserve existing server error handling; do not silently turn unexpected failures into empty or successful previews |

Anchors contain no modal/action-trigger metadata, AJAX behavior or modal replacement/stacking logic. Keep the
existing alert-dismiss behavior; dismissing an alert never grants deletion or reveals a form. Neither preview
nor link generation writes data or executes deletion callbacks.

The protected body explicitly enables Django autoescape for ordinary labels and URL attributes, including when
an ancestor disables autoescape. Preserve existing trusted SafeString semantics; this is not a new arbitrary
HTML sanitization API. Maintain list/alert semantics and the visible label as the accessible link name.

Rendering remains server-side and synchronous. There is no new loading spinner, skeleton, optimistic state,
retry control or live-region mechanism. Existing browser navigation/loading and modal lifecycle feedback remain.
Partial cascade counts retain their existing incomplete-preview warning; partial protected URL availability is
represented by per-item plain-text fallbacks, without dropping visible items.

Long labels and lists retain natural text wrapping and document/modal scrolling. No imposed truncation,
line clamp, pagination, max-height or fixed row width is added. Unbroken strings retain the host theme/browser's
existing overflow behavior; this phase does not introduce a universal word-breaking rule. Do not claim new
responsive or assistive-technology acceptance from preservation alone.

## Context, Customization and Migration Contract

Enabled previews expose one ordered protected_objects collection whose entries contain exactly obj (model
instance) and url (string or None). Link-disabled entries keep the same shape. RelatedObjects.protected,
provider results and visibility-filter inputs remain model-instance collections. has_protected_objects is
computed independently before display filtering and continues to govern blocked deletion/form omission.

The public body path is crud_views/snippets/delete/protected_objects.html. Bind items=protected_objects in
caller context and invoke cv_alert with body_template; do not pass the dictionaries through generic alert
items normalization. Overriding only the body preserves the shared alert frame, translated heading, icon,
role and dismissal. No new generic alert-item API, flag or setting is introduced.

The existing cv_get_related_object_url hook retains its signature and cascade semantics. Protected candidates
must identify inspectable local registered detail destinations for the same model/typed-PK/database row and
pass the destination access/state/queryset/parent policy. Missing/ineligible routes and expected denials yield
text. There is no fallback registry scan. The private adapter is not a new public authorization API; arbitrary
middleware, dispatch and custom object lookup remain enforced by the actual destination request.

D-01/D-02 require immediate copied-template migration without a parallel legacy model collection. Plan 03
owns paired Breaking/migration guidance, updated delete/theme references and accurate existing example guidance.
The complete copied content/related/body recipes use myapp/delete.content.html, myapp/delete_related.html and
myapp/delete_protected.html with uniquely adjacent protected-delete-recipe markers. Execute the exact documented
fence bytes, including their final LF. The custom body has data-protected-delete-recipe="body" so its use is
observable; stock and custom rendering retain identical link/text/escape/blocking behavior. Model-field access
in copies goes through entry.obj. Phase 7 receives these exact names and the unchanged hook boundary.
