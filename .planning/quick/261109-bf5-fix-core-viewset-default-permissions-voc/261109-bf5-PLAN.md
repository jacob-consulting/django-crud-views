<objective>
Remove the N+1 in the core `ViewSet.default_permissions` vocabulary loop: on a cold ViewSet it does one
`ContentType.objects.get_for_model`, one `Permission` query, and then reads `content_type` through the Permission
row's foreign key once per row (`.model` for suffix stripping, `.app_label` for the permission string), so a
four-permission model costs five `django_content_type` queries instead of one. `GuardianViewSet.default_permissions`
(`src/crud_views_guardian/lib/viewset.py`) already uses the single resolved content type; the core loop will do the
same. Semantics stay byte-identical: suffix stripping of the codename (#33), no caching of an empty result (#151),
the Resource guard, and the OrderedDict order (Django's `Permission.Meta.ordering`, one query with a join).

Purpose: the 06.18 cost measurement (06.18-COSTS.md cells 1-6 and 13-18, "Cold vocabulary") attributed ct 5 per
gated ancestor (ct 15 at depth 3 full cascade) to this pre-existing loop and logged it in deferred-items.md. The user
asked, after reviewing cells 1-4 during 06.18 UAT, to fix it on this branch. The fix is the smallest bounded change
(two attribute reads move to the already-resolved local), consistent with the CLAUDE.md maintainability rule and with
the sibling Guardian override.

Output: fixed `ViewSet.default_permissions`; a red-then-green regression test in `tests/test1/test_viewset.py`;
re-measured cost evidence under the phase's `evidence/261109-bf5/`; 06.18-COSTS.md, deferred-items.md and
CHANGELOG.md updated; full multicore suite green.
</objective>
