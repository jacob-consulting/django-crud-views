## 06.10-01

### 1. Summary
Plan `06.10-01` introduces the shared parent-chain resolver (`src/crud_views/lib/viewset/resolution.py`), adds the public request-free helpers `ViewSet.get_parent_pks()` and `ViewSet.get_url()` to `src/crud_views/lib/viewset/__init__.py`, and rewires `CrudView.cv_get_router_and_args()` in `src/crud_views/lib/view/base.py:576-610` to use object-over-page precedence for object destinations while preserving page scope for collection destinations. The design accurately targets the root defects in `cv_get_router_and_args()` (in-place caller dict mutation, unconditional page-kwarg overwrite, and truthiness checks on parent kwargs) and establishes a typed internal resolution outcome rather than broad `ValueError` suppression. However, there are subtle exception-contract differences between `ViewSet.get_url()` and existing `CrudView` callers, multi-table inheritance PK extraction traps, and potential reverse-relation side effects on `Publisher` in `tests/test1/app/models.py` that require explicit care during implementation.

### 2. Strengths
- **Fixes actual root-cause bugs in `CrudView.cv_get_router_and_args()`:** In `src/crud_views/lib/view/base.py:586-605`, the current implementation aliases `kwargs = extra_kwargs if extra_kwargs else {}` (mutating the caller's dict in place), unconditionally overwrites caller parent keys with `self.kwargs.get(name)` at lines 599–603, and rejects valid falsey PKs (`0`, `""`) via `if not value: raise ValueError(...)` at lines 601–602. Copying input dicts, separating explicit vs. page kwargs, and checking `is None`/key presence directly fixes all three defects.
- **Metadata-aware `ForeignKey.to_field` handling aligns with `ViewSet.get_queryset()`:** In `src/crud_views/lib/viewset/__init__.py:297-302`, `ViewSet.get_queryset()` filters nested querysets using `q_kwargs.update({f"{attribute}__pk": view.kwargs[pk_name]})`, which joins on `to_field` but compares against the parent model's actual primary key (`__pk`). Requiring `field.target_field == parent_model._meta.pk` before taking the raw FK `attname` shortcut prevents `to_field` values from being emitted into `<parent_pk>` URL kwargs where `get_queryset()` would 404.
- **Typed internal unavailability result preserves D-12/D-14:** Returning a structured `_ParentResolution` with `unavailable_reason` instead of catching `ValueError` around the public operation guarantees that custom `@property` or `cv_get_url_extra_kwargs()` exceptions (and caller conflicts) propagate even when `strict=False`.
- **Preserves `Resource` leaf-only and import-leaf invariants:** `src/crud_views/lib/resource.py:9-16` must remain an import leaf (`Resource` exposes row PKs via `_PkShim` at `resource.py:87-104`), and `src/crud_views/lib/viewset/__init__.py:216-225` (`E261`) enforces that `Resource` ViewSets can only be leaves. Reading only `obj.pk` for `self.is_resource` and deriving parent PKs solely from supplied `parent_obj`/`kwargs`/page scope respects both constraints.

### 3. Concerns
- **[HIGH] Adding a new `ForeignKey(Publisher, ...)` in `tests/test1/app/models.py` alters `Publisher`'s reverse relation graph for deletion inspection suites:** Task `01-02` proposes adding `NestedUrlParent` with a "root FK to Publisher" in `tests/test1/app/models.py`. In `src/crud_views/lib/deletion.py:118`, `_DeleteInspector.visit()` iterates `get_candidate_relations_to_delete(Publisher._meta)` for every `Publisher` deletion preview across `tests/test1/test_delete.py`, `tests/test1/test_guardian_delete.py`, `tests/test1/test_delete_inspection.py`, and `tests/test1/test_delete_databases.py`. Adding a permanent reverse relation onto `Publisher` adds extra `SELECT` queries to every `Publisher` deletion inspection (e.g., `tests/test1/test_delete_inspection.py:54`) and, if any non-cascade `on_delete` is used, changes `inspection.boundaries` on `Publisher` (e.g., `tests/test1/test_guardian_delete.py:271` asserts `len(boundaries) == 1`).
- **[MEDIUM] Exception type divergence between `ViewSet.get_url()` and `CrudView.cv_get_router_and_args()` / `cv_get_cls_assert_object()`:** The resolution contract table states that an unknown destination key raises `NoReverseMatch` in strict mode and that a missing required object raises `ValueError`. However, in `src/crud_views/lib/viewset/__init__.py:342`, `ViewSet.get_view_class(key)` raises `ViewSetKeyFoundError` (which subclasses `CrudViewError` in `src/crud_views/lib/exceptions.py:12`, not `NoReverseMatch`), and `CrudView.cv_get_cls_assert_object()` (`src/crud_views/lib/view/base.py:550-556`) raises `CrudViewError` when `obj` is missing. Crucially, `CrudView.cv_resolved_actions()` (`base.py:674`), `_cv_get_action_context()` (`base.py:748, 754`), `_cv_cancel_origin_url()` (`base.py:893`), `_cv_cancel_fallback()` (`base.py:914`), and `LinkDetailColumnMixin.get_url()` (`src/crud_views/lib/table/columns.py:48`) all explicitly catch `ViewSetKeyFoundError`. If `cv_get_router_and_args()` or `get_view_class()` translates unknown keys to `NoReverseMatch`, those existing `except ViewSetKeyFoundError:` handlers will break.
- **[MEDIUM] Multi-table inheritance with a distinct child PK can return the wrong parent identifier if `.pk` is read directly on a subclass instance:** When a compatible subclass instance is passed as `parent_obj` (or traversed via a relation), reading `parent_instance.pk` returns the subclass's most-derived PK. While standard multi-table inheritance (`Car(Vehicle)` in `tests/test1/app/models.py:178`) shares the parent's PK via `vehicle_ptr`, a multi-table subclass with its own non-parent-link primary key has `subclass_instance.pk != getattr(subclass_instance, parent_model._meta.pk.attname)`.
- **[LOW] `cv_get_cls_assert_object()` truthiness check on `obj` and `obj.pk`:** In `src/crud_views/lib/view/base.py:555`, `cv_raise(cls.cv_object is False or (cls.cv_object is True and obj), ...)` uses `bool(obj)` (which fails if a custom model or `Resource` defines `__len__` returning `0`) and does not check `obj.pk is not None` (`base.py:591` blindly puts `obj.pk` into `kwargs` even when `obj.pk is None`, which only later fails inside `reverse()`).

### 4. Suggestions
- **Isolate the 3-level test root model from `Publisher`:** In `tests/test1/app/models.py`, either add a dedicated `NestedUrlRoot` model as the root of `NestedUrlParent -> NestedUrlChild -> NestedUrlLeaf` (4 models = 3 parent levels) or use `Profile` (`tests/test1/app/models.py:202`), leaving `Publisher`'s reverse relation graph in `get_candidate_relations_to_delete(Publisher._meta)` completely untouched.
- **Keep `ViewSetKeyFoundError` on `get_view_class()` / `cv_get_router_and_args()` and translate only in `ViewSet.get_url()` (if desired):** Have `ViewSet.get_url(key, ...)` catch `ViewSetKeyFoundError` and either return `None` when `strict=False` or raise `NoReverseMatch` (or document `ViewSetKeyFoundError`) when `strict=True`, while keeping `ViewSet.get_view_class()` and `CrudView.cv_get_cls_assert_object()` raising `ViewSetKeyFoundError` so `base.py:674, 748, 754, 893, 914` and `columns.py:48` continue to work unchanged. Also check `obj is not None and obj.pk is not None` instead of truthiness on `obj`.
- **Extract parent PKs via the registered parent model's PK field:** Use `parent_vs.model._meta.pk.value_from_object(parent_instance)` (or `getattr(parent_instance, parent_vs.model._meta.pk.attname)`) after `isinstance(parent_instance, parent_vs.model)` validation, rather than `parent_instance.pk`.

### 5. Risk Assessment
**Risk Level: MEDIUM**
The core resolution matrix and query bounds are well-specified, but sharing code between `ViewSet.get_url()` and `CrudView.cv_get_router_and_args()` requires preserving `ViewSetKeyFoundError` for view callers and keeping `Publisher`'s reverse-relation metadata clean for existing deletion tests.
