## Resolution contract

Classify the target by its actual `cv_object`, including list-to-card fallback. Public kwargs are explicit; the private assembler accepts separate page kwargs. Copy all dictionaries. Missing means None/absent, never merely falsey.

| Destination/context | Selected ancestry | Invalid/unavailable rule |
|---|---|---|
| Object with actual single-parent chain O and page W | O at every known level | Ignore stale W, never splice unrelated W ancestors |
| Object with explicit kwargs E and/or parent_obj P | O, checking E/P at every known level | Any explicit known conflict is ValueError in both modes |
| Collection with W, own-child O, no E/P | Coherent W | O may differ; null O does not invalidate independent W |
| Collection without W/E/P, with own-child O | O | Missing/null required scope is unavailable |
| Collection with E/P | Explicit coherent chain | Validate E against P and known O; callers choosing a different collection omit contradictory obj |
| M2M boundary with E/P or W | Supplied context | No membership query or related-manager iteration, even for zero/one/many parents |
| M2M without supplied context | Unavailable | ValueError strict, None optional |
| Resource row with supplied E/P or W | Supplied context | Read row PK only; preserve Resource leaf-only restriction |
| Required object or PK missing | Unavailable | ValueError strict, None optional |
| Unknown destination key/native reverse mismatch | Unavailable route | NoReverseMatch strict, None optional |

`parent_obj` is the immediate parent; derive its ancestors through the same resolver. Own-model `obj` is a child/destination, including compatible proxy/inherited instances. An unambiguous immediate-parent instance may serve as collection parent context; self-nesting ambiguity is resolved only by explicit `parent_obj`. An object destination still needs an own-model row. Wrong-model inputs and malformed explicit identifiers always raise ValueError.

Choose a chain as a unit. Partial explicit context can fill from object/parent evidence only when overlapping normalized identifiers agree. Page fragments may fill an unresolved boundary only when the known connecting parent agrees; otherwise report unavailable instead of combining two chains. Full explicit kwargs without object evidence require no relationship lookup: they assert coordinates, not membership or ancestry validity. Normalize comparisons with the corresponding model PK field; preserve native values for Django reverse.

Recognized unavailability is an internal result, never inferred by broadly catching ValueError. Evaluate custom properties/managers and URL hooks outside native exception suppression. A Django relation descriptor's native missing-row result may be classified only with provenance at that descriptor; custom ValueError/AttributeError/ObjectDoesNotExist/NoReverseMatch retain original exception identity. Catch NoReverseMatch only at stock Django reversal. Extra-kwargs hooks run once; preserve existing non-parent overwrite ordering, but treat their parent values as explicit constraints so they cannot overwrite certified ancestry.

Compatibility boundary (C1-M01/M02): only the new public ViewSet.get_url translates an unknown registered key to NoReverseMatch/optional None. ViewSet.get_view_class and existing view callers retain ViewSetKeyFoundError, including action skipping and LinkDetailColumnMixin's decorator; cv_get_cls_assert_object retains ViewSetError for absent/falsey object instances, because its cv_raise call uses that default exception. Public helpers distinguish obj is None from a supplied falsey compatible instance. A valid PK of 0 is present in either path; absent PK is unavailable in public helpers and follows the existing view assertion/reversal behavior in view wrappers. Ordinary row/action/column URL rendering remains strict: recognized null/unscoped parent unavailability raises ValueError before access/hide/disable rendering; it is not silently changed to an inaccessible action. Optional delete candidates alone use strict=False. Test these boundaries explicitly; no broad exception catch is introduced.

The private resolver accepts an optional materialize_parent switch for access consumers. Retain any known immediate parent/coordinates even if higher ancestry is unavailable; direct-parent permission policy does not become an ancestor gate. Validate wrong-model and malformed explicit inputs before returning an unavailable route result, including when the destination key is unknown.

View-path query contract (C2-M01): record pre-change URL-only counts for the existing two-level BookNote → Book → Publisher fixture at the start of 01-01, before resolver edits. In 01-02 add queries_view_multilevel cases for both a single bound view and an in-scope list of N=1/4 fresh rows, separating relation SQL from row fetching, metadata warmup and permission work. Compare independently fetched rows with creation-cached and select_related ancestry; fixed object/collection action sets must reuse each row's already-loaded relations. Commit exact observed counts and deltas with the existing h-1 ordinary-FK traversal bound, rather than asserting an unmeasured zero delta. Keep the three-level/to_field fixture's separate bounds. Matching the immediate raw FK to page kwargs does not prove older ancestors: include a same-immediate-parent/stale-grandparent case and follow the object URL under actual ancestry per D-01. Page coordinates alone cannot replace that derivation; reuse only already-resolved model evidence whose registered identity/database and connecting relation agree, and still traverse its actual higher chain. Plan 02 measures the complete list render and breadcrumb separately.
